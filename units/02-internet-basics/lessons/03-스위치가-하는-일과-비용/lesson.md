## 출발지에서 목적지까지

네트워크에서 데이터는 출발한 컴퓨터에서 목적지 컴퓨터까지 한 번에 이동하지 않습니다. 중간 네트워크 장비들이 연결된 길을 따라 여러 구간을 거칩니다. 서울에서 부산까지 자동차로 간다고 생각해 보세요. 운전자는 고속도로 진입로와 나들목, 도시의 교차로를 차례로 지납니다. 각 지점에서 다음 구간으로 넘어가야 목적지에 가까워집니다.

네트워크에서는 전달할 데이터를 패킷(Packet)이라는 단위로 다룹니다. 패킷에는 목적지 주소 정보가 들어 있고, 중간 장비는 패킷을 받아 다음 구간으로 내보냅니다. 한 장비가 패킷을 보낸 뒤에는 다음 장비가 이어서 판단합니다. 출발지 장비가 인터넷 전체의 모든 길을 한 번에 지정하는 것은 아닙니다.

이 비유에서 도로망은 네트워크, 자동차 한 대는 패킷, 갈림길은 장비가 다음 방향을 고르는 지점입니다. 실제 네트워크에서는 주소와 표를 이용한다는 점이 도로와 다릅니다. **먼저 기억할 것:** 패킷은 중간 장비들을 거쳐 이동하고, 각 장비는 다음 구간을 정합니다.

## 경로를 선택하는 근거

갈림길에서 방향을 고르려면 근거가 있어야 합니다. 운전자는 목적지 표지판을 읽거나 지도를 보고 우회전할지 직진할지 정합니다. 네트워크 장비도 데이터에서 필요한 정보를 읽고, 연결된 출구 가운데 어디로 내보낼지 고릅니다. 어떤 정보를 읽는지는 장비가 어느 계층에서 동작하는지에 따라 달라집니다.

L2 스위치는 Ethernet 프레임 안의 목적지 MAC 주소와 학습한 정보를 이용해 연결된 장치 쪽으로 전달합니다. 라우터는 패킷의 목적지 IP 주소와 라우팅 정보를 보고 다른 네트워크로 보낼 방향을 정합니다. 웹 트래픽을 다루는 일부 L7 장비는 HTTP 요청의 호스트 이름이나 경로처럼 더 높은 계층의 정보를 보고 분기할 수 있습니다.

그래서 스위칭을 배울 때마다 “무엇을 보고 출구를 고르는가?”라고 질문하면 좋습니다. **외울 틀:** 판단에 쓰는 정보 → 선택할 다음 인터페이스 → 그 정보를 다루는 계층 순서로 연결하세요.

## Switching · 갈 길을 고르기

Switching(스위칭)은 장치가 들어온 데이터를 어느 인터페이스로 내보낼지 선택하는 동작입니다. 인터페이스는 네트워크 케이블이나 무선 연결이 장치와 만나는 접점, 쉽게 말해 데이터를 주고받는 출구입니다. 여러 포트가 있는 장비는 들어온 데이터마다 목적지와 전달 정보를 보고 보낼 출구를 고릅니다.

예를 들어 목적지 IP가 `10.0.0.7`인 패킷이 라우터에 도착했다고 합시다. 라우터는 패킷을 아무 출구로나 보내지 않습니다. 라우팅 테이블에서 목적지에 맞는 항목을 찾고, 그 항목에 연결된 다음 홉이나 인터페이스를 선택합니다. 목적지 IP를 근거로 전달 방향을 정하는 것은 L3 스위칭입니다. IP 주소가 OSI의 L3 네트워크 계층 정보이기 때문입니다.

‘스위치’라는 이름만 보면 물리적인 상자만 떠올리기 쉽지만, 이 Lesson의 핵심은 판단 동작입니다. **외울 문장:** 스위칭은 전달할 데이터의 정보를 보고 다음 출구(인터페이스)를 선택하는 일입니다.

## Router와 라우팅 테이블

패킷은 목적지로 가는 동안 라우터 같은 L3 장비를 만납니다. 라우터는 목적지 IP를 확인하지만 인터넷에 있는 모든 장치의 위치를 하나씩 외우지는 않습니다. 대신 목적지 네트워크와 다음 전달 방향을 연결해 둔 라우팅 테이블을 참고합니다. 라우팅 테이블은 경로를 결정할 때 사용하는 표 형태의 자료구조입니다.

도로 안내판에 ‘부산 방향은 이 고속도로’라고 적혀 있는 것처럼, 라우터의 표에도 목적지 주소 범위와 다음 홉(다음 라우터), 내보낼 인터페이스 같은 정보가 들어갈 수 있습니다. 예를 들어 `10.0.0.7`로 가는 패킷이 오면, 라우터는 그 주소와 맞는 경로 항목을 찾아 다음 방향으로 전달합니다. 다음 라우터에 도착하면 그 장비도 자기 표를 보고 이어서 판단합니다.

출발지 장비가 최종 목적지까지의 모든 이동을 한 번에 정하는 것이 아니라, 각 라우터가 다음 한 구간을 정합니다. **외울 말:** 라우팅 테이블은 ‘목적지 범위 → 다음 전달 방향’을 기록한 표입니다.

## 계층마다 다른 스위칭 근거

계층 번호는 장비가 어떤 정보를 보고 전달을 결정하는지 기억하게 해 줍니다. L2에서는 Ethernet 프레임의 MAC 주소가 중요한 기준입니다. 같은 사무실 네트워크에서 프린터로 프레임을 보낼 때, L2 스위치는 목적지 MAC 주소와 학습한 정보를 이용해 어느 포트 쪽으로 전달할지 판단합니다.

L3에서는 IP 주소를 기준으로 네트워크 사이의 방향을 선택합니다. 라우터가 대표적입니다. L4 정보를 다루는 장비는 TCP나 UDP의 포트 번호를 이용해 서비스 흐름을 분배할 수 있습니다. L7 장비는 HTTP의 호스트 이름이나 URL 경로처럼 응용 계층 정보를 읽어 웹 요청을 다른 서버로 보낼 수 있습니다.

한 패킷에 여러 계층의 정보가 들어 있어도 모든 장비가 모든 정보를 살펴보는 것은 아닙니다. 장비가 맡은 기능에 맞는 정보를 사용합니다. **외울 순서:** L2는 MAC, L3는 IP, L4는 포트 번호, L7은 HTTP 같은 응용 정보를 보고 전달을 결정합니다.

## Metric · 경로의 비용

같은 목적지로 이어지는 경로가 둘 이상이면 선택을 위한 비교 기준이 필요합니다. 라우팅에서 경로를 비교할 때 쓰는 값을 Metric(메트릭)이라고 합니다. 비용이라고 부르지만 실제로 지불하는 돈은 아닙니다. 거리, 링크 속도, 관리자가 정한 우선순위처럼 라우팅 방식이 정한 기준을 숫자로 나타낸 값입니다.

처음 개념을 잡기 위해 낮은 Metric을 낮은 비용으로 비유해 봅시다. 같은 목적지에 이르는 두 후보 경로의 Metric이 10과 50이라면, 이 단순한 비교에서는 10인 경로가 더 낮은 비용입니다. 다만 실제 선택은 목적지 주소 범위와 경로 종류 등 다른 조건도 함께 따집니다. 서로 다른 목적지 범위의 행을 놓고 숫자만 비교하면 안 됩니다.

Metric은 ‘항상 가장 작은 숫자를 고르면 된다’는 규칙이 아니라, 적용 가능한 후보 경로를 비교할 때 쓰는 값입니다. **외울 말:** Metric은 경로를 비교하는 비용이며, 산정 방식은 라우팅 방식에 따라 달라집니다.

## 라우팅 테이블 확인

Windows에서 명령 프롬프트를 열고 `route print`를 입력하면 컴퓨터의 라우팅 테이블을 볼 수 있습니다. 표에는 목적지 네트워크, 네트워크 마스크, 게이트웨이, 인터페이스, Metric 같은 열이 나옵니다. 네트워크 마스크는 뒤에서 자세히 배우므로, 지금은 목적지 범위를 구별하는 정보라고만 생각하면 됩니다.

화면에 Metric 숫자가 여러 개 보여도 표의 모든 숫자를 한 줄로 세워 가장 낮은 값을 고르는 것은 아닙니다. 먼저 목적지 주소와 맞는 항목을 찾습니다. 같은 목적지에 적용되는 후보가 여럿이면 Metric 등의 기준을 비교합니다. 예를 들어 같은 목적지에 적용되는 두 후보의 값이 35와 291이라면, 이 예에서는 35가 더 낮은 Metric입니다. 서로 다른 네트워크 대상에 붙은 숫자는 직접 비교하지 않습니다.

이 명령은 현재 경로 정보를 읽어 보여 주는 진단 명령입니다. 출력값은 컴퓨터의 네트워크 상태에 따라 달라집니다. **확인 순서:** 목적지 범위 찾기 → 적용 가능한 후보 경로 찾기 → 후보들의 Metric 비교하기.

## 패킷·라우터·이정표 정리

도로 비유를 실제 네트워크 용어와 다시 연결해 보겠습니다. 목적지를 향해 이동하는 자동차는 패킷, 교차로는 다음 전달 방향을 정하는 라우터, 갈림길의 이정표는 라우팅 테이블입니다. 이 표를 읽고 어느 길을 택할지 정하는 동작이 스위칭이고, 경로 후보의 비용을 비교하는 숫자가 Metric입니다.

한 번의 전달을 순서대로 따라가면 이렇습니다. 패킷이 라우터에 도착합니다. 라우터는 목적지 IP를 확인합니다. 목적지와 맞는 경로 정보를 라우팅 테이블에서 찾습니다. 후보가 여러 개면 해당 경로들의 조건과 Metric을 비교합니다. 선택한 다음 홉으로 연결된 인터페이스를 통해 패킷을 내보냅니다. 다음 라우터에서도 같은 판단이 이어집니다.

이 Lesson에서 꼭 외울 연결 관계는 네 가지입니다. 패킷은 이동하는 데이터, 라우터는 L3에서 방향을 고르는 장치, 라우팅 테이블은 목적지와 다음 방향을 연결한 표, Metric은 경로 비교 비용입니다. **한 줄 암기:** 목적지 IP 확인 → 라우팅 테이블 조회 → 적용 가능한 경로 선택 → 다음 인터페이스로 전달.
