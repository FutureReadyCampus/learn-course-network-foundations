핵심 개념을 주제별로 정리했다.

## OSI 계층을 훑어보기

OSI 7 layer는 아래에서부터 물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용 계층으로 나뉜다. 이 과정에서는 물리 계층의 전선 규격, 신호 세기, 전압, 이격거리 등을 자세히 다루지 않는다. 데이터 링크 계층에서는 주로 Ethernet을 다룬다. 흔히 접하는 유선 네트워크가 이에 해당하며, 무선 네트워크는 공유기를 통해 익숙하게 접할 수 있다. 네트워크 계층에서는 인터넷을 중심으로 설명한다. 이 계층의 프로토콜이 인터넷만 있는 것은 아니지만, 이 과정은 인터넷에 범위를 맞춘다. 전송 계층에서는 TCP와 UDP를 다루되 TCP를 더 자세히 살펴본다. 그림의 세션 계층에는 TLS를 연결해 설명한다. 예전 이름인 SSL도 널리 사용되며, 응용 계층의 대표적인 프로토콜은 HTTP다. HTTP에 SSL을 결합한 HTTPS도 함께 연결해 이해한다. 표현 계층은 별도로 깊이 다루지 않는다. 처음에는 계층 이름 일곱 개를 한꺼번에 외우기보다, 아래층이 실제 신호와 가까운 부분이고 위층으로 갈수록 프로그램이 쓰는 기능과 가까워진다고 잡으면 쉽다. 예를 들어 브라우저의 HTTP 요청은 아래 계층의 TCP, IP, Ethernet 처리를 거쳐 네트워크로 나간다. 각 층은 자기 역할에 필요한 정보를 덧붙이거나 처리한다.

**외울 순서(아래→위):** 물리 → 데이터 링크 → 네트워크 → 전송 → 세션 → 표현 → 응용. 이 과정에서 Ethernet은 L2, IP는 L3, TCP/UDP는 L4, HTTP는 L7의 대표 예다.

## 계층을 실제 구성요소에 연결하기

계층을 실제 구성 요소에 연결하면 아래에는 NIC와 장치 드라이버가 있고, 그 위에 IP와 TCP를 구현한 소프트웨어가 있다. User mode에는 HTTP를 사용하는 Chrome 같은 브라우저가 놓인다. 그림에서 IP는 L3, TCP는 L4에 해당한다. L2는 드라이버와 하드웨어에 걸쳐 표현된다. 이 절은 아래쪽 구성 요소부터 위쪽으로 올라가며 핵심 내용을 살펴보는 방식으로 진행한다. 노트북에서 브라우저로 웹 페이지를 열면 브라우저가 HTTP 요청을 만들고, 운영체제의 네트워크 기능이 TCP와 IP 처리를 맡으며, 드라이버와 NIC가 Ethernet 프레임을 실제 네트워크로 내보낸다. 한 계층이 모든 일을 하는 것이 아니라 각 구성 요소가 자기 구간의 일을 이어서 수행한다.

## 식별자는 무엇을 구별할까

식별자는 어떤 대상을 구별하는 근거가 되는 정보다. 사람의 이름, 학생의 학번이나 반 번호, 대한민국 국민의 주민등록번호를 예로 들 수 있다. 네트워크에서도 계층마다 어떤 대상을 무엇으로 식별하는지 구분하는 것이 중요하다. 아파트로 비유하면 단지 주소로 건물을 찾고, 건물 안에서는 출입문을 고르고, 도착한 건물 안에서는 방이나 서비스를 찾는 식이다. 네트워크도 통신 단계에 따라 MAC, IP, 포트 번호처럼 다른 식별 정보를 사용한다.

## MAC 주소 · 인터페이스

L2 Ethernet에서 중요한 식별자는 MAC 주소다. 하드웨어 주소 또는 Physical Address라고도 부른다. MAC 주소가 식별하는 대상은 NIC, 즉 네트워크 인터페이스다. 컴퓨터 자체에 하나씩 붙는 식별자로 생각해서는 안 된다. 이 단원의 예에서 컴퓨터에 NIC가 3개 있으면 MAC 주소도 3개, NIC가 5개 있으면 MAC 주소도 5개다. 예를 들어 노트북에 Wi-Fi NIC와 유선 랜 어댑터가 모두 있으면 각각 별도의 MAC 주소를 갖는다. 그래서 ‘노트북 한 대의 MAC 주소’라고 말할 때는 어느 네트워크 인터페이스의 주소인지 확인해야 한다.

**외울 말:** MAC 주소는 컴퓨터 전체가 아니라 NIC 하나하나를 식별한다.

## IP 주소 · 호스트

L3 네트워크 계층에서 중요한 식별자는 IP 주소다. IP에는 버전 4와 6이 있으며, 이 과정에서는 IPv4만 다룬다. 같은 아파트 단지 안에서 여러 집을 구분하듯, IP 주소는 네트워크에서 호스트를 찾아갈 때 사용하는 주소다. 이후에는 IPv4를 네 부분의 숫자로 적는 방법과, 그 주소가 어느 네트워크를 가리키는지 차례로 배운다. 여기서는 우선 ‘IP 주소는 호스트를 식별하는 정보’라는 역할을 기억한다.

**외울 말:** IP 주소는 L3에서 호스트를 식별하고 목적지 네트워크를 찾는 데 쓰인다.

## 포트 번호 · 관점에 따른 의미

IP 주소는 인터넷을 사용하는 컴퓨터인 호스트를 식별한다. L4에서 중요한 식별자는 포트 번호다. 다만 ‘포트’라는 말은 업무와 관점에 따라 다른 대상을 가리킬 수 있다. 케이블을 연결하는 L2 장비를 다루는 관점에서는 물리적인 포트, 즉 인터페이스를 뜻한다. 네트워크 관리 관점에서는 웹 서비스를 위해 포트를 개방한다는 식으로 서비스 식별자라고 설명한다. PC나 서버의 소프트웨어를 개발·관리하는 관점에서는 프로세스를 식별하는 값으로 설명한다. 예를 들어 같은 서버 컴퓨터에서 웹 서버와 다른 네트워크 프로그램이 동시에 실행될 수 있다. IP 주소만으로는 어느 프로그램에 데이터를 전달할지 정하기 어려우므로, 포트 번호를 함께 사용해 목적 서비스를 구분한다. 여기서 케이블을 꽂는 물리 포트와 숫자로 쓰는 포트 번호는 서로 다른 뜻이다. 따라서 포트라는 표현이 나올 때는 물리 인터페이스를 말하는지, 서비스나 프로세스와 연결된 포트 번호를 말하는지 문맥을 구별해야 한다. 컴퓨터의 네트워크 정보를 확인하는 명령으로는 Windows의 ipconfig가 있다.

## 내 컴퓨터의 식별자 확인

Windows 명령 프롬프트에서 ipconfig /all을 실행하면 네트워크 인터페이스 정보를 확인할 수 있다. 출력의 ‘물리적 주소’가 MAC 주소다. 예시 화면에서는 88, 36, 6C 등의 16진수로 표현되며, 전체 길이는 48비트다. 같은 출력에서 IPv4 주소도 확인할 수 있다. 직접 명령을 실행해 MAC 주소와 IP 주소가 어떻게 표시되는지 살펴보면 좋다. Linux에서 확인하는 명령으로 ifconfig를 소개한다. 예를 들어 출력에서 인터페이스 이름을 먼저 찾고, 그 아래의 물리 주소(MAC)와 IPv4 주소를 구별해 읽는다. 기기의 설정이나 운영체제에 따라 명령과 표시 형식이 다를 수 있지만, 확인하려는 대상은 같다.

**읽는 순서:** 어떤 인터페이스인가 → MAC 주소는 무엇인가 → IP 주소는 무엇인가. MAC과 IP를 같은 종류의 주소로 외우지 않는다. 각 정보의 자세한 의미는 해당 주제를 다룰 때 다시 설명한다.

## DoD 분류와 계층 묶기

계층을 나누는 방법이 OSI만 있는 것은 아니다. 미국 국방부의 DoD 분류는 네 계층으로 묶는다. OSI의 L1과 L2를 Network Access 계층으로, L3를 Internet 계층으로, L4를 Host to Host 계층으로 설명하고, 상위 계층은 Application으로 묶는다. ‘액세스 계층’이나 ‘액세스 단’이라는 표현은 하드웨어와 가까운 관점의 설명에서 등장한다. Host는 컴퓨터라는 뜻으로 이해하면 된다. OSI 분류와 함께 이러한 묶음 방식도 알아두면 네트워크 설명을 읽는 데 도움이 된다. 이름이 달라도 같은 기능을 서로 다르게 묶어 설명할 수 있다. 그러므로 DoD 계층과 OSI 계층을 숫자만으로 일대일 대응시키기보다, 각 계층이 어떤 기능을 포함하는지 연결해 본다.

## 세 가지 식별자 정리

여기서 기억할 핵심은 식별 대상이다. MAC 주소는 NIC를, IP 주소는 호스트를 식별한다. 포트라는 말은 L2 인터페이스를 뜻할 수도 있고, 포트 번호를 통해 서비스나 프로세스를 가리킬 수도 있다. 구체적인 의미는 이후 여기서 문맥에 맞추어 다시 다룬다. 예를 들어 ‘스위치의 포트에 케이블을 꽂는다’는 문장의 포트는 인터페이스이고, ‘서버의 443번 포트로 접속한다’에서 포트는 서비스 통신에 쓰는 번호다. 같은 단어가 나오면 숫자인지, 장비의 연결 구멍인지 주변 문장을 보고 판단한다.

**한 줄 암기:** MAC은 NIC, IP는 호스트/네트워크 통신, 포트 번호는 호스트 안의 서비스·프로세스를 구분하는 데 쓰인다.
