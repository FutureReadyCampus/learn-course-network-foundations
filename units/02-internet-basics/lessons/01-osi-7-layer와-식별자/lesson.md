네트워크를 배우다 보면 계층, MAC 주소, IP 주소, 포트 번호처럼 낯선 이름을 자주 만난다. 이 Lesson에서는 이 이름들이 무엇을 가리키는지 먼저 한 바퀴 살펴본다. 지금은 각 개념의 세부 동작을 외우기보다 전체 지도를 그리는 시간이다. NIC와 MAC 주소는 Unit 03에서, IP 주소는 Unit 04에서, 포트 번호와 TCP·UDP는 Unit 05에서 다시 자세히 살펴본다. Host라는 말도 다음 Lesson에서 역할과 함께 풀어본다.

## OSI 계층을 훑어보기

OSI 7 layer는 통신을 일곱 계층으로 나누어 보는 지도다. 아래에서부터 물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용 계층 순서로 쌓여 있다. 이 과정이 모든 계층을 똑같이 깊이 다루는 것은 아니다. 물리 계층에서는 전선 규격, 신호 세기, 전압, 전선 사이의 거리 같은 세부 사항을 다루지 않는다. 데이터 링크 계층에서는 흔히 유선 네트워크에서 쓰는 Ethernet을 중심으로 보고, 무선 네트워크는 공유기를 통해 익숙한 모습으로 연결해 본다. 네트워크 계층에서는 여러 프로토콜 중 인터넷에 초점을 맞춘다. 전송 계층에서는 TCP와 UDP를 만나며 TCP를 더 자세히 살펴본다. 그림에서는 세션 계층을 TLS와 연결해 설명한다. SSL은 TLS의 예전 이름으로 널리 쓰여 왔다. 응용 계층에서는 대표적인 프로토콜인 HTTP와, HTTP에 TLS를 적용한 HTTPS를 함께 살펴본다. 표현 계층은 별도로 깊이 다루지 않는다. 우선 계층마다 다루는 주제가 다르고, 이 과정이 그중 일부를 골라 배운다는 점만 잡으면 충분하다.

## 계층을 실제 구성요소에 연결하기

이 계층들이 컴퓨터 안의 실제 구성 요소와 어떻게 이어지는지 간단히 보자. 아래쪽에는 네트워크에 연결되는 NIC와 이를 다루는 장치 드라이버가 있다. 그 위에는 IP와 TCP를 구현한 소프트웨어가 있고, User mode에는 HTTP를 사용하는 Chrome 같은 브라우저가 있다. 이 그림에서 IP는 L3, TCP는 L4에 해당한다. L2는 드라이버와 하드웨어에 걸쳐 나타난다. 계층 하나가 부품 하나와 꼭 일대일로 짝을 이루는 것은 아니다. 뒤에서 아래쪽 구성 요소부터 차례로 살펴볼 테니, 여기서는 컴퓨터 안에도 계층과 연결되는 구성 요소가 있다는 정도로 보면 된다.

## 식별자는 무엇을 구별할까

식별자는 여러 대상 중에서 하나를 알아보도록 돕는 정보다. 사람의 이름이나 학생의 학번, 반 번호를 떠올려 보자. 반 번호는 같은 반 안에서 학생을 구별하고, 학번은 학교에서 학생을 구별한다. 주민등록번호는 대한민국 국민을 구별하는 데 쓰인다. 네트워크에서도 마찬가지로 계층마다 구별하려는 대상이 다르다. 그래서 “이 값은 무엇을 가리키지?”를 먼저 물어보면 낯선 주소 이름들을 이해하기 쉬워진다.

## MAC 주소 · 인터페이스

L2 Ethernet에서 자주 만날 식별자는 MAC 주소다. 하드웨어 주소 또는 Physical Address라고도 부른다. 우선 MAC 주소는 컴퓨터 전체보다 NIC, 즉 네트워크 인터페이스를 가리키는 이름표라고 기억하자. 컴퓨터 한 대에도 NIC가 여러 개 있을 수 있으므로 MAC 주소도 하나로 정해져 있지 않다. 예를 들어 NIC가 3개라면 MAC 주소도 3개, NIC가 5개라면 MAC 주소도 5개다. NIC가 무엇이고 MAC 주소가 실제로 어떻게 쓰이는지는 Unit 03에서 다시 자세히 살펴본다.

## IP 주소 · 호스트

L3 네트워크 계층에서 만날 식별자는 IP 주소다. 여기서는 우선 인터넷에 연결된 컴퓨터, 즉 호스트를 찾아가는 주소라고 생각하면 된다. IP에는 버전 4와 버전 6이 있지만 이 과정에서는 IPv4를 다룬다. 주소가 어떤 부분으로 이루어지고 네트워크 안에서 어떻게 쓰이는지는 Unit 04에서 천천히 살펴본다.

## 포트 번호 · 관점에 따른 의미

IP 주소가 호스트를 찾아가는 주소라면, L4에서는 포트 번호를 만난다. 우선 큰 건물에 주소가 있고 건물 안에 여러 방이 있는 모습을 떠올리면 된다. IP 주소가 어느 컴퓨터인지 가리킨다면, 포트 번호는 그 컴퓨터 안에서 어느 서비스나 프로그램으로 전달할지 구별하는 데 쓰인다. 다만 ‘포트’라는 말은 상황에 따라 다른 뜻으로도 쓰인다. L2 장비에서 케이블을 꽂는 물리적인 구멍도 포트 또는 인터페이스라고 부른다. 네트워크 관리자는 서비스에 접속할 때 쓰는 포트 번호를 서비스 식별자처럼 설명하기도 하고, PC나 서버의 소프트웨어를 개발·관리하는 사람은 포트 번호가 프로세스를 구별한다고 설명하기도 한다. 처음에는 ‘케이블 구멍’과 ‘번호’를 구분하고, 포트 번호가 서비스나 프로그램과 연결된다는 정도로 기억하면 된다. 정확히 어떤 뜻인지는 문맥을 보고 판단하며, Unit 05에서 TCP·UDP와 함께 다시 자세히 다룬다. 컴퓨터의 네트워크 정보를 확인할 때는 Windows의 ipconfig 같은 명령을 쓸 수 있다.

## 내 컴퓨터의 식별자 확인

이름표가 실제 컴퓨터에서 어떻게 보이는지 잠깐 확인해 보자. Windows 명령 프롬프트에서 `ipconfig /all`을 실행하면 네트워크 인터페이스 정보를 볼 수 있다. 출력의 ‘물리적 주소’가 MAC 주소다. 예시 화면에서는 88, 36, 6C 같은 16진수로 표시되며, 전체 길이는 48비트다. 같은 출력에서 IPv4 주소도 찾을 수 있다. 직접 명령을 실행해 두 주소가 화면에서 어떻게 보이는지 살펴보면 좋다. Linux에서 확인하는 명령으로는 `ifconfig`를 소개한다. 지금은 주소가 어디에 나타나는지 확인하는 것으로 충분하다. 각 정보가 왜 그런 모양인지, 통신에서 어떻게 쓰이는지는 해당 주제에서 다시 설명한다.

## DoD 분류와 계층 묶기

계층을 나누는 지도는 OSI 하나만 있는 것이 아니다. 미국 국방부의 DoD 분류는 계층을 네 묶음으로 보여준다. OSI의 L1과 L2를 Network Access로, L3를 Internet으로, L4를 Host to Host로 묶고, 그보다 위의 계층은 Application으로 묶는다. 지도마다 경계와 이름을 다르게 그리는 것과 비슷하다. ‘액세스 계층’ 또는 ‘액세스 단’이라는 말은 하드웨어와 가까운 쪽을 설명할 때 나온다. 여기서 Host는 컴퓨터를 가리키는 말로 읽으면 된다. 이 네 묶음의 세부 역할을 지금 외울 필요는 없다. OSI와 다른 방식으로 계층을 묶기도 한다는 사실을 먼저 알아두고, 두 분류를 함께 보면 네트워크 설명을 읽을 때 도움이 된다.

## 세 가지 식별자 정리

이번 Lesson에서는 세 이름이 가리키는 대상을 먼저 훑었다. MAC 주소는 NIC를, IP 주소는 호스트를 가리킨다. 포트라는 말은 케이블을 꽂는 L2 인터페이스를 뜻할 때도 있고, 포트 번호는 호스트 안의 서비스나 프로세스를 가리킬 때도 있다. 지금은 이 차이를 완벽하게 설명하기보다 이름과 대상을 연결해 두면 된다. 다음 Lesson에서는 Host를 더 살펴보고, 이후 Unit 03에서 MAC과 NIC, Unit 04에서 IP 주소, Unit 05에서 포트 번호와 TCP·UDP를 차례로 다시 배운다. 지금의 비유는 첫 번째 길잡이이며, 실제 네트워크에서 어떻게 동작하는지는 그때 구체적으로 확인한다.
