핵심 개념을 주제별로 정리했다.

## Network ID와 Host ID

Windows의 ipconfig와 상세 옵션 /all, Linux의 ifconfig를 이용하면 네트워크 설정을 확인할 수 있다. 출력에는 IP 주소뿐 아니라 서브넷 마스크도 있다. IP 주소는 앞의 Network ID와 뒤의 Host ID로 나누어 이해한다. 서브넷 마스크는 이 경계를 정하는 값이다.

## Subnet Mask의 역할

서브넷 마스크의 비트 값을 기준으로 Network ID와 Host ID를 구분한다. 예를 들어 255.255.255.0은 앞의 24비트가 1, 뒤의 8비트가 0이다. 255는 2진수로 1111 1111, 16진수로 FF에 해당한다.

## AND 연산으로 Network ID 구하기

IP 주소와 서브넷 마스크를 비트별로 AND 연산하면 Network ID를 얻을 수 있다. 0 AND 1은 0, 1 AND 1은 1이므로 마스크가 1인 위치는 원래 값이 남고, 0인 위치는 지워진다. 예시의 192.168.0으로 시작하는 주소에 255.255.255.0을 적용하면 Host ID 쪽이 0이 된다. 장비는 이렇게 얻은 Network ID를 비교해 어느 네트워크에 해당하는지 판단한다. 특정 비트를 남기거나 지우는 이 작업을 마스크 연산이라고 한다.

## 과거의 클래스 구분

과거에는 IP 주소를 클래스에 따라 나누어 사용했다. 설명의 예에서 Network ID를 8비트로 보면 A 클래스, 16비트로 보면 B 클래스, 24비트로 보면 C 클래스라는 구분으로 이어진다. 이때도 서브넷 마스크로 경계를 구분하고 마스크 연산의 결과를 비교했다. 이후에는 고정된 클래스 구분을 벗어나 주소를 표현하는 방식으로 발전했다. 클래스 기반 설명은 과거의 방식임을 구별해 두면 된다.

## CIDR · 비트 수로 표기

CIDR은 클래스 구분 없이 네트워크 경계를 표현하는 방식이다. 주소 뒤에 /24라고 쓰면 왼쪽부터 24비트를 Network ID로 본다는 뜻이다. 이는 주소와 함께 255.255.255.0을 따로 쓰는 것과 같은 경계를 나타낸다. 마스크 결과를 비교하는 관점과 정해진 길이의 비트를 직접 비교하는 관점을 연결해 설명한다. 핵심은 네트워크 경계를 비트 수로 간결하게 나타낸다는 점이다. AWS 같은 서비스를 공부할 때도 CIDR 표기를 만나므로, 서브넷 마스크 표기와 슬래시 뒤의 비트 수 표기를 함께 익히면 좋다.

## Subnetting · 네트워크를 더 나누기

이미 구분된 네트워크를 더 작은 네트워크로 나누는 것을 Subnetting이라고 한다. 예를 들어 기존 24비트 경계에서 Network ID를 2비트 늘리면 마지막 옥텟의 마스크가 192가 된다. Host ID에는 6비트가 남아 2의 6제곱 가지 값을 표현할 수 있다. 서브넷 마스크는 경계를 표현하는 값이고, 서브네팅은 네트워크를 더 나누는 작업이다. 먼저 개념을 이해한 뒤 /24, /26 같은 CIDR 표기를 익힌다.
