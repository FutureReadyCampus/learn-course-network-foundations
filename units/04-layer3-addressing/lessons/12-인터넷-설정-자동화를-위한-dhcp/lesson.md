핵심 개념을 주제별로 정리했다.

## 인터넷 사용에 필요한 설정

인터넷을 사용하려면 호스트를 식별하는 IP 주소와 서브넷 마스크, 게이트웨이 주소를 설정해야 한다. IPv4라면 32비트 주소를 사용하지만, 사용자가 임의로 아무 값을 정하는 것은 아니다. 인터넷 서비스를 구매하면 ISP(Internet Service Provider)가 보유한 주소 중 사용할 수 있는 주소를 제공한다. DNS 서버 주소도 필요하다. www.naver.com 같은 이름을 입력했을 때 해당 IP 주소를 알아내는 데 사용한다. IP·서브넷 마스크·게이트웨이는 이 설명에서 L3 설정에 해당한다.

## 수동 설정과 자동 설정

필요한 값을 모두 수동으로 입력할 수도 있지만 보통은 자동 설정을 이용한다. Windows에서는 제어판의 네트워크 설정에서 확인할 수 있다. 예시 구성에서는 IP 설정을 자동으로 받고 DNS 서버는 Google DNS인 8.8.8.8로 지정한다. 둘 다 자동으로 설정하는 방식도 일반적이다. 이 자동 설정을 담당하는 프로토콜이 DHCP다.

## DHCP의 역할

DHCP는 Dynamic Host Configuration Protocol이다. 호스트가 사용할 IP 주소, 서브넷 마스크, 게이트웨이, DNS 등의 TCP/IP 설정을 자동화한다. DHCP는 클라이언트와 서버로 구성된다. 서버가 설정 정보를 보유하고 있다가 클라이언트에 사용할 값을 알려 준다. 따라서 자동 설정을 이용하려면 이를 제공하는 서버가 필요하다.

## 동적으로 주소를 할당하기

Dynamic은 동적이라는 뜻이며, 여기서는 Runtime, 즉 컴퓨터가 작동하는 중에 결정된다는 관점으로 설명한다. 미리 고정해 두는 Static과 대비된다. 예시에서는 가정의 공유기가 게이트웨이 역할을 하는 작은 네트워크를 가정한다. 네트워크가 동작하는 중에 PC가 사용할 주소를 받는 과정을 살펴본다.

## 서버를 찾는 브로드캐스트

게이트웨이가 192.168.0.1, 서브넷 마스크가 255.255.255.0인 네트워크에 DHCP 서버가 있다고 하자. PC 전원을 켜면 DHCP 서버를 찾는 Discover 트래픽이 브로드캐스트로 나간다. 이를 받은 액세스 스위치는 같은 브로드캐스트 범위의 다른 연결과 업링크로 전달한다. 특정 서버의 주소를 미리 모르더라도 범위 안의 DHCP 서버를 찾을 수 있는 방식이다.

## 주소를 제안하고 사용하기

DHCP 서버는 요청을 보고 응답하며, 다른 일반 컴퓨터는 DHCP 서버가 아니므로 응답하지 않는다. 이전에 주소를 받은 클라이언트는 같은 주소를 계속 사용할 수 있는지 요청할 수 있다. 사용할 수 있으면 그대로 쓰고, 이미 다른 대상이 사용 중이면 서버가 다른 주소를 알려 주는 식이다. 처음 접속한 PC도 서버에서 사용할 주소를 받는다. 실제 메시지와 상태의 세부 규칙은 DHCP 프로토콜을 따로 살펴보아야 한다.

## IP와 함께 받는 설정 정보

서버가 192.168.0.100을 할당한다면 IP만 알려 주는 것이 아니다. 게이트웨이 192.168.0.1, DNS 주소, 서브넷 마스크 등 필요한 설정을 함께 제공한다. 서버는 할당할 IP 주소의 풀(Address Pool)을 관리한다. PC가 켜질 때 이 풀의 주소 중 하나를 사용할 수 있도록 제공하는 구조다.

## 같은 브로드캐스트 도메인

서버는 서로 다른 PC에 같은 주소를 중복 할당하지 않도록 관리한다. 이미 100번을 쓰는 PC가 있는데 다른 PC에도 같은 번호를 주면 문제가 생기기 때문이다. 이 단원의 기본 구성에서는 클라이언트와 DHCP 서버가 같은 Broadcast Domain 안에 있어야 한다. 인터넷 너머의 네이버 서버를 그대로 DHCP 서버로 삼아 응답을 받는 구성으로 설명하는 것은 아니다. VPN 등으로 구성이 달라질 수 있다는 언급은 있지만, 여기서는 브로드캐스트가 도달하는 범위 안의 서버가 설정을 제공한다는 점을 기억하면 된다.

## DHCP로 자동화하는 범위 정리

DHCP의 핵심은 인터넷 사용에 필요한 설정을 자동화하는 것이다. 세부 동작을 공부하려면 프로토콜 규격을 읽고 Wireshark로 메시지를 분석할 수 있다. 소켓 프로그래밍에 익숙하다면 규격을 바탕으로 서버를 직접 구현해 보는 학습도 가능하다. 이 단계에서는 서버가 설정 정보를 제공하고 주소 풀을 관리한다는 구조를 이해하면 된다.
