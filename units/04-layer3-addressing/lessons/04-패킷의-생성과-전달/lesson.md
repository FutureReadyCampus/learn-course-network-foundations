## 데이터로 택배 만들기

패킷이 만들어져 목적지에 도착하는 과정을 택배로 떠올려 보자. 철수가 영희에게 책을 보내려면 책을 상자에 넣고, 상자 겉에 보내는 곳과 받을 곳을 적은 송장을 붙인다. 상자 안에 넣은 책처럼 실제로 전달하려는 내용은 **페이로드(payload)**이고, 어디서 왔고 어디로 가는지 알려 주는 송장 정보는 **헤더(header)**에 비유할 수 있다. 네트워크에서도 데이터만 보내는 것이 아니라 전달에 필요한 정보와 함께 묶어 보낸다.

철수가 택배를 기사에게 건네면 기사는 여러 사람의 택배를 모아 분류하고 운반한다. 철수가 직접 영희의 집까지 운반하는 것은 아니다. 네트워크에서도 프로그램이 데이터를 내보낸 뒤에는 운영체제와 네트워크 장비가 각자의 역할을 맡아 전달한다. 택배가 중간 물류센터를 거치듯, 데이터도 여러 장비와 네트워크를 거쳐 목적지로 갈 수 있다. 다만 실제 네트워크의 전달 절차가 택배사의 절차와 똑같다는 뜻은 아니다. 택배 비유는 각 정보가 맡은 역할을 구별하기 위한 출발점이다.

## 호스트까지 가는 주소

택배 기사가 영희의 집을 찾으려면 도로명 주소와 건물 번호가 필요하다. 네트워크에서 그 집 주소에 해당하는 것이 목적지 **IP 주소**이고, 그 주소를 사용하는 컴퓨터나 서버가 **호스트(host)**다. IP 주소는 네트워크를 통해 어느 호스트까지 데이터를 전달할지 나타낸다. 집 주소만으로 그 집 안의 누구에게 택배를 줄지 알 수 없듯, IP 주소만으로는 호스트 안에서 어느 프로그램이 데이터를 받을지 알 수 없다.

철수가 책을 보낼 때는 목적지인 영희의 주소를 적지만, 중간에 있는 모든 물류센터의 주소를 송장에 적지는 않는다. 마찬가지로 보내는 쪽은 최종 목적지 IP 주소를 지정하고, 중간의 라우터들이 그 주소를 보고 다음에 전달할 곳을 정한다. 실제로 패킷이 지나가는 경로와 다음 홉은 네트워크의 상태와 라우팅 정보에 따라 결정된다.

## 집 안의 수신자를 구별하기

영희의 집에 영희뿐 아니라 동생과 부모도 함께 산다고 하자. 집 주소만으로는 집 안에서 누가 받을 물건인지 구별하기 어려우므로, 송장에는 받는 사람 이름도 적는다. 호스트 안에서도 웹 브라우저, 메신저, 게임처럼 여러 프로그램이 네트워크 데이터를 주고받을 수 있다. 이때 받을 프로그램을 구별하는 데 쓰이는 번호가 **포트 번호(port number)**다.

택배 비유에서는 IP 주소가 집 주소, 포트 번호가 집 안의 받는 사람 이름에 가깝다. 정확히 말하면 IP 주소는 목적지 호스트를 찾고, TCP나 UDP의 포트 번호는 그 호스트에서 데이터를 받을 애플리케이션 프로세스를 구별한다. 예를 들어 웹 서버 호스트까지 찾아온 데이터는 목적지 포트 번호를 보고 웹 서비스를 담당하는 프로세스에 전달될 수 있다. 집 주소와 사람 이름은 비유이고, 네트워크는 주소와 숫자로 된 포트 번호를 사용한다는 점을 기억하자.

## 수신 측에서 전달하기

기사는 목적지 주소를 보고 영희의 집까지 간다. 집 앞에 물건을 놓거나, 문을 연 어머니에게 건넬 수도 있다. 어머니가 대신 택배를 받더라도 받는 사람 이름이 영희라면 영희에게 전달한다. 네트워크에서도 먼저 목적지 IP 주소에 해당하는 호스트까지 데이터를 전달한 뒤, 목적지 포트 번호를 확인해 그 호스트 안의 수신 프로세스에 전달한다.

따라서 “목적지에 도착했다”는 말에는 두 단계가 있다. IP 주소로 목적지 호스트에 도착하는 단계와, 포트 번호로 그 안의 프로그램에 도착하는 단계다. 웹 브라우저가 웹 페이지를 요청할 때 서버 컴퓨터까지 가는 것만으로 끝나지 않고, 서버 안에서 웹 요청을 처리하는 프로그램이 받아야 응답을 만들 수 있다.

## 송신 프로세스와 데이터

이제 비유의 요소를 실제 네트워크에 대응시켜 보자. 책을 보내는 철수와 받는 영희는 데이터를 주고받는 프로그램, 즉 **프로세스(process)**에 해당하고, 책은 그 프로세스가 보내려는 데이터다. 프로세스는 데이터를 운영체제에 전달하고, 운영체제가 네트워크로 내보내는 데 필요한 처리를 맡는다. 네트워크에 연결된 컴퓨터나 서버는 호스트이며, 네트워크 케이블이나 무선 네트워크와 이어지는 지점은 네트워크 **인터페이스(interface)**다.

영희가 다른 네트워크에 있다면 철수는 택배를 가까운 집하 장소에 맡기듯 데이터를 먼저 **게이트웨이(gateway)**에 보낸다. 보통 이때의 기본 게이트웨이는 호스트가 외부 네트워크로 데이터를 보낼 때 처음 전달하는 라우터다. 게이트웨이는 최종 목적지가 아니라 다음 단계로 넘겨주는 출구에 가깝다. 그 뒤 라우터들은 목적지 IP 주소를 바탕으로 패킷을 다음 홉으로 전달한다. 택배 기사와 물류센터는 역할을 이해하기 위한 비유이며, 실제 장비와 물류 과정이 일대일로 대응하는 것은 아니다.

## 수신 프로세스와 포트

목적지 호스트에 도착한 데이터는 그 안에서 기다리는 어느 프로그램으로 가야 할까? 송장의 받는 사람 이름에 해당하는 정보가 포트 번호다. 예를 들어 서버의 IP 주소가 건물 주소라면, 그 서버에서 웹 서비스를 제공하는 프로세스는 그 건물 안의 특정 수신자로 생각할 수 있다. 목적지 IP 주소는 호스트를 찾고, 목적지 포트 번호는 호스트 안에서 데이터를 받을 프로세스를 구별한다.

같은 호스트에서 웹 서버와 다른 네트워크 프로그램이 함께 실행되어도 포트 번호를 이용하면 각 프로그램에 맞는 데이터로 전달할 수 있다. 포트 번호는 물리적인 구멍이나 방의 위치가 아니라, TCP 또는 UDP 헤더에 기록되어 수신 프로그램을 식별하는 숫자다. 이 구분 덕분에 하나의 컴퓨터에서 여러 네트워크 프로그램이 동시에 통신할 수 있다.

## 소켓을 통한 입출력

프로그램이 네트워크로 데이터를 보내고 받으려면 운영체제에 요청해야 한다. 이때 프로그램과 운영체제의 네트워크 기능 사이에서 사용하는 인터페이스가 **소켓(socket)**이다. 소켓은 프로그램이 TCP/IP의 세부 동작을 모두 직접 처리하지 않고도 데이터를 주고받을 수 있게 해 준다. 운영체제에서 소켓을 파일처럼 다룰 수 있는 경우도 있어, 프로그램이 파일에 쓰고 읽는 방식과 연결해 이해할 수 있다.

예를 들어 웹 브라우저는 웹 서버와 통신할 소켓을 통해 요청 데이터를 운영체제에 전달한다. 그러면 운영체제의 커널이 프로토콜에 맞는 헤더를 붙이고 네트워크 인터페이스로 내보내는 일을 맡는다. 소켓은 택배 그 자체나 네트워크 케이블이 아니라, 프로그램이 운영체제에 네트워크 입출력을 요청하는 창구다.

## 계층을 내려가며 포장하기

프로그램이 소켓을 통해 보낼 데이터를 운영체제에 넘기면, 데이터는 네트워크로 나가기 전에 계층별로 필요한 정보가 더해진다. TCP를 사용하는 경우 전송 계층은 송신지와 목적지 포트 같은 정보를 담은 TCP 헤더를 데이터 앞에 붙인다. 이 단위를 TCP **세그먼트(segment)**라고 부른다. 네트워크 계층은 IP 주소 같은 정보를 담은 IP 헤더를 더해 **패킷(packet)**을 만들고, 데이터 링크 계층은 같은 링크에서 전달하는 데 필요한 Ethernet 헤더와 트레일러를 더해 **프레임(frame)**으로 만든다.

택배에 내용물을 넣고 송장을 붙인 다음 운송용 상자에 넣는 과정처럼 생각할 수 있다. 다만 각 계층이 붙이는 정보와 역할은 서로 다르다. 수신 측에서는 프레임에서 Ethernet 정보를 확인해 벗기고, IP 정보를 처리한 뒤 TCP 정보를 확인해 해당 포트의 프로세스까지 데이터를 올려 보낸다. 보내는 쪽에서 계층별 정보를 덧붙이는 과정을 **캡슐화**, 받는 쪽에서 차례로 확인하고 벗기는 과정을 **역캡슐화**라고 한다.

## 라우터를 거쳐 도착하기

철수의 컴퓨터에서 나온 프레임은 먼저 같은 LAN의 L2 액세스 스위치로 간다. 스위치는 프레임을 로컬 네트워크 안에서 목적지 쪽으로 전달하고, 라우터는 IP 패킷의 목적지 주소를 보고 다음 네트워크로 보낸다. 라우터를 통과하면 다음 링크에 맞는 Ethernet 프레임이 새로 만들어져 프레임의 MAC 주소가 바뀔 수 있지만, 일반적인 라우팅에서는 패킷의 최종 출발지와 목적지 IP 주소를 기준으로 전달한다. 즉, 프레임은 각 링크를 건너기 위한 포장이고, IP 패킷은 호스트와 호스트 사이를 향하는 정보다.

목적지 호스트에 도착하면 데이터는 계층을 거슬러 올라간다. Ethernet 프레임의 정보가 처리되고, IP 패킷과 TCP 세그먼트의 정보가 확인된 뒤, 목적지 포트에 해당하는 프로세스가 데이터를 받는다. 전체 흐름을 짧게 이어 보면 **프로세스의 데이터 → TCP 세그먼트 → IP 패킷 → Ethernet 프레임 → 스위치와 라우터를 거친 전달 → 목적지 프로세스**다. 이 순서와 각 주소가 맡은 역할을 연결해 기억하자. TCP 연결과 세그먼트의 세부 동작은 뒤에서 다룬다.
