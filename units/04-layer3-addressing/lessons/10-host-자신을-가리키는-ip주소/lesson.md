## 자기 컴퓨터 안에 접속한다는 것은?

브라우저에서 `http://127.0.0.1:8000`을 열었더니 내 컴퓨터에서 실행 중인 웹 페이지가 나타나는 상황을 떠올려 보자. 이 주소로 접속할 때 데이터가 인터넷 너머 다른 컴퓨터로 가는 것은 아니다. `127.0.0.1`은 지금 브라우저를 실행 중인 컴퓨터 자신을 가리킨다. 물론 그 주소와 포트에서 웹 서버 프로그램이 실제로 실행 중이어야 페이지가 열린다.

네트워크를 배울 때는 보통 내 컴퓨터에서 다른 컴퓨터로 데이터를 보낸다. 나와 떨어져 있는 상대 컴퓨터를 **원격지(Remote)**라고 부른다. 그런데 같은 컴퓨터 안에 있는 프로그램끼리 데이터를 주고받는 일도 있다. 개발할 때 브라우저로 내 컴퓨터의 웹 서버를 확인하거나, 한 프로그램이 같은 컴퓨터에서 실행 중인 다른 프로그램에 요청을 보낼 때다.

IP 주소는 네트워크에 연결된 컴퓨터, 즉 **호스트(Host)**를 찾는 주소다. 다만 데이터를 실제로 보내고 받는 일은 컴퓨터 안에서 실행 중인 프로그램들이 한다. 그러므로 “내 컴퓨터가 자기 자신에게 접속한다”는 말을 정확히 풀면, **한 호스트 안에서 실행 중인 프로그램 하나가 같은 호스트의 다른 프로그램에 접속한다**는 뜻이다.

이 Lesson에서는 먼저 같은 컴퓨터 안에서도 프로그램끼리 통신할 수 있음을 살펴본다. 이어서 `127.0.0.1`과 `localhost`가 어떤 주소인지, 그 통신이 실제 네트워크 밖으로 나가는지 확인한다.

### 이 Lesson에서 가져갈 것

- **기억하기 (Recall):** `127.0.0.1`은 현재 Host 자신을 가리키는 IPv4 루프백 주소다.
- **적용하기 (Apply):** 로컬 웹 서버가 실행 중일 때만 `127.0.0.1:port` 접속이 응답함을 설명한다.
- **찾아보기 (Lookup):** `localhost` 해석과 포트 사용 상태는 OS 이름 설정·서버 상태를 확인한다.

## 한 컴퓨터 안에서도 두 프로세스가 통신한다

컴퓨터에서 실행 중인 프로그램 하나하나를 **프로세스(Process)**라고 한다. 예를 들어 브라우저를 켜면 브라우저 프로세스가 실행되고, 로컬 웹 서버를 켜면 서버 프로세스가 실행된다. 저장된 프로그램 파일과 지금 실행되어 작업하는 프로세스는 구별할 수 있다. 같은 앱을 두 번 실행하면 같은 프로그램에서 프로세스 두 개가 생길 수도 있다.

서버와 클라이언트도 컴퓨터의 종류가 아니라 프로세스가 맡는 역할이다. 연결을 기다리는 쪽이 서버이고, 먼저 연결을 요청하는 쪽이 클라이언트다. 그래서 한 대의 노트북에서 웹 서버를 실행하고 브라우저를 열면, 서버 역할을 하는 프로세스와 클라이언트 역할을 하는 프로세스가 같은 컴퓨터 안에 함께 있을 수 있다.

프로세스가 네트워크 통신을 맡기고 데이터를 주고받는 통로를 **소켓(Socket)**이라고 한다. IP 주소가 어느 호스트를 찾을지 알려 준다면, 포트 번호는 그 호스트 안에서 어느 통신 서비스로 데이터를 전달할지 구별하는 데 쓰인다. 같은 호스트에서 실행되는 브라우저와 서버도 소켓을 통해 연결된다. 포트의 자세한 역할은 앞서 배운 내용을 떠올리면 된다.

예를 들어 컴퓨터의 네트워크 주소가 `192.168.0.10`이고, 그 안에서 서버가 `8000`번 포트로 요청을 기다린다고 하자. 같은 컴퓨터의 클라이언트는 `192.168.0.10:8000`으로 접속할 수 있다. 서버는 반드시 먼 인터넷에 있는 컴퓨터일 필요가 없다. 다만 이 주소는 네트워크 설정에 따라 바뀔 수 있어, 같은 컴퓨터 안을 가리키는 더 분명한 주소가 유용하다.

아래 그림처럼 상자 하나가 컴퓨터 한 대이고, 그 안의 두 칸이 실행 중인 프로세스라고 생각해 보자. 클라이언트와 서버가 서로 다른 호스트에 있어야만 통신하는 것이 아니다. 한 호스트 안에서도 클라이언트가 서버에 연결할 수 있다.

### 이 Lesson에서 가져갈 것

- **기억하기 (Recall):** 같은 컴퓨터에서 실행되는 브라우저와 서버는 서로 다른 Process일 수 있다.
- **적용하기 (Apply):** 한 장치에서 Client와 Server 프로세스가 통신하는 상황을 설명한다.
- **찾아보기 (Lookup):** Process 목록과 PID는 운영체제 작업 도구에서 찾아본다.

## 127.0.0.1과 localhost는 내 컴퓨터를 가리킨다

IPv4에서 `127.0.0.1`은 자기 호스트를 가리키는 대표적인 **루프백(Loopback) 주소**다. 루프(loop)는 고리처럼 돌아온다는 뜻이다. 내 컴퓨터에서 이 주소로 보낸 데이터는 다른 컴퓨터의 주소를 찾으러 인터넷으로 나가는 대신, 현재 컴퓨터 안의 네트워크 통신 경로로 되돌아온다.

`localhost`는 주소 숫자 대신 자기 컴퓨터를 부를 때 자주 사용하는 이름이다. 흔한 IPv4 환경에서는 `127.0.0.1`로 이어지며, IPv6 환경에서는 `::1` 같은 루프백 주소가 함께 사용될 수 있다. 따라서 `localhost`는 사람이 기억하기 쉬운 이름이고 `127.0.0.1`은 대표적인 IPv4 주소라고 구분하면 좋다. 브라우저 주소창에서 `http://localhost:8000`을 열어 로컬 서버에 접속하는 것도 같은 예다.

`192.168.0.10` 같은 주소는 네트워크 인터페이스에 설정된 주소다. 네트워크 인터페이스는 Wi-Fi나 유선 랜처럼 컴퓨터가 네트워크에 연결되는 지점이다. 집에서 카페로 이동하면 공유기가 주는 주소가 달라질 수 있지만, `127.0.0.1`은 특정 Wi-Fi나 랜 주소를 가리키지 않고 언제나 현재 컴퓨터 자신을 가리킨다.

주소를 비유로 구분해 보자. `192.168.0.10`은 집이나 건물에 붙은 주소처럼 네트워크에서 이 컴퓨터를 찾게 한다. 반면 `127.0.0.1`은 “이 컴퓨터 안으로”라는 약속된 표시다. 컴퓨터가 네트워크에 연결되어 있는지와 관계없이 자기 컴퓨터에서 실행 중인 프로그램을 시험할 때 쓸 수 있다.

### 이 Lesson에서 가져갈 것

- **기억하기 (Recall):** `localhost`는 현재 컴퓨터를 부르는 이름이고 `127.0.0.1`은 IPv4 주소다.
- **적용하기 (Apply):** 두 표기 모두 로컬 서비스에 접속할 수 있지만 이름 해석을 구별한다.
- **찾아보기 (Lookup):** IPv6 loopback `::1`의 처리 차이는 OS 설정에서 확인한다.

## 루프백 통신은 컴퓨터 안에서 끝난다
<!-- learn-page-id: loopback-address -->

일반적인 통신에서는 데이터가 운영체제의 네트워크 기능을 거쳐 네트워크 카드와 케이블 또는 Wi-Fi 전파를 통해 다른 호스트로 이동한다. 루프백 주소로 보낸 패킷은 그 물리 네트워크로 나가지 않는다. 운영체제가 컴퓨터 내부에서 패킷을 처리해 같은 호스트의 대상 프로그램에 전달한다. 그림의 복도나 유턴은 이해를 돕는 비유이며, 실제로 컴퓨터 안에 그런 물리적인 복도가 있는 것은 아니다.

이런 식으로 같은 컴퓨터에서 실행 중인 프로세스끼리 데이터를 주고받는 일을 **프로세스 간 통신(IPC, Inter Process Communication)**이라고 한다. 루프백과 소켓은 IPC를 구현하는 한 방법이다. 같은 컴퓨터 안의 프로세스는 공유 메모리처럼 다른 방식으로도 데이터를 주고받을 수 있으므로, IPC가 모두 루프백 통신이라는 뜻은 아니다.

직접 확인하려면 Windows 검색에서 ‘명령 프롬프트’를 열고 `ping 127.0.0.1`을 실행한다. macOS에서는 `Command+Space`를 눌러 Spotlight를 열고 ‘터미널’을 찾아 실행한 뒤 `ping -c 4 127.0.0.1`을 입력한다. 응답이 돌아오면 인터넷 연결을 시험한 것이 아니라, 현재 컴퓨터의 IP 통신 기능이 루프백 요청을 처리했음을 확인한 것이다. 이 결과만으로 특정 웹 서버 프로그램이 실행 중인지까지 확인할 수는 없다.

개발자는 브라우저에서 로컬 웹 서버를 시험하거나, 한 컴퓨터의 웹 프로그램과 데이터베이스 프로그램을 연결할 때 루프백 주소를 자주 쓴다. 브라우저에서 페이지를 열 때에는 서버 프로세스가 요청을 기다리고 있어야 한다. 주소만 입력한다고 서버가 저절로 생기는 것은 아니다.


### 찾아보기: 0.0.0.0은 어디에 적혔는지 보자

`127.0.0.1`은 자기 컴퓨터를 가리키지만, `0.0.0.0`은 쓰인 자리와 함께 읽어야 한다. 아직 IPv4 주소를 받지 못한 컴퓨터는 주소를 요청하는 DHCP 메시지의 **출발지 IP**에 `0.0.0.0`을 쓸 수 있다. 이때는 “아직 내 주소를 정하지 못했다”는 뜻이다. 실제 메시지는 [Unit 6 Lesson 2 Page 4 「Discover 브로드캐스트로 DHCP 서버를 찾는다」](https://futurereadycampus.github.io/learn-course-network-foundations/m2-network/unit/6/lesson/2/page/4)에서 다시 본다.

반면 **라우팅 표의 목적지**에 쓰인 `0.0.0.0/0`은 모든 IPv4 목적지를 포함하는 기본 경로다. `/0`은 비교할 네트워크 비트가 0개라는 뜻이므로 어느 목적지와도 일치한다. 더 구체적으로 맞는 경로가 없을 때 이 경로를 사용한다. 여기서 `0.0.0.0`은 실제로 접속할 서버 한 대의 주소가 아니다. 같은 숫자라도 DHCP의 출발지 주소인지, 라우팅 표의 목적지와 마스크인지부터 확인하자.

이제 같은 호스트 안의 프로그램 통신과 루프백 주소를 살펴보았다. 다음 Unit 6에서는 새 컴퓨터가 IP 설정을 얻는 방법과, 같은 네트워크의 상대를 찾는 과정을 이어서 배운다.

### 이 Lesson에서 가져갈 것

- **기억하기 (Recall):** Loopback 패킷은 물리 NIC를 통해 다른 호스트로 나가지 않고 로컬에서 처리된다.
- **적용하기 (Apply):** `ping 127.0.0.1` 성공을 인터넷 연결이나 서버 실행 증거와 구분한다.
- **찾아보기 (Lookup):** loopback 전체 `127.0.0.0/8` 범위와 진단 명령 옵션은 공식 문서에서 본다.
