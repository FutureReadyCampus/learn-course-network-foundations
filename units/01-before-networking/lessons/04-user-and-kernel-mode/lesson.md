## 소프트웨어와 하드웨어 · 0:00

컴퓨터는 하드웨어와 소프트웨어로 이루어지고, 소프트웨어는 User mode 애플리케이션과 Kernel mode 소프트웨어로 나뉜다. 운영체제 관련 기초 내용을 알고 있다는 전제로 이 구조를 네트워크와 연결해 살펴본다.

하드웨어 중에서 주로 다룰 대상은 NIC(Network Interface Card)다. 흔히 LAN 카드라고 부르는 장치이며, 뒤에서 다시 설명한다.

## NIC와 장치 드라이버 · 0:40

Windows 같은 범용 운영체제에는 하드웨어를 제어하는 소프트웨어인 장치 드라이버가 있다. NIC를 컴퓨터에 장착하거나 USB 방식으로 연결해도, 이를 작동시키려면 드라이버가 필요하다.

그 위에는 커널을 이루는 구성 요소가 있고, TCP와 IP 같은 프로토콜을 구현한 소프트웨어도 포함된다. 여기까지가 운영체제 수준의 구성이다.

## 애플리케이션과 커널 · 1:33

Chrome 같은 애플리케이션은 User mode에서 실행된다. 동영상을 보거나 네이버·구글에 접속할 때도 애플리케이션이 커널의 네트워크 기능을 사용한다.

커널은 User mode 프로세스가 필요한 기능에 접근할 수 있도록 정해진 인터페이스를 제공한다. 원문은 이를 서로 다른 영역 사이에서 정해진 방식으로 메시지를 전달하는 상황에 비유한다. 애플리케이션은 이 인터페이스를 거쳐 커널에 요청한다.

## 소켓이라는 인터페이스 · 2:45

이 강의에서는 TCP/IP를 추상화한 인터페이스를 파일 형태로 설명하며, 이 특별한 파일을 소켓(socket)이라고 부른다. 소켓의 구체적인 동작은 뒤에서 다시 다룬다.

이제 이 구현 구조를 OSI 계층과 연결해 볼 수 있다.

## OSI 계층과 구현 위치 · 3:23

OSI의 아래쪽에는 L1 물리 계층과 L2 데이터 링크 계층이 있고, 그 위로 L3 네트워크 계층과 L4 전송 계층이 이어진다. 상위에는 Session, Presentation, Application 계층이 있다.

OSI는 개념이므로 실제로 어디에서 구현되는지 연결해 보는 것이 중요하다. 이 강의의 그림에서는 L5 이상을 User mode 애플리케이션과 프로세스 수준의 기능으로 설명한다. 전송 계층은 운영체제에 구현된 TCP와 연결해 이해한다.

## TCP·IP가 작동하는 영역 · 4:43

TCP는 L4 전송 계층, IP는 L3 네트워크 계층에 해당한다. 계층을 그림으로 표현하면 TCP 아래에 IP가 놓인다. TCP/IP라고 쓰는 표기는 두 프로토콜이 서로 다른 계층에 있다는 관계와 함께 이해하면 된다.

TCP는 전송의 문제를, IP는 네트워크 계층의 문제를 다룬다. 그 아래의 데이터 링크·물리 계층은 드라이버와 NIC 같은 실제 구성 요소에 연결된다. NIC는 하드웨어이며, 데이터 링크 계층의 기능은 그림에서 드라이버와 하드웨어에 걸쳐 표현된다.

## 드라이버와 네트워크 추상화 · 5:55

데이터 링크 계층을 구현 위치에 연결할 때는 커널의 드라이버 영역과 하드웨어의 일부 펌웨어까지 함께 생각한다. 이후 강의에서 User mode와 Kernel mode를 언급할 때 이 구조를 떠올리면 된다.

소켓은 네트워크를 추상화한 파일 형태의 인터페이스다. 소켓을 열고 닫는 주체는 프로세스다. 따라서 ‘어떤 프로세스가 어떤 소켓, 즉 파일을 열었다’는 관계를 분명히 이해해야 한다.
