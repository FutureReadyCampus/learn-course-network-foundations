  - id: concept-basic-04-01
    terms:
      - term: 하드웨어(Hardware)
        plain: CPU, 메모리, 네트워크 카드처럼 눈에 보이고 만질 수 있는 부품입니다.
      - term: 소프트웨어(Software)
        plain: 하드웨어를 움직이는 명령의 묶음입니다. 크게 User mode 애플리케이션과 Kernel mode 소프트웨어로 나뉩니다.
      - term: User mode / Kernel mode
        plain: 프로그램이 실행되는 두 구역입니다. 일반 애플리케이션은 User mode에서, 운영체제의 핵심부는 Kernel mode에서 움직입니다. ‘user’는 사람이 아니라 구역 이름입니다.
      - term: NIC(Network Interface Card)
        plain: 컴퓨터를 네트워크에 연결해 주는 하드웨어로, 흔히 LAN 카드라고 부릅니다.
    anim: null
  - id: concept-basic-04-02
    terms:
      - term: 장치 드라이버(Device driver)
        plain: 특정 하드웨어를 운영체제가 다룰 수 있도록 중간에서 통역해 주는 소프트웨어입니다. 하드웨어를 ‘운전한다(drive)’는 뜻에서 나온 이름입니다.
      - term: 범용 운영체제
        plain: Windows처럼 여러 종류의 컴퓨터와 다양한 장치에서 두루 쓰도록 만든 운영체제입니다.
    tryit:
      - title: 내 컴퓨터의 NIC와 드라이버 찾아보기
        steps:
          - Windows는 시작 버튼을 마우스 오른쪽으로 눌러 ‘장치 관리자’를 열고 ‘네트워크 어댑터’ 항목을 펼칩니다.
          - 목록에서 Wi-Fi 또는 Ethernet(이더넷)이 들어간 이름을 더블클릭하고 ‘드라이버’ 탭을 눌러 공급자와 버전을 확인합니다.
          - Mac은 터미널(Spotlight에서 ‘터미널’ 검색)을 열고 networksetup -listallhardwareports 를 입력합니다. 또는 Option 키를 누른 채 Apple
            메뉴의 ‘시스템 정보’를 열어 ‘네트워크’ 항목을 봅니다.
        expect: 'Windows에서는 제조사 이름이 들어간 네트워크 장치 이름과 드라이버 버전이, Mac에서는 Hardware Port: Wi-Fi 같은 줄이 보이면 성공입니다. 이름과 숫자는
          컴퓨터마다 다릅니다.'
    anim:
      file: assets/l04-nic-driver-stack.svg
      title: NIC 위에 드라이버와 TCP/IP가 쌓이는 모습
      caption: NIC 혼자서는 쓸 수 없고, 드라이버가 끼워지고 그 위에 TCP/IP 소프트웨어가 얹혀야 운영체제 수준의 네트워크가 완성됩니다.
      alt: 맨 아래 NIC 상자 위에 드라이버 블록이 끼워지고, 그 위에 TCP와 IP 블록이 차례로 쌓이는 장면입니다. 마지막에 위에서 내려온 데이터가 NIC를 통해 선으로 나갑니다.
      storyboard: '0~2초: 화면 아래쪽에 NIC 상자만 덩그러니 놓여 있고 위에 회색 물음표가 깜박이며 ‘NIC만으로는 말이 안 통함’ 표시. / 2~5초: 위에서 ‘드라이버’ 블록이
        내려와 NIC 위에 딱 끼워지고, 두 블록 사이에 말풍선 두 개(공통 말 → NIC의 말)가 오가며 통역을 보여 줌. / 5~8초: 드라이버 위로 IP 블록, 그 위로 TCP 블록이 차례로
        쌓이고 왼쪽에 ‘운영체제 수준’ 괄호가 위에서 아래로 그려짐. / 8~10초: 맨 위에서 작은 데이터 상자가 아래로 내려오며 각 블록을 지나 NIC에 닿고 NIC 옆 선으로 신호가 빠져나가며
        ‘전체가 한 세트’ 자막이 뜸.'
      intended_takeaway: NIC는 드라이버라는 통역사가 있어야 움직이고, 그 위에 TCP와 IP를 구현한 커널 소프트웨어가 층층이 쌓여 있다.
  - id: concept-basic-04-03
    terms:
      - term: 인터페이스(Interface)
        plain: 서로 다른 두 쪽이 만나는 정해진 접점입니다. 여기서는 프로그램이 커널에 요청하는 정해진 창구를 뜻합니다.
      - term: 시스템 콜(System call)
        plain: User mode의 프로그램이 커널의 기능을 쓰기 위해 하는 정해진 방식의 요청입니다.
    anim: null
  - id: concept-basic-04-04
    terms:
      - term: 소켓(Socket)
        plain: 프로그램이 네트워크를 쓰기 위해 여는, 파일 모양의 인터페이스입니다. 열고, 쓰고, 읽고, 닫는 식으로 다룹니다.
      - term: 추상화(Abstraction)
        plain: 복잡한 내부 동작은 감추고 쓰기 쉬운 겉모습만 보여 주는 것입니다.
    tryit:
      - title: 지금 열려 있는 네트워크 연결 구경하기
        steps:
          - Chrome 같은 브라우저를 켜고 아무 사이트나 열어 둡니다.
          - Windows는 cmd(명령 프롬프트)를 열어 netstat -ano | findstr ESTABLISHED 를 입력하고 Enter를 누릅니다.
          - Mac은 터미널을 열어 netstat -an | grep ESTABLISHED 를 입력하고 Enter를 누릅니다.
        expect: 줄마다 내 주소와 상대 주소, 그리고 ESTABLISHED라는 글자가 한 줄씩 나오면 성공입니다. 대략 이 한 줄 한 줄이 지금 열려 있는 소켓에 해당합니다. 줄 수와 주소는
          컴퓨터마다 다릅니다.
    anim:
      file: assets/l04-socket-handset.svg
      title: 소켓이라는 수화기로 요청이 커널에 전해지는 모습
      caption: Chrome은 소켓을 열고 글자를 써 넣기만 하고, TCP/IP 포장과 전송은 커널이 맡습니다.
      alt: 위쪽 User mode의 Chrome과 아래쪽 Kernel mode 사이 경계에 수화기 모양 소켓이 생기고, Chrome이 쓴 글자가 소켓을 지나 커널의 TCP/IP를 거쳐 NIC로
        나가는 장면입니다.
      storyboard: '0~2초: 화면을 위아래로 나눠 위는 ‘User mode’ 구역에 Chrome 아이콘, 아래는 ‘Kernel mode’ 구역에 TCP/IP 블록과 NIC가 보이고 가운데
        가로 경계선이 그어져 있음. / 2~5초: 경계선 한가운데에 수화기 모양 ‘소켓’이 켜지듯 나타나고 Chrome에서 선이 이어지며 ‘open’ 글자가 뜸. / 5~8초: Chrome 안의
        ‘안녕’ 글자 상자가 ‘write’ 표시와 함께 소켓을 통과해 아래로 내려가 TCP, IP 블록을 지날 때마다 껍데기가 한 겹씩 입혀짐. / 8~10초: 포장된 상자가 NIC 밖으로 빠져나가고,
        소켓 부분이 깜박이며 ‘소켓 = 앱과 커널 사이의 단순한 창구’ 자막이 나타남.'
      intended_takeaway: 소켓은 앱이 복잡한 TCP/IP 내부를 몰라도 열고, 쓰고, 닫기만 하면 되게 해 주는 커널의 단순한 창구다.

    terms:
      - term: OSI 7계층
        plain: 통신 과정을 일곱 개 층으로 나누어 설명하는 개념 모델입니다. 아래부터 물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용 계층입니다.
      - term: 구현 위치
        plain: 개념으로 나눈 계층을 실제 컴퓨터의 어느 부분이 맡는지를 가리키는 말입니다.
    anim: null
  - id: concept-basic-04-06
    terms:
      - term: TCP
        plain: L4 전송 계층의 프로토콜로, ‘전송’의 문제를 다룹니다. 자세한 동작은 뒤에서 배웁니다.
      - term: IP
        plain: L3 네트워크 계층의 프로토콜로, 주소를 바탕으로 목적지 쪽으로 보내는 일을 다룹니다.
      - term: TCP/IP 표기
        plain: 슬래시로 묶어 적지만 두 프로토콜은 서로 다른 계층에 있고, 그림에서는 TCP가 위, IP가 아래에 놓입니다.
    anim:
      file: assets/l04-layer-map.svg
      title: OSI 계층이 실제 구성 요소에 자리 잡는 모습
      caption: 개념으로 나눈 계층(L1~L7)을 앱, TCP, IP, 드라이버, NIC라는 실제 위치에 하나씩 놓아 봅니다.
      alt: 왼쪽의 OSI 층 사다리가 오른쪽의 Chrome, TCP, IP, 드라이버, NIC 칸과 선으로 이어지고, User mode와 Kernel mode와 하드웨어 영역이 색으로 구분되는
        장면입니다.
      storyboard: '0~2초: 왼쪽에 L7부터 L1까지 층 라벨이 세로로 쌓인 사다리가 나타나고, 오른쪽에는 Chrome, TCP, IP, 드라이버, NIC가 위에서 아래로 빈 칸으로 놓여
        있음. / 2~5초: L5~L7 묶음이 Chrome 칸으로, L4가 TCP 칸으로, L3가 IP 칸으로 선이 이어지며 각각 색이 켜짐. / 5~8초: L2와 L1에서 선이 나와 드라이버와
        NIC 칸에 걸쳐 이어지고 ‘걸쳐 있음’ 괄호가 표시됨. / 8~10초: 오른쪽 칸 위에 ‘User mode’, ‘Kernel mode’, ‘하드웨어’ 영역 띠가 차례로 칠해지며 ‘개념의
        층 = 실제 위치’ 자막이 뜸.'
      intended_takeaway: OSI 계층은 개념일 뿐이며, 앱은 L5 이상, TCP는 L4, IP는 L3, 데이터 링크·물리는 드라이버와 NIC 쪽에 연결해 이해한다.

## 하드웨어·소프트웨어와 NIC·드라이버

### 하드웨어와 소프트웨어의 역할

큰 호텔에서 하룻밤 묵는 장면을 떠올려 보겠습니다. 손님인 나는 객실에서 텔레비전을 켜고 샤워를 하지만, 보일러가 어떻게 돌아가고 엘리베이터 모터가 어떻게 움직이는지는 신경 쓰지 않습니다. 호텔에는 눈에 보이는 기계 설비와 그것을 다루는 직원, 그리고 손님이 머무는 객실이 함께 들어 있기 때문입니다.

컴퓨터도 같은 구조입니다. 하드웨어(hardware)는 만질 수 있는 부품, 즉 CPU, 메모리, 저장 장치, 네트워크 카드 같은 설비입니다. 소프트웨어(software)는 만질 수는 없지만 그 부품을 실제로 움직이는 명령의 묶음입니다. 보일러가 있어도 그것을 켜고 끄는 사람이 없으면 방이 따뜻해지지 않듯이, 하드웨어만으로는 아무 일도 일어나지 않습니다.

그런데 소프트웨어도 한 덩어리가 아닙니다. 우리가 직접 실행하는 Chrome, 메모장, 카카오톡 같은 프로그램은 손님이 머무는 객실에 해당하고, 이 구역을 User mode(유저 모드)라고 부릅니다. 반대로 설비실과 프런트에서 건물 전체를 관리하는 운영체제의 핵심부는 커널(Kernel)이라 하며, 이 구역을 Kernel mode(커널 모드)라고 합니다. 손님이 설비실에 마음대로 드나들 수 없는 것처럼, 일반 프로그램은 하드웨어를 직접 만지지 않고 커널을 거칩니다.

#### 네트워크 연결을 맡는 NIC

이 강의에서 하드웨어 가운데 가장 눈여겨볼 대상은 NIC(Network Interface Card)입니다. 흔히 LAN 카드라고 부르는 장치로, 호텔로 치면 건물 밖의 세상과 이어지는 출입구입니다. 자세한 이야기는 뒤에서 다시 하니, 지금은 ‘컴퓨터를 네트워크에 연결해 주는 부품’ 정도로 기억해 두면 충분합니다.

헷갈리기 쉬운 점이 하나 있습니다. User mode의 ‘user’는 키보드 앞에 앉은 사람이 아니라, 프로그램이 실행되는 구역의 이름입니다. 또 호텔은 벽과 문으로 구역을 나누지만, 컴퓨터에서는 CPU와 운영체제가 정해 둔 규칙으로 구역을 나눈다는 점이 다릅니다. 한 줄로 되짚으면, 컴퓨터는 하드웨어 위에 커널 쪽 소프트웨어와 일반 애플리케이션이 나뉘어 올라간 구조이고, 네트워크의 열쇠를 쥔 부품이 NIC입니다.

### NIC와 드라이버가 협력하는 방식

컴퓨터의 하드웨어와 소프트웨어가 역할을 나누듯, 네트워크 장치도 NIC와 드라이버가 역할을 나눕니다. 먼저 눈에 보이는 부품과 운영체제 안의 소프트웨어가 어떻게 협력하는지 살펴보겠습니다.

새 프린터를 컴퓨터에 꽂았더니 ‘드라이버를 설치하는 중입니다’라는 안내가 뜨는 장면을 본 적이 있을 것입니다. 마우스는 꽂자마자 움직이는데 어떤 장치는 왜 이런 절차를 거칠까요? 네트워크 카드, 곧 NIC도 마찬가지입니다. 메인보드에 장착하든 USB 단자에 꽂든, 드라이버가 준비되어야 비로소 쓸 수 있습니다.

#### 드라이버가 장치별 명령을 번역하기

이유는 장치마다 조작하는 방법이 제각각이기 때문입니다. 같은 NIC라도 제조사와 모델에 따라 신호를 내보내는 절차가 다릅니다. 운영체제가 세상의 모든 장치 언어를 미리 알 수는 없으니, 장치마다 전용 통역사를 한 명씩 붙여 줍니다. 이 통역사가 장치 드라이버(device driver)입니다. 운영체제는 ‘이 데이터를 내보내라’고 모든 장치에 공통된 말로 요청하고, 드라이버가 그것을 해당 NIC만 알아듣는 말로 바꿔 전달합니다.

그 위에는 커널을 이루는 다른 구성 요소들이 올라가 있고, 그 안에는 TCP와 IP 같은 프로토콜을 소프트웨어로 만들어 둔 부분도 들어 있습니다. 프로토콜은 통신의 약속인데, 약속은 말만으로는 일하지 못하므로 그 약속대로 움직이는 프로그램을 운영체제 안에 넣어 둔 것입니다. 정리하면 아래에서부터 NIC(하드웨어), 드라이버(통역사), TCP와 IP를 구현한 커널 소프트웨어가 차례로 쌓여 있고, 여기까지가 운영체제 수준의 구성입니다.

헷갈리는 점은 NIC와 드라이버가 한 세트처럼 불리지만 서로 다른 것이라는 사실입니다. NIC는 만질 수 있는 부품이고, 드라이버는 눈에 보이지 않는 소프트웨어입니다. 또 통역사는 사람이지만 드라이버는 사람이 아니라 커널 쪽에서 움직이는 프로그램이라는 점에서 비유가 끝납니다.

한 줄로 되짚으면, 드라이버는 운영체제가 하는 공통의 말을 특정 NIC의 말로 바꿔 주는 통역사이고, 그 위에 TCP와 IP 소프트웨어가 얹혀 있습니다.

## 애플리케이션·커널과 소켓

### 애플리케이션은 커널에 요청한다

호텔 객실에서 수건이 더 필요해졌다고 해 보겠습니다. 손님이 직접 세탁실에 들어가 꺼내 오지는 않습니다. 객실 전화로 프런트에 ‘수건 두 장 부탁합니다’라고 전하면 직원이 가져다줍니다. 그렇다면 컴퓨터의 프로그램은 어떻게 네트워크 기능을 쓸까요? 우리는 Chrome을 켜서 동영상을 보고 네이버나 구글에 접속하지만, Chrome이 NIC를 직접 만지지는 않습니다.

Chrome 같은 애플리케이션은 객실에 해당하는 User mode에서 실행됩니다. 예를 들어 주소창에 naver.com을 쳤다면 Chrome은 ‘이 주소로 연결해 주고 내 글자를 보내 달라’는 요청을 커널에 전합니다. 그러면 설비실에 해당하는 커널이 TCP와 IP를 처리하고 드라이버와 NIC를 거쳐 실제로 내보냅니다. 손님은 요청만 하고, 설비는 직원이 다루는 구조입니다.

#### 요청을 주고받는 인터페이스

이때 요청은 아무렇게나 하지 않고 커널이 정해 둔 접점, 곧 인터페이스(interface)를 통해서만 합니다. 호텔에서도 프런트 내선 번호와 요청하는 순서가 정해져 있는 것과 같습니다. 원문은 이를 서로 다른 영역 사이에서 정해진 방식으로 메시지를 주고받는 상황에 빗대었습니다. 이렇게 막아 두는 까닭은 일반 프로그램 하나가 실수하거나 나쁜 뜻을 품어도 건물 전체의 설비가 멈추지 않게 하려는 것입니다. 이런 정해진 요청 방식을 흔히 시스템 콜(system call)이라고 부릅니다.

헷갈리는 점은 ‘인터페이스’라는 말이 여러 곳에 쓰인다는 사실입니다. NIC의 이름 Network Interface Card에도 들어 있지만, 여기서는 ‘프로그램과 커널이 만나는 정해진 창구’라는 뜻입니다. 또 실제 컴퓨터에서의 요청은 전화 통화가 아니라 정해진 호출 절차라는 점에서 비유와 다릅니다.

한 줄로 되짚으면, 애플리케이션은 User mode에 머물면서 커널이 열어 둔 창구를 통해서만 네트워크 기능을 부탁합니다.

### 소켓으로 네트워크 기능 사용하기

애플리케이션은 네트워크 기능을 쓰기 위해 커널에 요청합니다. 그 요청을 주고받는 정해진 창구가 소켓입니다. 앞의 두 역할을 연결해 요청이 어디를 지나는지 따라가 보겠습니다.

여러분은 컴퓨터에서 메모장 파일을 열고, 글자를 쓰고, 저장하고 닫아 본 적이 있을 것입니다. 열기, 쓰기, 닫기는 누구에게나 익숙한 동작이지요. 그렇다면 네트워크 통신도 이처럼 익숙한 방식으로 다룰 수는 없을까요? 앞에서 본 커널의 창구 가운데 네트워크를 맡은 것이 바로 소켓(socket)이고, 이 강의는 그것을 ‘특별한 파일’처럼 생각해 보자고 말합니다.

호텔의 내선 전화기를 생각하면 쉽습니다. 손님은 수화기를 들고 말하기만 하면 되고, 신호가 어떤 교환기를 거쳐 프런트에 닿는지는 알 필요가 없습니다. 소켓이 바로 그 수화기입니다. 프로그램은 소켓을 하나 열고(open), 보낼 내용을 쓰고(write), 받은 내용을 읽고(read), 끝나면 닫습니다(close). 그 사이에 TCP와 IP가 어떻게 일하는지는 커널이 알아서 처리합니다.

#### 소켓이 내부 동작을 감추는 추상화

이처럼 복잡한 내부를 가리고 단순한 겉모습만 보여 주는 것을 추상화(abstraction)라고 합니다. 자동차에서 운전자가 핸들과 페달만 다루고 엔진 속은 몰라도 되는 것과 같습니다. 가령 Chrome이 소켓 하나를 열고 naver.com을 향해 글자를 쓰면, 커널이 그것을 TCP와 IP 규칙에 맞게 포장해 내보냅니다. 소켓의 구체적인 동작은 뒤에서 다시 다루니, 지금은 ‘네트워크로 가는 파일 모양의 수화기’로 기억하면 충분합니다.

헷갈리는 점은 이름입니다. socket은 영어로 전기 콘센트처럼 ‘끼우는 구멍’을 뜻하지만 전기와는 관계가 없고, 이 과정 뒤에서 배울 포트(port)와도 다른 말입니다. 또 호텔 내선 전화는 한 번에 한 통화만 하지만, 컴퓨터에서는 소켓을 여러 개 동시에 열 수 있다는 점에서 비유가 끝납니다.

한 줄로 되짚으면, 소켓은 TCP/IP라는 복잡한 일을 파일처럼 열고 쓰고 닫는 단순한 동작으로 바꿔 준 창구입니다.

## OSI에서 TCP/IP·장치까지

### OSI의 층과 실제 구현 위치

건물 설계도에는 ‘1층은 로비, 2층은 사무실, 3층은 회의실’이라고 층마다 역할이 적혀 있습니다. 하지만 설계도만 보고서는 지금 이 건물에서 어느 회사가 어느 층을 실제로 쓰는지 알 수 없습니다. 그렇다면 OSI 7계층도 마찬가지로 ‘개념으로만’ 알고 있으면 부족하지 않을까요? 이 강의가 강조하는 것이 바로 이 점입니다. 계층이라는 설계도를 실제 컴퓨터의 어느 부분이 맡는지 연결해 보자는 것입니다.

OSI의 층을 아래에서 위로 다시 적어 보겠습니다. L1은 물리 계층(Physical), L2는 데이터 링크 계층(Data Link), L3는 네트워크 계층(Network), L4는 전송 계층(Transport)이고, 그 위에 Session, Presentation, Application 계층이 있습니다. 이 층들은 한 건물의 층수일 뿐이어서 위층이 아래층의 도움을 받아 일한다고 이해하시면 됩니다.

#### User mode와 Kernel mode에 연결하기

이제 설계도에 입주 회사를 적어 넣어 보겠습니다. 이 강의의 그림에서는 L5 이상, 즉 Session·Presentation·Application 층을 User mode의 애플리케이션과 프로세스 수준의 기능으로 봅니다. Chrome이 웹 페이지를 요청하는 일이 대표적인 예입니다. 그 아래 L4 전송 계층은 운영체제 안에 구현된 TCP와 연결해서 이해합니다. 따라서 앞에서 본 User mode와 Kernel mode의 경계는 대략 ‘L5 이상’과 ‘L4 이하’ 사이에 놓입니다.

다만 이것은 이 강의의 그림에서 이해를 돕기 위해 연결한 방식입니다. 실제 프로그램은 한 층에 딱 맞게 만들어지지 않는 경우도 있으므로, ‘L5 이상은 앱’이라는 말은 외우기 좋은 기준선으로 받아들이시면 됩니다. 건물의 층 구분이 실제 사무실 칸막이와 정확히 일치하지 않을 수도 있는 것과 비슷합니다.

한 줄로 되짚으면, OSI는 설계도이고 구현 위치는 입주 현황이며, L5 이상은 User mode 애플리케이션 쪽, L4는 운영체제의 TCP 쪽에 해당합니다.

### TCP와 IP의 역할 구분하기

앞에서 본 OSI의 역할을 이제 실제 컴퓨터의 구성 요소와 연결합니다. 설계도의 L4와 L3에는 TCP와 IP가 이어지고, 더 아래에서는 데이터 링크와 물리 계층이 드라이버와 NIC로 이어집니다.

택배를 보내는 장면을 생각해 보겠습니다. 내가 상자에 물건을 담으면 택배 회사가 송장을 붙이고, 배송 기사가 주소를 보고 목적지 쪽으로 옮기며, 마지막에 받는 사람이 물건을 잘 받았는지까지 챙깁니다. 네트워크도 한 번에 한 가지 일만 하는 역할이 층층이 나뉘어 있습니다. 그렇다면 TCP와 IP는 이 택배에서 각각 어디쯤 있을까요?

#### L4 TCP와 L3 IP

IP는 L3 네트워크 계층에 해당하고, 송장에 주소를 적어 목적지 쪽으로 보내는 일에 가깝습니다. 가령 내 컴퓨터가 192.168.0.10이라는 주소를 가졌다면, 그런 주소가 쓰이는 곳이 바로 IP의 영역입니다. TCP는 L4 전송 계층에 해당하고, 정리문의 표현대로 ‘전송의 문제’를 다룹니다. 택배로 치면 보낸 물건이 제대로 전해지는지를 신경 쓰는 쪽이며, 자세한 방식은 뒤에서 배웁니다.

‘TCP/IP’라고 한 줄로 적으니 같은 층의 짝처럼 보이지만, 계층 그림에서는 TCP가 위에, IP가 아래에 놓입니다. 두 프로토콜이 서로 다른 층에 있고 위층이 아래층의 도움을 받는다는 관계를 함께 기억해야 합니다. 한 번의 요청이 위에서 아래로 내려가는 길을 따라가 보면 Chrome의 글자는 TCP를 거치고, IP를 거치고, 드라이버를 지나 NIC에 닿습니다.

그 아래의 데이터 링크 계층과 물리 계층은 실제 구성 요소와 이어집니다. NIC는 하드웨어이고, 데이터 링크 계층의 기능은 그림에서 드라이버와 하드웨어에 걸쳐 표현됩니다. 한 층이 꼭 한 가지 부품에만 대응하지는 않는다는 점이 헷갈릴 수 있으니, ‘걸쳐 있다’는 표현을 그대로 받아들이시면 됩니다.

택배 비유는 이쯤에서 끝납니다. 실제 네트워크에서는 사람이 아니라 소프트웨어와 장치가 일을 나누어 맡습니다. 한 줄로 되짚으면 TCP는 L4, IP는 L3이고, 그 아래 L2·L1은 드라이버와 NIC 쪽으로 이어집니다.

### 드라이버·NIC·프로세스까지 이어 보기

TCP와 IP의 역할을 구분한 다음, 아래 계층이 드라이버와 NIC에 어떻게 나뉘어 구현되는지 확인합니다. 마지막으로 NIC 안의 펌웨어와 소켓을 여는 프로세스까지 살펴보며 한 번의 요청이 지나는 길을 마무리합니다.

호텔 엘리베이터에는 제어 보드가 내장되어 있어서 관리실이 일일이 명령하지 않아도 층 버튼에 반응합니다. 마찬가지로 NIC 같은 하드웨어 안에도 장치 자체에 내장된 작은 소프트웨어가 들어 있는데, 이를 펌웨어(firmware)라고 부릅니다. 앞에서 데이터 링크 계층이 ‘드라이버와 하드웨어에 걸쳐 있다’고 한 것은, 이 계층의 일이 커널의 드라이버 영역과 하드웨어 안의 펌웨어에 나뉘어 있기 때문입니다.

그렇다면 이 구조는 앞으로의 강의에서 어떻게 쓰일까요? 이후에 User mode와 Kernel mode가 언급될 때마다 ‘이 일은 앱 쪽, 이 일은 커널과 드라이버 쪽, 이 일은 장치 쪽’ 하고 위치를 떠올리면 됩니다. 길을 잃었을 때 건물 안내도를 보는 것과 같습니다.

#### 소켓을 열고 닫는 주체는 프로세스

소켓에 대해서는 한 가지를 분명히 해 두어야 합니다. 소켓은 네트워크를 추상화한, 파일 모양의 인터페이스이고, 이것을 열고 닫는 주체는 프로세스(process)입니다. 프로세스란 실행 중인 프로그램을 말합니다. 하드디스크에 설치만 되어 있을 때는 ‘프로그램’이고, 더블클릭해서 실제로 움직이는 순간 ‘프로세스’가 됩니다. 호텔에 빗대면 수화기를 드는 것은 객실이 아니라 그 객실에 머무는 손님이므로, ‘507호 손님이 프런트 수화기를 들었다’는 식으로 누가 무엇을 열었는지가 정해집니다.

그래서 ‘어떤 프로세스가 어떤 소켓을 열었다’는 관계를 분명히 알아야 합니다. 예를 들어 번호 4321인 Chrome 프로세스가 소켓 하나를 열었다면, 그 통신의 주인은 4321번 Chrome 프로세스입니다(번호는 예시입니다). 네트워크가 이상할 때 ‘누가 통신하고 있는가’를 찾아가는 출발점이 바로 이 관계입니다.

헷갈리는 점은 애플리케이션, 프로그램, 프로세스가 비슷하게 쓰인다는 것입니다. 일상에서는 같은 말처럼 쓰지만 여기서는 실행 중인 상태를 가리킬 때 프로세스라고 합니다. 한 줄로 되짚으면, 소켓은 파일 모양의 네트워크 창구이고 그것을 열고 닫는 주체는 프로세스입니다.
