# 문제 해결 과정을 블로그에 기록하기

## 오늘의 문제와 고민 고르기

실습에서 만난 문제 하나를 골라 **내 GitHub 블로그에 문제 해결 과정**을 남깁니다. 따로 답안 파일을 만들지 않고 글 한 편에 바로 씁니다. 실무에서도 기록을 다시 보는 사람은 정답보다 문제 상황, 선택한 방법과 그 이유, 확인한 결과를 알고 싶어 합니다.

예를 들어 요청을 언제 거절할지, 이미 승인한 요청을 다시 처리하지 않게 할지 중 실제로 고민한 주제를 골라 보세요. 완성하지 못했다면 어디까지 시도했고 어디에서 막혔는지 적어도 됩니다.

## 어떤 내용을 남기나요?

처음 읽는 사람에게 **문제, 선택과 이유, 검증 결과**가 차례로 보이도록 씁니다.

다음 다섯 가지를 내 말로 적습니다. 실제로 확인하지 않은 내용은 확인했다고 쓰지 않습니다.

1. **문제 상황**: 무엇을 만들고 있었고 무엇이 문제였나요?
2. **시도와 선택**: 어떤 방법을 시도하거나 선택했나요? 다른 방법 대신 그것을 고른 이유는 무엇인가요?
3. **확인한 결과**: 어떤 입력으로 실행했고 화면에서 무엇을 봤나요? 필요한 출력 한두 줄을 함께 적어도 좋습니다.
4. **배운 점과 다음 행동**: 알게 된 점은 무엇이고 아직 확인하지 못한 점은 무엇인가요?
5. **AI 도움**: 사용했다면 무엇을 물었고, 답변 중 무엇을 직접 확인했나요? 사용하지 않았다면 생략합니다.

예시: “이미 승인한 요청을 다시 승인하면 어떤 문제가 생길지 고민했습니다. 검토 중인 요청만 승인하도록 상태를 확인하고, 이미 승인한 요청을 다시 실행했습니다. 두 번째 승인 시도가 막히는 출력으로 확인했습니다. 아직 다른 입력은 확인하지 못했습니다.” 자신의 경험과 다르면 그대로 쓰지 말고 내 상황을 씁니다.

## 블로그 글 파일 만들기

Unit 1에서 만든 `network-study-notes` 저장소를 VS Code로 엽니다. 아직 GitHub Pages를 설정하지 않았다면 [Unit 1 시작하기](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 준비합니다.

1. 저장소 안 `_posts` 폴더를 오른쪽 클릭하고 **New File**을 선택합니다.
2. 새 글은 오늘 날짜와 주제를 담은 영문 파일명으로 저장합니다. 예를 들어 2026년 11월 24일에 이 주제로 썼다면 `_posts/2026-11-24-prevent-double-approval.md`입니다. 이미 게시한 글은 기존 주소가 유지되도록 파일명을 그대로 두세요.
3. 아래 글 틀을 복사해 파일에 붙여 넣습니다. 제목과 날짜도 내 글과 오늘 날짜로 바꿉니다. 날짜는 파일명과 같게 씁니다.

첫 문장에는 이 과정을 모르는 독자도 상황을 떠올릴 수 있게 어떤 권한을 누가 요청하거나 점검했는지 적으세요. 틀의 질문은 자신의 문장으로 바꾸고, 쓰지 않은 항목은 지웁니다. 다른 문제를 골랐다면 제목도 바꾸세요. 이 예시에서는 `access_control/req_review.py`에서 판단을 내리는 줄과 직접 본 출력이 근거가 됩니다. 글을 올린 뒤 GitHub에서 해당 코드 파일을 열고 주소를 복사해 글의 「검증 결과」에 붙입니다. Markdown에서는 `[req_review.py 코드 보기](복사한 주소)`에서 괄호 안을 실제 주소로 바꾸면 링크가 됩니다. 수정한 글을 다시 올린 뒤 「전체 글」에서 제목을 눌러 본문과 코드 링크를 열어 봅니다.

## 내 경험으로 채우기

각 질문을 내 실제 경험으로 바꾸어 적고 저장합니다(`Ctrl + S`). 코드나 출력은 문제와 결과를 이해하는 데 필요한 부분만 넣습니다. AI에게 글을 정리하도록 도움을 요청할 수 있지만, 답변은 직접 실행하거나 실습 내용과 대조한 뒤 내 말로 씁니다.

> **확인** — 문제, 시도와 선택 이유, 직접 본 결과, 배운 점이 글에 들어 있나요? 아직 확인하지 못한 것은 그 상태 그대로 적습니다.

## 공개 전 확인하고 올리기

글과 `access_control` 코드에 비밀번호, 토큰, 개인 이메일·전화번호, 실제 다른 사람의 이름이 없는지 확인합니다. 화면 캡처가 있다면 내 컴퓨터 사용자 이름 등 개인 정보도 확인합니다. 자세한 내용은 [공개 전 점검](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)을 참고하세요.

이제 글과 실습 코드를 함께 올립니다. VS Code에서 `network-study-notes` 폴더를 열고 **Terminal › New Terminal**로 Git Bash를 엽니다. `pwd` 결과가 `…/network-study-notes`로 끝나는지 확인합니다. 다르면 저장소 폴더를 오른쪽 클릭하고 **Open in Integrated Terminal**을 선택합니다.

1. `git status -u`로 올릴 파일을 살펴봅니다. `.env`나 `.venv`가 보이면 올리지 말고 `.gitignore` 설정을 확인합니다.
2. `python check_publish.py`를 실행합니다. 오류나 주의가 나오면 내용을 고치고 다시 실행합니다.
3. 확인을 마쳤으면 아래 명령을 차례로 실행합니다.

```bash
git add .
git commit -m "Add module 3 unit 2 practice and post"
git push
```

4. GitHub 저장소에 실습 코드가 있는지, 공개 사이트의 「전체 글」에서 제목을 눌러 본문이 열리는지 확인합니다. 글이 보이지 않으면 [첫 화면 확인하고 막힐 때](__SITE__/exercises/module/3/unit/1/lesson/1/page/9)를 확인합니다. `git push`가 거절되면 변경 사항을 먼저 확인하고 원격 저장소의 변경을 받아온 뒤 다시 시도합니다.
