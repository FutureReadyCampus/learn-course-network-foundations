# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 쓴 요청서 코드와 그때 한 고민을 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 글은 깃허브의 내 저장소 `network-study-notes` 의 `_posts/` 폴더에 올립니다(이 저장소가 내 GitHub Pages 포트폴리오입니다). 포트폴리오를 아직 만들지 않았다면 [Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 따라 합니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

보고서에 이미 답을 적은 질문을 고르면 빨리 시작할 수 있습니다.

**오늘의 글감 (핵심 실습)**

1. 요청자가 적은 만료 시각(`until`)을 그대로 믿고 승인해도 될까요? 승인 전에 확인할 것을 두 가지 이상 써 보세요.
2. 이미 승인한 요청서를 다시 승인하지 못하게 막은 이유는 무엇인가요? 막지 않으면 어떤 일이 생길까요?
3. 요청한 본인이 처리하는 것만 막으면 충분할까요? 친구에게 대신 승인을 부탁하는 경우까지 막으려면 무엇이 더 필요할까요?

**선택 글감 (응용 2-2를 했다면)**

1. 기한을 넘긴 요청을 찾았을 때 알림만 보낼 경우와 윗사람에게 넘길 경우를 어떤 기준으로 나누었나요?
2. 상태(`reviewing`)를 보지 않고 접수 시각만으로 기한을 따지면 리스트에 어떤 문제가 생기나요?

세 문장이면 충분합니다. 막혀서 끝내지 못한 이야기도 좋은 글입니다. 어디까지 해 봤고 어디서 멈췄는지를 적어 두면, 다음에 다시 볼 때 가장 쓸모 있는 기록이 됩니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 「보고서 쓰기」에서 가장 오래 고민한 질문과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Unit 1 오늘의 글 쓰기에서 한 것처럼, 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고 터미널에서 올립니다. 글 틀 세 가지의 내용은 [Unit 1 시작하기 레슨의 「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `_templates/post-practice.md` |

**올리는 순서**

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-20-m3-u2-request-approval.md` 처럼 만듭니다(경로 `_posts/2026-11-20-m3-u2-request-approval.md`). 앞은 오늘 날짜, 뒤는 영문 제목입니다.
2. 고른 글 틀을 붙여 넣고 맨 위 머리말(front matter)을 고칩니다.
   1. `module: 3`, `unit: 2` 로 씁니다. 글 틀의 `unit:` 숫자는 예시이니 꼭 `2` 로 바꿉니다. 이 두 줄이 첫 화면 「나의 진행」에서 Module 3 줄의 2번 칸을 채웁니다.
   2. `title` 과 `date` 를 내 글에 맞게 고칩니다. `date:` 는 파일 이름의 날짜와 같게 씁니다. 날짜가 미래면 글이 목록에 나오지 않습니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 오늘 날짜 이름(예: `_posts/2026-11-20-m3-u2-request-approval.md`)으로 글 파일을 만들고 글 틀을 붙여 넣었다
<!-- /checklist -->

3. 빈칸을 채우고 저장합니다. 코드는 따로 옮기지 않습니다. 오늘 만든 `access_control/req_create.py` · `access_control/req_review.py` 가 같은 저장소에 이미 올라가 있으니, 글에는 `전체 코드: access_control/req_review.py` 처럼 위치만 적습니다.

<!-- checklist -->
- [ ] 머리말을 `module: 3` · `unit: 2` 와 내 `title` · `date` 로 고치고 세 칸을 채워 저장했다
<!-- /checklist -->

4. 올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 맨 위 머리말에 `module: 3` · `unit: 2` 가 있으면 성공입니다. 없으면 1번에서 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

무엇을 쓸지 떠오르지 않으면 아래에서 하나를 골라 시작합니다.

| 고른 글감 | 붙일 줄 | 이어 쓸 것 |
|---|---|---|
| 글감 1 | `req_create.py` 의 `if until <= received_at:` | 거르는 것(지난 시각)과 못 거르는 것(먼 미래)을 나눔 |
| 글감 2 | `req_review.py` 의 `if request["status"] != "reviewing":` | 채우기 전 `2 승인 -> True 승인` 과 채운 뒤를 비교 |
| 글감 3 | `if request["user"] == approver:` | 막는 것(본인 승인)과 못 막는 것(대신 승인)을 나눔 |

1. 실행 결과는 출력 전체를 붙이지 않아도 됩니다. 글에서 말하는 줄 한두 개만 글 안의 코드 상자(```` ``` ```` 로 감싼 칸)에 붙이고, 그 줄에서 무엇을 봐야 하는지 한 문장을 덧붙입니다.
2. 무엇부터 쓸지 모르겠으면 보고서 `report_u2.md` 에 쓴 내 답 하나를 글 틀의 「왜 골랐나」 칸에 옮기고, 앞의 두 문장을 거기에 맞춰 씁니다.

생각을 정리하는 AI 도우미 프롬프트 세 가지는 [Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에 붙여 넣는 글과 코드에는 비밀키·개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 표의 「붙일 줄」을 붙이고 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 코드(`access_control/` 의 파일 포함)에 비밀키 · 토큰 · `.env` 내용이 없습니다.
2. 개인 이메일 · 전화번호가 없습니다.
3. 실습 데이터의 이름(`seoyeon`, `gaeun` 등)이 아닌 실제 사람 이름이 없습니다.
4. 머리말이 `module: 3`, `unit: 2` 입니다.

**올리기** — **[터미널]** 네 줄을 모두 확인했으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..` → `python check_publish.py`(맥북은 `python3`) → `git add .` → `git commit -m "Add unit 2 post"` → `git push` → `cd access_control`. 점검에서 `[오류]` 가 나오면 그 부분을 지우고 다시 돌린 뒤 올립니다.
