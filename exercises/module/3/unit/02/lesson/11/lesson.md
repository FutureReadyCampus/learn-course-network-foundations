# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 쓴 요청서 코드와 그때 한 고민을 글 한 편으로 남깁니다. 글은 내 GitHub Pages 포트폴리오의 `_posts/` 폴더에 올립니다. 포트폴리오를 아직 만들지 않았다면 [Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 따라 합니다.

**40분은 이렇게 나눕니다**

1. 고르기 5분: 아래 글감 질문 중 하나를 고릅니다. 보고서에 이미 답을 적은 질문을 고르면 빨리 시작할 수 있습니다.
2. 쓰기 25분: 글 틀을 복사해 빈칸을 채웁니다.
3. 점검 · 올리기 10분: 공개해도 되는 내용인지 확인하고 올립니다.

**핵심 실습 글감 질문** (실습 2-1 · 2-2)

1. 요청자가 적은 만료 시각(`until`)을 그대로 믿고 승인해도 될까요? 승인 전에 확인할 것을 두 가지 이상 써 보세요.
2. 이미 승인한 요청서를 다시 승인하지 못하게 막은 이유는 무엇인가요? 막지 않으면 어떤 일이 생길까요?
3. 요청한 본인이 처리하는 것만 막으면 충분할까요? 친구에게 대신 승인을 부탁하는 경우까지 막으려면 무엇이 더 필요할까요?

**도전 2-2를 했다면 쓸 수 있는 글감** (선택)

1. 기한을 넘긴 요청을 찾았을 때 알림만 보낼 경우와 윗사람에게 넘길 경우를 어떤 기준으로 나누었나요?
2. 상태(`reviewing`)를 보지 않고 접수 시각만으로 기한을 따지면 리스트에 어떤 문제가 생기나요?

세 문장만 써도 한 편의 글입니다. 오늘 막혀서 실습을 다 못 했다면, 어디서 막혔는지 쓴 글도 좋은 글입니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Unit 1 시작하기에서 한 것처럼 **GitHub 웹 화면**에서 파일을 만들고 붙여 넣습니다. 글 틀 세 가지의 내용은 [Unit 1 시작하기 레슨의 「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**글 틀 고르기**

| 오늘의 나 | 고를 글 틀 |
|---|---|
| 실습 하나(예: 실습 2-2)를 글 한 편으로 쓰고 싶다 | `_templates/post-practice.md` |
| 시간이 5분밖에 없다 | `_templates/post-short.md` |
| 실습하다 막혔다 | `_templates/post-stuck.md` |

**올리는 순서**

1. 내 포트폴리오 저장소에서 **Add file → Create new file** 을 누릅니다.
2. 파일 이름 칸에 `_posts/날짜-영문제목.md` 를 적습니다. 예: `_posts/2026-11-20-m3-u2-request-approval.md`
3. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)의 `module: 3`, `unit: 2` 를 이렇게 적습니다. 그래야 첫 화면 「나의 진행」에서 Module 3의 2번 칸이 채워집니다. `date:` 는 파일 이름의 날짜와 같게 씁니다.
4. 빈칸을 채우고 오른쪽 위 **Commit changes** 를 누른 뒤, 나오는 창에서 한 번 더 **Commit changes** 를 누릅니다.
5. 코드를 함께 남기려면 `code/` 폴더에 같은 방법으로 파일을 만들고 내 코드를 붙여 넣습니다. 예: `code/m3_u2_req_review.py`. 글에는 `전체 코드: code/m3_u2_req_review.py` 처럼 위치를 적습니다.
6. 1~2분 뒤 내 사이트 첫 화면을 열어 최신 글에 새 글이 보이는지, Module 3의 2번 칸이 채워졌는지 확인합니다.

## 막힐 때 힌트

무엇을 쓸지 떠오르지 않으면 아래에서 하나를 골라 시작합니다.

1. 글감 1을 골랐다면 `req_create.py` 의 `if until <= received_at:` 줄을 붙이고, 이 줄이 걸러 내는 것(이미 지난 시각)과 걸러 내지 못하는 것(너무 먼 미래)을 나누어 씁니다.
2. 글감 2를 골랐다면 `req_review.py` 의 `if request["status"] != "reviewing":` 줄과 실행 결과의 `1 승인 -> False 검토 중이 아님` 줄을 함께 붙이고, 이 줄을 뺐을 때 어떻게 되는지 씁니다.
3. 글감 3을 골랐다면 `if request["user"] == approver:` 줄이 막는 것(본인 승인)과 막지 못하는 것(친구의 대신 승인)을 한 문단씩 씁니다.
4. 실행 결과는 터미널 출력을 복사해 글 안의 코드 상자(```` ``` ```` 로 감싼 칸)에 붙입니다. 출력 전체보다 내가 설명할 줄 두세 줄만 붙이면 읽기 쉽습니다.
5. 보고서 `report_u2.md` 에 적은 답이 있으면 그 답을 첫 문단으로 옮기고, 「왜 그렇게 생각했는지」를 한 문단 더 붙입니다.

생각을 정리하는 AI 도우미 프롬프트 세 가지는 [Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에 붙여 넣는 글과 코드에는 비밀키·개인정보를 넣지 않습니다.

## 공개 전 점검

올리기 전에 하나씩 확인합니다.

- [ ] 비밀키 · 토큰 · `.env` 내용이 글과 코드에 없다
- [ ] 개인 이메일 · 전화번호가 없다
- [ ] 실습 데이터의 이름(`seoyeon`, `gaeun` 등)이 아닌 실제 사람 이름이 없다
- [ ] 머리말이 `module: 3`, `unit: 2` 이다
