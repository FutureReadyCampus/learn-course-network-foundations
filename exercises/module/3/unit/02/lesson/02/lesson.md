# 시작하기

## 목표: 요청서 접수·승인·부여

**먼저 확인해 보세요.** Unit 1에서 GitHub Pages 포트폴리오를 만들고 내 사이트 주소를 열어 샘플 글이 보였나요? 아직 만들지 않았거나 화면이 나오지 않으면 [Unit 1 시작하기의 「내 기록 남기기: 소개」](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 설정하고, 「첫 화면 확인하고 막힐 때」까지 확인한 뒤 돌아옵니다. GitHub Pages에서 Jekyll을 쓰는 데 내 컴퓨터에 Jekyll을 따로 설치할 필요는 없습니다.

Unit 2는 Module 3의 두 번째 단계인 **권한 주기**입니다. Unit 1 실습에서는 판정 함수 두 개를 만들었습니다.
- `check_permission`(`rbac.py`): 사용자 파일과 역할 파일을 읽어 허용 · 거부를 정합니다.
- `evaluate_access`(`policy.py`): 여기에 **예외**(기간을 정해 따로 허락한 권한)까지 보고 최종으로 정합니다.

이번 Unit에서는 직원이 「이 자료를 보게 해 주세요」라고 하는 **요청**을 요청서로 받아 기록으로 남깁니다. 그다음 **보안 담당**(회사에서 누가 무엇을 볼 수 있는지 관리하는 사람)이 승인하거나 반려하는 흐름을 만듭니다. 학교에서 체험학습 신청서를 내면 담임 선생님이 허락하거나(**승인**) 고칠 점을 적어 돌려보내는(**반려**) 것과 같습니다.

**오늘의 계획 (약 2시간 40분)**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 시작하기 | 15분 | 이 레슨을 읽고 Unit 1 파일이 있는지 확인 |
| 2. 핵심 실습 | 약 110분 | 실습 2-1 · 2-2, 「권한 부여 준비」, 실습의 결과 확인 |
| 3. 마무리 | 15분 | 「이번 Unit 마무리」 레슨에서 올리기 |
| 4. 글쓰기 | 20분 | 「문제 해결 과정을 블로그에 기록하기」에서 글 한 편 |

실습에서 고민한 점을 떠올려 두고 글쓰기 20분에 문제와 해결 과정을 블로그에 남깁니다. 하루 3시간에서 남는 20분쯤은 밀린 곳을 따라잡는 여유 시간입니다.

시작하기 전에 앞의 「준비 · 내 작업 폴더 열기」 레슨에서 Unit 1에 사용한 내 작업 폴더를 열어 둡니다.

**오늘 만들 것 두 가지**

| 실습 | 파일 | 직접 쓰는 곳 | 하는 일 |
|---|---|---|---|
| **실습 2-1** | `req_create.py` | `create_request` 의 세 줄 | 요청서를 리스트에 모으고 잘못된 요청을 거름 |
| **실습 2-2** | `req_review.py` | `approve_request` 의 두 줄 | 검토 중인 요청서만 승인 · 반려함 |

「권한 부여 준비」 `req_grant.py` 에는 함수 `grant_request` 가 들어 있습니다. 승인된 요청서를 정책(회사가 정해 둔 허용 규칙)으로 한 번 더 확인하고, 통과한 것만 예외 권한을 줍니다. 직접 쓰지 않고 완성본을 복사해 둡니다.

**응용 2-1 ~ 2-3은 여유가 되면 해 보세요.** 핵심 실습 두 개와 글쓰기를 먼저 마칩니다. 응용을 하지 않아도 다음 Unit을 따라가는 데 문제가 없습니다.

| 응용 | 하는 일 |
|---|---|
| 응용 2-1 | `grant_request` 를 직접 써 봄 |
| 응용 2-2 | 처리 기한(SLA · 에스엘에이)을 넘긴 요청서를 찾음 |
| 응용 2-3 | 요청서 전체를 파일로 저장함 |

SLA 는 정해 둔 시간 안에 처리하겠다는 약속입니다. 예를 들어 「요청서는 접수하고 4시간 안에 답한다」처럼 정합니다.

> **확인** — 오늘 할 네 가지(시작 · 핵심 실습 · 마무리 · 글쓰기)와 직접 쓰는 곳(실습 2-1 세 줄, 실습 2-2 두 줄)을 말할 수 있으면 성공입니다. 헷갈리면 위 「오늘의 계획」 표를 한 번 더 봅니다.

## 터미널 열고 앞에서 만든 파일 확인하기

1. **[VS Code]** 왼쪽 목록의 `access_control` 폴더를 오른쪽 클릭 › **Open in Integrated Terminal** 로 터미널을 엽니다.
   - 터미널 오른쪽 위 이름이 **bash** 가 아니면(예: `powershell`) `+` 옆 **∨** 에서 **Select Default Profile** › **Git Bash** 를 고른 뒤 터미널을 닫고 1번을 다시 합니다. 이 Unit의 명령은 모두 Git Bash 기준입니다.
2. **[터미널]** 위치와 파일을 확인합니다. 결과가 `…/network-study-notes/access_control` 로 끝나야 합니다.
   ```bash
   pwd
   ls
   ls config
   # 이 명령은 전체를 복사해 Git Bash에 붙여 넣어 실행하세요.
   python -c "
   from datetime import datetime
   from policy import evaluate_access
   from exception_policy import EXCEPTIONS
   print('이전 파일 정상', len(EXCEPTIONS))
   print(evaluate_access('dami', 'SALES', 'QUERY', datetime(2026, 10, 23, 10, 0)))
   "
   ```
   - 명령 풀이: `python -c "…"` 따옴표 안의 파이썬 코드를 파일로 만들지 않고 바로 실행함. 여기서는 Unit 1 파일을 불러와 예외 수를 세고, `dami` 의 영업 실적 조회를 판정해 봅니다.
   - 마지막 두 줄에 `이전 파일 정상 5` 와 `(False, '퇴사한 계정')` 이 나와야 합니다. `dami` 는 Unit 1 사용자 파일에서 퇴사(회사를 그만둠)로 적힌 계정이라 거부가 맞습니다.

- [ ] `python -c` 명령을 실행해 `이전 파일 정상 5` 와 `(False, '퇴사한 계정')` 이 나왔다
<!-- /checklist -->

3. 오늘 코드는 아래 파일을 불러 씁니다. `ls` 와 `ls config` 에 모두 보여야 합니다.

   | 파일 | 담긴 것 | 없으면 |
   |---|---|---|
   | `config/users.json` · `config/roles.json` | 사용자 파일과 역할 파일 | Unit 1 정답 레슨의 실습 1-1 정답에서 복사 |
   | `rbac.py` | 사용자 딕셔너리 `USERS`, 역할 판정 함수 `check_permission` | Unit 1 실습 1-2 레슨의 코드 상자 + 정답 레슨의 실습 1-2 채운 코드 |
   | `config/exceptions.json` | 예외 파일 | Unit 1 「예외 판정 준비」 레슨에서 복사 |
   | `exception_policy.py` | 예외 리스트 `EXCEPTIONS`, 시각 형식 `TIME_FORMAT` | Unit 1 「예외 판정 준비」 레슨에서 복사 |
   | `config_loader.py` | 안전한 읽기 함수 `load_json` | Unit 1 「예외 판정 준비」 레슨에서 복사 |
   | `policy.py` | 최종 판정 함수 `evaluate_access` | Unit 1 실습 1-3 레슨의 코드 상자 + 정답 레슨의 실습 1-3 채운 코드 |

   - `rbac.py` · `policy.py` 는 레슨의 코드 상자를 붙여 넣고, 빈칸을 정답 레슨의 채운 코드로 채웁니다.
   - `config` 안의 파일은 `config` 폴더에 만듭니다. 만든 뒤 2번의 마지막 줄을 다시 칩니다.

<!-- checklist -->
- [ ] `access_control` 폴더에서 위 표의 Unit 1 파일을 확인하고, 없던 파일은 「없으면」 칸대로 만들었다
<!-- /checklist -->

4. **파일은 이렇게 만듭니다.** 이 Unit의 파일은 모두 레슨의 코드 상자에서 복사해 만들고, 따로 내려받는 파일은 없습니다. 「`파일이름` 파일을 만들어 아래 내용을 붙여 넣습니다」라고 하면:
   1. **[VS Code]** 왼쪽 목록에서 알려 준 폴더를 오른쪽 클릭 › **New File** 을 누르고, 알려 준 **파일 이름을 그대로** 적고 Enter 를 칩니다.
   2. 코드 상자의 복사 버튼으로 내용을 복사해 새 파일에 붙여 넣고, `Ctrl + S` 로 저장합니다.
   - 실습을 마친 뒤 블로그 글에 고민과 결과를 적습니다.
5. 실습은 **할 일 → 순서**대로 하고, `[창 이름]` 이 지금 쓸 창입니다. 코드는 `# ←` 가 있는 주석 바로 아래 줄에 한 줄씩 채우고, 막히면 「직접 쓰는 곳」의 힌트를 본 뒤 이 Unit 뒤쪽의 정답을 봅니다.

> 실행은 VS Code 의 ▶ 단추가 아니라 **터미널**에서 합니다. 3번의 파일은 오늘 고치지 않고 불러 쓰기만 합니다. 오늘 만드는 파일은 모두 새 파일입니다.

> **확인** — 2번의 마지막 두 줄에 `이전 파일 정상 5` 와 `(False, '퇴사한 계정')` 이 나오면 성공입니다. `ModuleNotFoundError` 나 `FileNotFoundError` 가 나오면 오류 끝에 적힌 파일 이름을 3번 표에서 찾아 그 「없으면」 칸대로 만든 뒤 다시 칩니다.
