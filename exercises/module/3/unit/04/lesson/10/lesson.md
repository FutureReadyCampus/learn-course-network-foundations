# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

하루의 마지막 40분은 오늘 한 회수를 내 말로 남기는 시간입니다. 글은 내 GitHub Pages 포트폴리오에 올립니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**40분은 이렇게 나눕니다**

| 순서 | 시간 | 할 일 |
|---|---|---|
| 고르기 | 5분 | 아래 글감 질문 중 하나를 고릅니다 |
| 쓰기 | 25분 | 글 틀을 복사해 내 답을 글로 풉니다 |
| 점검 · 올리기 | 10분 | 공개 전 점검을 하고 GitHub 에 올린 뒤 첫 화면을 확인합니다 |

- 글감은 보고서 `report_u4.md` 에 적은 답 가운데 가장 오래 고민한 것을 고르면 쉽습니다.

**글감 질문 (실습 4-1 · 4-2)**

1. 권한을 없애는 일인데도 쓰기 권한이나 한 번에 여러 권한이 사라지는 회수는 승인을 받게 했습니다. 승인 없이 바로 회수하게 했다면 무엇이 위험할까요?
2. 회수 전후 판정이 그대로인 권한도 회수하고 이력을 남겼습니다. 이미 막혀 있는 권한을 정리하는 이유는 무엇인가요?
3. 반년 뒤 「이 권한이 왜 없어졌나요?」라는 질문에 답하려면 회수 이력에 무엇이 더 있어야 할까요?

**선택 글감 (응용 4-2 · 4-3을 했다면)**

1. 거부 이유를 하나만 알려 주는 방식과 어긋난 조건을 모두 알려 주는 방식 중 무엇을 골랐나요? 정상 사용자, 계정을 가로챈 사람, 관제 담당자의 입장을 나눠 생각해 보세요.
2. 계정에 권한이 있어도 새벽 2시 외부 접속 요청은 거부해야 하는 이유는 무엇인가요? 로그인 때 한 번만 확인했다면 어떻게 되었을까요?

세 문장만 써도 한 편의 글입니다. 오늘 막혀서 실습을 다 못 했다면 그 막힌 이야기도 좋은 글이 됩니다. 어디서 멈췄는지 남겨 두면 다음에 나도, 글을 읽는 사람도 도움을 받습니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Unit 1 시작하기 레슨에서 한 것처럼 **GitHub 웹 화면**에서 파일을 만들고 붙여 넣습니다. 글 틀 세 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 나의 상황 | 고를 글 틀 |
|---|---|
| 실습 4-1 이나 4-2 하나를 글 한 편으로 쓰고 싶다 | `_templates/post-practice.md` |
| 시간이 5분밖에 없다 | `_templates/post-short.md` |
| 실습하다 막혔다 | `_templates/post-stuck.md` |

**2. 새 글 파일 만들기**

1. 내 포트폴리오 저장소에서 `_posts` 폴더를 열고 **Add file › Create new file** 을 누릅니다.
2. 파일 이름은 `날짜-영문제목.md` 모양으로 적습니다. 예: `_posts/2026-11-20-m3-u4-revoke-approval.md`
3. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit 에 맞게 고칩니다.
   ```
   module: 3
   unit: 4
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 3 의 **4번** 칸을 채웁니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다.
4. 빈칸을 채우고, 이 레슨 마지막 페이지 「공개 전 점검」의 네 가지를 확인한 뒤 **Commit changes** 를 누릅니다.

**3. 코드 올리기**

글에서 소개한 코드는 저장소의 `code/` 폴더에 올립니다. `code` 폴더에서 **Add file › Create new file** 을 누르고, 이름은 Unit 번호가 보이게 적습니다.

- 예: `code/m3_u4_revoke_approve.py`(실습 4-1), `code/m3_u4_revoke.py`(실습 4-2)
- 글 안에는 핵심 몇 줄만 코드 상자로 붙이고, 「전체 코드: `code/m3_u4_revoke.py`」처럼 위치를 적습니다.

**4. 확인하기**

올리고 1~2분 기다린 뒤 내 사이트 첫 화면을 엽니다. 최신 글에 내 글이 보이고, 「나의 진행」의 Module 3 · 4번 칸이 채워졌으면 끝입니다. 보이지 않으면 저장소의 **Actions** 탭을 먼저 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(승인)**: `needs_approval` 의 마지막 줄 `return is_sensitive or is_big_impact` 를 글에 붙이고, 「민감한 권한이거나 영향이 2건 이상이면 승인」이라는 규칙을 내 말로 풀어 씁니다. 그다음 실습 4-1 출력에서 `승인 대기` 로 끝나는 줄(junho 의 `SALES:CHANGE`) 한 줄을 붙이고, 승인이 없었다면 이 계획이 어떻게 되었을지 씁니다.
2. **글감 2(그대로인 권한)**: 실습 4-2 출력 단계 2에서 `바뀜` 으로 끝나는 줄(junho 의 `SALES:QUERY`) 하나와 `그대로` 로 끝나는 줄 하나를 나란히 붙입니다. 두 줄이 왜 다른지부터 쓰면 글의 절반이 됩니다.
3. **글감 3(회수 이력)**: `revocation_log.json` 의 이력 한 건을 코드 상자로 붙이고, 여섯 키(`time` · `user` · `permission` · `method` · `approval` · `result`) 옆에 「이 키로 답할 수 있는 질문」을 하나씩 적습니다. 답할 수 없는 질문이 남으면 거기에 필요한 키 이름을 붙입니다.
4. **실행 결과 붙이기**: 터미널 출력은 전부 붙이지 않아도 됩니다. 내 말과 연결되는 두세 줄만 코드 상자(```` ``` ````)로 붙이고, 그 아래에 「이 줄에서 무엇을 보았는지」를 한 문장으로 씁니다. 화면 캡처를 쓰려면 이미지를 `assets/images/` 에 올리고 글에 연결합니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 4-1에서 「승인됨」이 하나도 없고 「승인 대기」가 3건 나왔다면, 그 출력과 내가 의심한 줄(`elif decision == "승인":`)을 적고 어떻게 찾았는지 씁니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

## 공개 전 점검

**Commit changes** 를 누르기 전에 한 번 더 봅니다.

1. 글과 `code/` 파일에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다
4. 머리말이 `module: 3`, `unit: 4` 이고, `sample: true` 줄이 없다
