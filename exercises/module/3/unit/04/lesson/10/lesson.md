# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 한 회수와 그때 한 고민을 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 글은 내 GitHub Pages 포트폴리오에 올립니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

- 글감은 보고서 `report_u4.md` 에 적은 답 가운데 가장 오래 고민한 것을 고르면 쉽습니다.

**오늘의 글감 (핵심 실습)**

1. 권한을 없애는 일인데도 쓰기 권한이나 한 번에 여러 권한이 사라지는 회수는 승인을 받게 했습니다. 승인 없이 바로 회수하게 했다면 무엇이 위험할까요?
2. 회수 전후 판정이 그대로인 권한도 회수하고 이력을 남겼습니다. 이미 막혀 있는 권한을 정리하는 이유는 무엇인가요?
3. 반년 뒤 「이 권한이 왜 없어졌나요?」라는 질문에 답하려면 회수 이력에 무엇이 더 있어야 할까요?

**선택 글감 (응용을 했다면)**

1. 거부 이유를 하나만 알려 주는 방식과 어긋난 조건을 모두 알려 주는 방식 중 무엇을 골랐나요? 정상 사용자, 계정을 가로챈 사람, 관제 담당자의 입장을 나눠 생각해 보세요.
2. 계정에 권한이 있어도 새벽 2시 외부 접속 요청은 거부해야 하는 이유는 무엇인가요? 로그인 때 한 번만 확인했다면 어떻게 되었을까요?

세 문장이면 충분합니다. 오늘 막혀서 실습을 다 못 했다면 그 막힌 이야기도 좋은 글이 됩니다. 어디서 멈췄는지 남겨 두면 다음에 나도, 글을 읽는 사람도 도움을 받습니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 보고서 `report_u4.md` 에서 가장 오래 고민한 질문과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Unit 1 오늘의 글 쓰기에서 한 것처럼, 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고 터미널에서 올립니다. 글 틀 세 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `_templates/post-practice.md` |

**2. 새 글 파일 만들고 쓰기**

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-20-m3-u4-revoke-approval.md` 처럼 만듭니다(경로 `_posts/2026-11-20-m3-u4-revoke-approval.md`). 앞은 오늘 날짜, 뒤는 영문 제목입니다.
2. 고른 글 틀을 붙여 넣고 맨 위 머리말을 고칩니다.
   ```
   module: 3
   unit: 4
   ```
   1. `module: 3`, `unit: 4` 로 씁니다. 글 틀의 `unit:` 숫자는 예시이니 꼭 `4` 로 바꿉니다. 이 두 줄이 첫 화면 「나의 진행」에서 Module 3 줄의 4번 칸을 채웁니다.
   2. `title` 과 `date` 를 내 글에 맞게 고칩니다. 날짜가 미래면 글이 목록에 나오지 않습니다. 샘플 글에 있던 `sample: true` 줄은 넣지 않습니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 오늘 날짜 이름(예: `_posts/2026-11-20-m3-u4-revoke-approval.md`)으로 글 파일을 만들고 글 틀을 붙여 넣었다
<!-- /checklist -->

3. 빈칸을 채우고 저장합니다. 코드는 따로 옮기지 않습니다. 오늘 만든 `access_control/revoke_approve.py`(실습 4-1) · `access_control/revoke.py`(실습 4-2) 가 같은 저장소 안에 있으니, 글에는 `전체 코드: access_control/revoke.py` 처럼 위치만 적고, 글 안에는 핵심 몇 줄만 코드 상자로 붙입니다.

<!-- checklist -->
- [ ] 머리말을 `module: 3` · `unit: 4` 와 내 `title` · `date` 로 고치고 세 칸을 채워 저장했다
<!-- /checklist -->

4. 올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 맨 위 머리말에 `module: 3` · `unit: 4` 가 있으면 성공입니다. 없으면 1번에서 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(승인)**: `needs_approval` 의 마지막 줄 `return is_sensitive or is_big_impact` 를 글에 붙이고, 「민감한 권한이거나 영향이 2건 이상이면 승인」이라는 규칙을 내 말로 풀어 씁니다. 그다음 실습 4-1 출력에서 `승인 대기` 로 끝나는 줄(junho 의 `SALES:CHANGE`) 한 줄을 붙이고, 승인이 없었다면 이 계획이 어떻게 되었을지 씁니다.
2. **글감 2(그대로인 권한)**: 실습 4-2 출력 단계 2에서 `바뀜` 으로 끝나는 줄(junho 의 `SALES:QUERY`) 하나와 `그대로` 로 끝나는 줄 하나를 나란히 붙입니다. 두 줄이 왜 다른지부터 쓰면 글의 절반이 됩니다.
3. **글감 3(회수 이력)**: `revocation_log.json` 의 이력 한 건을 코드 상자로 붙이고, 여섯 키(`time` · `user` · `permission` · `method` · `approval` · `result`) 옆에 「이 키로 답할 수 있는 질문」을 하나씩 적습니다. 답할 수 없는 질문이 남으면 거기에 필요한 키 이름을 붙입니다.
4. **실행 결과 붙이기**: 터미널 출력은 전부 붙이지 않아도 됩니다. 내 말과 연결되는 두세 줄만 코드 상자(```` ``` ````)로 붙이고, 그 아래에 「이 줄에서 무엇을 보았는지」를 한 문장으로 씁니다. 화면 캡처를 쓰려면 이미지를 `assets/images/` 에 올리고 글에 연결합니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 4-1에서 「승인 대기」가 하나도 없고 「승인됨」이 1건만 나왔다면, 그 출력과 내가 의심한 줄(`return is_sensitive and is_big_impact`)을 적고 어떻게 찾았는지 씁니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 힌트의 붙일 줄을 붙이고 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 코드(`access_control/` 의 파일 포함)에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다
4. 머리말이 `module: 3`, `unit: 4` 이고, `sample: true` 줄이 없다

**올리기** — **[터미널]** 네 줄을 모두 확인했으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..` → `python check_publish.py`(맥북은 `python3`) → `git add .` → `git commit -m "Add unit 4 post"` → `git push` → `cd access_control`. 점검에서 `[오류]` 가 나오면 그 부분을 지우고 다시 돌린 뒤 올립니다.
