# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 만든 것과 그때 한 고민을 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 보고서는 질문에 답하는 파일이고, 이 글은 그 답 가운데 하나를 내 말로 풀어 쓰는 기록입니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

**오늘의 글감 (핵심 실습)**

1. 역할 매트릭스에서 필요 이상으로 보이는 ○ 를 하나 골랐다면 왜 그렇게 봤나요? 그 권한이 남아 있을 때의 위험은 무엇인가요?
2. `roles.json` 에 없는 역할(`intern`)의 사용자는 허용으로 판정해야 할까요, 거부일까요? 그렇게 정한 이유를 써 보세요.
3. 퇴사자 `dami` 에게 예외가 남아 있어도 거부되게 판정 순서를 정했습니다. 순서가 바뀌면 무엇이 열리고, 그것을 어떻게 알아챌 수 있을까요?

**선택 글감 (응용을 했다면)**

1. 응용 1-2를 했다면
   1. 영업에서 재무로 옮긴 사람에게 이전 역할의 권한이 남으면 어떤 문제가 생기나요? 역할 값 하나를 바꾼 결과를 비교해 써 보세요.
   2. 퇴사 통보가 사흘 늦게 왔다면 그 사흘 동안 무슨 일이 생길 수 있나요? 이 간격을 줄이려면 코드와 업무 중 무엇을 바꾸겠습니까?
2. 응용 1-4를 했다면
   1. 설정 파일이 깨졌을 때 멈추지 않고 빈 설정으로 모두 거부하는 것이 왜 더 안전한가요? 멈췄을 때 현장에서 생기는 일과 비교해 보세요.
   2. 모두 거부되어 업무가 멈췄을 때 운영자가 빨리 알게 하려면 무엇을 추가하겠습니까? 가장 먼저 할 것과 그 이유를 써 보세요.

세 문장이면 충분합니다. 막혀서 끝내지 못한 이야기도 좋은 글입니다. 어디까지 해 봤고 어디서 멈췄는지를 적어 두면, 다음에 다시 볼 때 가장 쓸모 있는 기록이 됩니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 「보고서 쓰기」에서 가장 오래 고민한 질문과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

오늘 글이 포트폴리오의 첫 글입니다. 저장소가 아직 없으면 [시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 준비하고, 글 틀을 복사하는 방법은 [시작하기 레슨의 「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)를 봅니다.

**글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `_templates/post-practice.md` |

**올리는 순서**

설치할 것은 없습니다. 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고, 터미널에서 올립니다.

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-20-m3-u1-role-permission.md` 처럼 만듭니다(경로 `_posts/2026-11-20-m3-u1-role-permission.md`). 앞은 오늘 날짜, 뒤는 영문 제목입니다.
2. 고른 글 틀을 붙여 넣고 맨 위 머리말을 고칩니다.
   1. `module: 3`, `unit: 1` 로 씁니다. 글 틀의 `unit:` 숫자는 예시이니 꼭 `1` 로 바꿉니다. 이 두 줄이 첫 화면 「나의 진행」에서 Module 3 줄의 1번 칸을 채웁니다.
   2. `title` 과 `date` 를 내 글에 맞게 고칩니다. 날짜가 미래면 글이 목록에 나오지 않습니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 오늘 날짜 이름(예: `_posts/2026-11-20-m3-u1-role-permission.md`)으로 글 파일을 만들고 글 틀을 붙여 넣었다
<!-- /checklist -->

3. 빈칸을 채우고 저장합니다. 코드는 따로 옮기지 않습니다. 오늘 만든 `access_control/policy.py` · `access_control/rbac.py` 가 같은 저장소에 이미 올라가 있으니, 글에는 `전체 코드: access_control/policy.py` 처럼 위치만 적습니다.
   - (선택) 시작하기 7쪽에서 만든 샘플 글 `_posts/2026-01-01-hello.md` 는 이제 지워도 됩니다. VS Code 왼쪽 목록에서 그 파일을 오른쪽 클릭 › **Delete** 합니다. 지운 것도 아래 올리기의 `git add .` 로 함께 올라가고, 첫 화면 최신 글에서 샘플 글이 사라집니다.

<!-- checklist -->
- [ ] 머리말을 `module: 3` · `unit: 1` 과 내 `title` · `date` 로 고치고 세 칸을 채워 저장했다
<!-- /checklist -->

4. 올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 맨 위 머리말에 `module: 3` · `unit: 1` 이 있으면 성공입니다. 없으면 1번에서 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

**오늘 Unit에서 글이 막힐 때**

고른 글감에 따라 아래 줄을 그대로 붙이고 이어 씁니다.

| 고른 글감 | 붙일 줄 | 이어 쓸 것 |
|---|---|---|
| 글감 1(필요 이상인 ○) | `config/roles.json` 에서 그 권한이 들어 있는 줄 | 「이 줄이 없어도 그 역할의 일은 되는가」를 한 문장으로 |
| 글감 2(`intern`) | `rbac.py` 의 `check_permission` 에서 `role not in ROLES` 검사 줄 | 이 줄이 없을 때 `ROLES["intern"]` 에서 `KeyError` 로 멈추는 것과 「역할이 없음」으로 거부하는 것을 나란히 비교 |
| 글감 3(판정 순서) | `policy.py` 의 `evaluate_access` 에서 「권한 없음」일 때만 예외를 보는 줄, 실습 1-3 출력의 `dami` 줄 | 「순서 덕분에 이렇게 나왔다」고 이어 씀 |

1. 실행 결과는 `exercise1-3_run.py` 의 출력 전체를 붙이지 않아도 됩니다. 글에서 말하는 줄 한두 개(예: `10:00 dami SALES QUERY -> False 퇴사한 계정`)만 코드 상자에 붙이고, 그 줄에서 무엇을 봐야 하는지 한 문장을 덧붙입니다.
2. 무엇부터 쓸지 모르겠으면 보고서 `report_u1.md` 에 쓴 내 답 하나를 글 틀의 「왜 골랐나」 칸에 옮기고, 앞의 두 문장을 거기에 맞춰 씁니다.

**AI 도우미**

코드 설명 정리, 초안 다듬기, 내 글 점검에 쓰는 프롬프트 세 가지는 [시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 글과 코드에는 비밀키·토큰·개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 표의 「붙일 줄」을 붙이고 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 코드(`access_control/` 의 파일 포함)에 `.env` 내용, API 키, 토큰이 없습니다.
2. 개인 이메일·전화번호가 없습니다.
3. 실습 속 가상의 사용자 이름(`seoyeon` · `dami` 등) 말고, 실제 다른 사람의 이름이 없습니다.
4. 실행 결과 화면 캡처에 내 컴퓨터 사용자 이름이나 다른 창의 개인 정보가 보이지 않습니다.

**올리기** — **[터미널]** 네 줄을 모두 「없음」으로 답할 수 있으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..`(터미널이 이미 `network-study-notes`에 있으면 건너뜁니다) → `python check_publish.py` → `git add .` → `git commit -m "Add unit 1 post"` → `git push` → `cd access_control`. 점검에서 `[오류]` 가 나오면 그 부분을 지우고 다시 돌린 뒤 올립니다.

<!-- /checklist -->

올리고 1~2분 뒤 내 사이트 첫 화면을 엽니다.
