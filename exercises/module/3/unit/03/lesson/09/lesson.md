# 문제 해결 과정을 블로그에 기록하기

## 실습에서 만난 문제 고르기

핵심 실습 3-1 또는 3-2에서 실제로 고민한 문제 하나를 고릅니다. 응용 문제를 하지 않아도 쓸 수 있는 주제여야 합니다. 예를 들면 권한 현황을 어떤 단위로 모았는지, 90일 기준을 어떻게 적용했는지, 기록이 없는 권한을 바로 회수하지 않기로 한 이유가 있습니다.

문제 상황, 선택한 방법과 그 이유, 확인한 결과를 GitHub 블로그 글 한 편에 기록합니다. 실무에서도 답만 남기기보다 왜 그 결정을 했고 무엇을 확인했는지 남겨야 다음 담당자가 판단을 이어갈 수 있습니다.

## 기록할 내용

처음 읽는 사람에게 **문제, 선택과 이유, 검증 결과**가 차례로 보이도록 씁니다.

1. **문제 상황**: 무엇을 확인하거나 만들고 있었나요?
2. **고민한 선택지**: 어떤 방법을 생각했나요? 무엇을 비교했나요?
3. **선택과 이유**: 어떤 방법을 골랐고, 그 이유는 무엇인가요?
4. **확인한 결과**: 실행한 입력과 실제로 본 결과는 무엇인가요?
5. **남은 질문**: 아직 모르는 점이나 다음에 확인할 것은 무엇인가요?
6. **AI와 나눈 대화**: AI에게 도움을 받았다면 질문과 답 중 직접 확인한 내용을 요약합니다. 사용하지 않았다면 생략합니다.

실제로 하지 않은 확인을 했다고 적지 않습니다. 실패한 시도도 문제와 배운 점을 설명하는 데 도움이 됩니다.

## 블로그 글 만들기

M3 Unit 1에서 만든 `network-study-notes` 저장소의 `_posts` 폴더에 새 글을 만듭니다. GitHub Pages와 Jekyll을 아직 설정하지 않았다면 [M3 Unit 1의 설정 안내](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)로 돌아가 먼저 설정합니다.

1. `_posts`에서 **New File**을 선택합니다.
2. 새 글은 오늘 날짜와 주제를 담은 영문 파일명으로 저장합니다. 예를 들어 2026년 11월 24일에 이 주제로 썼다면 `_posts/2026-11-24-stale-permissions-90-days.md`입니다. 이미 게시한 글은 기존 주소가 유지되도록 파일명을 그대로 두세요.
3. 아래 글 틀을 붙여 넣고 실제로 고민한 내용으로 고칩니다. 제목에는 다룬 문제나 내 선택을 적고, 날짜는 파일명 앞의 날짜에 맞춥니다.

<pre class="copyable"><code>---
layout: post
title: "마지막 사용 후 90일과 91일, 어느 권한을 점검할까?"
date: 2026-11-24
module: 3
unit: 3
---

&#35;# 문제
마지막으로 쓴 날을 기준으로 점검 후보를 고를 때 경계가 되는 날짜를 설명하세요.

&#35;# 선택과 이유
어떤 방법을 골랐고, 왜 그 방법을 선택했나요?

&#35;# 검증 결과
현황과 후보 목록에서 90일째인 권한이 어디에 있는지 확인하세요. 그 결과가 코드의 비교 연산과 어떻게 연결되나요?

&#35;# 남은 질문
아직 확인하지 못한 것은 무엇인가요?

&#35;# AI와 나눈 대화 (사용했다면)
어떤 질문을 했고, 답변에서 무엇을 직접 확인했나요?
</code></pre>

첫 문장에는 이 과정을 모르는 독자도 상황을 떠올릴 수 있게 어떤 권한을 누가 요청하거나 점검했는지 적으세요. 틀의 질문은 자신의 문장으로 바꾸고, 쓰지 않은 항목은 지웁니다. 다른 문제를 골랐다면 제목도 바꾸세요. 이 예시에서는 `access_control/review_unused.py`에서 판단을 내리는 줄과 직접 본 출력이 근거가 됩니다. 글을 올린 뒤 GitHub에서 해당 코드 파일을 열고 주소를 복사해 글의 「검증 결과」에 붙입니다. Markdown에서는 `[review_unused.py 코드 보기](복사한 주소)`에서 괄호 안을 실제 주소로 바꾸면 링크가 됩니다. 수정한 글을 다시 올린 뒤 「전체 글」에서 제목을 눌러 본문과 코드 링크를 열어 봅니다.

## 공개 전에 확인하고 올리기

글과 `access_control` 코드에 비밀번호, 토큰, 개인 이메일·전화번호, 다른 사람의 실제 이름이 들어 있지 않은지 확인합니다. 화면 캡처에 사용자 이름이나 경로가 보이면 공개해도 되는지 살핍니다.

터미널에서 저장소 루트(`network-study-notes`)로 이동해 올릴 내용을 확인합니다.

```bash
cd ~/network-study-notes
git status --short
python check_publish.py
```

`.env`나 `.venv`가 목록에 있으면 올리지 말고 `.gitignore`를 확인합니다. 확인을 마치면 핵심 실습 코드와 블로그 글을 올립니다.

```bash
git add access_control _posts
git commit -m "Record module 3 unit 3 access review"
git push
```

GitHub 저장소에 핵심 실습 코드가 있고 공개 사이트의 「전체 글」에서 제목을 눌러 본문이 열리는지 확인합니다. `git push`가 거절되면 변경을 확인하고 원격 저장소의 안내에 따라 다시 시도합니다. 나중에 응용 코드를 더했다면 이 올리기 순서를 다시 진행합니다.
