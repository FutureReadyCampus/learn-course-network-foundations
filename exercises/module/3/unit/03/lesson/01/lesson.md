# 시작하기

## 목표와 오늘의 계획

핵심 실습 전에 [블로그 초안 준비](__SITE__/exercises/module/3/unit/3/lesson/1/page/3)에서 이번 유닛의 글 파일을 엽니다.

지난 Unit 2(권한 주기)에서는 권한을 **주는** 흐름(요청 → 승인 → 예외 권한 부여)을 만들었습니다. 이번에는 반대로 이미 **부여돼 있는 권한** 가운데 필요 없어진 것을 찾는 **접근 점검**을 만듭니다. 동아리를 그만둔 사람이 동아리방 열쇠를 아직 갖고 있지 않은지 명단을 보며 확인하는 일과 비슷합니다. 찾기까지만 하고, 찾은 권한을 실제로 거두는 일은 다음 Unit 4(권한 거두기)에서 합니다.

<h2>오늘의 계획 (약 2시간 40분)</h2>

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 시작 | 15분 | 이 레슨을 읽고, M3 Unit 1 파일 확인 및 핵심 준비 함수 만들기 |
| 2. 핵심 실습 | 약 110분 | 핵심 준비 → 실습 3-1 → 실습 3-2 |
| 3. 문제 해결 기록 | 20분 | 두 핵심 실습의 고민과 근거를 블로그 글 한 편으로 기록 |
| 4. 응용 | 남는 시간 | 핵심 실습과 블로그 기록을 마친 뒤 선택 문제에 도전 |

핵심 실습 3-2에 필요한 `review_rules.py`를 먼저 준비합니다. 실습마다 출력을 바로 확인하고, 두 핵심 실습을 마친 뒤에는 문제 상황과 선택 이유, 확인한 결과를 블로그 글 한 편에 기록합니다. 응용 문제는 그 뒤에 시간이 남으면 선택합니다.

<h2>오늘 만들 것 두 가지</h2>

대부분은 미리 채워 두었고, 실습마다 빈칸 두 곳만 직접 씁니다.

| 실습 | 직접 쓰는 것 | 함수 | 만드는 것 |
|---|---|---|---|
| **실습 3-1** | `review_list.py` 의 빈칸 두 곳(①·②) | `build_access_list` | 누가 어떤 권한을 어떤 방법(역할 · 예외)으로 갖고 있는지 한곳에 모은 **현황 리스트** |
| **실습 3-2** | `review_unused.py` 의 빈칸 두 곳(①·②) | `find_unused` | 사용 이력과 비교해 찾은 **90일 넘게 안 쓴 권한** 후보 |

퇴사(회사를 그만둠) · 만료(정해 둔 기간이 끝남)로 이미 필요 없어진 권한은 핵심 준비 레슨의 `review_rules.py`가 먼저 걸러 줍니다.

**응용 3-1 ~ 3-3은 여유가 되면 해 보세요.** 핵심 실습 두 개와 글쓰기를 마치고 시간이 남을 때 합니다. 응용마다 해당 레슨 안에서 필요한 파일을 직접 만듭니다. 핵심 준비 레슨에는 `review_rules.py`만 있습니다.

| 응용 | 파일 | 하는 일 |
|---|---|---|
| 응용 3-1 | `review_rules.py` | 퇴사 · 만료 규칙으로 필요 없어진 권한을 찾음 |
| 응용 3-2 | `overprivilege.py` | 두 점검 결과를 합쳐 한 장짜리 리포트를 만듦 |
| 응용 3-3 | `report_exclude.py` | 회수하지(거두지) 않을 권한을 가려냄 |

응용을 하지 않아도 핵심 실습은 진행할 수 있습니다. 다음 Unit 4에서 필요한 나머지 함수와 데이터는 그 Unit의 안내에 따라 준비합니다.

**이번 Unit에서 불러 쓰는 이전 파일** — 이번 Unit 코드는 M3 Unit 1(권한 정하기)에서 만든 파일만 불러 씁니다. M3 Unit 2(권한 주기)의 파일(요청서 · 승인 파일)은 쓰지 않으므로 따로 준비할 것이 없습니다.

| 불러 쓰는 것 | 들어 있는 파일 | 쓰는 곳 | 없으면 만드는 곳 |
|---|---|---|---|
| 사용자 · 역할 딕셔너리 `USERS` · `ROLES` | `config/users.json` · `config/roles.json` · `rbac.py` | 실습 3-1 | M3 Unit 1 실습 1-1 · 1-2 |
| 예외 리스트 `EXCEPTIONS` · 시각 형식 `TIME_FORMAT` | `config/exceptions.json` · `exception_policy.py` | 실습 3-1 · 3-2 | M3 Unit 1 시작하기 |
| 설정 파일을 안전하게 읽는 `load_json` | `config_loader.py` | 실습 3-2 | M3 Unit 1 시작하기 |

M3 Unit 1에서 두 JSON 파일은 「실습 1-1」의 코드 상자와 「실습 1-1 정답」으로 만듭니다. `rbac.py`는 M3 Unit 1 「실습 1-2」 레슨의 코드 상자에 「실습 1-2 정답」의 채운 코드(①·②)를 붙여서 만듭니다. M3 Unit 1 시작하기에 있는 설정 파일과 함수를 그대로 사용합니다.

이번 Unit에서 만드는 파일도 뒤에서 이어 씁니다. 실습 3-1의 `review_list.py`는 실습 3-2와 응용에서, 실습 3-2의 `review_unused.py`는 응용 3-2 · 3-3과 다음 Unit 4에서 씁니다.

> **확인** — 오늘 할 흐름(시작 · 핵심 실습 · 문제 해결 기록 · 선택 응용)를 순서대로 말할 수 있으면 성공입니다. 헷갈리면 위 「오늘의 계획」 표를 한 번 더 봅니다.

## 터미널 열고 이전 파일 확인하기

이번 Unit 의 작업 폴더는 저장소 폴더 `network-study-notes` 안의 `access_control` 입니다. 아래에 나오는 파일 경로는 모두 이 `access_control` 폴더를 기준으로 씁니다(예: `config/users.json` 은 `access_control` 안의 `config` 폴더에 있는 `users.json`).

1. **[VS Code]** 왼쪽 목록의 `access_control` 폴더를 오른쪽 클릭 › **Open in Integrated Terminal** 로 터미널을 엽니다.
   - 터미널 오른쪽 위 이름 칸에 **bash** 가 보여야 합니다. 다른 이름(예: powershell)이면 `+` 옆의 **∨** 를 눌러 **Git Bash** 를 고른 뒤 `cd access_control` 로 작업 폴더에 들어갑니다.
2. **[터미널]** 위치와 이전 파일을 확인합니다. `pwd` 의 결과가 `…/network-study-notes/access_control` 로 끝나야 합니다.
   아래 코드 상자를 통째로 복사해 실행합니다.

   ```bash
   # 이 명령은 전체를 복사해 Git Bash에 붙여 넣어 실행하세요.
   pwd
   ls
   ls config
   python - <<'PYTHON'
   from rbac import USERS, ROLES
   from exception_policy import EXCEPTIONS, TIME_FORMAT
   from config_loader import load_json

   print("이전 파일 정상", len(USERS), len(ROLES), len(EXCEPTIONS))
   PYTHON
   ```
   - macOS에서는 `python3`를 씁니다. Windows에서 `python`이 안 되고 `py`가 되면 `python`을 `py`로 바꿉니다. 마지막 줄에 `이전 파일 정상 6 5 5`(사용자 6명 · 역할 5개 · 예외 5건)가 나와야 합니다.
   - 오류가 나면 시작하기 첫 페이지의 「이번 Unit 에서 불러 쓰는 이전 파일」을 보고 빠진 파일을 만듭니다(`config` 안의 파일은 `config` 폴더에). 그다음 코드 상자 전체를 다시 실행합니다.
3. **코드 파일은 이렇게 만듭니다.** 「`파일이름` 파일을 만들어 아래 내용을 붙여 넣습니다」라고 하면:
   1. **[VS Code]** 왼쪽 목록에서 알려 준 폴더를 오른쪽 클릭 › **New File** 을 누르고, 알려 준 **파일 이름을 그대로** 적고 Enter 를 칩니다.
   2. 코드 상자의 복사 버튼으로 내용을 복사해 새 파일에 붙여 넣고, `Ctrl + S` 로 저장합니다.
   - 실습 결과와 고민은 핵심 실습 뒤 [문제 해결 과정을 블로그에 기록하기](__SITE__/exercises/module/3/unit/3/lesson/9/page/1)에서 한 편의 글로 정리합니다.
4. 문제는 **할 일 → 순서**대로 하고, `[창 이름]` 이 지금 쓸 창입니다. 코드를 채울 때는 `# ←` 가 붙은 주석 바로 아래 줄에 그 주석이 말하는 일을 한 줄로 쓰고, 막히면 각 실습 바로 아래의 답안 펼침을 봅니다.

> 실행은 VS Code 의 ▶ 단추가 아니라 **터미널**에서 합니다. **이전 Unit 의 파일은 고치지 않습니다.** 이번 Unit 에서 만드는 파일은 모두 새 파일입니다.

> **확인** — 2번의 마지막 줄에 `이전 파일 정상 6 5 5` 가 나오면 성공입니다. 안 나오면 오류 메시지에 나온 파일 이름을 보고, 첫 페이지의 「이번 Unit 에서 불러 쓰는 이전 파일」 표에서 그 파일을 만드는 곳을 찾아 만듭니다.
