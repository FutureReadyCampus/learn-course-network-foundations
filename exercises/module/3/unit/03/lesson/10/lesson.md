# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 실습 3-1 · 3-2에서 쓴 코드와 그때 한 고민을 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 보고서는 질문에 답하는 파일이고, 이 글은 그 답 가운데 하나를 내 말로 풀어 쓰는 기록입니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

**오늘의 글감 (핵심 실습)** — 하나만 골라도 충분합니다.

1. 판정 함수가 이미 거부하는 권한을 현황 리스트에서 빼지 않고 남겨 둔 이유는 무엇인가요? 빼 버리면 점검에서 무엇을 놓치게 되나요? (실습 3-1)
2. 90일째와 91일째를 하루 차이로 나누는 기준은 합리적인가요? 경계 부근의 권한을 담당자가 어떻게 다시 확인하면 좋을지 써 보세요. (실습 3-2)
3. 사용 이력이 없는 권한을 바로 지우면 위험한 경우는 언제인가요? 지우기 전에 무엇을 확인하겠습니까? (실습 3-2)

**선택 글감 (응용 3-2를 했다면)**

1. 이유가 둘인 후보는 담당자가 처리 순서를 정할 때 어떤 도움이 되나요? 이유를 문자열이 아니라 리스트로 담은 선택도 비교해 보세요.
2. 리포트에 후보만 담고 나머지는 전체 건수로만 남긴 방식과, 전부 담는 방식 중 담당자에게 어느 쪽이 나은가요?

「보고서 쓰기」 레슨에서 같은 질문에 적은 답이 있다면 그 답이 글의 재료가 됩니다. 세 문장이면 충분합니다. 막혀서 끝내지 못한 이야기도 좋은 글입니다. 어디까지 해 봤고 어디서 멈췄는지를 적어 두면, 다음에 다시 볼 때 가장 쓸모 있는 기록이 됩니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 「보고서 쓰기」에서 가장 오래 고민한 질문과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Unit 1 오늘의 글 쓰기에서 한 것처럼, 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고 터미널에서 올립니다. 아직 저장소가 없다면 [Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 따라 합니다.

**1. 글 틀 고르기** — 내 저장소의 `_templates/` 폴더에 있는 세 가지 중 하나를 고릅니다. 각 틀의 생김새는 [Unit 1 시작하기 레슨의 「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `post-short.md` |
| 막혀서 끝내지 못했다 | `post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `post-practice.md` |

**2. 새 글 파일 만들고 쓰기**

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-21-m3-u3-unused-permissions.md` 처럼 만듭니다(경로 `_posts/2026-11-21-m3-u3-unused-permissions.md`). 앞은 오늘 날짜, 뒤는 영문 제목입니다.
2. 고른 글 틀을 붙여 넣고 맨 위 머리말을 고칩니다.
   ```
   module: 3
   unit: 3
   ```
   1. `module: 3`, `unit: 3` 로 씁니다. 글 틀의 `unit:` 숫자는 예시이니 꼭 `3` 로 바꿉니다. 이 두 줄이 첫 화면 「나의 진행」에서 Module 3 줄의 3번 칸을 채웁니다.
   2. `title` 과 `date` 를 내 글에 맞게 고칩니다. 날짜가 미래면 글이 목록에 나오지 않습니다. 샘플 글에 있던 `sample: true` 줄은 넣지 않습니다.
3. 빈칸을 채우고 저장합니다. 코드는 따로 옮기지 않습니다. 오늘 만든 `access_control/review_unused.py` 가 같은 저장소 안에 있으니, 글에는 `전체 코드: access_control/review_unused.py` 처럼 위치만 적습니다.
4. 올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 맨 위 머리말에 `module: 3` · `unit: 3` 가 있으면 성공입니다. 없으면 1번에서 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

무엇을 쓸지 떠오르지 않으면 코드 한 줄과 출력 한 줄을 나란히 놓고, 「이 줄 때문에 이 결과가 나왔다」를 내 말로 씁니다.

1. **글감 1(거부되는 권한을 남긴 이유)**: 실습 3-1 출력에서 `dami SALES:QUERY <- 역할 sales | 재직 False` 줄을 붙이고, `build_access_list` 가 재직 여부를 따지지 않고 모든 권한을 담는다는 점과 연결합니다. 이 줄이 현황에 없었다면 퇴사자의 권한을 찾을 수 있었을지 생각해 봅니다.
2. **글감 2(90일 · 91일 경계)**: 실습 3-2 단계 1 출력의 `junho SALES:QUERY -> 91 일째 안 씀` 과 `junho SETTLE:QUERY -> 90 일째 안 씀` 두 줄, 그리고 `find_unused` 의 `elif days_since(used_text, now) > limit_days:` 한 줄을 함께 붙입니다. `>` 를 `>=` 로 바꾸면 후보가 몇 건이 되는지 직접 돌려 보고 그 결과를 적어도 좋습니다.
3. **글감 3(이력 없는 권한)**: `gaeun ACCOUNT:CHANGE -> 사용 이력 없음` 줄과 `if used_text is None:` 줄을 연결합니다. 「이력이 없다」와 「필요 없다」가 같은 말인지, 계정 관리 담당에게 이 권한이 언제 필요할지 써 봅니다.
4. **실행 결과 붙이기**: 터미널 출력을 복사해 글의 실행 결과 코드 상자에 붙입니다. `--- 단계 1` · `--- 단계 2` 제목 줄까지 그대로 붙이면 읽는 사람이 어느 단계의 결과인지 압니다. 화면 캡처로 올릴 때는 `assets/images/` 에 넣습니다.
5. **막힌 글**: `NameError: name 'used_text' is not defined` 나 `TypeError: strptime() argument 1 must be str, not None` 이 났거나 후보가 3건이 아니었다면 `post-stuck.md` 로 씁니다. 오류 메시지, 그때 고친 줄(② 의 `if` 를 `elif` 로 바꾼 것 등), 아직 모르는 것을 차례로 적습니다.

AI 도우미에게 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. 프롬프트에 비밀키 · 토큰 · 개인정보는 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 힌트의 출력 한 줄을 붙이고 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 코드(`access_control/` 의 파일 포함)에 API 키 · 토큰 · `.env` 내용이 없습니다.
2. 개인 이메일 · 전화번호가 없습니다.
3. 다른 사람의 실제 이름이 없습니다. 실습 파일의 seoyeon · junho 같은 사용자 이름은 연습용이라 그대로 써도 됩니다.
4. 머리말이 `module: 3`, `unit: 3` 입니다.

**올리기** — **[터미널]** 네 줄을 모두 확인했으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..` → `python check_publish.py`(맥북은 `python3`) → `git add .` → `git commit -m "Add unit 3 post"` → `git push` → `cd access_control`. 점검에서 `[오류]` 가 나오면 그 부분을 지우고 다시 돌린 뒤 올립니다.

올리고 1~2분 뒤 내 사이트 첫 화면을 엽니다.

> **확인** — 최신 글에 오늘 글이 보이고 「나의 진행」의 Module 3 · Unit 3 칸이 채워지면 성공입니다. 안 보이면 [Unit 1 시작하기 레슨의 「첫 화면 확인하고 막힐 때」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/9)의 「글이 목록에 안 나옴」 줄을 봅니다.
