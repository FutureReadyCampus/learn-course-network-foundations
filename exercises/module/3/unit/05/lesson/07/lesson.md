# 실습 결과와 문제 해결 과정을 기록하기

## 기록할 문제 고르기

두 핵심 실습에서 실제로 판단하기 어려웠던 문제를 하나 고릅니다. 예를 들어 예외 만료 점검이 통과했는데도 퇴사자 계정 점검을 다시 확인해야 했던 이유를 다룰 수 있습니다. 아래 페이지에서 근거가 될 출력과 코드, 상황 분석을 골라 블로그 글 한 편으로 정리합니다.

## 기록할 근거 모으기

처음 본 증상과 그때 확인한 데이터, 비교한 방법, 선택한 조치를 메모합니다. 출력 전체가 길다면 판단을 뒷받침한 두세 줄만 남겨도 됩니다. AI의 도움을 받았다면 어떤 질문을 했고 답변 중 무엇을 직접 검증했는지 적습니다.

## 실습 5-1 · 점검 체크리스트로 어긋난 곳 찾기

퇴사자·만료 예외·부서와 역할의 결과를 각각 읽습니다. 하나의 점검이 통과해도 다른 기준은 실패할 수 있습니다. 어떤 두 결과를 함께 봤는지, 그 결과만으로는 무엇을 결정할 수 없었는지 실제 출력과 함께 메모합니다.

## 실습 5-2 · 상황별 원인과 해결법 정리하기

실습에서 고른 상황 가운데 확인 과정이 가장 선명한 것을 고릅니다. 같은 증상이 데이터와 판정 규칙 중 어디에서 생길 수 있는지 비교합니다. 실제로 바꿔 보았다면 전후 결과를, 조치를 검토했다면 다음에 무엇부터 확인할지 적습니다.

## 문제 해결 과정을 블로그에 기록하기

핵심 실습 5-1 또는 Module 3 상황 정리에서 실제로 고민한 문제 하나를 고릅니다. 예를 들면 점검이 「통과」여도 다른 점검을 함께 봐야 했던 이유, 점검 코드가 알려 주지 못하는 원인, 어떤 파일과 근거를 확인해 조치했는지 기록할 수 있습니다. 응용 5-1을 하지 않아도 쓸 수 있는 주제여야 합니다.

읽는 사람이 문제 상황과 선택 이유를 따라갈 수 있게 씁니다. 실행한 결과와 앞으로 확인할 내용을 구분하고, 사용한 AI 답변은 직접 검증한 부분 위주로 요약합니다.

### 기록할 내용

1. **문제 상황**: 무엇이 어긋났거나 확인이 필요했나요?
2. **확인한 근거**: 어떤 점검 결과, 코드, 데이터 또는 출력을 살펴봤나요?
3. **가능한 원인**: 사람의 업무 변화, 데이터 오류, 규칙 문제 중 무엇을 고려했나요?
4. **선택과 이유**: 어떤 파일이나 절차를 고치기로 했고, 그 이유는 무엇인가요?
5. **다시 확인한 결과**: 어떤 실행이나 출력으로 조치가 맞는지 확인했나요?
6. **남은 질문**: 아직 모르는 점이나 다음에 확인할 것은 무엇인가요?

### GitHub 블로그에 글 남기기

공개 전에 글과 `access_control` 코드에 비밀번호, 토큰, 개인 이메일·전화번호, 다른 사람의 실제 이름이 없는지 확인합니다. 저장소 루트에서 올릴 내용을 확인한 뒤 GitHub에 올리고, Pages에서 글이 보이는지 확인합니다.

```bash
cd ~/network-study-notes
git status --short
python check_publish.py
git add access_control _posts
git commit -m "Record module 3 unit 5 problem solving"
git push
```

맥북은 `python` 대신 `python3`를 사용합니다. `.env`나 `.venv`가 보이면 올리지 말고 `.gitignore`를 확인합니다.
