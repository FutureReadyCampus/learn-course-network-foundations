# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 만든 것과 그때 한 고민을 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 보고서는 질문에 답하는 파일이고, 이 글은 그 답 가운데 하나를 내 말로 풀어 쓰는 기록입니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

**오늘의 글감 (핵심 실습)**

1. 점검 결과가 「통과」여도 「문제 없음」으로만 읽으면 안 되는 사례를 하나 들어 보세요. 함께 읽어야 할 다른 점검은 무엇인가요?
2. 점검 코드가 알려 주는 것과 알려 주지 못하는 것은 무엇인가요? 코드가 권한을 바로 회수하지 않고 담당자에게 넘기게 한 이유를 써 보세요.
3. Module 3의 상황 8개 중 데이터를 고친 상황과 규칙을 고친 상황을 하나씩 골라, 실수했을 때 영향이 어디까지 퍼지는지 비교해 보세요.

**선택 글감 (응용을 했다면)**

1. 응용 5-1을 했다면
   1. 거부가 4번 이상인 dami 와 gaeun 에게 같은 조치를 하면 안 되는 이유를 로그 몇 줄을 근거로 써 보세요.
   2. 로그가 빈 주의 「거부율 0%」를 안전하다고 읽지 않으려면 보고서에 무엇을 더 넣겠습니까?
2. Module 3 돌아보기 — 이번 Unit은 Module 3의 마지막 Unit입니다. 다섯 Unit 중 가장 오래 고민한 것 하나를 골라, 그때 어디서 막혔고 지금은 어떻게 이해하는지 써 보아도 좋습니다.

세 문장이면 충분합니다. 막혀서 끝내지 못한 이야기도 좋은 글입니다. 어디까지 해 봤고 어디서 멈췄는지를 적어 두면, 다음에 다시 볼 때 가장 쓸모 있는 기록이 됩니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 「보고서 쓰기」에서 가장 오래 고민한 질문과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Module 3 Unit 1에서 만든 내 저장소 `network-study-notes` 를 GitHub 웹 화면에서 열고 그대로 합니다. 글 틀을 복사하는 방법은 [Unit 1 시작하기 레슨의 「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)를 봅니다.

**글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `_templates/post-practice.md` |

**올리는 순서**

1. 내 저장소에서 **Add file → Create new file** 을 누르고, 이름 칸에 `_posts/2026-11-02-m3-u5-weekly-check.md` 처럼 적습니다. 앞은 오늘 날짜, 뒤는 영문 제목입니다.
2. 고른 글 틀을 붙여 넣고 맨 위 머리말을 고칩니다.
   1. `module: 3`, `unit: 5` 로 씁니다. 글 틀의 `unit:` 숫자는 예시이니 꼭 `5` 로 바꿉니다. 이 두 줄이 첫 화면 「나의 진행」에서 Module 3 줄의 5번 칸을 채웁니다.
   2. `title` 과 `date` 를 내 글에 맞게 고칩니다. 날짜가 미래면 글이 목록에 나오지 않습니다.
3. 빈칸을 채우고, 이 레슨 마지막 페이지 「공개 전 점검」의 네 줄을 먼저 확인한 뒤 **Commit changes** 를 누릅니다. 나오는 창에서 한 번 더 **Commit changes** 를 누릅니다.
4. 코드는 `code/` 폴더에 올립니다. **Add file → Create new file** 에서 이름을 `code/m3_u5_checklist.py` 로 적고, VS Code 에서 연 `access_control/checklist.py` 의 내용을 복사해 붙여 넣습니다. 응용 5-1을 글로 쓴다면 같은 방법으로 `code/m3_u5_log_summary.py` 를 만듭니다. 글에는 `전체 코드: code/m3_u5_checklist.py` 처럼 위치를 적습니다.
5. 올리고 1~2분 뒤 내 사이트 첫 화면을 엽니다.

> **확인** — 최신 글에 오늘 글이 보이고 「나의 진행」의 Module 3 · Unit 5 칸이 채워지면 성공입니다. 안 보이면 [Unit 1 시작하기 레슨의 「첫 화면 확인하고 막힐 때」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/9)의 「글이 목록에 안 나옴」 줄을 봅니다.

## 막힐 때 힌트

- **글감 1 (「통과」 읽기)**: 실습 5-1 출력에서 `만료 예외 점검 | 통과 | []` 줄과 `퇴사자 계정 점검 | 실패 | ['dami']` 줄을 코드 상자에 함께 붙입니다. 그 아래에 「예외 3번은 dami 의 것」이라는 사실을 이어 쓰면, 두 줄을 같이 읽어야 하는 이유가 저절로 드러납니다.
- **글감 2 (알려 주는 것과 못 하는 것)**: `check_dept` 의 `if expected_dept != info["dept"]:` 한 줄을 붙이고, 이 줄이 비교하는 것은 「부서 표기와 역할」 두 값뿐이라는 점에서 시작합니다. junho 가 실제로 무슨 일을 하는지는 이 줄로 알 수 없으니, 그다음은 담당자가 확인할 일로 나눠 씁니다.
- **글감 3 (데이터와 규칙)**: 실습 5-2 정답의 「데이터 문제 · 규칙 문제」 표를 떠올리고, 고칠 파일 이름(예: `users.json` 과 `conditions.json`)을 하나씩 적습니다. 데이터는 한 사람에게, 규칙은 그 규칙을 거치는 모든 요청에 영향을 준다는 차이를 내 말로 씁니다.
- **응용 글감**: `week_log.jsonl` 에서 dami 와 gaeun 의 거부 줄을 두세 줄씩 골라 붙이고, 거부 사유(`퇴사한 계정` 과 `허용되지 않은 접속 위치`)가 다르다는 점부터 씁니다. 「거부율 0%」 글감은 주간 보고서 1절의 `전체 요청:` 줄과 함께 읽습니다.
- **실행 결과 붙이기**: 터미널 출력은 전체를 붙이지 않아도 됩니다. 글에서 말하는 줄 한두 개만 글자 그대로 복사해 코드 상자(```` ``` ````)에 붙이고, 그 줄에서 무엇을 봐야 하는지 한 문장을 덧붙입니다.
- **무엇부터 쓸지 모를 때**: 보고서 `report_u5.md` 에 쓴 내 답 하나를 글 틀의 「왜 골랐나」 칸에 옮기고, 앞의 두 문장을 거기에 맞춰 씁니다.

코드 설명 정리, 초안 다듬기, 내 글 점검에 쓰는 AI 도우미 프롬프트 세 가지는 [Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 이메일 · 실명을 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 힌트에서 고른 글감에 붙이라고 한 줄을 붙이고, 그 줄을 한 문장으로 설명합니다.
