# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

하루의 마지막 40분은 글쓰기 시간입니다. 「보고서 쓰기」 레슨에서 `report_u5.md` 에 적은 답을 바탕으로, 내 포트폴리오에 글 한 편을 올립니다.

**40분은 이렇게 나눕니다**

1. 고르기 5분: 아래 글감 중 하나를 고릅니다. 보고서를 쓰면서 가장 오래 고민한 질문이 좋습니다.
2. 쓰기 25분: 글 틀을 복사해 빈칸을 채웁니다.
3. 점검 · 올리기 10분: 비밀키 · 개인정보가 없는지 보고 올린 뒤, 첫 화면에서 확인합니다.

**핵심 실습 글감** (실습 5-1 · 5-2)

1. 점검 결과가 「통과」여도 「문제 없음」으로만 읽으면 안 되는 사례를 하나 들어 보세요. 함께 읽어야 할 다른 점검은 무엇인가요?
2. 점검 코드가 알려 주는 것과 알려 주지 못하는 것은 무엇인가요? 코드가 권한을 바로 회수하지 않고 담당자에게 넘기게 한 이유를 써 보세요.
3. Module 3의 상황 8개 중 데이터를 고친 상황과 규칙을 고친 상황을 하나씩 골라, 실수했을 때 영향이 어디까지 퍼지는지 비교해 보세요.

**도전 글감 (선택)** — 도전 5-1을 했다면 이 글감도 좋습니다.

1. 거부가 4번 이상인 dami 와 gaeun 에게 같은 조치를 하면 안 되는 이유를 로그 몇 줄을 근거로 써 보세요.
2. 로그가 빈 주의 「거부율 0%」를 안전하다고 읽지 않으려면 보고서에 무엇을 더 넣겠습니까?

**Module 3 돌아보기 (선택)** — 이번 Unit은 Module 3의 마지막 Unit입니다. 다섯 Unit 중 가장 오래 고민한 것 하나를 골라, 그때 어디서 막혔고 지금은 어떻게 이해하는지 써 보아도 좋습니다.

세 문장만 써도 됩니다. 끝까지 풀지 못한 이야기도 좋은 글입니다. 어디까지 확인했는지 남겨 두면 나중에 다시 이어 갈 수 있습니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Module 3 Unit 1 「시작하기」 레슨에서 만든 내 저장소를 GitHub 웹 화면에서 열고 그대로 합니다.

**1. 글 틀 고르기** — 글 틀 세 가지는 Unit 1 「시작하기」 레슨의 「글 틀로 글 쓰기」 페이지에 있습니다. 상자의 **복사** 버튼으로 복사합니다.

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 실습 하나(예: 실습 5-1)를 글 한 편으로 남긴다 | `post-practice.md` |
| 시간이 5분뿐이다 | `post-short.md` |
| 막혀서 끝내지 못했다 | `post-stuck.md` |

**2. 새 글 파일 만들기**

1. 내 저장소에서 **Add file → Create new file** 을 누릅니다.
2. 이름 칸에 `_posts/날짜-영문제목.md` 모양으로 적습니다. 예: `_posts/2026-11-02-m3-u5-weekly-check.md`. 날짜는 글을 쓰는 오늘 날짜로 바꿉니다.
3. 복사한 글 틀을 붙여 넣고, 맨 위 머리말을 고칩니다.
   - `module: 3`, `unit: 5` 로 씁니다. 그래야 첫 화면 「나의 진행」에서 Module 3 줄의 5번 칸이 채워집니다.
   - `title` 과 `date` 도 내 글에 맞게 바꿉니다.
4. 빈칸을 채우고 **Commit changes** 를 누릅니다. 나오는 창에서 한 번 더 **Commit changes** 를 누릅니다.

**3. 코드 올리기** — 글에는 핵심 몇 줄만 붙이고, 파일 전체는 `code/` 폴더에 둡니다.

1. 내 저장소에서 **Add file → Create new file** 을 누르고 이름 칸에 `code/m3_u5_checklist.py` 를 적습니다.
2. VS Code 에서 `access_control/checklist.py` 를 열어 내용 전체를 복사해 붙여 넣고 **Commit changes** 를 누릅니다.
3. 도전 5-1을 글로 쓴다면 같은 방법으로 `code/m3_u5_log_summary.py` 를 만듭니다.
4. 글의 「내 코드」 칸에는 `전체 코드: code/m3_u5_checklist.py` 처럼 위치를 적습니다.

**4. 확인하기** — 올리고 1~2분 뒤 내 사이트 첫 화면을 새로 고칩니다. 「최신 글」에 글이 보이고 Module 3 줄의 5번 칸이 빨갛게 바뀌면 됩니다. 안 보이면 Unit 1 「시작하기」 레슨의 「첫 화면 확인하고 막힐 때」 표를 봅니다.

## 막힐 때 힌트

- **글감 1 (「통과」 읽기)**: 실습 5-1 출력에서 `만료 예외 점검 | 통과 | []` 줄과 `퇴사자 계정 점검 | 실패 | ['dami']` 줄을 코드 상자에 함께 붙입니다. 그 아래에 「예외 3번은 dami 의 것」이라는 사실을 이어 쓰면, 두 줄을 같이 읽어야 하는 이유가 저절로 드러납니다.
- **글감 2 (알려 주는 것과 못 하는 것)**: `check_dept` 의 `if expected_dept != info["dept"]:` 한 줄을 붙이고, 이 줄이 비교하는 것은 「부서 표기와 역할」 두 값뿐이라는 점에서 시작합니다. junho 가 실제로 무슨 일을 하는지는 이 줄로 알 수 없으니, 그다음은 담당자가 확인할 일로 나눠 씁니다.
- **글감 3 (데이터와 규칙)**: 실습 5-2 정답의 「데이터 문제 · 규칙 문제」 표를 떠올리고, 고칠 파일 이름(예: `users.json` 과 `conditions.json`)을 하나씩 적습니다. 데이터는 한 사람에게, 규칙은 그 규칙을 거치는 모든 요청에 영향을 준다는 차이를 내 말로 씁니다.
- **도전 글감**: `week_log.jsonl` 에서 dami 와 gaeun 의 거부 줄을 두세 줄씩 골라 붙이고, 거부 사유(`퇴사한 계정` 과 `허용되지 않은 접속 위치`)가 다르다는 점부터 씁니다. 「거부율 0%」 글감은 주간 보고서 1절의 `전체 요청:` 줄과 함께 읽습니다.
- **실행 결과 붙이기**: 터미널 출력은 글자 그대로 복사해 코드 상자(```` ``` ````)에 붙입니다. 화면 캡처를 쓰고 싶으면 이미지로 저장해 `assets/images/` 에 올립니다.

쓰기 질문 10개와 AI 도우미 프롬프트 세 가지는 Unit 1 「시작하기」 레슨의 「쓰기 질문과 AI 도우미」 페이지에 있습니다. AI 도우미에 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 이메일 · 실명을 넣지 않습니다.

## 공개 전 점검

- [ ] 글과 코드에 비밀키 · 토큰 · 비밀번호가 없다
- [ ] 내 이메일 · 전화번호 같은 개인정보가 없다
- [ ] 실습 데이터의 이름(dami, junho 등) 말고 실제 사람의 이름을 쓰지 않았다
- [ ] 머리말이 `module: 3`, `unit: 5` 다
