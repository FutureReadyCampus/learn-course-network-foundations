# 문제 해결 과정을 블로그에 기록

## 기록할 문제 고르기

기록 시간은 20분입니다. 실습에서 발견한 문제와 해결 과정을 GitHub Pages 블로그에 남깁니다. 블로그를 아직 설정하지 않았다면 M3 Unit 1 시작하기 레슨의 Jekyll 및 GitHub Pages 설정 안내부터 진행합니다. `report_u5.md` 가 실행 결과와 질문에 대한 기술 기록이라면, 블로그 글은 문제를 어떻게 파악하고 어떤 근거로 해결 방법을 골랐는지 보여 주는 포트폴리오 기록입니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

**핵심 실습에서 고를 기록 주제**

1. 점검 결과가 「통과」여도 「문제 없음」으로만 읽으면 안 되는 사례를 하나 들어 보세요. 함께 읽어야 할 다른 점검은 무엇인가요?
2. 점검 코드가 알려 주는 것과 알려 주지 못하는 것은 무엇인가요? 코드가 권한을 바로 회수하지 않고 담당자에게 넘기게 한 이유를 써 보세요.
3. Module 3의 상황 8개 중 데이터를 고친 상황과 규칙을 고친 상황을 하나씩 골라, 실수했을 때 영향이 어디까지 퍼지는지 비교해 보세요.

세 문장 틀을 쓰되, 각 문장을 실무 기록처럼 구체적으로 채웁니다.

- **문제**: 어떤 접근통제 문제를 확인했는지 씁니다.
- **선택과 이유**: 어떤 출력이나 코드 근거를 보고 수정 방법을 골랐는지 씁니다.
- **검증 결과**: 선택한 방법이 문제를 어떻게 해결했는지, 다시 실행해 무엇을 확인했는지 씁니다. 아직 해결되지 않았다면 다음에 확인할 일을 적습니다.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 「실습 결과 기록 준비」에서 가장 오래 고민한 질문과 이어지는 글감으로 정합니다.

## 문제 해결 기록을 작성하고 올리기

Jekyll 블로그 설정이 되어 있는지 먼저 확인합니다. 아직 설정하지 않았다면 [M3 Unit 1 시작하기 레슨의 Jekyll 설명과 GitHub Pages 설정 안내](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)를 따라 설정한 뒤 돌아옵니다. 설정이 되어 있다면 Unit 1의 글쓰기 안내를 따라 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고 터미널에서 올립니다. 글 틀을 복사하는 방법은 [Unit 1 시작하기 레슨의 「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)를 봅니다.

**글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 문제 해결 과정 요약 | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |

**쓰는 순서**

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-02-departed-account-review.md` 처럼 만듭니다(경로 `_posts/2026-11-02-departed-account-review.md`). 앞은 오늘 날짜, 뒤는 다룬 문제를 담은 영문 이름입니다. 이미 게시한 글은 기존 주소가 유지되도록 파일명을 그대로 두세요.
2. 고른 글 틀을 붙여 넣고 머리말의 `title`에 한 줄 제목을, `date`에 파일명에 쓴 날짜를 적습니다. 만료 예외와 퇴사자 계정의 점검 결과를 함께 읽었다면 제목을 「만료 예외 점검을 통과해도 퇴사자 계정을 다시 확인하는 이유」로 쓸 수 있습니다. 날짜가 미래면 글이 목록에 나오지 않습니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 오늘 날짜 이름(예: `_posts/2026-11-02-departed-account-review.md`)으로 글 파일을 만들고 글 틀을 붙여 넣은 뒤 머리말을 내 글의 `title` · `date` 로 고쳤다
<!-- /checklist -->

3. 빈칸을 채우고 저장합니다. 만료 예외와 퇴사자 계정을 다뤘다면 두 점검이 각각 무엇을 검사하는지 설명하고, 직접 본 출력에서 한 줄씩 인용합니다. 글을 올린 뒤 GitHub에서 판단에 쓴 코드 파일(예: `access_control/checklist.py`)을 열고 주소를 복사해 「검증 결과」 문단에 넣습니다. Markdown에서 `[점검 코드 보기](복사한 주소)`의 괄호 안을 실제 주소로 바꾸세요. 글을 다시 올리고 「전체 글」에서 제목을 눌러 본문과 코드 링크를 열어 보세요.

<!-- checklist -->
- [ ] 문제 상황, 판단 근거, 해결 방법과 확인 결과가 세 문장에 담기도록 쓰고 저장했다
<!-- /checklist -->

4. 올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 문제 해결 기록이 있고, 머리말에 내 글의 제목과 작성일이 있으면 성공입니다. 없으면 1번에서 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 핵심 실습 기록을 다듬기

- **글감 1 (「통과」 읽기)**: 실습 5-1 출력에서 `만료 예외 점검 | 통과 | []` 줄과 `퇴사자 계정 점검 | 실패 | ['dami']` 줄을 코드 상자에 함께 붙입니다. 그 아래에 「예외 3번은 dami 의 것」이라는 사실을 이어 쓰면, 두 줄을 같이 읽어야 하는 이유가 저절로 드러납니다.
- **글감 2 (알려 주는 것과 못 하는 것)**: `check_dept` 의 `if expected_dept != info["dept"]:` 한 줄을 붙이고, 이 줄이 비교하는 것은 「부서 표기와 역할」 두 값뿐이라는 점에서 시작합니다. junho 가 실제로 무슨 일을 하는지는 이 줄로 알 수 없으니, 그다음은 담당자가 확인할 일로 나눠 씁니다.
- **글감 3 (데이터와 규칙)**: 실습 5-2 정답의 「데이터 문제 · 규칙 문제」 표를 떠올리고, 고칠 파일 이름(예: `users.json` 과 `conditions.json`)을 하나씩 적습니다. 데이터는 한 사람에게, 규칙은 그 규칙을 거치는 모든 요청에 영향을 준다는 차이를 내 말로 씁니다.
- **핵심 실습 기록**: `week_log.jsonl` 에서 dami 와 gaeun 의 거부 줄을 두세 줄씩 골라 붙이고, 거부 사유(`퇴사한 계정` 과 `허용되지 않은 접속 위치`)가 다르다는 점부터 씁니다. 「거부율 0%」 글감은 주간 보고서 1절의 `전체 요청:` 줄과 함께 읽습니다.
- **실행 결과 붙이기**: 터미널 출력은 전체를 붙이지 않아도 됩니다. 글에서 말하는 줄 한두 개만 글자 그대로 복사해 코드 상자(```` ``` ````)에 붙이고, 그 줄에서 무엇을 봐야 하는지 한 문장을 덧붙입니다.
- **무엇부터 쓸지 모를 때**: 보고서 `report_u5.md` 에 쓴 내 답 하나를 글 틀의 「검증 결과」 문장에 옮기고, 앞의 두 문장을 거기에 맞춰 씁니다.

코드 설명 정리, 초안 다듬기, 내 글 점검에 쓰는 AI 도우미 프롬프트 세 가지는 [Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 이메일 · 실명을 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇이 문제였나 · 무엇을 근거로 판단했나 · 해결 후 무엇을 확인했나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 힌트에서 고른 글감에 붙이라고 한 줄을 붙이고, 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 코드(`access_control/` 의 파일 포함)에 비밀키 · 토큰 · 비밀번호가 없다
2. 내 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터의 이름(dami, junho 등) 말고 실제 사람의 이름을 쓰지 않았다
4. 글 제목이 내용을 드러내고 작성일이 파일명의 날짜와 같다

**올리기** — **[터미널]** 네 줄을 모두 확인했으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..` → `python check_publish.py` → `git add .` → `git commit -m "Add unit 5 post"` → `git push` → `cd access_control`. 점검에서 `[오류]` 가 나오면 그 부분을 지우고 다시 돌린 뒤 올립니다.
