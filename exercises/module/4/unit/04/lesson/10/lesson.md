# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 매긴 위험 점수와 줄인 오탐을 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 글은 내 GitHub Pages 포트폴리오에 올립니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「자기소개 두 문장으로 시작하기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검 · 올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

- 글감은 기술 기록 `report_u4.md` 에 남긴 판단 가운데 가장 오래 고민한 것을 고르면 쉽습니다.

**글감 질문 (실습 4-1 · 4-2)**

1. 위험 점수 파일에 점수만 남기지 않고 탐지된 규칙 이름(이유)까지 함께 저장했습니다. 이유가 없다면 담당자는 무엇을 할 수 없을까요?
2. 경로 스캔 IP `198.51.100.90` 은 30점이라 low 였습니다. low 등급이면 그 기록을 무시해도 될까요? 등급이 무엇을 정하는 기준인지 함께 써 보세요.
3. 믿는 IP 예외를 한 규칙(`SaaS 평소와 다른 IP`)에만 걸었습니다. IP 하나로 모든 알림을 뺐다면 무엇이 지워졌을까요? 예외를 둔 규칙에서는 어떤 공격을 놓칠 수 있을까요?

**선택 글감 (응용 4-1 · 4-2를 했다면)**

1. 여러 로그의 이벤트를 한 사건으로 묶은 기준은 무엇인가요? 이 묶음만으로 공격이라고 확정할 수 있나요?
2. 조사해 보니 서버 설정 오류였던 알림은 왜 오탐인가요? 그래도 한 번은 확인해야 했던 이유는 무엇인가요?

세 문장이면 충분합니다. 오늘 막혀서 실습을 다 못 했다면 그 막힌 이야기도 좋은 글이 됩니다. 어디서 멈췄는지 남겨 두면 다음에 나도, 글을 읽는 사람도 도움을 받습니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 「실습 결과 기록 준비」에서 가장 오래 고민한 판단과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고, 터미널에서 올립니다. 글 틀 세 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 나의 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 실습하다 막혔다 | `_templates/post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `_templates/post-practice.md` |

**2. 새 글 파일 만들기**

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-20-m4-u4-risk-scores.md` 처럼 만듭니다(경로 `_posts/2026-11-20-m4-u4-risk-scores.md`). 앞은 오늘 날짜, 뒤는 영문 제목입니다. `anomaly_detection` 안이 아니라 저장소 바로 아래의 `_posts` 폴더입니다.
2. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)의 `title`에 한 줄 제목을, `date`에 파일명에 쓴 날짜를 적습니다. 날짜가 미래면 글이 목록에 나오지 않습니다.
3. 빈칸을 채우고 저장합니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 오늘 날짜 이름(예: `_posts/2026-11-20-m4-u4-risk-scores.md`)으로 글 파일을 만들고 글 틀을 붙여 넣었다
- [ ] 머리말을 내 글의 `title` · `date` 로 고치고 세 칸을 채워 저장했다
<!-- /checklist -->

**3. 코드 위치 적기**

코드는 따로 옮기지 않습니다. 오늘 만든 `anomaly_detection/risk_scores.py`(실습 4-1) · `anomaly_detection/tuning.py`(실습 4-2) 파일이 같은 저장소 안에 있으니, 글 안에는 핵심 몇 줄만 코드 상자로 붙이고 「전체 코드: `anomaly_detection/risk_scores.py`」처럼 위치만 적습니다.

올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 머리말에 내 글의 제목과 작성일이 있으면 성공입니다. 없으면 1번에서 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(이유 저장)**: 실습 4-1 출력 단계 4의 `mid seoyeon 45 ['평소와 다른 IP', '대량 다운로드']` 한 줄을 붙이고, 「45 라는 숫자만 있었다면」과 「이유가 함께 있으면」을 나란히 적어 봅니다. 담당자가 다음에 무엇을 확인하러 갈지 쓰면 글의 절반이 됩니다.
2. **글감 2(low 등급)**: 단계 4의 `low 198.51.100.90 30 ['경로 스캔']` 줄과, `normalized_events.json` 에서 이 IP 의 요청 3개(09:20:10 ~ 09:20:12, 모두 실패)를 붙입니다. 「점수 기준」과 「기록을 남길지」를 따로 나누어 씁니다.
3. **글감 3(예외 규칙)**: `is_removed = is_ip_rule & is_trusted` 한 줄을 붙이고, 실습 4-2의 정답 펼침 「자주 틀리는 곳」에서 `is_ip_rule &` 를 뺐을 때 A6 까지 빠진 출력(`진짜 문제였던 알림 수: 1`)과 내 출력(`0`)을 비교합니다.
4. **실행 결과 붙이기**: 터미널 출력은 전부 붙이지 않아도 됩니다. 내 말과 연결되는 두세 줄만 코드 상자(```` ``` ````)로 붙이고, 그 아래에 「이 줄에서 무엇을 보았는지」를 한 문장으로 씁니다. 화면 캡처를 쓰려면 이미지를 `assets/images/` 에 올리고 글에 연결합니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 4-1에서 `AttributeError: 'function' object has no attribute 'sort_values'` 가 났다면, 그 오류와 내가 의심한 줄(`totals = grouped["points"].sum`)을 적고 괄호가 빠진 것을 어떻게 찾았는지 씁니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 힌트에서 붙일 줄을 골라 붙이고 그 줄을 한 문장으로 설명합니다.

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Module 3 Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

4. 글 제목이 내용을 드러내고 작성일이 파일명의 날짜와 같다
