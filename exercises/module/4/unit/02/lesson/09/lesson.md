# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 센 숫자와 그때 한 고민을 내 GitHub Pages 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 할 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검 · 올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

글감은 보고서 `report_u2.md` 에 적은 답 가운데 가장 오래 고민한 것을 고르면 쉽습니다.

**오늘의 글감 (핵심 실습)**

1. 실패 개수가 가장 많은 소스가 가장 문제가 큰 소스라고 할 수 있나요? 소스마다 전체 이벤트 수가 다르다는 것과 함께 써 보세요.
2. 사용자 이름이 비어 있는 이벤트의 실패는 사용자별로 셀 때 어떻게 되나요? 사용자 대신 어떤 열로 같은 대상의 반복을 알 수 있을까요?
3. 203.0.113.50 은 로그인에 5번 실패해 알림 대상이 되었습니다. 알림이 났다는 것과 공격이라는 것은 어떻게 다를까요? 4번 실패하고 5번째에 성공한 접속은 알림이 나지 않는데, 그렇다면 「알림 없음」은 무엇을 뜻할까요?

**선택 글감 (응용을 했다면)**

1. 알림 기준을 평균이 아니라 최댓값보다 1 큰 값으로 정한 이유는 무엇인가요? 평균을 썼다면 지난 7일 중 며칠에 알림이 났을까요? 지난 7일 중 하루가 평소와 달랐다면 기준은 어떻게 바뀌고, 그 기준을 계속 쓰면 어떤 문제가 생길까요?
2. 「기타 실패」 15개에는 어떤 일들이 섞여 있었나요? 규칙의 순서를 바꾸면 무엇을 구분하지 못하게 될까요?

세 문장이면 충분합니다. 오늘 막혀서 실습을 다 못 했다면 그 막힌 이야기도 좋은 글이 됩니다. 어디서 멈췄는지 남겨 두면 다음에 나도, 글을 읽는 사람도 도움을 받습니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 「보고서 쓰기」에서 가장 오래 고민한 질문과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Module 3 Unit 1 시작하기 레슨에서 한 것처럼 **GitHub 웹 화면**에서 파일을 만들고 붙여 넣습니다. 글 틀 세 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 나의 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `_templates/post-practice.md` |

**2. 새 글 파일 만들기**

1. 내 포트폴리오 저장소에서 `_posts` 폴더를 열고 **Add file › Create new file** 을 누릅니다.
2. 파일 이름은 `날짜-영문제목.md` 모양으로 적습니다. 예: `_posts/2026-11-20-m4-u2-login-failure-rule.md`
3. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit 에 맞게 고칩니다.
   ```
   module: 4
   unit: 2
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 4 의 **2번** 칸을 채웁니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다.
4. 빈칸을 채우고 **Commit changes** 를 누릅니다.

**3. 코드 올리기**

글에서 소개한 코드는 저장소의 `code/` 폴더에 올립니다. `code` 폴더에서 **Add file › Create new file** 을 누르고, 이름은 Unit 번호가 보이게 적습니다.

이름의 예입니다.

| 실습 | 올릴 파일 이름 |
|---|---|
| 실습 2-1 | `code/m4_u2_events_basic.py` |
| 실습 2-2 | `code/m4_u2_events_time.py` |
| 실습 2-3 | `code/m4_u2_login_detection.py` |

- 글 안에는 핵심 몇 줄만 코드 상자로 붙이고, 「전체 코드: `code/m4_u2_login_detection.py`」처럼 위치를 적습니다.

**4. 확인하기**

올리고 1~2분 기다린 뒤 내 사이트 첫 화면을 엽니다.

> **확인** — 최신 글에 오늘 글이 보이고 「나의 진행」의 Module 4 · 2번 칸이 채워지면 성공입니다. 안 보이면 저장소의 **Actions** 탭을 먼저 보고, [Module 3 Unit 1 시작하기 레슨의 「첫 화면 확인하고 막힐 때」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/9)의 「글이 목록에 안 나옴」 줄을 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(개수와 비율)**: 실습 2-1 출력의 단계 3(실패한 이벤트의 소스별 개수)과 단계 4(전체 이벤트의 소스별 개수)를 나란히 붙입니다. 소스마다 「실패 ÷ 전체」를 계산해 한 줄씩 적으면, 개수로 본 순서와 비율로 본 순서가 다르다는 것이 글의 중심이 됩니다.
2. **글감 2(비어 있는 값)**: 실습 2-2 단계 1의 사용자별 횟수를 모두 더한 값과 실습 2-1의 실패 23개를 비교합니다. 모자란 개수가 어느 소스의 몇 개와 같은지 쓰고, `groupby("user")` 가 오류 없이 빼고 센다는 점을 내 말로 풉니다.
3. **글감 3(알림과 공격)**: 실습 2-3 단계 3의 출력 두 줄과 3.1 표에서 203.0.113.50 의 9번 ~ 17번 행을 붙입니다. 시각 간격, 6번째의 성공, 그 뒤의 `/admin` 요청을 차례로 적고, 그래도 확정하려면 무엇이 더 필요한지 한 가지를 씁니다.
4. **실행 결과 붙이기**: 터미널 출력은 전부 붙이지 않아도 됩니다. 내 말과 연결되는 두세 줄만 코드 상자(```` ``` ````)로 붙이고, 그 아래에 「이 줄에서 무엇을 보았는지」를 한 문장으로 씁니다. 화면 캡처를 쓰려면 이미지를 `assets/images/` 에 올리고 글에 연결합니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 2-3에서 `ValueError: The truth value of a Series is ambiguous` 가 났다면, 그 줄과 내가 의심한 줄(`both_true = is_login and is_fail`)을 적고 `&` 로 바꿔 어떻게 풀었는지 씁니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 힌트에서 말한 출력 줄을 붙이고 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

**Commit changes** 를 누르기 전에 한 번 더 봅니다.

1. 글과 `code/` 파일에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다. 샘플 이벤트의 `jiwoo` · `seoyeon` 같은 계정 이름과 `203.0.113.50` 같은 예시 주소는 실습 데이터라 써도 됩니다
4. 머리말이 `module: 4`, `unit: 2` 이고, `sample: true` 줄이 없다

> **확인** — 네 줄을 모두 「그렇다」로 답할 수 있으면 성공입니다. 하나라도 걸리면 그 부분을 고치고 다시 **Commit changes** 합니다.
