# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

GitHub Pages 포트폴리오의 Jekyll과 GitHub Pages 설정은 끝냈나요? 끝냈다면 오늘 핵심 실습에서 확인한 문제와 해결 근거를 **세 문장 문제 해결 기록**으로 남깁니다. 아직 설정하지 않았다면 M3 Unit 1 시작하기의 [Jekyll·GitHub Pages 설정 안내](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)로 돌아가 먼저 완료한 뒤 여기로 돌아옵니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 할 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검 · 올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

실습 결과 기록 `practice_record_u2.md` 에 남긴 결과를 바탕으로 가장 오래 고민한 핵심 문제 하나를 고르면 쉽습니다.

**오늘의 글감 (핵심 실습)**

1. 실패 개수가 가장 많은 소스가 가장 문제가 큰 소스라고 할 수 있나요? 소스마다 전체 이벤트 수가 다르다는 것과 함께 써 보세요.
2. 사용자 이름이 비어 있는 이벤트의 실패는 사용자별로 셀 때 어떻게 되나요? 사용자 대신 어떤 열로 같은 대상의 반복을 알 수 있을까요?
3. 203.0.113.50 은 로그인에 5번 실패해 알림 대상이 되었습니다. 알림이 났다는 것과 공격이라는 것은 어떻게 다를까요? 4번 실패하고 5번째에 성공한 접속은 알림이 나지 않는데, 그렇다면 「알림 없음」은 무엇을 뜻할까요?

세 문장이면 충분합니다. 실습을 다 끝내지 못했다면 어디서 멈췄고 무엇을 확인했는지 기록합니다.

**공개 글 예시**

**실패 건수와 실패율로 조사 순서 비교하기**

샘플 로그에서 실패 건수가 가장 많은 소스부터 조사할지 살펴봤습니다. 소스별 전체 이벤트 수가 달라서 실패 건수를 전체 건수로 나눈 실패율도 함께 비교했습니다. 실패 건수는 웹이 13건으로 가장 많았고, 실패율은 서버가 15건 중 9건으로 웹의 28건 중 13건보다 높았습니다.

예시를 참고해 내가 실제로 한 결정과 본 출력으로 바꿔 씁니다. 과정 밖 독자도 제목만 보고 무엇을 살펴본 글인지 알 수 있게 적습니다.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 핵심 실습 결과 기록에서 가장 오래 고민한 판단과 이어지는 글감을 고릅니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고, 터미널에서 올립니다. 글 틀 두 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 나의 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |

**2. 새 글 파일 만들기**

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-20-compare-log-failure-rates.md` 처럼 만듭니다(경로 `_posts/2026-11-20-compare-log-failure-rates.md`). 앞은 글을 쓰는 날짜, 뒤는 글 내용을 나타내는 영문 단어입니다. `anomaly_detection` 안이 아니라 저장소 바로 아래의 `_posts` 폴더입니다.
2. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)의 `title`에 한 줄 제목을, `date`에 파일명에 쓴 날짜를 적습니다. 날짜가 미래면 글이 목록에 나오지 않습니다.
3. 문제, 그 방법을 택한 이유, 실행해서 확인한 결과를 씁니다. 막힌 상태라면 어디까지 확인했는지 적습니다. 제목이나 본문을 고칠 때는 이미 공개한 글의 파일 이름과 작성일을 유지합니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 오늘 날짜 이름(예: `_posts/2026-11-20-compare-log-failure-rates.md`)으로 글 파일을 만들고 글 틀을 붙여 넣었다
- [ ] 머리말을 내 글의 `title` · `date`로 고치고 문제·선택 이유·확인 결과를 적어 저장했다
<!-- /checklist -->

**3. 코드와 실행 근거 넣기**

코드는 `anomaly_detection/`에 둡니다. 글에서 설명한 코드가 그 폴더에 있으면 아래 예시처럼 글 본문에 링크를 붙입니다. 다른 글감이라면 `events_time.py`나 `login_detection.py`처럼 그 글에 맞는 파일 경로를 씁니다.

<pre class="copyable"><code>[소스별 실패 및 전체 이벤트를 집계하는 코드]({{ "/anomaly_detection/events_basic.py" | relative_url }})</code></pre>

`relative_url`은 내 GitHub Pages 주소의 저장소 경로를 링크에 붙여 줍니다. 본문에는 판단에 필요한 코드나 실습 출력만 몇 줄 옮기고, 그 줄에서 무엇을 확인했는지 적습니다. 공개 가능한 화면 캡처가 필요하면 `assets/images/`에 넣어 연결합니다.

올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 머리말에 내 글의 제목과 작성일이 있으면 성공입니다. 없으면 1번에서 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(개수와 비율)**: 실습 2-1 출력의 단계 3(실패한 이벤트의 소스별 개수)과 단계 4(전체 이벤트의 소스별 개수)를 나란히 붙입니다. 소스마다 「실패 ÷ 전체」를 계산해 한 줄씩 적으면, 개수로 본 순서와 비율로 본 순서가 다르다는 것이 글의 중심이 됩니다.
2. **글감 2(비어 있는 값)**: 실습 2-2 단계 1의 사용자별 횟수를 모두 더한 값과 실습 2-1의 실패 23개를 비교합니다. 모자란 개수가 어느 소스의 몇 개와 같은지 쓰고, `groupby("user")` 가 오류 없이 빼고 센다는 점을 내 말로 풉니다.
3. **글감 3(알림과 공격)**: 실습 2-3 단계 3의 출력 두 줄과 3.1 표에서 203.0.113.50 의 9번 ~ 17번 행을 붙입니다. 시각 간격, 6번째의 성공, 그 뒤의 `/admin` 요청을 차례로 적고, 그래도 확정하려면 무엇이 더 필요한지 한 가지를 씁니다.
4. **실행 결과 붙이기**: 같은 출력에서 실패 건수와 전체 건수를 짝지어 보여 주고, 실패율의 분모가 무엇인지 설명합니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 2-3에서 `ValueError: The truth value of a Series is ambiguous` 가 났다면, 그 줄과 내가 의심한 줄(`both_true = is_login and is_fail`)을 적고 `&` 로 바꿔 어떻게 풀었는지 씁니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

> **확인** — 실습을 처음 보는 사람이 문제와 선택 이유를 자기 말로 설명할 수 있고, 내가 확인한 결과를 어떤 출력이나 코드로 읽을 수 있는지 알 수 있으면 충분합니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Module 3 Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 코드(`anomaly_detection/` 의 파일 포함)에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다. 샘플 이벤트의 `jiwoo` · `seoyeon` 같은 계정 이름과 `203.0.113.50` 같은 예시 주소는 실습 데이터라 써도 됩니다
4. 글 제목이 내용을 드러내고 작성일이 파일명의 날짜와 같다

**올리기** — **[터미널]** 네 줄을 모두 「그렇다」로 답할 수 있으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..` → `python check_publish.py` → `git add .` → `git commit -m "Add module 4 unit 2 post"` → `git push` → `cd anomaly_detection`. `pwd` 가 이미 `…/network-study-notes` 로 끝나면 맨 앞 `cd ..` 는 건너뜁니다. 점검에서 `[오류]` 가 나오면 그 부분을 고치고 다시 돌린 뒤 올립니다.
