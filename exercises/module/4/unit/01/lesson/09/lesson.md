# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

하루의 마지막 40분은 오늘 한 로그 읽기와 정규화를 내 말로 남기는 시간입니다. 글은 내 GitHub Pages 포트폴리오에 올립니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**40분은 이렇게 나눕니다**

1. 고르기 5분: 아래 글감 질문 중 하나를 고릅니다. 보고서 `report_u1.md` 에 적은 답 가운데 가장 오래 고민한 것을 고르면 쉽습니다.
2. 쓰기 25분: 글 틀을 복사해 내 답을 글로 풉니다.
3. 점검 · 올리기 10분: 공개 전 점검을 하고 GitHub 에 올린 뒤 첫 화면을 확인합니다.

**글감 질문 (실습 1-1 · 1-2)**

1. 로그 한 줄만 보고 알 수 있는 것과 알 수 없는 것을 나눠 보세요. 접속자가 누구인지, 로그인에 성공했는지도 알 수 있나요?
2. 404 한 번과 `/.env` · `/wp-login.php` · `/phpmyadmin` 에 연달아 404 가 난 요청은 같은 일일까요? 한 줄만 보고 판단하기 어려운 이유를 써 보세요.
3. 시각을 `02/Nov/2026:09:00:00 +0900` 모양 그대로 문자열로 정렬하면 12월과 11월 중 무엇이 앞에 올까요? 공통 모양으로 바꾼 뒤 무엇이 달라졌나요?
4. 공통 이벤트에 원래 로그 줄(`raw`)을 남겨 둔 이유는 무엇인가요? 정규화하면 사라지는 정보의 예를 들어 보세요.

**선택 글감 (도전 1-1 ~ 1-3을 했다면)**

1. 상태 코드와 경로만 보는 규칙이 놓친 요청은 무엇이었나요? 줄을 하나씩만 보는 규칙의 한계를 내 말로 써 보세요.
2. 판정 서버 로그에 없는 접속 주소를 `None` 으로 두었습니다. 가짜 주소 `0.0.0.0` 을 채웠다면 주소별로 셀 때 무엇이 틀어질까요?
3. 세 로그를 합쳐 시간순으로 놓자 gaeun 의 일이 어떤 순서로 보였나요? 로그를 따로 볼 때와 무엇이 달랐나요?

세 문장만 써도 한 편의 글입니다. 오늘 막혀서 실습을 다 못 했다면 그 막힌 이야기도 좋은 글이 됩니다. 어디서 멈췄는지 남겨 두면 다음에 나도, 글을 읽는 사람도 도움을 받습니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Module 3 Unit 1 시작하기 레슨에서 한 것처럼 **GitHub 웹 화면**에서 파일을 만들고 붙여 넣습니다. 글 틀 세 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 나의 상황 | 고를 글 틀 |
|---|---|
| 실습 1-1 이나 1-2 하나를 글 한 편으로 쓰고 싶다 | `_templates/post-practice.md` |
| 시간이 5분밖에 없다 | `_templates/post-short.md` |
| 실습하다 막혔다 | `_templates/post-stuck.md` |

**2. 새 글 파일 만들기**

1. 내 포트폴리오 저장소에서 `_posts` 폴더를 열고 **Add file › Create new file** 을 누릅니다.
2. 파일 이름은 `날짜-영문제목.md` 모양으로 적습니다. 예: `_posts/2026-11-20-m4-u1-log-normalize.md`
3. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit 에 맞게 고칩니다.
   ```
   module: 4
   unit: 1
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 4 의 **1번** 칸을 채웁니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다.
4. 빈칸을 채우고 **Commit changes** 를 누릅니다.

**3. 코드 올리기**

글에서 소개한 코드는 저장소의 `code/` 폴더에 올립니다. `code` 폴더에서 **Add file › Create new file** 을 누르고, 이름은 Module 과 Unit 번호가 보이게 적습니다.

- 예: `code/m4_u1_log_parse.py`(실습 1-1), `code/m4_u1_normalize_web.py`(실습 1-2)
- 글 안에는 핵심 몇 줄만 코드 상자로 붙이고, 「전체 코드: `code/m4_u1_normalize_web.py`」처럼 위치를 적습니다.

**4. 확인하기**

올리고 1~2분 기다린 뒤 내 사이트 첫 화면을 엽니다. 최신 글에 내 글이 보이고, 「나의 진행」의 Module 4 · 1번 칸이 채워졌으면 끝입니다. 보이지 않으면 저장소의 **Actions** 탭을 먼저 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(한 줄로 알 수 있는 것)**: `access_sample.log` 에서 `203.0.113.50` 의 `POST /login` 401 줄 하나를 코드 상자로 붙이고, 그 아래에 「알 수 있는 것」과 「알 수 없는 것」을 두 줄 목록으로 적습니다. 실습 1-2에서 웹 서버 이벤트의 `user` 가 `None` 이었던 것과 이어 쓰면 글이 한 단계 깊어집니다.
2. **글감 2(404 두 경우)**: `198.51.100.21` 의 `GET /board/99` 한 줄과 `198.51.100.90` 의 세 줄을 나란히 붙입니다. 세 줄의 시각이 1초 간격이라는 것과 요청 프로그램이 `curl` 이라는 것을 짚으면 「여러 줄을 묶어 봐야 보인다」는 결론까지 쉽게 갑니다.
3. **글감 3(시각 정렬)**: 정답 레슨 「실습 1-2 정답」의 비교 코드 여섯 줄을 직접 돌려 `True` · `False` 출력을 붙이고, 문자열이 앞 글자부터 비교된다는 것을 한 문장으로 씁니다.
4. **글감 4(`raw`)**: 실습 1-2 출력 단계 2의 실패 이벤트를 붙이고, `'result': '실패'` 와 `raw` 안의 `401` 을 나란히 적습니다. `401` 이 `500` 이었어도 `result` 는 같았을 거라는 점에서 「사라지는 정보」가 보입니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 오류를 그대로 붙입니다. 예를 들어 `log_parse.py` 를 채우기 전에 실행해 `IndentationError: unexpected indent` 가 났다면, 그 오류와 8번 `if` 줄을 쓰고 나서 풀린 과정을 적습니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

## 공개 전 점검

**Commit changes** 를 누르기 전에 한 번 더 봅니다.

1. 글과 `code/` 파일에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 샘플이 아닌 실제 회사나 내 컴퓨터의 로그를 붙이지 않았다(샘플 로그의 `203.0.113.50` 같은 주소는 문서용 예시 주소라 그대로 써도 됩니다)
4. 머리말이 `module: 4`, `unit: 1` 이고, `sample: true` 줄이 없다
