# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 한 로그 읽기와 정규화를 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 보고서는 질문에 답하는 파일이고, 이 글은 그 답 가운데 하나를 내 말로 풀어 쓰는 기록입니다. 글은 내 GitHub Pages 포트폴리오에 올립니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검 · 올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

글감은 보고서 `report_u1.md` 에 적은 답 가운데 가장 오래 고민한 것을 고르면 쉽습니다.

**오늘의 글감 (핵심 실습)**

1. 로그 한 줄만 보고 알 수 있는 것과 알 수 없는 것을 나눠 보세요. 접속자가 누구인지, 로그인에 성공했는지도 알 수 있나요?
2. 404 한 번과 `/.env` · `/wp-login.php` · `/phpmyadmin` 에 연달아 404 가 난 요청은 같은 일일까요? 한 줄만 보고 판단하기 어려운 이유를 써 보세요.
3. 시각을 `02/Nov/2026:09:00:00 +0900` 모양 그대로 문자열로 정렬하면 12월과 11월 중 무엇이 앞에 올까요? 공통 모양으로 바꾼 뒤 무엇이 달라졌나요?
4. 공통 이벤트에 원래 로그 줄(`raw`)을 남겨 둔 이유는 무엇인가요? 정규화하면 사라지는 정보의 예를 들어 보세요.

**선택 글감 (응용을 했다면)**

1. 상태 코드와 경로만 보는 규칙이 놓친 요청은 무엇이었나요? 줄을 하나씩만 보는 규칙의 한계를 내 말로 써 보세요.
2. 판정 서버 로그에 없는 접속 주소를 `None` 으로 두었습니다. 가짜 주소 `0.0.0.0` 을 채웠다면 주소별로 셀 때 무엇이 틀어질까요?
3. 세 로그를 합쳐 시간순으로 놓자 gaeun 의 일이 어떤 순서로 보였나요? 로그를 따로 볼 때와 무엇이 달랐나요?

세 문장이면 충분합니다. 막혀서 끝내지 못한 이야기도 좋은 글입니다. 어디까지 해 봤고 어디서 멈췄는지를 적어 두면, 다음에 다시 볼 때 가장 쓸모 있는 기록이 됩니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 보고서에서 가장 오래 고민한 질문과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고, 터미널에서 올립니다. 글 틀 세 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `_templates/post-practice.md` |

**2. 새 글 파일 만들기**

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-20-m4-u1-log-normalize.md` 처럼 만듭니다(경로 `_posts/2026-11-20-m4-u1-log-normalize.md`). 앞은 오늘 날짜, 뒤는 영문 제목입니다. `anomaly_detection` 안이 아니라 저장소 바로 아래의 `_posts` 폴더입니다.
2. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit 에 맞게 고칩니다.
   ```
   module: 4
   unit: 1
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 4 의 **1번** 칸을 채웁니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다. 날짜가 미래면 글이 목록에 나오지 않습니다.
3. 빈칸을 채우고 저장합니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 오늘 날짜 이름(예: `_posts/2026-11-20-m4-u1-log-normalize.md`)으로 글 파일을 만들고 글 틀을 붙여 넣었다
- [ ] 머리말을 `module: 4` · `unit: 1`, 내 `title` · `date` 로 고치고 세 칸을 채워 저장했다
<!-- /checklist -->

**3. 코드 위치 적기**

코드는 따로 옮기지 않습니다. 오늘 만든 `anomaly_detection/log_parse.py`(실습 1-1) · `anomaly_detection/normalize_web.py`(실습 1-2) 파일이 같은 저장소 안에 있으니, 글 안에는 핵심 몇 줄만 코드 상자로 붙이고 「전체 코드: `anomaly_detection/normalize_web.py`」처럼 위치만 적습니다.

올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 맨 위 머리말에 `module: 4` · `unit: 1` 두 줄이 있으면 성공입니다. 없으면 1번에서 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(한 줄로 알 수 있는 것)**: `access_sample.log` 에서 `203.0.113.50` 의 `POST /login` 401 줄 하나를 코드 상자로 붙이고, 그 아래에 「알 수 있는 것」과 「알 수 없는 것」을 두 줄 목록으로 적습니다. 실습 1-2에서 웹 서버 이벤트의 `user` 가 `None` 이었던 것과 이어 쓰면 글이 한 단계 깊어집니다.
2. **글감 2(404 두 경우)**: `198.51.100.21` 의 `GET /board/99` 한 줄과 `198.51.100.90` 의 세 줄을 나란히 붙입니다. 세 줄의 시각이 1초 간격이라는 것과 요청 프로그램이 `curl` 이라는 것을 짚으면 「여러 줄을 묶어 봐야 보인다」는 결론까지 쉽게 갑니다.
3. **글감 3(시각 정렬)**: 정답 레슨 「실습 1-2 정답」의 비교 코드 여섯 줄을 직접 돌려 `True` · `False` 출력을 붙이고, 문자열이 앞 글자부터 비교된다는 것을 한 문장으로 씁니다.
4. **글감 4(`raw`)**: 실습 1-2 출력 단계 2의 실패 이벤트를 붙이고, `'result': '실패'` 와 `raw` 안의 `401` 을 나란히 적습니다. `401` 이 `500` 이었어도 `result` 는 같았을 거라는 점에서 「사라지는 정보」가 보입니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 오류를 그대로 붙입니다. 예를 들어 `log_parse.py` 를 채우기 전에 실행해 `NameError: name 'prefix' is not defined` 가 났다면, 그 오류와 ① 줄을 쓰고 나서 풀린 과정을 적습니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 힌트에서 고른 글감의 로그 줄이나 출력을 붙이고, 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Module 3 Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 코드(`anomaly_detection/` 의 파일 포함)에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 샘플이 아닌 실제 회사나 내 컴퓨터의 로그를 붙이지 않았다(샘플 로그의 `203.0.113.50` 같은 주소는 문서용 예시 주소라 그대로 써도 됩니다)
4. 머리말이 `module: 4`, `unit: 1` 이고, `sample: true` 줄이 없다

**올리기** — **[터미널]** 네 줄을 모두 「그렇다」로 답할 수 있으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..` → `python check_publish.py`(맥북은 `python3`) → `git add .` → `git commit -m "Add module 4 unit 1 post"` → `git push` → `cd anomaly_detection`. `pwd` 가 이미 `…/network-study-notes` 로 끝나면 맨 앞 `cd ..` 는 건너뜁니다. 점검에서 `[오류]` 가 나오면 그 부분을 고치고 다시 돌린 뒤 올립니다.
