# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

하루의 마지막 40분은 오늘 한 AI 요약과 Module 4 총정리를 내 말로 남기는 시간입니다. 글은 내 GitHub Pages 포트폴리오에 올립니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**40분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 질문 중 하나를 고름 |
| 2. 쓰기 | 25분 | 글 틀을 복사해 내 답을 글로 풂 |
| 3. 점검 · 올리기 | 10분 | 공개 전 점검을 하고 GitHub 에 올린 뒤 첫 화면을 확인 |

- 글감은 보고서 `report_u5.md` 에 적은 답 가운데 가장 오래 고민한 것을 고르면 쉽습니다.

**글감 질문 (실습 5-1 · 5-2)**

1. AI 에게 주는 지시문에서 하지 말라고 한 것 두 가지는 무엇인가요? AI 가 그 일을 하면 담당자에게 왜 위험한가요?
2. AI 요약 하나를 점수 기록 표와 비교해 보세요. 표에 없는 내용이 섞여 있었나요? 있다면 지시문을 어떻게 고치겠습니까? API 키가 없어 대체 문장만 나왔다면, 대체 문장으로도 프로그램이 끝까지 돈 것이 왜 중요한지 써도 됩니다.
3. Module 4의 상황 8개를 데이터 문제 · 규칙 문제 · 운영 설정 문제로 나누어 보세요. 어느 쪽에서 실수하면 더 위험하다고 생각하나요?

**선택 글감 (도전 5-1 ~ 5-3을 했다면)**

1. `docker run` 으로 서버를 켜는 것과 `compose.yaml` 로 켜는 것을 비교해 컴포즈가 나은 점을 두 가지 써 보세요. 사고 뒤 「같은 구성으로 다시 켜 보라」는 요청을 받았다면 어느 쪽이 답할 수 있을까요?
2. `"8081:80"` 과 `"127.0.0.1:8081:80"` 은 누가 접속할 수 있는지가 어떻게 다른가요? 관리 화면을 밖에 열어 두면 무엇이 위험한가요?
3. AI 호출이 실패해도 `pipeline.py` 가 멈추지 않게 만든 이유는 무엇인가요? 대체 문장이 들어간 대상을 담당자는 어떻게 읽어야 할까요?

**Module 4 돌아보기 (선택)** — 이번 Unit은 Module 4의 마지막 Unit입니다. 다섯 Unit 중 가장 오래 고민한 로직 하나를 골라, 그때 어디서 막혔고 지금은 어떻게 이해하는지 써 보아도 좋습니다.

세 문장만 써도 한 편의 글입니다. 오늘 막혀서 실습을 다 못 했다면 그 막힌 이야기도 좋은 글이 됩니다. 어디서 멈췄는지 남겨 두면 다음에 나도, 글을 읽는 사람도 도움을 받습니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Module 3 Unit 1 시작하기 레슨에서 한 것처럼 **GitHub 웹 화면**에서 파일을 만들고 붙여 넣습니다. 글 틀 세 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 나의 상황 | 고를 글 틀 |
|---|---|
| 실습 5-1 이나 5-2 하나를 글 한 편으로 쓰고 싶다 | `_templates/post-practice.md` |
| 시간이 5분밖에 없다 | `_templates/post-short.md` |
| 실습하다 막혔다 | `_templates/post-stuck.md` |

**2. 새 글 파일 만들기**

1. 내 포트폴리오 저장소에서 `_posts` 폴더를 열고 **Add file › Create new file** 을 누릅니다.
2. 파일 이름은 `날짜-영문제목.md` 모양으로 적습니다. 예: `_posts/2026-11-20-m4-u5-ai-summary.md`. 날짜는 글을 쓰는 오늘 날짜로 바꿉니다.
3. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit에 맞게 고칩니다.
   ```
   module: 4
   unit: 5
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 4의 **5번** 칸을 채웁니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다.
4. 빈칸을 채우고 **Commit changes** 를 누릅니다.

**3. 코드 올리기**

글에서 소개한 코드는 저장소의 `code/` 폴더에 올립니다. `code` 폴더에서 **Add file › Create new file** 을 누르고, 이름은 Module 과 Unit 번호가 보이게 적습니다.

- 예: `code/m4_u5_event_summary.py`(실습 5-1), `code/m4_u5_pipeline.py`(도전 5-3)
- VS Code 에서 `anomaly_detection/event_summary.py` 를 열어 내용 전체를 복사해 붙여 넣고 **Commit changes** 를 누릅니다.
- 글 안에는 핵심 몇 줄만 코드 상자로 붙이고, 「전체 코드: `code/m4_u5_event_summary.py`」처럼 위치를 적습니다.
- `llm_client.py` 를 올린다면 키가 들어 있지 않은지 한 번 더 봅니다. 키는 `.env` 에만 있어야 합니다.

**4. 확인하기**

올리고 1~2분 기다린 뒤 내 사이트 첫 화면을 엽니다. 최신 글에 내 글이 보이고, 「나의 진행」의 Module 4 5번 칸이 채워졌으면 끝입니다. 보이지 않으면 저장소의 **Actions** 탭을 먼저 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(지시문)**: `event_summary.py` 의 `PROMPT_RULES` 두 문장을 코드 상자로 붙이고, 「지어내지 말고」와 「단정하지 마세요」에 밑줄을 긋듯 하나씩 풀어 씁니다. 그다음 dami 의 [사실]에 있는 탐지 내용(`퇴사한 계정` 하나)을 보고, AI 가 「공격이 있었다」고 썼다면 담당자가 무엇을 잘못 믿게 되는지 씁니다.
2. **글감 2(요약과 표 비교)**: 실습 5-1 단계 3 의 `[사실]` 줄과 단계 4 의 요약 한 줄을 위아래로 나란히 붙입니다. [사실]에 있는 말에 표시하고, 요약에만 있는 말이 남는지 봅니다. 키가 없었다면 `[LLM 호출 실패] API 키 없음` 과 대체 문장 줄을 붙이고, 그래도 점수 · 등급 · 순서는 그대로였다는 점부터 씁니다.
3. **글감 3(원인 나누기)**: 실습 5-2 정리의 표에서 「데이터를 고치는 곳」 · 「규칙을 고치는 곳」 · 「운영 설정을 고치는 곳」 세 줄을 옮겨 적고, 내가 쓴 상황 번호를 하나씩 그 줄에 붙입니다. 규칙 하나를 바꾸면 그 규칙을 거치는 모든 알림이 바뀐다는 점을 데이터 한 줄을 고치는 경우와 비교합니다.
4. **도전 글감**: `compose.yaml` 과 `compose.secure.yaml` 의 `web2` 포트 줄 두 개를 나란히 붙이고, `docker compose ps` 의 PORTS 에서 `0.0.0.0:` 과 `127.0.0.1:` 이 어떻게 달랐는지 한 줄씩 적습니다. `pipeline.py` 글감은 단계 3 제목 줄의 `(실패 … 건)` 과 단계 5 의 순서를 함께 붙입니다.
5. **실행 결과 붙이기**: 터미널 출력은 전부 붙이지 않아도 됩니다. 내 말과 연결되는 두세 줄만 코드 상자(```` ``` ````)로 붙이고, 그 아래에 「이 줄에서 무엇을 보았는지」를 한 문장으로 씁니다. 화면 캡처를 쓰려면 이미지를 `assets/images/` 에 올리고 글에 연결합니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

## 공개 전 점검

**Commit changes** 를 누르기 전에 한 번 더 봅니다.

1. 글과 `code/` 파일에 Gemini API 키 · 토큰 · `.env` 내용이 없다(`AIza` 로 시작하는 글자가 없다)
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터(dami, seoyeon 등)가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다
4. 머리말이 `module: 4`, `unit: 5` 이고, `sample: true` 줄이 없다
