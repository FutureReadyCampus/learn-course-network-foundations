# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 한 AI 요약과 Module 4 총정리를 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 기술 기록에는 출력과 작업 근거를 남기고, 이 글에는 문제를 어떻게 이해하고 해결했는지 남깁니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「자기소개 두 문장으로 시작하기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

- 글감은 기술 기록 `report_u5.md` 에 남긴 판단 가운데 가장 오래 고민한 것을 고르면 쉽습니다.

**오늘의 글감 (핵심 실습)**

1. AI 에게 주는 지시문에서 하지 말라고 한 것 두 가지는 무엇인가요? AI 가 그 일을 하면 담당자에게 왜 위험한가요?
2. API 키가 없거나 호출이 실패해도 대체 문장으로 프로그램이 끝까지 돈 것이 왜 중요한가요? 빈칸으로 나왔다면 담당자가 무엇을 놓쳤을까요?
3. Module 4의 상황 가운데 내가 쓴 것을 데이터 문제 · 규칙 문제 · 환경 설정 문제로 나누어 보세요. 어느 쪽에서 실수하면 더 위험하다고 생각하나요?

세 문장이면 충분합니다. 막혀서 끝내지 못한 과정도 기록할 가치가 있습니다. 어디까지 해 봤고 어디서 멈췄는지를 적어 두면 다음에 다시 볼 때 도움이 됩니다.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 「실습 결과 기록 준비」에서 가장 오래 고민한 문제와 이어지는 글감을 고릅니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고, 터미널에서 올립니다. 글 틀 두 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |

**2. 새 글 파일 만들기**

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-20-m4-u5-ai-summary.md` 처럼 만듭니다(경로 `_posts/2026-11-20-m4-u5-ai-summary.md`). 앞은 오늘 날짜, 뒤는 영문 제목입니다. `anomaly_detection` 안이 아니라 저장소 바로 아래의 `_posts` 폴더입니다.
2. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit 에 맞게 고칩니다.
   ```
   module: 4
   unit: 5
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 4 의 **5번** 칸을 채웁니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다. 날짜가 미래면 글이 목록에 나오지 않습니다.
3. 빈칸을 채우고 저장합니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 오늘 날짜 이름(예: `_posts/2026-11-20-m4-u5-ai-summary.md`)으로 글 파일을 만들고 글 틀을 붙여 넣었다
- [ ] 머리말을 `module: 4` · `unit: 5`, 내 `title` · `date` 로 고치고 세 칸을 채워 저장했다
<!-- /checklist -->

**3. 코드 위치 적기**

코드는 따로 옮기지 않습니다. 오늘 만든 `anomaly_detection/event_summary.py`(실습 5-1) 파일이 같은 저장소 안에 있으니, 글 안에는 핵심 몇 줄만 코드 상자로 붙이고 「전체 코드: `anomaly_detection/event_summary.py`」처럼 위치만 적습니다.

- `llm_client.py` 를 글에서 소개한다면 키가 들어 있지 않은지 한 번 더 봅니다. 키는 `.env` 에만 있어야 합니다.

올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 맨 위 머리말에 `module: 4` · `unit: 5` 두 줄이 있으면 성공입니다. 없으면 1번에서 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(지시문)**: `event_summary.py` 의 `PROMPT_RULES` 두 문장을 코드 상자로 붙이고, 「지어내지 말고」와 「단정하지 마세요」를 하나씩 풀어 씁니다. 그다음 dami 의 [사실]에 있는 탐지 내용(`퇴사한 계정` 하나)을 보고, AI 가 「공격이 있었다」고 썼다면 담당자가 무엇을 잘못 믿게 되는지 씁니다.
2. **글감 2(대체 문장)**: 내가 채운 ② · ③ 두 줄과 단계 4 의 `dami : (요약 실패 — 점수와 이유를 직접 확인)` 줄을 위아래로 붙입니다. ② · ③ 을 쓰기 전에 요약 자리가 비어 나온 모습과 비교하고, 그래도 점수 · 등급 · 순서는 그대로였다는 점을 씁니다.
3. **글감 3(원인 나누기)**: 실습 5-2 정리의 표에서 「데이터를 고치는 곳」 · 「규칙을 고치는 곳」 · 「운영 설정을 고치는 곳」 세 줄을 옮겨 적고, 내가 쓴 상황 번호를 하나씩 그 줄에 붙입니다. 규칙 하나를 바꾸면 그 규칙을 거치는 모든 알림이 바뀐다는 점을 데이터 한 줄을 고치는 경우와 비교합니다.
4. **실행 결과 붙이기**: 터미널 출력은 전부 붙이지 않아도 됩니다. 내 말과 연결되는 두세 줄만 코드 상자(```` ``` ````)로 붙이고, 그 아래에 「이 줄에서 무엇을 보았는지」를 한 문장으로 씁니다. 화면 캡처를 쓰려면 이미지를 `assets/images/` 에 올리고 글에 연결합니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 힌트에서 붙이라고 한 줄을 붙이고, 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Module 3 Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 코드(`anomaly_detection/` 의 파일 포함)에 Gemini API 키 · 토큰 · `.env` 내용이 없다(`AIza` 로 시작하는 글자가 없다)
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터(dami, seoyeon 등)가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다
4. 머리말이 `module: 4`, `unit: 5` 이고, `sample: true` 줄이 없다

**올리기** — **[터미널]** 네 줄을 모두 「그렇다」로 답할 수 있으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..` → `python check_publish.py` → `git add .` → `git commit -m "Add module 4 unit 5 post"` → `git push` → `cd anomaly_detection`. `pwd` 가 이미 `…/network-study-notes` 로 끝나면 맨 앞 `cd ..` 는 건너뜁니다. 점검에서 `[오류]` 가 나오면 그 부분을 고치고 다시 돌린 뒤 올립니다.
