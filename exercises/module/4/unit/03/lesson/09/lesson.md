# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

하루의 마지막 40분은 오늘 만든 탐지 규칙을 내 말로 남기는 시간입니다. 글은 내 GitHub Pages 포트폴리오에 올립니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**40분은 이렇게 나눕니다**

1. 고르기 5분: 아래 글감 질문 중 하나를 고릅니다. 보고서 `report_u3.md` 에 적은 답 가운데 가장 오래 고민한 것을 고르면 쉽습니다.
2. 쓰기 25분: 글 틀을 복사해 내 답을 글로 풉니다.
3. 점검 · 올리기 10분: 공개 전 점검을 하고 GitHub 에 올린 뒤 첫 화면을 확인합니다.

**글감 질문 (실습 3-1 · 3-2)**

1. 급증으로 탐지된 09:12 의 IP 와 행동을 살펴보면, 이것만으로 공격이라고 확정할 수 있을까요? 확정하려면 무엇을 더 봐야 할까요?
2. 09:20 의 요청 3개는 급증 기준(6.0번)에 못 미쳐 탐지되지 않았습니다. 요청 수만 보는 규칙이 이 요청들을 왜 놓쳤는지 설명해 보세요.
3. dami 의 실패 4번(퇴사한 계정)과 gaeun 의 실패 3번(규칙은 허용인데 서버가 거절)은 무엇이 다른가요? 각각 먼저 무엇을 확인하겠습니까?
4. 「실패 3번 이상」 규칙 때문에 놓칠 수 있는 경우는 무엇인가요? 규칙을 어떻게 보완하겠습니까?

**선택 글감 (도전 3-1 ~ 3-3을 했다면)**

1. 로그인 실패 알림과 트래픽 급증 알림이 같은 주소의 일이었습니다. 두 알림을 한 사건으로 합쳐 조사할지, 따로 조사할지 고른 이유를 써 보세요.
2. 평소 IP 기록이 없는 사용자를 규칙에서 빼면 무엇을 얻고 무엇을 잃을까요?
3. 경로 목록(`SCANNER_PATTERN`)으로 스캔을 찾는 규칙은 목록에 없는 경로를 놓칩니다. 목록을 어떻게 관리하겠습니까?

세 문장만 써도 한 편의 글입니다. 오늘 막혀서 실습을 다 못 했다면 그 막힌 이야기도 좋은 글이 됩니다. 어디서 멈췄는지 남겨 두면 다음에 나도, 글을 읽는 사람도 도움을 받습니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Module 3 Unit 1 시작하기 레슨에서 한 것처럼 **GitHub 웹 화면**에서 파일을 만들고 붙여 넣습니다. 글 틀 세 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 나의 상황 | 고를 글 틀 |
|---|---|
| 실습 3-1 이나 3-2 하나를 글 한 편으로 쓰고 싶다 | `_templates/post-practice.md` |
| 시간이 5분밖에 없다 | `_templates/post-short.md` |
| 실습하다 막혔다 | `_templates/post-stuck.md` |

**2. 새 글 파일 만들기**

1. 내 포트폴리오 저장소에서 `_posts` 폴더를 열고 **Add file › Create new file** 을 누릅니다.
2. 파일 이름은 `날짜-영문제목.md` 모양으로 적습니다. 예: `_posts/2026-11-20-m4-u3-traffic-spike.md`
3. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit 에 맞게 고칩니다.
   ```
   module: 4
   unit: 3
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 4 의 **3번** 칸을 채웁니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다.
4. 빈칸을 채우고 **Commit changes** 를 누릅니다.

**3. 코드 올리기**

글에서 소개한 코드는 저장소의 `code/` 폴더에 올립니다. `code` 폴더에서 **Add file › Create new file** 을 누르고, 이름은 Module 과 Unit 번호가 보이게 적습니다.

- 예: `code/m4_u3_traffic_detection.py`(실습 3-1), `code/m4_u3_access_detection.py`(실습 3-2)
- 글 안에는 핵심 몇 줄만 코드 상자로 붙이고, 「전체 코드: `code/m4_u3_traffic_detection.py`」처럼 위치를 적습니다.

**4. 확인하기**

올리고 1~2분 기다린 뒤 내 사이트 첫 화면을 엽니다. 최신 글에 내 글이 보이고, 「나의 진행」의 Module 4 · 3번 칸이 채워졌으면 끝입니다. 보이지 않으면 저장소의 **Actions** 탭을 먼저 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(09:12 급증)**: 실습 3-1 출력 단계 4의 `2026-11-02 09:12:00    9` 줄을 붙이고, 그 아래에 `normalized_events.json` 에서 찾은 09:12 의 줄 두세 개(`POST /login` 실패, `GET /admin`)를 붙입니다. 「한 주소가 1분 안에 무엇을 했는가」를 순서대로 쓰면 확정할 수 없는 이유가 자연스럽게 나옵니다.
2. **글감 2(놓친 09:20)**: 단계 2의 `2026-11-02 09:20:00    3` 줄과 단계 3의 기준 `6.0` 을 나란히 붙입니다. 그 3개가 `/.env` · `/wp-login.php` · `/phpmyadmin` 이었다는 점을 더하면, 「수는 적지만 내용이 수상한 요청」을 글로 설명할 수 있습니다.
3. **글감 3(거절 이유)**: 실습 3-2 단계 3에서 `1 퇴사한 계정 dami …` 줄 하나와 `3 규칙은 허용인데 서버가 거절 gaeun …` 줄 하나를 붙입니다. 두 줄 옆에 「누가 할 일인가(계정 정리 · 서버 설정 확인)」를 적어 보면 차이가 보입니다.
4. **글감 4(3번 이상 규칙)**: seoyeon 의 11:40 `SETTLE:QUERY` 한 건을 예로 듭니다. `check_permission('seoyeon', 'SETTLE', 'QUERY')` 가 「권한 없음」인데도 한 번뿐이라 빠졌다는 점에서 시작해, 횟수 말고 무엇을 함께 보면 좋을지 씁니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 3-2 단계 2가 `0 개` 로 나왔다면, 그 출력과 내가 의심한 줄(`isin` 에 넣은 값)을 적고 `.index` 를 빠뜨린 것을 어떻게 찾았는지 씁니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

## 공개 전 점검

**Commit changes** 를 누르기 전에 한 번 더 봅니다.

1. 글과 `code/` 파일에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다
4. 머리말이 `module: 4`, `unit: 3` 이고, `sample: true` 줄이 없다
