# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

GitHub Pages 포트폴리오의 Jekyll과 GitHub Pages 설정은 끝냈나요? 끝냈다면 오늘 핵심 실습에서 확인한 문제와 해결 근거를 **세 문장 문제 해결 기록**으로 남깁니다. 아직 설정하지 않았다면 M3 Unit 1 시작하기의 [Jekyll·GitHub Pages 설정 안내](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)로 돌아가 먼저 완료한 뒤 여기로 돌아옵니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

- 실습 결과 기록 `practice_record_u3.md` 에 적은 출력에서 가장 오래 고민한 핵심 문제 하나를 고르면 쉽습니다.

**오늘의 글감 (핵심 실습)**

1. 급증으로 탐지된 09:12 의 IP 와 행동을 살펴보면, 이것만으로 공격이라고 확정할 수 있을까요? 확정하려면 무엇을 더 봐야 할까요?
2. 09:20 의 요청 3개는 급증 기준(6.0번)에 못 미쳐 탐지되지 않았습니다. 요청 수만 보는 규칙이 이 요청들을 왜 놓쳤는지 설명해 보세요.
3. dami 의 실패 4번(퇴사한 계정)과 gaeun 의 실패 3번(규칙은 허용인데 서버가 거절)은 무엇이 다른가요? 각각 먼저 무엇을 확인하겠습니까?
4. 「실패 3번 이상」 규칙은 어떤 기록을 놓칠 수 있나요? 이 기준을 쓸 때 추가로 확인할 점을 적어 보세요.

세 문장이면 충분합니다. 핵심 실습을 끝내지 못했다면 어디서 멈췄고 무엇을 확인했는지 기록해도 좋습니다.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 핵심 실습 결과 기록에서 가장 오래 고민한 판단과 이어지는 글감을 고릅니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고, 터미널에서 올립니다. 글 틀 두 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |

**2. 새 글 파일 만들기**

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-20-m4-u3-traffic-spike.md` 처럼 만듭니다(경로 `_posts/2026-11-20-m4-u3-traffic-spike.md`). 앞은 오늘 날짜, 뒤는 영문 제목입니다. 예의 `2026-11-20` 은 그대로 쓰지 않고 내가 글을 쓰는 실제 오늘 날짜로 바꿉니다. `anomaly_detection` 안이 아니라 저장소 바로 아래의 `_posts` 폴더입니다.
2. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit 에 맞게 고칩니다.
   ```
   module: 4
   unit: 3
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 4 의 **3번** 칸을 채웁니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다. 날짜가 미래면 글이 목록에 나오지 않습니다.
3. 빈칸을 채우고 저장합니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 오늘 날짜 이름(예: `_posts/2026-11-20-m4-u3-traffic-spike.md`)으로 글 파일을 만들고 글 틀을 붙여 넣었다
- [ ] 머리말을 `module: 4` · `unit: 3`, 내 `title` · `date` 로 고치고 세 칸을 채워 저장했다
<!-- /checklist -->

**3. 코드 위치 적기**

코드는 따로 옮기지 않습니다. 오늘 만든 `anomaly_detection/traffic_detection.py`(실습 3-1) · `anomaly_detection/access_detection.py`(실습 3-2) 파일이 같은 저장소 안에 있으니, 글 안에는 핵심 몇 줄만 코드 상자로 붙이고 「전체 코드: `anomaly_detection/traffic_detection.py`」처럼 위치만 적습니다.

올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 맨 위 머리말에 `module: 4` · `unit: 3` 두 줄이 있으면 성공입니다. 없으면 1번에서 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(09:12 급증)**: 실습 3-1 출력 단계 4의 `2026-11-02 09:12:00    9` 줄을 붙이고, 그 아래에 `normalized_events.json` 에서 찾은 09:12 의 줄 두세 개(`POST /login` 실패, `GET /admin`)를 붙입니다. 「한 주소가 1분 안에 무엇을 했는가」를 순서대로 쓰면 확정할 수 없는 이유가 자연스럽게 나옵니다.
2. **글감 2(놓친 09:20)**: 단계 2의 `2026-11-02 09:20:00    3` 줄과 단계 3의 기준 `6.0` 을 나란히 붙입니다. 그 3개가 `/.env` · `/wp-login.php` · `/phpmyadmin` 이었다는 점을 더하면, 「수는 적지만 내용이 수상한 요청」을 글로 설명할 수 있습니다.
3. **글감 3(거절 이유)**: 실습 3-2 단계 3에서 `1 퇴사한 계정 dami …` 줄 하나와 `3 규칙은 허용인데 서버가 거절 gaeun …` 줄 하나를 붙입니다. 두 줄 옆에 「누가 할 일인가(계정 정리 · 서버 설정 확인)」를 적어 보면 차이가 보입니다.
4. **글감 4(3번 이상 규칙)**: seoyeon 의 11:40 `SETTLE:QUERY` 한 건을 예로 듭니다. `check_permission('seoyeon', 'SETTLE', 'QUERY')` 가 「권한 없음」인데도 한 번뿐이라 빠졌다는 점에서 시작해, 횟수 말고 무엇을 함께 보면 좋을지 씁니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 3-2 단계 2가 `0 개` 로 나왔다면, 그 출력과 내가 의심한 줄(빈칸 ① 의 `.index`)을 적고 그것을 어떻게 찾았는지 씁니다.
6. 무엇부터 쓸지 모르겠으면 실습 결과 기록의 출력과 판단 근거를 확인한 뒤, 글 틀의 「무엇을 확인했고 어떻게 판단했나」 칸에 씁니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 힌트에서 고른 글감의 출력 줄을 붙이고 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Module 3 Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 코드(`anomaly_detection/` 의 파일 포함)에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다
4. 머리말이 `module: 4`, `unit: 3` 이고, `sample: true` 줄이 없다

**올리기** — **[터미널]** 네 줄을 모두 「그렇다」로 답할 수 있으면 저장소 루트(`network-study-notes`)에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더 `anomaly_detection` 으로 돌아옵니다. `pwd` 가 이미 `…/network-study-notes` 로 끝나면 맨 앞 `cd ..` 는 건너뜁니다.

```bash
cd ..
python check_publish.py
```

- 명령 풀이: `cd ..` 한 단계 위 폴더(`network-study-notes`)로 이동 · `python check_publish.py` 공개 전 점검 스크립트 실행
- 점검에서 `[오류]` 가 나오면 그 부분을 고치고 다시 돌립니다. `오류 0건` 이 나오면 올립니다.

```bash
git add .
git commit -m "Add module 4 unit 3 post"
git push
cd anomaly_detection
```

- 명령 풀이: `git add .` 바뀐 파일을 담음 · `git commit -m "…"` 기록으로 저장 · `git push` 깃허브로 올림 · `cd anomaly_detection` 작업 폴더로 돌아옴
