# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 만든 승인 게이트와 오탐 되돌리기를 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 보고서는 질문에 답하는 파일이고, 이 글은 그 답 가운데 하나를 내 말로 풀어 쓰는 기록입니다. 글은 내 GitHub Pages 포트폴리오에 올립니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검 · 올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

글감은 보고서 `report_u4.md` 에 적은 답 가운데 가장 오래 고민한 것을 고르면 쉽습니다.

**오늘의 글감 (핵심 실습)**

1. `REQ-1`(`dami`)과 `REQ-6`(`minsu`)은 둘 다 high 등급의 계정 잠금인데 결정이 달랐습니다. 대상 수(영향 범위)를 점수에 넣지 않았다면 어떤 일이 생길 수 있었을까요?
2. 승인 게이트는 허용 목록을 점수보다 먼저 보고, 기준 점수는 코드가 아니라 설정 파일에 둡니다. 두 결정이 각각 어떤 실수를 막아 주나요?
3. 오탐 신고를 받았을 때 롤백 함수만 실행하고 끝내면 무엇을 놓칠까요? 영향 확인 · 복구 확인 · 규칙 조정 제안이 각각 무엇을 막는지 내 출력으로 설명해 보세요.
4. `jiwoo` 의 세션 종료는 되돌릴 수 없었습니다. 되돌릴 수 없는 조치가 섞여 있을 때 담당자는 무엇을 더 해야 할까요?

**선택 글감 (응용을 했다면)**

1. 응용 4-1: 상태가 바뀐 티켓은 이후 점검에서 에스컬레이션되지 않았습니다. 그 조건이 없으면 어떤 문제가 생길까요? 같은 점검에서 티켓마다 올림 단계가 달랐던 이유도 응답 기한과 초과 시간으로 설명해 보세요.
2. 응용 4-3: 리포트에서 low 등급이 빠진 이유는 무엇인가요? 리포트에 「티켓이 없는 조치」 절이 없으면 고객사가 받는 리포트에서 어떤 사건이 빠질까요?
3. 응용 4-4: 점수가 같은데 세션 종료만 통제 갭이 있었습니다. 설정을 근거로 이유를 적고, 예방 통제(승인 게이트)와 탐지 통제(감사 기록)를 비교해 보세요.

세 문장이면 충분합니다. 오늘 막혀서 실습을 다 못 했다면 그 막힌 이야기도 좋은 글이 됩니다. 어디서 멈췄는지 남겨 두면 다음에 나도, 글을 읽는 사람도 도움을 받습니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 보고서 `report_u4.md` 에서 가장 오래 고민한 칸과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Module 3 Unit 1 시작하기 레슨에서 한 것처럼 **GitHub 웹 화면**에서 파일을 만들고 붙여 넣습니다. 글 틀 세 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `_templates/post-practice.md` |

**2. 새 글 파일 만들기**

1. 내 포트폴리오 저장소에서 `_posts` 폴더를 열고 **Add file › Create new file** 을 누릅니다.
2. 파일 이름은 `날짜-영문제목.md` 모양으로 적습니다. 예: `_posts/2026-11-20-m5-u4-approval-gate.md`
3. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit 에 맞게 고칩니다.
   ```
   module: 5
   unit: 4
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 5 의 **4번** 칸을 채웁니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다.
4. 빈칸을 채우고 **Commit changes** 를 누릅니다.

**3. 코드 올리기**

글에서 소개한 코드는 저장소의 `code/` 폴더에 올립니다. `code` 폴더에서 **Add file › Create new file** 을 누르고, 이름은 Unit 번호가 보이게 적습니다.

- 예: `code/m5_u4_approval_gate.py`(실습 4-1), `code/m5_u4_false_positive.py`(실습 4-2)
- 글 안에는 핵심 몇 줄만 코드 상자로 붙이고, 「전체 코드: `code/m5_u4_approval_gate.py`」처럼 위치를 적습니다.

**4. 확인하기**

올리고 1~2분 기다린 뒤 내 사이트 첫 화면을 엽니다.

> **확인** — 최신 글에 오늘 글이 보이고 「나의 진행」의 Module 5 · 4번 칸이 채워지면 성공입니다. 안 보이면 저장소의 **Actions** 탭을 먼저 보고, 머리말의 `date` 가 미래 날짜인지 확인합니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(영향 범위)**: 실습 4-1 출력 단계 2 에서 `REQ-1` 줄(`합계 2점`)과 `REQ-6` 줄(`대상 6개 +2, 합계 4점`)을 나란히 붙입니다. 두 줄의 차이가 `대상 6개 +2` 하나뿐이라는 것부터 쓰고, 계정 6개가 한꺼번에 잘못 잠기면 누가 곤란해지는지 이어서 씁니다.
2. **글감 2(허용 목록과 설정 파일)**: `decide_gate` 의 첫 두 줄(`if is_allowlisted(request, policy):` 와 그 아래 `return`)을 붙이고, `REQ-3` 이 점수로만 정해졌다면 몇 점이 되어 어떤 결정이 나왔을지 씁니다. 설정 파일 이야기는 `config/approval_policy.json` 의 `"approval_score": 3` 한 줄을 붙이고, 이 숫자를 4로 바꾸면 `REQ-5`(3점)가 어떻게 되는지 적으면 됩니다.
3. **글감 3(롤백만 하면 놓치는 것)**: 실습 4-2 출력에서 `[INC-301]` 의 다섯 줄을 붙이고, 줄마다 「이 줄이 없으면 무엇을 모르게 되는가」를 한 문장씩 답합니다. 영향 확인 줄에 `198.51.100.120` 이 없는 이유도 함께 쓰면 좋습니다.
4. **실행 결과 붙이기**: 터미널 출력은 전부 붙이지 않아도 됩니다. 내 말과 연결되는 두세 줄만 코드 상자(```` ``` ````)로 붙이고, 그 아래에 「이 줄에서 무엇을 보았는지」를 한 문장으로 씁니다. 화면 캡처를 쓰려면 이미지를 `assets/images/` 에 올리고 글에 연결합니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 4-2 에서 `IndentationError: expected an indented block after 'if' statement` 가 나왔다면, 그 오류와 내가 의심한 줄(② 의 `changes.append(record)` 와 그 들여쓰기)을 적고 어떻게 찾았는지 씁니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 힌트에서 붙이라고 한 출력 줄을 붙이고, 그 줄에서 본 것을 한 문장으로 씁니다.

## 공개 전 점검

**Commit changes** 를 누르기 전에 한 번 더 봅니다.

1. 글과 `code/` 파일에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다
4. 머리말이 `module: 5`, `unit: 4` 이고, `sample: true` 줄이 없다

> **확인** — 네 줄을 모두 「그렇다」로 답할 수 있으면 성공입니다. 하나라도 걸리면 그 부분을 지우거나 고친 뒤 다시 **Commit changes** 합니다.
