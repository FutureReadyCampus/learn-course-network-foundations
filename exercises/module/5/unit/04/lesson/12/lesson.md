# 문제 해결 기록을 포트폴리오에 남기기

## 승인 기준과 복구 판단을 글로 남기기

핵심 실습에서 가장 고민했던 결정 하나를 골라 포트폴리오에 세 문장으로 남깁니다. 실행 출력과 상태는 `report_u4.md` 에 보관하고, 이 글에는 문제를 어떻게 이해하고 판단했는지 씁니다. 아직 GitHub Pages 블로그를 준비하지 않았다면 [M3 Unit 1의 Jekyll·GitHub Pages 설정 안내](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)를 먼저 따라 합니다.

글감은 핵심 실습에서 하나 고릅니다.

1. 위험 점수와 대상 수를 함께 사용해 요청을 자동 · 승인 필요 · 차단 금지로 분류한 기준
2. 신고자의 정보만으로 계정을 복구하지 않고, 기록과 신고자 권한을 확인한 이유
3. 복구 시간이 기준을 넘거나 되돌릴 수 없는 조치가 남았을 때 담당자에게 전달할 내용

세 문장은 다음 순서로 씁니다.

1. 어떤 문제를 보았고, 출력이나 기록에서 무엇을 확인했는가?
2. 어떤 조건이나 대응을 선택했으며, 근거는 무엇이었는가?
3. 결과가 어떻게 달라졌고, 운영에서 다음에 무엇을 확인해야 하는가?

<!-- checklist -->
- [ ] 핵심 실습 하나를 골라 문제 · 판단 근거 · 결과를 세 문장으로 적었다
<!-- /checklist -->

틀이 필요하면 M3 Unit 1의 [글 틀 안내](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에서 `post-short` 또는 `post-stuck` 을 고릅니다.

**게시할 글 예시**

- 제목은 **자동 조치 전에 위험 점수와 영향 범위를 확인한 이유**로 쓸 수 있습니다.
- 예시 파일은 `_posts/YYYY-MM-DD-approval-impact.md`입니다. `YYYY-MM-DD`를 작성일로 바꿉니다.
- [실습 4-1 · 위험 점수로 조치 요청 분류하기](__SITE__/exercises/module/5/unit/4/lesson/2/page/3)에서 코드와 출력 위치를 찾습니다.

> 실습에서 한 IP를 여러 계정이 함께 쓰는 조치 요청을 확인했다. 영향이 큰 요청을 조치 전에 걸러 내도록 허용 목록과 대상 수를 확인하고 위험 점수를 계산했다. 실습 요청 여덟 건이 자동 3건, 승인 필요 3건, 차단 금지 2건으로 분류된 것을 확인했다.

위 문장은 교재의 실습 예시입니다. 내 실행에서 같은 결과를 확인했다면 내 말로 써 봅니다. 실행 결과가 다르거나 막혔다면 내 실제 출력과 다음에 확인할 내용을 적습니다.

<!-- /checklist -->

## 글을 저장하고 올리기

1. **[VS Code]** 저장소 `network-study-notes`의 `_posts/`에 `YYYY-MM-DD-approval-impact.md`처럼 새 파일을 만들고 `YYYY-MM-DD`를 작성일로 바꿉니다. 이미 게시한 글은 기존 주소를 유지하도록 파일명과 `date`를 그대로 두고 내용을 고칩니다.
2. 글 틀을 붙여 넣고 머리말의 `title`에 글 제목을, `date`에 파일명의 날짜를 적습니다.
3. 내 문제, 고른 기준과 이유, 확인한 결과를 세 문장으로 적고 저장합니다.

**코드와 실행 근거 연결하기**

1. 글에 내 실행 결과 한 줄과 그 줄로 확인한 내용을 적습니다. 예시 글은 `자동 : 3 건`, `승인 필요 : 3 건`, `차단 금지 : 2 건` 세 줄에서 분류 결과를 확인했습니다.
2. 코드는 `soar_response/`에 둡니다. 아래 한 줄을 복사해 글 본문에 붙이면 Pages가 내 사이트 주소에 맞게 코드 링크를 만듭니다. 다른 글감을 골랐다면 링크의 `approval_gate.py`를 `false_positive.py` 등 내 글에 해당하는 파일명으로 바꿉니다.
3. 공개해도 되는 기술 기록을 연결하려면 내 GitHub 저장소에서 `soar_response/report_u4.md`를 열고 그 주소를 붙입니다. 글을 올린 뒤 링크를 직접 열어 확인합니다.

**게시하기**

1. 저장소 루트에서 공개 전 점검을 실행하고 올립니다. 글과 코드·로그·캡처에 비밀키, `.env`, 토큰, 실제 사람의 개인정보나 회사 자료가 없는지 먼저 확인합니다. 점검에서 발견한 항목을 검토하고 수정한 뒤 `git status`를 봅니다.

   ```bash
   python check_publish.py
   git status
   git add _posts/오늘-만든-파일.md
   git commit -m "Add M5 Unit 4 problem-solving record"
   git push
   ```

2. 사이트에서 새 글을 열고 내 실행 결과를 봅니다. 브라우저의 비공개 창에서도 근거 링크가 열리는지 확인합니다.
