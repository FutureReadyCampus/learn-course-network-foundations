# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 한 되돌리기와 티켓 만들기를 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 보고서는 질문에 답하는 파일이고, 이 글은 그 답 가운데 하나를 내 말로 풀어 쓰는 기록입니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

글감은 보고서 `report_u3.md` 에 적은 답 가운데 가장 오래 고민한 것을 고르면 쉽습니다.

**오늘의 글감 (핵심 실습)**

1. 실습 3-1에서 `junho` 의 계정은 되돌린 뒤에도 잠겨 있었습니다. 왜 그랬나요? 되돌림 조건(조치 전과 후가 같으면 되돌리지 않는다)이 없었다면 어떤 일이 생겼을까요?
2. 조치를 되돌릴 수 있도록 기록에 `before`(조치 전)와 `after`(조치 후)를 남겼습니다. 이 기록이 없었다면 오탐을 어떻게 되돌렸을까요? 세션 종료처럼 되돌릴 수 없는 조치는 왜 따로 남겨야 할까요?
3. 실습 3-2에서 티켓마다 등급별로 다른 응답 기한을 적었습니다. 모든 티켓에 같은 응답 기한을 적용하면 어떤 문제가 생기나요? `INC-207` 처럼 조치 확인에 실패한 건을 따로 표시하지 않으면 담당자가 무엇을 놓칠까요?

**선택 글감 (응용을 했다면)**

1. 응용 3-2를 했다면: 같은 사건의 알림이 기존 티켓에 병합된 경우(`INC-210`)와 새 티켓이 생긴 경우(`INC-211`)는 무엇이 달랐나요? 티켓의 마지막 갱신 시각을 근거로 써 보세요.
2. 응용 3-3을 했다면: 같은 티켓에 30분 간격을 두고 알림을 보냈습니다. 간격 없이 알림이 올 때마다 보냈다면 담당자에게 어떤 일이 생겼을까요?

세 문장이면 충분합니다. 막혀서 끝내지 못한 이야기도 좋은 글입니다. 어디까지 해 봤고 어디서 멈췄는지를 적어 두면, 다음에 다시 볼 때 가장 쓸모 있는 기록이 됩니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 「보고서 쓰기」에서 가장 오래 고민한 질문과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고, 터미널에서 올립니다. 글 틀 세 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `post-short` |
| 막혀서 끝내지 못했다 | `post-stuck` |
| 응용: 여유가 있어 긴 글을 쓴다 | `post-practice` |

글 틀은 저장소에 파일로 없어도 됩니다. 위에 링크한 「글 틀로 글 쓰기」 페이지에서 고른 글 틀의 상자를 복사해 씁니다.

**2. 새 글 파일 만들기**

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-20-m5-u3-rollback-ticket.md` 처럼 만듭니다(경로 `_posts/2026-11-20-m5-u3-rollback-ticket.md`). 앞은 오늘 날짜, 뒤는 영문 제목입니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 오늘 날짜 이름(예: `_posts/2026-11-20-m5-u3-rollback-ticket.md`)으로 글 파일을 만들었다
<!-- /checklist -->

2. 링크한 페이지에서 고른 글 틀(예: `post-short`) 상자를 복사해 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit 에 맞게 고칩니다.
   ```
   module: 5
   unit: 3
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 5 의 **3번** 칸을 채웁니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다.
3. 빈칸을 채우고 저장합니다. 올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

<!-- checklist -->
- [ ] 글 틀을 붙여 넣고 머리말을 `module: 5` · `unit: 3` 과 내 `title` · `date` 로 고친 뒤 세 칸을 채워 저장했다
<!-- /checklist -->

**3. 코드 위치 적기**

코드는 따로 옮기지 않습니다. 오늘 만든 `soar_response/rollback.py`(실습 3-1) · `soar_response/ticketing.py`(실습 3-2) 가 같은 저장소에 이미 올라가 있습니다.

- 글 안에는 핵심 몇 줄만 코드 상자로 붙이고, 「전체 코드: `soar_response/rollback.py`」처럼 위치만 적습니다.

**4. 확인하기**

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 맨 위 머리말에 `module: 5` · `unit: 3` 이 있으면 성공입니다. 없으면 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(잠겨 있는 `junho`)**: `should_undo` 에 직접 쓴 ① · ② 두 줄(`if record["before"] == record["after"]:` 와 `return False`)을 글에 붙입니다. 그다음 `containment_log.json` 에서 `junho` 의 계정 잠금 기록(`잠김 → 잠김`) 한 건과 실습 3-1 출력 단계 5의 `잠긴 계정: ['junho']` 줄을 나란히 붙이고, 두 값이 어떻게 이어지는지 씁니다.
2. **글감 2(`before` · `after` 기록)**: `dami` 의 기록 두 건(계정 잠금 `잠기지 않음 → 잠김`, 세션 종료 `세션 2개 → 세션 0개`)을 붙입니다. 실습 3-1 단계 2에서 하나는 `계정 해제` 가 되고 하나는 `되돌리기 불가` 가 된 이유부터 쓰면 글의 절반이 됩니다.
3. **글감 3(응답 기한과 직접 확인)**: 실습 3-2 출력의 TCK-1(기한 15분) · TCK-2(기한 243분) 줄을 붙이고, 내가 쓴 ② `sla_due = alert["minute"] + sla_minutes` 한 줄로 두 숫자가 어떻게 나왔는지 풉니다. 단계 4의 TCK-7 줄을 덧붙이면 확인 실패 이야기로 이어집니다.
4. **실행 결과 붙이기**: 터미널 출력은 전부 붙이지 않아도 됩니다. 내 말과 연결되는 두세 줄만 코드 상자(```` ``` ````)로 붙이고, 그 아래에 「이 줄에서 무엇을 보았는지」를 한 문장으로 씁니다. 화면 캡처를 쓰려면 이미지를 `assets/images/` 폴더에 넣고 글에 연결합니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 3-1에서 채운 뒤에도 단계 3 에 `junho` 의 `계정 해제` 가 나왔다면, 그 출력과 내가 의심한 줄(`should_undo` 의 ① · ②)을 적고 어떻게 찾았는지 씁니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 힌트의 붙일 줄을 붙이고 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

올리기 전에 한 번 더 봅니다.

1. 글과 `soar_response/` 의 파일에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다
4. 머리말이 `module: 5`, `unit: 3` 이고, `sample: true` 줄이 없다

**올리기** — **[터미널]** 네 줄을 모두 「그렇다」으로 답할 수 있으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..` → `python check_publish.py` → `git add .` → `git commit -m "Add module 5 unit 3 post"` → `git push` → `cd soar_response`. 터미널이 이미 `network-study-notes` 에 있으면 `cd ..` 는 건너뜁니다. 점검에서 `[오류]` 가 나오면 그 부분을 지우고 다시 돌린 뒤 올립니다.
