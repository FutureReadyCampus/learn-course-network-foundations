# 문제 해결 기록을 포트폴리오에 남기기

## 핵심 실습에서 내린 판단을 글로 남기기

오늘 한 핵심 실습에서 가장 고민했던 판단 하나를 골라, 포트폴리오에 세 문장으로 남깁니다. 실행 출력과 파일 목록은 `report_u3.md` 에 보관하고, 이 글에는 문제를 어떻게 이해하고 해결했는지 기록합니다. 아직 포트폴리오가 없다면 [M3 Unit 1 시작하기의 「자기소개 두 문장으로 시작하기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 설정합니다.

아래 중 하나를 골라 씁니다.

1. 실습 3-1에서 `before` 와 `after` 를 비교해 조치 전부터 잠겨 있던 `junho` 계정을 그대로 둔 이유
2. 자동 조치로 생긴 상태만 되돌리고, 세션 종료는 사람이 이어서 확인하도록 남긴 이유
3. 실습 3-2의 응답 기한과 직접 확인 표시가 담당자에게 알려 주는 것

세 문장은 다음 순서로 씁니다.

1. 어떤 문제가 있었고, 출력에서 무엇을 확인했는가?
2. 어떤 조건이나 구현을 선택했으며, 근거는 무엇이었는가?
3. 결과가 어떻게 달라졌고, 실제 업무에서 무엇을 확인해야 하는가?

틀을 고르는 데 막히면 M3 Unit 1의 [글 틀 안내](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에서 `post-short` 또는 `post-stuck`을 씁니다.

**게시할 글 예시**

- 제목은 **자동 조치만 되돌리고 기존 잠금은 유지한 이유**로 쓸 수 있습니다.
- 예시 파일은 `_posts/YYYY-MM-DD-keep-existing-locks.md`입니다. `YYYY-MM-DD`를 작성일로 바꿉니다.
- [실습 3-1 · 기록을 보고 자동이 바꾼 것만 되돌리기](__SITE__/exercises/module/5/unit/3/lesson/2/page/3)에서 코드와 출력 위치를 찾습니다.

> 오탐을 처리하는 실습에서 자동 조치 전부터 잠겨 있던 계정을 찾았다. 기존 잠금을 유지하기 위해 기록의 `before`와 `after`가 같은 계정은 복구 대상에서 뺐다. 재실행 결과에서 기존 계정 잠금이 유지됐고, 종료된 세션은 복구 불가로 기록됐다.

위 문장은 교재의 실습 예시입니다. 내 실행에서 같은 결과를 확인했다면 내 말로 써 봅니다. 실행 결과가 다르거나 막혔다면 내 실제 출력과 다음에 확인할 내용을 적습니다.

## 글을 저장하고 올리기

1. **[VS Code]** 저장소 `network-study-notes`의 `_posts/`에 `YYYY-MM-DD-keep-existing-locks.md`처럼 새 파일을 만들고 `YYYY-MM-DD`를 작성일로 바꿉니다. 이미 게시한 글은 기존 주소를 유지하도록 파일명과 `date`를 그대로 두고 내용을 고칩니다.
2. 글 틀을 붙여 넣고 머리말의 `title`에 글 제목을, `date`에 파일명의 날짜를 적습니다.
3. 내 문제, 고른 기준과 이유, 확인한 결과를 세 문장으로 적고 저장합니다.

**코드와 실행 근거 연결하기**

1. 글에 내 실행 결과 한 줄과 그 줄로 확인한 내용을 적습니다. 예시 글의 근거는 `잠긴 계정: ['junho']`입니다.
2. 코드는 `soar_response/`에 둡니다. 아래 한 줄을 복사해 글 본문에 붙이면 Pages가 내 사이트 주소에 맞게 코드 링크를 만듭니다. 다른 글감을 골랐다면 링크의 `rollback.py`를 `ticketing.py` 등 내 글에 해당하는 파일명으로 바꿉니다.
3. 공개해도 되는 기술 기록을 연결하려면 내 GitHub 저장소에서 `soar_response/report_u3.md`를 열고 그 주소를 붙입니다. 글을 올린 뒤 링크를 직접 열어 확인합니다.

**게시하기**

1. `network-study-notes` 저장소 루트에서 공개 전 점검을 실행하고 올립니다. 글과 코드·로그·캡처에 비밀키, `.env`, 토큰, 실제 사람의 개인정보나 회사 자료가 없는지 먼저 확인합니다. 점검에서 발견한 항목을 검토하고 수정한 뒤 `git status`를 봅니다.

   ```bash
   python check_publish.py
   git status
   git add _posts/오늘-만든-파일.md
   git commit -m "Add M5 Unit 3 problem-solving record"
   git push
   ```

2. 사이트에서 새 글을 열고 내 실행 결과를 봅니다. 브라우저의 비공개 창에서도 근거 링크가 열리는지 확인합니다.
