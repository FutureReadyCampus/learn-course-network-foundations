# 문제 해결 기록을 포트폴리오에 남기기

## 오늘 쓸 글 고르기

핵심 실습에서 발견한 문제, 선택한 봉쇄 방법과 검증 결과를 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. `report_u2.md` 에는 확인한 출력과 기술적 근거를 기록하고, 이 글에는 문제를 어떻게 이해하고 해결했는지와 다음에 개선할 점을 씁니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「자기소개 두 문장으로 시작하기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

글감은 `report_u2.md` 에 기록한 핵심 실습 결과 가운데 가장 오래 고민한 문제에서 고릅니다.

**오늘의 글감 (핵심 실습)**

1. VIP 계정 `gaeun` 은 잠기지 않았습니다. 경로 정하기에서 이미 `승인 필요` 로 걸렀는데도 조치 함수(`check_policy`)가 정책을 한 번 더 검사하는 이유는 무엇인가요?
2. 계정을 잠갔는데도 `dami` 의 세션 두 개가 남아 있었습니다. 잠금만으로 부족한 이유와, 잠금이 확인된 계정만 세션을 끊게 한 이유를 써 보세요.
3. 계정 잠금, IP 차단, 세션 종료 중 잘못 실행했을 때 가장 피해가 큰 것은 무엇이라고 보나요? 이유를 써 보세요.

세 문장이면 충분합니다. 막혀서 끝내지 못한 이야기도 좋은 글입니다. 어디까지 해 봤고 어디서 멈췄는지를 적어 두면, 다음에 다시 볼 때 가장 쓸모 있는 기록이 됩니다. 세 문장으로 해결 과정과 배운 점을 명확히 남기면 충분합니다.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 핵심 실습에서 가장 오래 고민한 문제를 고릅니다.

**게시할 글 예시**

- 제목은 **계정을 잠근 뒤에도 열린 세션을 확인한 이유**로 쓸 수 있습니다.
- 예시 파일은 `_posts/YYYY-MM-DD-verify-open-sessions.md`입니다. `YYYY-MM-DD`를 작성일로 바꿉니다.
- [실습 2-2 · 활성 세션 종료와 잔존 세션 점검하기](__SITE__/exercises/module/5/unit/2/lesson/4/page/3)에서 코드와 출력 위치를 찾습니다.

> 실습의 첫 점검에서 이미 잠긴 계정에 열린 세션이 남은 것을 확인했다. 새 로그인을 막은 뒤에도 기존 세션이 열려 있을 수 있어 잠금 확인, 세션 종료, 재점검 순서로 처리했다. 다시 실행한 실습에서 ‘빈틈이 남은 계정: []’을 확인했다.

위 문장은 교재의 실습 예시입니다. 내 실행에서 같은 결과를 확인했다면 내 말로 써 봅니다. 실행 결과가 다르거나 막혔다면 내 실제 출력과 다음에 확인할 내용을 적습니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고, 터미널에서 올립니다. 글 틀을 복사하는 방법은 [시작하기 레슨의 「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)를 봅니다.

**1. 글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |

**2. 새 글 파일 만들기**

1. **[VS Code]** 저장소 `network-study-notes`의 `_posts/`에 `YYYY-MM-DD-verify-open-sessions.md`처럼 새 파일을 만들고 `YYYY-MM-DD`를 작성일로 바꿉니다. 이미 게시한 글은 기존 주소를 유지하도록 파일명과 `date`를 그대로 두고 내용을 고칩니다.
2. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)의 `title`에 한 줄 제목을, `date`에 파일명에 쓴 날짜를 적습니다. 날짜가 미래면 글이 목록에 나오지 않습니다.
3. 내 문제, 고른 방법과 이유, 확인한 결과를 세 문장으로 적고 저장합니다. 올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 작성일로 시작하는 이름(예: `_posts/YYYY-MM-DD-verify-open-sessions.md`)으로 새 글을 만들었거나, 기존 글의 파일명과 날짜를 유지했다
- [ ] 머리말을 내 글의 `title` · `date` 로 고치고 문제, 판단 이유, 확인한 결과를 적고 저장했다
<!-- /checklist -->

**코드와 실행 근거 연결하기**

1. 글에 내 실행 결과 한 줄과 그 줄로 확인한 내용을 적습니다. 예시 글의 근거는 `빈틈이 남은 계정: []`입니다.
2. 코드는 `soar_response/`에 둡니다. 아래 한 줄을 복사해 글 본문에 붙이면 Pages가 내 사이트 주소에 맞게 코드 링크를 만듭니다. 다른 글감을 골랐다면 링크의 `containment.py`를 `account_actions.py` 등 내 글에 해당하는 파일명으로 바꿉니다.
3. 공개해도 되는 기술 기록을 연결하려면 내 GitHub 저장소에서 `soar_response/report_u2.md`를 열고 그 주소를 붙입니다. 글을 올린 뒤 링크를 직접 열어 확인합니다.

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 머리말에 내 글의 제목과 작성일이 있으면 성공입니다. 없으면 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

고른 글감에 따라 아래 줄을 그대로 붙이고 이어 씁니다.

| 고른 글감 | 붙일 줄 | 이어 쓸 것 |
|---|---|---|
| 글감 1(VIP) | `check_policy` 의 `if user in vip_accounts:` 두 줄, 단계 2 의 INC-003 줄 | 경로 설정이 틀린 경우와 `lock_account` 를 바로 부른 경우로 나눠 한 문장씩 |
| 글감 2(세션) | 실습 2-2 단계 1 의 `['junho']`, 단계 2 의 `dami` 두 줄 | 잠금만 했다면 `S-101` · `S-102` 로 할 수 있었던 일 |
| 글감 3(피해) | 세 조치 × 「누가 못 쓰나 · 되돌릴 수 있나」 작은 표 | 공유 IP `192.0.2.41`(`junho` · `hana`) 같은 오늘 데이터를 예로 |

1. 실행 결과는 출력 전체를 붙이지 않아도 됩니다. 내 말과 연결되는 두세 줄만 코드 상자(```` ``` ````)로 붙이고, 그 아래에 「이 줄에서 무엇을 보았는지」를 한 문장으로 씁니다.
2. 막힌 이야기를 쓸 때는 `post-stuck.md` 초안에서 증상을 적는 곳에 내 출력을 그대로 붙입니다. 예를 들어 실습 2-1 에서 `dami` 가 `잠기지 않음 (확인 실패)` 로 나왔다면, 그 줄과 내가 의심한 곳(② `verify_locked` 의 `return` 인지, ③ 잠그는 `append` 인지)을 적고 어떻게 찾았는지 씁니다.
3. 어디서부터 쓸지 막혔다면 `report_u2.md`에서 직접 확인한 출력 한 줄을 먼저 골라 보세요. 그 출력으로 확인한 결과를 적고, 그 결과에 이르게 된 문제와 판단을 앞에 씁니다.

**AI 도우미**

코드 설명 정리, 초안 다듬기, 내 글 점검에 쓰는 프롬프트 세 가지는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

> **확인** — 글에서 실습의 문제, 내가 선택한 방법과 이유, 실행 결과를 읽을 수 있으면 성공입니다. 결과를 설명하기 어렵다면 위 표에서 근거가 될 줄을 골라 무엇을 봤는지 한 문장으로 씁니다.

## 공개 전 점검

올리기 전에 한 번 더 봅니다. 자세한 점검 방법은 [시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 `soar_response/` 의 파일에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다
4. 글 제목이 내용을 드러내고 작성일이 파일명의 날짜와 같다

**올리기** — **[터미널]** 네 줄을 모두 「맞음」으로 답할 수 있으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..` → `python check_publish.py` → `git add .` → `git commit -m "Add module 5 unit 2 post"` → `git push` → `cd soar_response`. 터미널이 이미 `network-study-notes` 에 있으면 `cd ..` 는 건너뜁니다. 점검에서 `[오류]` 가 나오면 그 부분을 지우고 다시 돌린 뒤 올립니다.
