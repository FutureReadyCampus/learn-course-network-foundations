# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 한 봉쇄 조치와 그때 한 고민을 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 보고서는 질문에 답하는 파일이고, 이 글은 그 답 가운데 하나를 내 말로 풀어 쓰는 기록입니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

글감은 보고서 `report_u2.md` 에 적은 답 가운데 가장 오래 고민한 것을 고르면 쉽습니다.

**오늘의 글감 (핵심 실습)**

1. VIP 계정 `gaeun` 은 잠기지 않았습니다. 경로 정하기에서 이미 `승인 필요` 로 걸렀는데도 조치 함수(`check_policy`)가 정책을 한 번 더 검사하는 이유는 무엇인가요?
2. 계정을 잠갔는데도 `dami` 의 세션 두 개가 남아 있었습니다. 잠금만으로 부족한 이유와, 잠금이 확인된 계정만 세션을 끊게 한 이유를 써 보세요.
3. 계정 잠금, IP 차단, 세션 종료 중 잘못 실행했을 때 가장 피해가 큰 것은 무엇이라고 보나요? 이유를 써 보세요.

**선택 글감 (응용을 했다면)**

1. 응용 2-1을 했다면: 결정이 「승인」인데 실행되지 않은 알림(INC-005)은 왜 그랬나요? 권한 확인이 없으면 어떤 위험이 생길까요?
2. 응용 2-2를 했다면: 실패했을 때 재시도 횟수를 3번으로 정한 이유는 무엇인가요? 끝없이 다시 시도하면 무엇이 위험할까요?

세 문장이면 충분합니다. 막혀서 끝내지 못한 이야기도 좋은 글입니다. 어디까지 해 봤고 어디서 멈췄는지를 적어 두면, 다음에 다시 볼 때 가장 쓸모 있는 기록이 됩니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 「보고서 쓰기」에서 가장 오래 고민한 질문과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고, 터미널에서 올립니다. 글 틀을 복사하는 방법은 [시작하기 레슨의 「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)를 봅니다.

**1. 글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `_templates/post-practice.md` |

**2. 새 글 파일 만들기**

1. **[VS Code]** 왼쪽 목록의 `network-study-notes` 안 `_posts` 폴더를 오른쪽 클릭 › **New File** 로 `2026-11-20-m5-u2-account-lockout.md` 처럼 만듭니다(경로 `_posts/2026-11-20-m5-u2-account-lockout.md`). 앞은 오늘 날짜, 뒤는 영문 제목입니다.
2. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit 에 맞게 고칩니다.
   ```
   module: 5
   unit: 2
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 5 의 **2번** 칸을 채웁니다. 글 틀의 `unit:` 숫자는 예시이니 꼭 `2` 로 바꿉니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다. 날짜가 미래면 글이 목록에 나오지 않습니다.
3. 빈칸을 채우고 저장합니다. 올리기는 이 레슨 마지막 페이지 「공개 전 점검」을 마친 뒤 그 페이지에서 합니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 오늘 날짜 이름(예: `_posts/2026-11-20-m5-u2-account-lockout.md`)으로 글 파일을 만들고 글 틀을 붙여 넣었다
- [ ] 머리말을 `module: 5` · `unit: 2` 와 내 `title` · `date` 로 고치고 세 칸을 채워 저장했다
<!-- /checklist -->

**3. 코드 위치 적기**

코드는 따로 옮기지 않습니다. 오늘 만든 `soar_response/account_actions.py`(실습 2-1) · `soar_response/containment.py`(실습 2-2) 가 같은 저장소에 이미 올라가 있습니다.

- 글 안에는 핵심 몇 줄만 코드 상자로 붙이고, 「전체 코드: `soar_response/account_actions.py`」처럼 위치만 적습니다.

**4. 확인하기**

> **확인** — VS Code 왼쪽 목록의 `_posts` 폴더 안에 오늘 글 파일이 있고, 맨 위 머리말에 `module: 5` · `unit: 2` 이 있으면 성공입니다. 없으면 오른쪽 클릭한 폴더가 `_posts` 인지 봅니다.

## 막힐 때 힌트

고른 글감에 따라 아래 줄을 그대로 붙이고 이어 씁니다.

| 고른 글감 | 붙일 줄 | 이어 쓸 것 |
|---|---|---|
| 글감 1(VIP) | `check_policy` 의 `if user in vip_accounts:` 두 줄, 단계 2 의 INC-003 줄 | 경로 설정이 틀린 경우와 `lock_account` 를 바로 부른 경우로 나눠 한 문장씩 |
| 글감 2(세션) | 실습 2-2 단계 1 의 `['junho']`, 단계 2 의 `dami` 두 줄 | 잠금만 했다면 `S-101` · `S-102` 로 할 수 있었던 일 |
| 글감 3(피해) | 세 조치 × 「누가 못 쓰나 · 되돌릴 수 있나」 작은 표 | 공유 IP `192.0.2.41`(`junho` · `hana`) 같은 오늘 데이터를 예로 |

1. 실행 결과는 출력 전체를 붙이지 않아도 됩니다. 내 말과 연결되는 두세 줄만 코드 상자(```` ``` ````)로 붙이고, 그 아래에 「이 줄에서 무엇을 보았는지」를 한 문장으로 씁니다.
2. 막힌 이야기를 쓸 때는 `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 2-1 에서 `dami` 가 `잠기지 않음 (확인 실패)` 로 나왔다면, 그 줄과 내가 의심한 곳(② `verify_locked` 의 `return` 인지, ③ 잠그는 `append` 인지)을 적고 어떻게 찾았는지 씁니다.
3. 무엇부터 쓸지 모르겠으면 보고서 `report_u2.md` 에 쓴 내 답 하나를 글 틀의 「왜 골랐나」 칸에 옮기고, 앞의 두 문장을 거기에 맞춰 씁니다.

**AI 도우미**

코드 설명 정리, 초안 다듬기, 내 글 점검에 쓰는 프롬프트 세 가지는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 표의 「붙일 줄」을 붙이고 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

올리기 전에 한 번 더 봅니다. 자세한 점검 방법은 [시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 `soar_response/` 의 파일에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다
4. 머리말이 `module: 5`, `unit: 2` 이고, `sample: true` 줄이 없다

**올리기** — **[터미널]** 네 줄을 모두 「맞음」으로 답할 수 있으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..` → `python check_publish.py`(맥북은 `python3`) → `git add .` → `git commit -m "Add module 5 unit 2 post"` → `git push` → `cd soar_response`. 터미널이 이미 `network-study-notes` 에 있으면 `cd ..` 는 건너뜁니다. 점검에서 `[오류]` 가 나오면 그 부분을 지우고 다시 돌린 뒤 올립니다.
