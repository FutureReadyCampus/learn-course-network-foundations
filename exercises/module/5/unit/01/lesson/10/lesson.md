# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘의 마지막 40분은 글쓰기 시간입니다. 오늘 만든 코드와 그때 한 고민을 내 포트폴리오에 글 한 편으로 남깁니다. 보고서는 질문에 답하는 파일이고, 이 글은 그 답 가운데 하나를 내 말로 풀어 쓰는 기록입니다.

**40분은 이렇게 나눕니다**

1. 고르기 5분: 아래 글감 가운데 하나를 고릅니다. 「보고서 쓰기」에서 가장 오래 고민한 질문과 이어지는 글감이 쓰기 쉽습니다.
2. 쓰기 25분: 글 틀을 복사해 빈칸을 채웁니다.
3. 점검·올리기 10분: 공개해도 되는지 확인하고 올린 뒤, 첫 화면에서 칸이 채워졌는지 봅니다.

**오늘의 글감 (핵심 실습)**

1. 알림 두 건을 손으로 처리하며 `system_state.json` 을 직접 고친 곳은 몇 군데였나요? 알림이 100건이라면 어떤 문제가 생길까요?
2. 손으로 하던 처리를 `playbook_runner.py` 로 옮기면서 무엇이 가장 달라졌나요? 승인이 필요한 알림이 멈추고 감사 기록이 남는 것을 보고 새로 보인 것이 있었나요?
3. INC-005 처럼 맥락이 모두 초기값(`False` · `None`)으로 남은 알림은 왜 그렇게 되었나요? 확인되지 않은 대상을 「재직 중」으로 보면 어떤 일이 생길지 조회 함수의 `if` 조건을 근거로 써 보세요.

**선택 글감 (도전을 했다면)**

1. 도전 1-1을 했다면
   1. 알림을 `승인 필요` · `오탐 종료` · `기본` 경로로 나눈 기준은 무엇인가요? 기준이 틀리면 어떤 일이 생길까요?
   2. VIP 판정을 신뢰 IP 판정보다 먼저 둔 이유를, 순서를 바꿨을 때의 결과와 비교해 써 보세요.
2. 도전 1-2를 했다면
   1. 같은 알림을 두 번 처리해도 `dami` 가 한 번만 잠기게 한 장치는 무엇인가요? 그 장치가 없으면 현장에서 무엇이 불편해지나요?
   2. 한 번에 잠그는 계정을 3개로 제한해도 잘못 잠긴 계정이 남았습니다. 한도가 막아 주는 것과 막지 못하는 것을 나눠 써 보세요.

세 문장만 써도 됩니다. 막혀서 끝내지 못한 이야기도 좋은 글입니다. 어디까지 해 봤고 어디서 멈췄는지를 적어 두면, 다음에 다시 볼 때 가장 쓸모 있는 기록이 됩니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. **GitHub 웹 화면**에서 파일을 만들고 붙여 넣습니다. 포트폴리오 저장소가 아직 없으면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 준비하고, 글 틀 세 가지의 내용은 [Module 3 Unit 1 시작하기 레슨의 「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 오늘 실습 하나를 글 한 편으로 남긴다 | `_templates/post-practice.md` |
| 시간이 5분밖에 없다 | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |

**올리는 순서**

1. 내 포트폴리오 저장소에서 **Add file → Create new file** 을 누릅니다.
2. 파일 이름 칸에 `_posts/날짜-영문제목.md` 를 적습니다. 예: `_posts/2026-11-20-m5-u1-playbook-runner.md`
3. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)의 `module: 5`, `unit: 1` 을 이렇게 적습니다. 그래야 첫 화면 「나의 진행」에서 Module 5의 1번 칸이 채워집니다. `date:` 는 파일 이름의 날짜와 같게 씁니다. 날짜가 미래면 글이 목록에 나오지 않습니다.
4. 빈칸을 채우고 오른쪽 위 **Commit changes** 를 누른 뒤, 나오는 창에서 한 번 더 **Commit changes** 를 누릅니다.
5. 코드를 함께 남기려면 `code/` 폴더에 같은 방법으로 파일을 만들고 내 코드를 붙여 넣습니다. 예: `code/m5_u1_playbook_runner.py`(VS Code 에서 연 `playbook_runner.py` 의 내용). `enrichment.py` 도 올린다면 `code/m5_u1_enrichment.py` 로 만듭니다. 글에는 `전체 코드: code/m5_u1_playbook_runner.py` 처럼 위치를 적습니다.
6. 1~2분 뒤 내 사이트 첫 화면을 열어 최신 글에 새 글이 보이는지, Module 5의 1번 칸이 채워졌는지 확인합니다.

## 막힐 때 힌트

**오늘 Unit에서 글이 막힐 때**

1. 글감 1(고친 곳의 수)을 골랐다면 실습 1-1의 5번 확인 명령 출력(예: `['dami'] ['198.51.100.90'] 2`)을 코드 상자에 붙이고, 그 한 줄을 만들려고 손으로 고친 곳을 하나씩 적은 뒤 「알림이 100건이면」으로 이어 씁니다.
2. 글감 2(손 처리 → 실행기)를 골랐다면 `playbook_runner.py` 의 `if playbook["approval"] != "자동":` 부터 `return False` 까지 세 줄을 붙이고, 실습 1-1에서 손으로 INC-005 를 처리한 것과 실행기가 INC-005 를 `승인 대기` 로 멈춘 것을 나란히 비교합니다.
3. 글감 3(맥락 초기값)을 골랐다면 `enrichment.py` 의 `if entity in users_info:` 한 줄과 실습 1-3 출력의 INC-005 줄(`재직: 계정 아님 · … · 접속 IP: 없음`)을 함께 붙이고, 「이 `if` 가 거짓이라 초기값이 남았다」고 이어 씁니다.
4. 감사 기록은 `action_log.json` 전체를 붙이지 않아도 됩니다. 글에서 말하는 줄 한두 개(예: `INC-002 PB-002 전체 : 승인 대기`)만 코드 상자에 붙이고, 그 줄에서 무엇을 봐야 하는지 한 문장을 덧붙입니다.
5. 무엇부터 쓸지 모르겠으면 보고서 `report_u1.md` 에 쓴 내 답을 글 틀의 「고민한 선택과 이유」 칸에 옮기고, 거기서부터 문장을 늘립니다.

**AI 도우미**

코드 설명 정리, 초안 다듬기, 내 글 점검에 쓰는 프롬프트 세 가지는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 글과 코드에는 비밀키·토큰·개인정보를 넣지 않습니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Module 3 Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 코드에 `.env` 내용, API 키, 토큰이 없습니다.
2. 개인 이메일·전화번호가 없습니다.
3. 실습 속 가상의 사용자 이름(`dami` · `gaeun` 등)과 연습용 IP(`198.51.100.90` 등) 말고, 실제 다른 사람의 이름이나 실제 회사 IP 가 없습니다.
4. 실행 결과 화면 캡처에 내 컴퓨터 사용자 이름이나 다른 창의 개인 정보가 보이지 않습니다.
