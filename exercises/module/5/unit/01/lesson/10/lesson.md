# 문제 해결 기록을 포트폴리오에 남기기

## 오늘 쓸 글 고르기

핵심 실습에서 발견한 문제, 선택한 해결 방법, 결과를 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. `report_u1.md` 에는 기술적 결과와 확인 출력을 기록하고, 이 글에는 문제를 어떻게 이해하고 해결했는지와 다음에 개선할 점을 씁니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

「실습 결과 기록 준비」에서 기록한 핵심 실습의 결과를 바탕으로 글감을 고릅니다.

**오늘의 글감 (핵심 실습)**

1. 알림 두 건을 손으로 처리하며 `system_state.json` 을 직접 고친 곳은 몇 군데였나요? 알림이 100건이라면 어떤 문제가 생길까요?
2. 손으로 하던 처리를 `playbook_runner.py` 로 옮기면서 무엇이 가장 달라졌나요? 승인이 필요한 알림이 멈추고 감사 기록이 남는 것을 보고 새로 보인 것이 있었나요?
3. INC-005 처럼 맥락이 모두 초기값(`False` · `None`)으로 남은 알림은 왜 그렇게 되었나요? 확인되지 않은 대상을 「재직 중」으로 보면 어떤 일이 생길지 조회 함수의 `if` 조건을 근거로 써 보세요.

세 문장이면 충분합니다. 막혀서 끝내지 못한 이야기도 좋은 글입니다. 어디까지 해 봤고 어디서 멈췄는지, 다음에는 무엇을 확인할지 적어 두면 다음 작업에 도움이 됩니다.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 핵심 실습에서 가장 오래 고민한 문제를 고릅니다.

**게시할 글 예시**

- 제목은 **알림 일괄 처리에서 승인 대기를 남긴 이유**로 쓸 수 있습니다.
- 예시 파일은 `_posts/YYYY-MM-DD-playbook-approval.md`입니다. `YYYY-MM-DD`를 작성일로 바꿉니다.
- [실습 1-2 · 실행기로 알림 5건 처리하기](__SITE__/exercises/module/5/unit/1/lesson/3/page/3)에서 코드와 출력 위치를 찾습니다.

> 가상 회사의 알림 다섯 건을 플레이북 실행기로 한 번에 처리했다. 조치 전에 승인이 필요한 알림을 멈추고 승인 대기 상태를 감사 기록에 남기도록 했다. 실습 출력과 감사 기록에서 INC-002가 ‘승인 대기’로 남은 것을 확인했다.

위 문장은 교재의 실습 예시입니다. 내 실행에서 같은 결과를 확인했다면 내 말로 써 봅니다. 실행 결과가 다르거나 막혔다면 내 실제 출력과 다음에 확인할 내용을 적습니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. 저장소 `network-study-notes` 를 연 VS Code 에서 글 파일을 만들고, 터미널에서 올립니다. 저장소 `network-study-notes` 가 아직 없으면 [Module 3 Unit 1 시작하기 레슨의 「자기소개 두 문장으로 시작하기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 준비하고, 글 틀 세 가지의 내용은 [Module 3 Unit 1 시작하기 레슨의 「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `_templates/post-practice.md` |

**올리는 순서**

1. **[VS Code]** 저장소 `network-study-notes`의 `_posts/`에 `YYYY-MM-DD-playbook-approval.md`처럼 새 파일을 만들고 `YYYY-MM-DD`를 작성일로 바꿉니다. 이미 게시한 글은 기존 주소를 유지하도록 파일명과 `date`를 그대로 두고 내용을 고칩니다.
2. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)에 내 글의 제목을 적습니다. `date:` 는 파일 이름의 날짜와 같게 씁니다. 날짜가 미래면 글이 목록에 나오지 않습니다.

<!-- checklist -->
- [ ] `_posts` 폴더에 작성일로 시작하는 이름(예: `_posts/YYYY-MM-DD-playbook-approval.md`)으로 새 글을 만들었거나, 기존 글의 파일명과 날짜를 유지했다
<!-- /checklist -->

3. 내 문제, 고른 기준과 이유, 확인한 결과를 세 문장으로 적고 저장합니다.

**코드와 실행 근거 연결하기**

1. 글에 내 실행 결과 한 줄과 그 줄로 확인한 내용을 적습니다. 예시 글의 근거는 `INC-002 PB-002 전체 : 승인 대기`입니다.
2. 코드는 `soar_response/`에 둡니다. 아래 한 줄을 복사해 글 본문에 붙이면 Pages가 내 사이트 주소에 맞게 코드 링크를 만듭니다. 다른 글감을 골랐다면 링크의 `playbook_runner.py`를 `enrichment.py` 등 내 글에 해당하는 파일명으로 바꿉니다.
3. 공개해도 되는 기술 기록을 연결하려면 내 GitHub 저장소에서 `soar_response/report_u1.md`를 열고 그 주소를 붙입니다. 글을 올린 뒤 링크를 직접 열어 확인합니다.

## 막힐 때 힌트

**오늘 Unit에서 글이 막힐 때**

고른 글감에 따라 코드 상자에 붙일 것과 이어 쓸 내용은 다음과 같습니다.

| 글감 | 코드 상자에 붙일 것 | 이어 쓰는 법 |
|---|---|---|
| 1 (고친 곳의 수) | 실습 1-1의 5번 확인 명령 출력(예: `['dami'] ['198.51.100.90'] 2`) | 그 한 줄을 만들려고 손으로 고친 곳을 하나씩 적고, 「알림이 100건이면」으로 이어 쓴다 |
| 2 (손 처리 → 실행기) | `playbook_runner.py` 의 `if playbook["approval"] != "자동":` 부터 `return False` 까지 세 줄 | INC-002 출력에서 실행기가 승인을 기다렸는지 확인하고, 그 결과를 코드와 연결한다 |
| 3 (맥락 초기값) | `enrichment.py` 의 `if entity in users_info:` 한 줄과 실습 1-3 출력의 INC-005 줄(`재직: 계정 아님 · … · 접속 IP: 없음`) | 「이 `if` 가 거짓이라 초기값이 남았다」고 이어 쓴다 |

1. 감사 기록은 `action_log.json` 전체를 붙이지 않아도 됩니다. 글에서 말하는 줄 한두 개(예: `INC-002 PB-002 전체 : 승인 대기`)만 코드 상자에 붙이고, 그 줄에서 무엇을 봐야 하는지 한 문장을 덧붙입니다.
2. 어디서부터 쓸지 막혔다면 `report_u1.md`에서 직접 확인한 출력 한 줄을 먼저 골라 보세요. 그 출력으로 확인한 결과를 적고, 그 결과에 이르게 된 문제와 판단을 앞에 씁니다.

**AI 도우미**

코드 설명 정리, 초안 다듬기, 내 글 점검에 쓰는 프롬프트 세 가지는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 글과 코드에는 비밀키·토큰·개인정보를 넣지 않습니다.

> **확인** — 글에서 실습의 문제, 내가 선택한 방법과 이유, 실행 결과를 읽을 수 있으면 성공입니다. 결과를 설명하기 어렵다면 위 표에서 근거가 될 줄을 골라 무엇을 봤는지 한 문장으로 씁니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Module 3 Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 코드(`soar_response/` 의 파일 포함)에 `.env` 내용, API 키, 토큰이 없습니다.
2. 개인 이메일·전화번호가 없습니다.
3. 실습 속 가상의 사용자 이름(`dami` · `gaeun` 등)과 연습용 IP(`198.51.100.90` 등) 말고, 실제 다른 사람의 이름이나 실제 회사 IP 가 없습니다.
4. 실행 결과 화면 캡처에 내 컴퓨터 사용자 이름이나 다른 창의 개인 정보가 보이지 않습니다.

**올리기** — **[터미널]** 네 줄을 모두 「없음」으로 답할 수 있으면 저장소 루트에서 점검 스크립트를 돌리고 올린 뒤 작업 폴더로 돌아옵니다: `cd ..` → `python check_publish.py` → `git add .` → `git commit -m "Add module 5 unit 1 post"` → `git push` → `cd soar_response`. 터미널이 이미 `network-study-notes` 에 있으면 `cd ..` 는 건너뜁니다. 점검에서 `[오류]` 가 나오면 그 부분을 지우고 다시 돌린 뒤 올립니다.
