# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

하루의 마지막 40분은 오늘 만든 통합 엔진과 정책 점검을 내 말로 남기는 시간입니다. 글은 내 GitHub Pages 포트폴리오에 올립니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**회고 문서와 글은 하는 일이 다릅니다.** 실습 5-2 끝에 쓴 `unit10_final_retrospective.md` 는 Module 5 전체를 표로 정리해 저장소에 남기는 문서입니다. 오늘의 글은 그 가운데 **질문 하나**를 골라, 왜 그렇게 만들었는지와 무엇을 고민했는지를 이야기로 풉니다. 회고 문서의 표를 글에 그대로 옮기지 않습니다.

**40분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 질문 중 하나를 고른다 |
| 2. 쓰기 | 25분 | 글 틀을 복사해 내 답을 글로 푼다 |
| 3. 점검 · 올리기 | 10분 | 공개 전 점검을 하고 GitHub 에 올린 뒤 첫 화면을 확인한다 |

글감은 보고서 `report_u5.md` 에 적은 답 가운데 가장 오래 고민한 것을 고르면 쉽습니다.

**글감 질문 (실습 5-1 · 5-2)**

1. 알림 `INC-402` 하나가 실패해도 나머지 알림은 처리됐습니다. `try` / `except` 가 없었다면 어떻게 되었을까요? 오류를 받아 넘기는 방식이 감출 수 있는 문제는 무엇인가요?
2. 같은 high 등급인데 `INC-404` 는 「차단 금지」, `INC-406` 은 「승인 대기」로 갈렸습니다. 두 이유를 비교하고, 승인 게이트가 조치 실행보다 먼저 와야 하는 이유를 써 보세요.
3. 승인 게이트를 끈 로그에는 모든 결정이 「자동」으로 적혀 있었습니다. 로그에 적힌 결정만 믿으면 왜 위반을 놓치나요? 저장된 요청으로 결정을 다시 구한 방법을 내 말로 설명해 보세요.

**선택 글감 (응용 5-1을 했다면)**

1. 엔진 앞의 입력 검증과 엔진 안의 오류 격리는 각각 무엇을 막나요? 등급이 `critical` 인 기록을 예로 들어, 둘 중 하나만 있을 때 생기는 일을 써 보세요.

세 문장만 써도 한 편의 글입니다. 오늘 막혀서 실습을 다 못 했다면 그 막힌 이야기도 좋은 글이 됩니다. 어디서 멈췄는지 남겨 두면 다음에 나도, 글을 읽는 사람도 도움을 받습니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. Module 3 Unit 1 시작하기 레슨에서 한 것처럼 **GitHub 웹 화면**에서 파일을 만들고 붙여 넣습니다. 글 틀 세 가지는 [「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)에 있습니다.

**1. 글 틀 고르기**

| 오늘 나의 상황 | 고를 글 틀 |
|---|---|
| 실습 5-1 이나 5-2 하나를 글 한 편으로 쓰고 싶다 | `_templates/post-practice.md` |
| 시간이 5분밖에 없다 | `_templates/post-short.md` |
| 실습하다 막혔다 | `_templates/post-stuck.md` |

**2. 새 글 파일 만들기**

1. 내 포트폴리오 저장소에서 `_posts` 폴더를 열고 **Add file › Create new file** 을 누릅니다.
2. 파일 이름은 `날짜-영문제목.md` 모양으로 적습니다. 예: `_posts/2026-11-20-m5-u5-soar-engine.md`
3. 고른 글 틀의 내용을 붙여 넣고, 맨 위 머리말(front matter)을 오늘 Unit 에 맞게 고칩니다.
   ```
   module: 5
   unit: 5
   ```
   - 이 두 줄이 첫 화면 「나의 진행」에서 Module 5 의 **5번** 칸을 채웁니다.
   - `title` 은 내 글의 한 줄 제목으로, `date` 는 오늘 날짜로 바꿉니다.
4. 빈칸을 채우고 **Commit changes** 를 누릅니다.

**3. 코드 올리기**

글에서 소개한 코드는 저장소의 `code/` 폴더에 올립니다. `code` 폴더에서 **Add file › Create new file** 을 누르고, 이름은 Unit 번호가 보이게 적습니다.

- 예: `code/m5_u5_soar_engine.py`(실습 5-1), `code/m5_u5_policy_check.py`(실습 5-2)
- 글 안에는 핵심 몇 줄만 코드 상자로 붙이고, 「전체 코드: `code/m5_u5_soar_engine.py`」처럼 위치를 적습니다.

**4. 확인하기**

올리고 1~2분 기다린 뒤 내 사이트 첫 화면을 엽니다. 최신 글에 내 글이 보이고, 「나의 진행」의 Module 5 · 5번 칸이 채워졌으면 끝입니다. 보이지 않으면 저장소의 **Actions** 탭을 먼저 봅니다.

## 막힐 때 힌트

글이 잘 안 풀리면 아래에서 고른 글감에 맞는 힌트를 하나 봅니다.

1. **글감 1(오류 격리)**: `run_all` 의 `try:` · `except Exception as error:` 두 줄과 그 사이 한 줄을 글에 붙입니다. 그다음 실습 5-1 단계 2 에서 `INC-402 hana → 실패 · KeyError: 'grade'` 줄과 바로 아래 `INC-403` 줄을 나란히 붙이고, 두 줄 사이에 무슨 일이 있었는지부터 씁니다. 감출 수 있는 문제는 정답 레슨 「자주 틀리는 곳」의 4번(4번을 비우면 `실패 : 6 건`)을 보면 찾을 수 있습니다.
2. **글감 2(게이트 순서)**: 단계 2 에서 `IP 차단 203.0.113.80 → 차단 금지 · 허용 목록 대상` 줄과 `계정 잠금 gaeun → 승인 필요 · 등급 high +2, VIP 계정 +3, 합계 5점` 줄을 붙입니다. 하나는 점수를 보지 않고, 하나는 점수로 정했다는 차이를 한 문장으로 쓰면 글의 절반이 됩니다.
3. **글감 3(다시 구하기)**: `gate_off_log.json` 의 `INC-405` 한 줄에서 `"decision": "자동"` 과 `"users_on_ip": 2` 를 짚습니다. 승인 정책의 점수(mid 1점 + 함께 쓰는 IP 2점)를 손으로 더해 합계 3점을 적고, 그 값이 승인 기준 3점과 같다는 데서 이야기를 시작합니다.
4. **실행 결과 붙이기**: 터미널 출력은 전부 붙이지 않아도 됩니다. 내 말과 연결되는 두세 줄만 코드 상자(```` ``` ````)로 붙이고, 그 아래에 「이 줄에서 무엇을 보았는지」를 한 문장으로 씁니다. 화면 캡처를 쓰려면 이미지를 `assets/images/` 에 올리고 글에 연결합니다.
5. **막힌 이야기를 쓸 때**: `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 5-1에서 `IndentationError: unexpected indent` 가 났다면, 그 오류와 내가 의심한 줄(5번 `if decision == "자동":` 아래 미리 채운 줄)을 적고 어떻게 찾았는지 씁니다.

질문 하나에서 시작해도 막히면 AI 도우미를 써도 됩니다. 붙여 넣는 프롬프트 세 가지(코드 설명 정리 · 글 초안 다듬기 · 내 글 점검)는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 코드와 글에는 비밀키 · 토큰 · 개인정보를 넣지 않습니다.

## 공개 전 점검

**Commit changes** 를 누르기 전에 한 번 더 봅니다.

1. 글과 `code/` 파일에 비밀키 · 토큰 · `.env` 내용이 없다
2. 이메일 · 전화번호 같은 개인정보가 없다
3. 실습 데이터가 아닌 실제 사람의 이름(나와 동료의 실명)이 없다
4. 머리말이 `module: 5`, `unit: 5` 이고, `sample: true` 줄이 없다
