# 오늘의 글 쓰기

## 오늘 쓸 글 고르기

오늘 글쓰기 시간은 20분입니다. 오늘 만든 통합 엔진과 정책 점검 가운데 하나를 골라 내 포트폴리오에 **세 문장 글** 한 편으로 남깁니다. 아직 포트폴리오가 없다면 [Module 3 Unit 1 시작하기 레슨의 「내 기록 남기기: 소개」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/4)부터 시작합니다.

**회고 문서와 글은 하는 일이 다릅니다.** 실습 5-2 끝에 쓴 `unit10_final_retrospective.md` 는 Module 5 전체를 표로 정리해 저장소에 남기는 문서이고, 실습 시간 안에 이미 끝냈습니다. 오늘의 글은 그 표를 옮겨 적지 않고, 아래 글감 **하나**를 골라 「무엇을 했나 · 무엇을 골랐나 · 왜 골랐나」를 세 문장으로 씁니다.

**20분은 이렇게 나눕니다**

| 순서 | 시간 | 하는 일 |
|---|---|---|
| 1. 고르기 | 5분 | 아래 글감 하나를 고릅니다 |
| 2. 쓰기 | 10분 | `post-short` 글 틀로 세 문장을 씁니다 |
| 3. 점검·올리기 | 5분 | 공개 점검 뒤 올리고 첫 화면을 봅니다 |

**오늘의 글감 (핵심 실습)**

1. 알림 `INC-402` 하나가 실패해도 나머지 알림은 처리됐습니다. `try` / `except` 가 없었다면 어떻게 되었을까요? 오류를 받아 넘기는 방식이 감출 수 있는 문제는 무엇인가요?
2. 같은 high 등급인데 `INC-404` 는 「차단 금지」, `INC-406` 은 「승인 대기」로 갈렸습니다. 두 이유를 비교하고, 승인 게이트가 조치 실행보다 먼저 와야 하는 이유를 써 보세요.
3. 승인 게이트를 끈 로그에는 모든 결정이 「자동」으로 적혀 있었습니다. 로그에 적힌 결정만 믿으면 왜 위반을 놓치나요? 저장된 요청으로 결정을 다시 구한 방법을 내 말로 설명해 보세요.

**선택 글감 (응용을 했다면)**

1. 응용 5-1을 했다면: 엔진 앞의 입력 검증과 엔진 안의 오류 격리는 각각 무엇을 막나요? 등급이 `critical` 인 기록을 예로 들어, 둘 중 하나만 있을 때 생기는 일을 써 보세요.

세 문장이면 충분합니다. 막혀서 끝내지 못한 이야기도 좋은 글입니다. 어디까지 해 봤고 어디서 멈췄는지를 적어 두면, 다음에 다시 볼 때 가장 쓸모 있는 기록이 됩니다. 긴 글(`post-practice`)은 **응용**입니다. 여유가 되면 써 보세요.

> **확인** — 글감 하나를 골라 그 번호를 말할 수 있으면 성공입니다. 못 고르겠으면 보고서 `report_u5.md` 에서 가장 오래 고민한 질문과 이어지는 글감으로 정합니다.

## 글 틀로 쓰고 올리기

설치할 것은 없습니다. 모두 GitHub 웹 화면에서 합니다. 글 틀을 복사하는 방법은 [Module 3 Unit 1 시작하기 레슨의 「글 틀로 글 쓰기」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/10)를 봅니다.

**글 틀 고르기**

| 오늘 상황 | 고를 글 틀 |
|---|---|
| 기본(세 문장 글) | `_templates/post-short.md` |
| 막혀서 끝내지 못했다 | `_templates/post-stuck.md` |
| 응용: 여유가 있어 긴 글을 쓴다 | `_templates/post-practice.md` |

**올리는 순서**

1. 깃허브의 내 저장소 `network-study-notes` 에서 **Add file → Create new file** 을 누르고, 이름 칸에 `_posts/2026-11-20-m5-u5-soar-engine.md` 처럼 적습니다. 앞은 오늘 날짜, 뒤는 영문 제목입니다.
2. 고른 글 틀을 붙여 넣고 맨 위 머리말을 고칩니다.
   1. `module: 5`, `unit: 5` 로 씁니다. 이 두 줄이 첫 화면 「나의 진행」에서 Module 5 줄의 5번 칸을 채웁니다.
   2. `title` 과 `date` 를 내 글에 맞게 고칩니다. 날짜가 미래면 글이 목록에 나오지 않습니다.
3. 빈칸을 채우고 **Commit changes** 를 누릅니다.
4. 코드는 `code/` 폴더에 올립니다. **Add file → Create new file** 에서 이름을 `code/m5_u5_soar_engine.py`(실습 5-1)나 `code/m5_u5_policy_check.py`(실습 5-2)처럼 적고, VS Code 에서 연 파일의 내용을 복사해 붙여 넣습니다. 글에는 `전체 코드: code/m5_u5_soar_engine.py` 처럼 위치를 적습니다.
5. 올리고 1~2분 뒤 내 사이트 첫 화면을 엽니다.

> **확인** — 최신 글에 오늘 글이 보이고 「나의 진행」의 Module 5 · Unit 5 칸이 채워지면 성공입니다. 안 보이면 [Module 3 Unit 1 시작하기 레슨의 「첫 화면 확인하고 막힐 때」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/9)의 「글이 목록에 안 나옴」 줄을 봅니다.

## 막힐 때 힌트

**오늘 Unit에서 글이 막힐 때**

고른 글감에 따라 아래 줄을 그대로 붙이고 이어 씁니다.

| 고른 글감 | 붙일 줄 | 이어 쓸 것 |
|---|---|---|
| 글감 1(오류 격리) | 단계 2 의 `INC-402` 실패 줄과 바로 아래 `INC-403` 줄 | 두 줄 사이에 ② 의 `except` 가 한 일을 한 문장으로 |
| 글감 2(게이트 순서) | 단계 2 의 `203.0.113.80` 줄과 `gaeun` 줄 | 하나는 점수를 안 보고, 하나는 점수로 정했다는 차이 |
| 글감 3(다시 구하기) | `gate_off_log.json` 의 `INC-405` 한 줄 | mid 1점 + 함께 쓰는 IP 2점 = 3점이 승인 기준과 같다는 데서 시작 |

1. 실행 결과는 출력 전체를 붙이지 않아도 됩니다. 글에서 말하는 줄 한두 개(예: `INC-402 hana → 실패 · KeyError: 'grade'`)만 코드 상자에 붙이고, 그 줄에서 무엇을 봐야 하는지 한 문장을 덧붙입니다.
2. 감출 수 있는 문제(글감 1)는 정답 레슨 실습 5-1 「자주 틀리는 곳」의 `desicion` 오타(`실패 : 6 건`)를 보면 찾을 수 있습니다.
3. 막힌 이야기를 쓸 때는 `post-stuck.md` 의 「증상」에 내 출력을 그대로 붙입니다. 예를 들어 실습 5-1에서 `IndentationError: unexpected indent` 가 났다면, 그 오류와 내가 의심한 줄(① 자리 아래 미리 채운 줄)을 적고 어떻게 찾았는지 씁니다.
4. 무엇부터 쓸지 모르겠으면 보고서 `report_u5.md` 에 쓴 내 답 하나를 글 틀의 「왜 골랐나」 칸에 옮기고, 앞의 두 문장을 거기에 맞춰 씁니다.

**AI 도우미**

코드 설명 정리, 초안 다듬기, 내 글 점검에 쓰는 프롬프트 세 가지는 [Module 3 Unit 1 시작하기 레슨의 「쓰기 질문과 AI 도우미」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/11)에 있습니다. AI 도우미에게 붙여 넣는 글과 코드에는 비밀키·토큰·개인정보를 넣지 않습니다.

> **확인** — 글 틀의 세 칸(무엇을 했나 · 무엇을 골랐나 · 왜 골랐나)에 한 문장씩 들어가 있으면 성공입니다. 비어 있는 칸은 위 표의 「붙일 줄」을 붙이고 그 줄을 한 문장으로 설명합니다.

## 공개 전 점검

올리기 전에 아래를 한 줄씩 확인합니다. 자세한 점검 방법은 [Module 3 Unit 1 시작하기 레슨의 「공개 전 점검」 페이지](__SITE__/exercises/module/3/unit/1/lesson/1/page/12)에 있습니다.

1. 글과 `code/` 파일에 `.env` 내용, API 키, 토큰이 없습니다.
2. 개인 이메일·전화번호가 없습니다.
3. 실습 속 가상의 사용자 이름(`dami` · `gaeun` 등) 말고, 실제 다른 사람의 이름이 없습니다.
4. 머리말이 `module: 5`, `unit: 5` 이고, `sample: true` 줄이 없습니다.

> **확인** — 네 줄을 모두 「문제 없음」으로 답할 수 있으면 성공입니다. 하나라도 걸리면 그 부분을 지우고 다시 **Commit changes** 합니다.
