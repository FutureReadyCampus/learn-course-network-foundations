# Exercise 3-1 · 설정 파일이 고장 나도 거부하기

## 개요

> **오늘 들어온 일**
> A사 보안 담당이 보낸 메시지: 「설정 파일을 고치다가 쉼표를 하나 빠뜨리면 판정 프로그램이 오류를 내고 멈춥니다. 판정이 멈추면 정산 포털을 쓰는 사람들이 급해져서, 담당자가 판정 기능을 아예 끄고 모든 요청을 허용할까 걱정입니다. 설정에 문제가 있어도 프로그램은 멈추지 않게 하고, 대신 모든 요청을 거부하게 해 주세요.」
> - 이 Exercise에서 하는 일: 설정 파일을 안전하게 읽는 함수 `load_json` 을 직접 쓰고, 파일이 없을 때와 깨졌을 때를 일부러 만들어 둘 다 멈추지 않고 빈 설정으로 이어지는지 확인합니다. 이 함수를 판정 프로그램에 연결하는 일은 오늘 하지 않습니다.
> - 끝나면 쓰는 것: 보고서 (가)~(다) 답

> **읽을거리 — 문제가 아닙니다.** 이 아래부터 첫 「 문제」 전까지는 이 Exercise의 배경지식입니다. 답할 질문도 따라 칠 명령도 없으니 읽고 이해만 합니다.

## 읽기 · 왜 필요한가

> **읽을거리 — 읽기만 합니다.** 문제가 아닙니다. 답할 질문도, 따라 칠 명령도 없습니다.

1. 지금 `rbac.py` 는 파일을 바로 열어서, 파일이 없으면 `FileNotFoundError`, JSON 이 깨지면 `JSONDecodeError` 로 프로그램이 멈춥니다. 오늘은 안전하게 읽는 함수를 새 파일에 만들어 시험합니다. 이 함수를 판정 프로그램에 연결하는 일은 오늘 하지 않고, 오전까지 만든 파일도 고치지 않습니다.
2. 판정 프로그램이 멈추면 현장에서는 판정을 건너뛰고 모두 통과시키는 일이 생깁니다. 판정을 건너뛰고 모두 통과시키는 이 상태를 **열림 기본 값**(fail-open · 페일 오픈)이라고 합니다.
3. 설정을 읽지 못했을 때 **빈 설정**을 쓰면 사용자가 한 명도 없습니다.
   - 그러면 어제의 판정 함수(`check_permission`)가 맨 처음 「사용자 파일에 있나?」 검사에서 모든 요청을 거부합니다.
   - 멈추지 않고 모두 막는 이 동작을 **닫힘 기본 값**(fail-closed · 페일 클로즈드)이라고 합니다.

## 읽기 · 1.1 안전하게 읽고, 실패하면 빈 설정

> **읽을거리 — 읽기만 합니다.** 문제가 아닙니다. 답할 질문도, 따라 칠 명령도 없습니다.

```
+-----------+     +-----------+
| 설정 파일 | --> | load_json | --> 성공 --> 읽은 내용 --> 평소대로 판정
+-----------+     +-----------+
                    |
                    +--> 파일이 없음 (FileNotFoundError)
                    |       |
                    |       v
                    |    「[경고] 설정 파일 없음: 경로」 출력
                    |
                    +--> JSON 이 깨짐 (json.JSONDecodeError)
                            |
                            v
                         「[경고] 설정 파일 깨짐: 경로」 출력

                    (두 경우 모두 프로그램은 멈추지 않고 기본값 default 를 리턴한다. 오늘은 default 가 {})
                       |
                       v
                    +------------+
                    | 빈 설정 {} |
                    +------------+
                       |
                       v
                    사용자가 한 명도 없음 --> 모든 요청이 「등록되지 않은 사용자」 로 거부
```

**이 시간에 나오는 말** (이미 배운 방법입니다)

- `try:` 안에서 오류가 나면 그 종류에 맞는 `except 오류이름:` 으로 넘어갑니다(9/28(월)).
- `with open(path, encoding="utf-8") as input_file:` 는 파일을 열어 `input_file` 로 받습니다(9/28(월), 어제 `rbac.py` 와 같습니다).
- `FileNotFoundError` 는 파일이 없을 때, `json.JSONDecodeError` 는 JSON 규칙이 틀렸을 때 납니다(9/28(월)).
- 함수가 기본값을 인자(`default`)로 받으면, 호출하는 쪽이 빈 딕셔너리 `{}` 나 빈 리스트 `[]` 를 골라 넣을 수 있습니다.

## 읽기 · 1.2 고장을 일부러 만들어 시험하기

> **읽을거리 — 읽기만 합니다.** 문제가 아닙니다. 답할 질문도, 따라 칠 명령도 없습니다.

- 고장이 났을 때 어떻게 되는지는 **일부러 고장을 만들어 봐야** 압니다. 오늘 시험할 경로는 세 개입니다.

| 경로 | 상태 | 기대하는 일 |
|---|---|---|
| `config/users.json` | 정상 파일 | 사용자 여섯 명을 읽고 판정을 계속한다 |
| `config/users_typo.json` | 이름을 잘못 적은 경로(파일이 없음) | `FileNotFoundError` → 경고, 빈 설정(사용자 0명) → 이 설정으로 판정하면 모두 거부 |
| `config/users_broken.json` | 마지막 항목 뒤에 쉼표가 남은 깨진 파일 | `JSONDecodeError` → 경고, 빈 설정(사용자 0명) → 같은 결과 |

- 기본값은 원래 자료와 **같은 모양**이어야 합니다. 사용자 파일은 딕셔너리라서 빈 딕셔너리 `{}`, 예외 파일은 딕셔너리들의 리스트라서 빈 리스트 `[]` 입니다. 모양이 다르면 뒤의 `for` 나 `in` 에서 또 오류가 납니다.
- 현업에서는 이런 고장 시험(장애 주입 · fault injection · 폴트 인젝션)을 미리 해 둬야 실제 고장 때 바로 대응할 수 있습니다.

> **여기부터 문제입니다.** 위는 읽을거리였고, 아래에서 직접 합니다.

## Exercise Exercise 2-2 · 설정 파일을 안전하게 읽는 함수 load_json 만들고, 고장 두 가지로 시험하기

** 이런 상황이 있습니다**

- 지금 `rbac.py` 는 설정 파일을 바로 열어서, 파일이 없거나 쉼표 하나가 틀리면 오류가 나고 프로그램이 멈춥니다. 보안 담당은 설정 파일을 읽는 함수 하나를 원합니다. 읽기에 실패해도 프로그램은 멈추지 않고, 무엇이 문제인지 경고를 출력해야 합니다.
- 그 함수가 정말 그렇게 동작하는지 고장을 일부러 두 가지 만들어 확인합니다. ① 파일 이름을 잘못 쓴 경우(파일이 없음) ② 쉼표가 하나 남은 파일(JSON 규칙이 틀림). 두 경우 모두 경고가 나오고, 프로그램은 계속 실행되며, 아무것도 들어 있지 않은 빈 설정 `{}` 을 얻어야 합니다.
- 빈 설정은 사용자가 한 명도 없는 상태입니다. 이 상태로 판정하면 모든 요청이 「등록되지 않은 사용자」로 거부됩니다. 이 연결은 읽고 이해만 합니다. Exercise 3-2의 4번 테스트는 빈 설정에 `seoyeon` 이 들어 있지 않은 것까지만 확인합니다.
- 현업의 보안 장비도 설정을 읽지 못하면 「기본 거부」 상태로 켜지고 경고를 남깁니다.

** 할 일**

1. `config_loader.py` 를 만들고 `load_json` 본문을 직접 씁니다.
2. 깨진 파일 `config/users_broken.json` 과 시험 파일 `day02_5-1_broken.py` 를 만듭니다.
3. 실행해서 <mark>세 경로의 결과</mark>를 읽습니다.

**`config_loader.py`**

```python
import json                                                      # JSON 파일을 읽는 모듈을 불러온다


def load_json(path, default):                                    # 파일 경로와 실패했을 때 쓸 기본값을 받는 함수
    """JSON 파일을 읽어 리턴하고, 파일이 없거나 깨졌으면 경고를 출력하고 default 를 리턴한다.
    설정 파일을 읽을 때마다 쓴다.
    """
    # ← 아래를 직접 씁니다 (주석은 두고 각 주석 바로 아래 줄에 씁니다)
    # 1. try: 로 시작한다
    # 2.   with open(path, encoding="utf-8") as input_file: 로 path 를 열어
    # 3.     json.load 로 읽은 내용을 바로 리턴한다
    # 4. except FileNotFoundError: 로 파일이 없을 때를 받는다
    # 5.   "[경고] 설정 파일 없음:" 과 path 를 출력하고
    # 6.   default 를 리턴한다
    # 7. except json.JSONDecodeError: 로 JSON 이 깨졌을 때를 받는다
    # 8.   "[경고] 설정 파일 깨짐:" 과 path 를 출력하고
    # 9.   default 를 리턴한다
```

- 주석은 모두 같은 자리에 있지만, 코드는 아래 칸 수로 씁니다. 각 주석 바로 아래 줄에 씁니다.
- `load_json` 의 들여쓰기: 1번 `try:` 는 4칸, 2번 `with` 는 8칸, 3번 `return` 은 12칸, 4 · 7번 `except` 는 4칸, 5 · 6 · 8 · 9번은 8칸입니다.

**`config/users_broken.json`** — 그대로 붙여 넣습니다. 마지막 항목 뒤에 쉼표가 남은 **일부러 깨진** 파일입니다. VS Code 가 이 파일에 빨간 줄을 긋는 것이 정상이니 쉼표를 지우지 않습니다. (`config/users_typo.json` 은 없는 파일이 목적이라 만들지 않습니다.)

```json
{
  "seoyeon": {"role": "sales", "employed": true},
}
```

**`day02_5-1_broken.py`** — 그대로 붙여 넣습니다. 학생이 쓰는 줄은 없습니다. 1.2 의 세 경로를 `load_json` 으로 읽어 결과를 출력합니다.

```python
from config_loader import load_json                              # 5-1 의 안전한 읽기 함수를 불러온다

PATHS = [                                                        # 시험할 경로 세 개
    "config/users.json",                                         # 정상 파일
    "config/users_typo.json",                                    # 이름을 잘못 적은 경로(파일이 없음)
    "config/users_broken.json",                                  # 일부러 깨진 파일
]

for path in PATHS:                                               # 경로를 하나씩 꺼낸다
    users = load_json(path, {})                                  # 안전하게 읽고, 실패하면 빈 딕셔너리
    if "seoyeon" in users:                                       # seoyeon 이 있으면
        print(path, "-> 사용자", len(users), "명을 읽음, 판정을 계속한다")   # 읽은 사용자 수를 알린다
    else:                                                        # 없으면
        print(path, "-> 사용자 0 명, 등록된 사용자가 없다")   # 빈 설정이라는 것을 알린다
```

- `load_json` 을 채우기 전에 실행하면 `TypeError: argument of type 'NoneType' is not iterable` 오류가 납니다. 함수가 아무것도 리턴하지 않아 `users` 가 `None` 이기 때문입니다. 본문을 채운 뒤에 실행합니다.

**순서**

1. **[VS Code 또는 터미널]** `config_loader.py` 를 만들고 붙여 넣습니다. 아래 세 가지 방법 중 **하나만** 고릅니다.
   - **방법 1 · VS Code 에서 만들기**
     1. VS Code 왼쪽 목록에서 `access_control` 폴더를 클릭해 선택합니다(선택하지 않으면 다른 폴더에 만들어집니다).
     2. 목록 위쪽의 **새 파일**(New File, 파일 모양에 `+`) 아이콘을 누릅니다.
     3. 이름 칸에 `config_loader.py` 라고 입력하고 Enter 를 누릅니다.
     4. 열린 파일에 내용을 복사해 붙여 넣고 저장합니다.
   - **방법 2 · touch**: `touch config_loader.py` → VS Code 에서 파일을 열어 붙여넣기
   - **방법 3 · vim 으로 만들기**: `vim config_loader.py` → `i` → 붙여넣기 → `Esc` → `:wq` Enter (줄 앞 공백이 줄마다 밀려 있으면 `Esc` → `:q!` 로 나와서 방법 1 이나 방법 2 로 다시 만듭니다)
2. **[VS Code]** `load_json` 본문을 직접 씁니다. 위 골격의 주석과 칸 수 안내를 보고 씁니다. `try` · `except` 는 함수 본문과 같은 깊이(4칸)이고, 그 안쪽은 4칸씩 더 들어갑니다.
3. **[VS Code 또는 터미널]** 나머지 두 파일을 만들고 각각 붙여 넣습니다. 파일마다 아래 세 가지 방법 중 **하나만** 고릅니다.
   - **방법 1 · VS Code 에서 만들기**: 파일마다 아래 네 가지를 반복합니다.
     1. VS Code 왼쪽 목록에서 `access_control` 폴더를 클릭해 선택합니다(선택하지 않으면 다른 폴더에 만들어집니다).
     2. 목록 위쪽의 **새 파일**(New File, 파일 모양에 `+`) 아이콘을 누릅니다.
     3. 이름 칸에 파일 이름을 입력하고 Enter 를 누릅니다. 이름은 차례로 `config/users_broken.json` · `day02_5-1_broken.py` 입니다. 앞에 폴더가 붙은 이름은 폴더도 함께 만들어집니다.
     4. 열린 파일에 위 코드 상자의 내용을 복사해 붙여 넣고 저장합니다.
   - **방법 2 · touch 로 만들기**: 터미널에서 파일마다 한 줄씩 치고, 각각 VS Code 에서 열어 붙여넣기: `touch config/users_broken.json` → `touch day02_5-1_broken.py`

4. **[터미널]** 위치가 `…/access_control` 인지 확인하고 실행합니다.

5. 세 경로의 결과 다섯 줄이 나옵니다. 경고 두 줄이 어느 경로에서 나왔는지 봅니다.
