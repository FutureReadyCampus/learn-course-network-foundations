# 실습 6-1 · 권한 현황 리스트 만들기

## 목표: 권한 현황 리스트

> **이번 실습에 들어온 일**
>
> A사 관제 담당이 보낸 메시지:
> 「지난주에 감사팀이 물었습니다. "지금 우리 회사에서 누가 어떤 권한을 갖고 있나요?" 저는 사용자 파일, 역할 파일, 예외 파일을 하나씩 열어 맞춰 보느라 오래 걸렸고, 그래도 빠뜨린 것이 없는지 자신이 없었습니다.
>
> 판정 함수는 요청이 올 때 허용인지 거부인지는 잘 가려 줍니다. 하지만 권한이 지금 어떻게 부여돼 있는지를 한곳에서 보여 주지는 않습니다. 먼저 누가 어떤 권한을 어떤 방법(역할 · 예외)으로 갖고 있는지 한곳에서 볼 수 있는 리스트를 만들어 주세요.」
> - **왜 중요한가**: 지금은 누가 어떤 권한을 갖고 있는지 파일 세 개를 열어 직접 맞춰 봐야 해서, 빠뜨린 권한이 있어도 알 수 없습니다. 리스트 하나로 모으면 ① 감사팀이 물을 때 바로 보여 줄 수 있고 ② 필요 없는 권한을 찾아 정리할 수 있습니다. 실습 6-2와 실습 6-3의 점검도 이 리스트에서 시작합니다.

> **읽을거리 — 문제가 아닙니다.** 이 아래부터 첫 「문제」 전까지는 이 실습의 배경지식입니다. 답할 질문도 따라 칠 명령도 없으니 읽고 이해만 합니다.

## Unit 1 ~ Unit 5 흐름 복습

> **읽을거리 — 읽기만 합니다.** 문제가 아닙니다. 답할 질문도, 따라 칠 명령도 없습니다.

| Unit | 만든 것 | 기억할 것 |
|---|---|---|
| Unit 1 | 역할 · 권한 파일, 판정 함수 `check_permission` | 허용 리스트에 없으면 모두 거부 |
| Unit 2 · Unit 3 | 역할 부여 · 회수, 기간이 정해진 예외, 최종 판정 `evaluate_access` | 예외는 만료 시각이 지나면 거부, 퇴사한 사용자는 모두 거부 |
| Unit 4 · Unit 5 | 요청서 접수 → 승인 · 반려 → 예외 권한 부여, 처리 기한(SLA) 점검, 이력 저장 | 요청서 상태는 `reviewing` → `approved` → `granted` |

## 왜 접근 점검이 필요한가

> **읽을거리 — 읽기만 합니다.** 문제가 아닙니다. 답할 질문도, 따라 칠 명령도 없습니다.

1. 권한은 **부여할 때는 절차를 거치지만, 회수할 때는 아무도 확인하지 않는** 일이 많습니다. 퇴사 · 부서 이동 · 프로젝트 종료가 지나도 권한이 그대로 남습니다.
2. 실제 업무에 필요한 것보다 많은 권한을 가진 상태를 **과다권한**(over-privilege · 오버 프리빌리지)이라고 합니다. 계정이 탈취되면 과다권한만큼 피해가 커집니다. 정기적으로 부여된 권한을 살펴보고 필요 없는 것을 가려내는 일을 **접근 점검**(access review · 액세스 리뷰)이라고 합니다.
3. 이번 Unit의 점검은 두 갈래입니다. 실습 6-2에서는 파일에 적힌 사실로 걸러 냅니다(퇴사 · 만료). 실습 6-3에서는 규칙으로 못 거르는 권한을 찾습니다.

## 1.1 현황 리스트의 한 건

> **읽을거리 — 읽기만 합니다.** 문제가 아닙니다. 답할 질문도, 따라 칠 명령도 없습니다.

- 현황 리스트의 **한 건은 사용자 한 명의 권한 하나**이고, 딕셔너리로 적습니다. 같은 사용자가 권한을 세 개 가졌으면 세 건입니다. 코드에서는 이 한 건을 `entry`(엔트리)라고 부릅니다.
- **키**(key)는 딕셔너리에서 값을 찾는 이름입니다. 한 건의 키는 아래와 같습니다.

| 키 | 뜻 | 값의 예 |
|---|---|---|
| `user` | 권한을 가진 사용자 | `"seoyeon"` |
| `permission` | 권한 (`자원:행위`) | `"SALES:QUERY"` |
| `source` | 어떻게 받았나 | `"역할 sales"` · `"예외 1번"` |
| `employed` | 재직 여부 | `True` · `False` |
| `expires` | 예외의 만료 시각 (**예외로 받은 권한에만 있음**) | `"2026-10-22 18:00"` |

- `batch-night` 은 사람이 아니라 밤에 자동으로 도는 집계 프로그램이 쓰는 계정입니다(`employed` 는 `True` 로 둡니다).
- 권한을 받는 방법은 두 가지입니다. **역할**로 받으면 그 역할의 권한 리스트가 모두 들어오고(Unit 1의 `roles.json`), **예외**로 받으면 기간이 정해진 권한 한 건이 들어옵니다(Unit 2의 `exceptions.json`).

```
+---------------------+
| build_access_list() |
+---------------------+
   |
   v
+-------------------------------------------+
| access_list = []  (현황을 담을 빈 리스트) |
+-------------------------------------------+
   |
   v
+--------------------------------------+
| 사용자를 한 명씩 꺼낸다 (user, info) |
+--------------------------------------+
   |
   v
+----------------------------------------------------------------------------------------------------------------------+
| role_entries(user, info) 로 그 사용자가 역할로 받은 권한 리스트를 얻어 access_list 뒤에 이어 붙인다 (미리 채운 함수) |
+----------------------------------------------------------------------------------------------------------------------+
   |
   v  사용자를 모두 꺼낸 뒤
+----------------------+
| 예외를 하나씩 꺼낸다 |
+----------------------+
   |
   v
+--------------------------------------------------------------------------------------------------+
| 권한 한 건을 만들어 access_list 에 추가한다  (source: 「예외 N번」, 만료 시각 expires 도 적는다) |
+--------------------------------------------------------------------------------------------------+
   |
   v  예외를 모두 꺼낸 뒤
access_list 를 리턴한다  (역할로 받은 권한 + 예외로 받은 권한)
```

**문법 상자 — 리스트 이어 붙이기**

`+` 로 리스트 두 개를 이으면, 두 리스트의 값이 차례로 들어 있는 새 리스트가 됩니다.

```python
first_list = ["QUERY", "CHANGE"]                                  # 첫째 리스트
second_list = ["SETTLE"]                                         # 둘째 리스트
print(first_list + second_list)                                  # 두 리스트를 이은 새 리스트를 출력한다

first_list = first_list + second_list                            # 이은 리스트를 first_list 에 다시 담는다
print(first_list)                                                # first_list 가 길어진 것을 출력한다
```

실행 결과:

```
['QUERY', 'CHANGE', 'SETTLE']
['QUERY', 'CHANGE', 'SETTLE']
```

- `role_list = role_entries(user, info)` 로 그 사용자의 권한 리스트를 만들고, `access_list = access_list + role_list` 로 `access_list` 뒤에 이어 붙인 리스트를 `access_list` 에 다시 담습니다.

> **여기부터 문제입니다.** 위는 읽을거리였고, 아래에서 직접 합니다.

## 실습 6-1 · 역할·예외 합친 권한 현황 만들기

**이런 상황이 있습니다**

- **지금은**: 누가 어떤 권한을 갖고 있는지 알려면 사용자 파일, 역할 파일, 예외 파일을 따로따로 열어 맞춰 봐야 합니다. 퇴사자나 만료된 예외가 섞여 있어도 한눈에 보이지 않습니다.
- **그래서 만드는 것**: `build_access_list` 입니다. 사용자마다 역할로 받은 권한 리스트(미리 채운 `role_entries`)를 모으고, 예외로 받은 권한도 한 건씩 만들어 하나의 리스트로 리턴합니다. 건마다 어떻게 받았는지(`source`)와 재직 여부(`employed`)를 적습니다.
- **실행하면**: 단계 1은 현황 리스트를 한 줄씩 출력하고, 단계 2는 사용자별 권한 개수를 출력합니다.
- **현업에서는**: 접근 점검 도구도 먼저 「누가 어떤 권한을 어떤 방법(역할 · 예외)으로 갖고 있나」 현황 리스트부터 뽑습니다.

**할 일**

1. `review_list.py` 와 `exercise6-1_run.py` 두 파일을 만들고, `build_access_list` 본문을 직접 씁니다.
2. 실행해서 <mark>부여돼 있는 권한 현황</mark>(단계 1: 현황)과 <mark>사용자별 권한 개수</mark>(단계 2: 점검)를 읽습니다.

**`review_list.py`**

```python
from rbac import USERS, ROLES                                    # Unit 1에서 만든 사용자 · 역할 딕셔너리를 불러온다
from exception_policy import EXCEPTIONS                          # Unit 2에서 만든 예외 리스트를 불러온다


def role_entries(user, info):                                    # 사용자 이름과 그 사용자의 정보 딕셔너리를 받는 함수
    """사용자 한 명이 역할로 받은 권한을 현황의 권한 한 개씩 만들어 리스트로 리턴한다.
    현재 갖고 있는 권한을 정리하기 시작할 때 쓴다.
    """
    role = info["role"]                                          # 그 사용자의 역할을 꺼낸다
    entries = []                                                 # 역할로 받은 권한을 담을 빈 리스트
    for permission in ROLES.get(role, []):                       # 역할의 권한을 하나씩 꺼낸다(역할 파일에 없는 역할이면 빈 리스트)
        entry = {                                                # 현황의 권한 한 건을 만든다
            "user": user,                                        # 사용자
            "permission": permission,                            # 권한
            "source": f"역할 {role}",                              # 받은 방식
            "employed": info["employed"],                        # 재직 여부
        }
        entries.append(entry)                                    # 리스트에 추가한다
    return entries                                               # 역할로 받은 권한 리스트를 리턴한다


def build_access_list():                                         # 지금 부여돼 있는 권한을 모두 모아 리스트로 만드는 함수
    """부여된 권한을 사용자별 · 권한별 리스트로 모은다.
    정기 점검을 시작할 때 누가 무엇을 갖고 있는지 정리하는 데 쓴다.
    """
    # ← 아래를 직접 씁니다 (주석은 두고 각 주석 바로 아래 줄에 씁니다)
    # 1. 현황을 담을 빈 리스트 access_list 를 만든다
    # 2. USERS 에서 user, info 를 하나씩 꺼낸다 (.items())
    # 3.   role_entries(user, info) 를 role_list 에 담는다 (그 사용자가 역할로 받은 권한 리스트)
    # 4.   access_list 와 role_list 를 + 로 이은 리스트를 access_list 에 다시 담는다
    # 5. EXCEPTIONS 에서 exception 을 하나씩 꺼낸다
    # 6.   exception["user"] 를 user 에 담는다
    # 7.   USERS[user] 를 user_info 에 담는다 (그 사용자의 정보 딕셔너리)
    # 8.   exception["id"] 를 exception_id 에 담는다
    # 9.   f"예외 {exception_id}번" 을 source_text 에 담는다 (받은 방식 문자열)
    # 10.  딕셔너리 entry 를 만든다: "user" 는 user, "permission" 은 exception["permission"], "source" 는 source_text, "employed" 는 user_info["employed"]
    # 11.  entry["expires"] 를 exception["expires"] 로 정한다 (예외에만 있는 키)
    # 12.  access_list 에 entry 를 추가한다
    # 13. access_list 를 리턴한다
```

- 본문은 모두 함수 안이라 앞에 공백 4개를 넣고(Tab 키 한 번), `for` 안쪽은 공백 4개 더(8개) 넣습니다. 마지막 `return` 은 `for` 밖이므로 공백 4개입니다. `role_entries` 는 미리 채워 두었으니 그대로 둡니다.
- 10번의 딕셔너리는 한 줄에 쓰거나, `{ }` 안에서 `,` 뒤에 줄을 바꿔 써도 됩니다.
- 채우기 전에 실행하면 `TypeError: object of type 'NoneType' has no len()` 오류가 납니다. 함수가 아무것도 리턴하지 않아 `len(access_list)` 를 셀 수 없기 때문입니다.

**`exercise6-1_run.py`** — 그대로 붙여 넣습니다. 학생이 쓰는 줄은 없습니다. 단계 1은 현황을 한 줄씩 출력하고, 단계 2는 사용자별 권한 개수를 셉니다.

```python
from review_list import build_access_list                        # 방금 만든 현황 함수를 불러온다

access_list = build_access_list()                                # 지금 부여돼 있는 권한 현황을 만든다

print("--- 단계 1: 현황 - 부여돼 있는 권한", len(access_list), "건")   # 단계 1 시작을 알리는 줄
for entry in access_list:                                        # 현황의 권한을 한 건씩 꺼낸다
    print(entry["user"], entry["permission"], "<-", entry["source"], "| 재직", entry["employed"])   # 사용자 · 권한 <- 출처 | 재직 여부를 출력한다

print("--- 단계 2: 점검 - 사용자별 권한 개수")                     # 단계 2 시작을 알리는 줄
counts = {}                                                      # 사용자 → 권한 개수를 담을 빈 딕셔너리
for entry in access_list:                                        # 현황의 권한을 한 건씩 꺼낸다
    count_key = entry["user"]                                    # 세는 기준이 되는 키
    old_count = counts.get(count_key, 0)                         # 그 키의 지금까지 센 수(처음이면 0)
    counts[count_key] = old_count + 1                            # 1 늘려서 다시 적는다
print(counts)                                                    # 사용자별 개수를 출력한다
```

   - (가) 실행한 출력 전체를 붙여 넣고, 부여돼 있는 권한이 모두 몇 건인지, 그중 예외로 받은 권한이 몇 건인지, 현황에 권한이 하나도 없는 사용자가 있다면 누구이고 그 이유는 무엇인지 적어 주세요.
     - 현황에 권한이 하나도 없는 사용자는 `config/users.json` 의 사용자와 출력의 사용자를 비교해 찾고, 이유는 그 사용자의 역할이 `config/roles.json` 에 있는지 열어 확인합니다.
   - (나) [핵심 질문] 현황 리스트에는 판정 함수(`check_permission` · `evaluate_access`)가 이미 거부하는 권한도 들어 있습니다. 어떤 권한이 그런지 예를 하나 들고, 거부되는 권한을 리스트에서 빼지 않고 남겨 두는 것이 점검에 왜 필요한지 적어 주세요.

## 실습 6-1 정리

| 하려는 일 | 코드 · 말 |
|---|---|
| 현황의 권한 한 건 | 딕셔너리. 키는 `user` · `permission` · `source` · `employed` (예외 권한은 `expires` 도) |
| 사용자와 정보를 같이 꺼내기 | `for user, info in USERS.items():` |
| 사용자가 역할로 받은 권한 리스트 | `role_list = role_entries(user, info)` (`role_entries` 는 미리 채움) |
| 리스트 이어 붙이기 | `access_list = access_list + role_list` |
| 예외를 받은 사용자의 정보 | `user_info = USERS[user]` |
| 예외로 받은 권한에만 추가하는 키 | `entry["expires"] = exception["expires"]` |
