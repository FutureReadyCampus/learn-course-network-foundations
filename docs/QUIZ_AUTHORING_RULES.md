# 퀴즈 작성 및 검토 규칙

## 1. 퀴즈의 역할과 초보자 관점

퀴즈는 설명을 대신하지 않고, 학습자가 방금 읽은 내용을 이해했는지 확인한다. 처음 배우는 사람에게 생소한 용어와 규칙은 문제보다 먼저 본문에서 쉬운 말과 예시로 설명한다. 본문에 근거가 없거나 다른 페이지의 지식이 필요한 문제는 설명을 보강하거나 삭제한다.

## 2. 퀴즈 형식과 정답 위치

퀴즈는 객관식으로만 만든다. 단답형은 만들지 않는다. 객관식은 기본적으로 보기 5개를 사용하고, 문제에서 요구한 답의 형태와 보기의 형태를 맞춘다. 정답 번호는 1~5번에 최대한 고르게 분산하고, 같은 번호가 연달아 반복되지 않는지 확인한다.

## 3. 페이지 전체를 아우르는 문제

페이지에서 여러 단계나 개념을 배운다면, 마지막에는 그 내용을 함께 이해했는지 확인하는 종합 문제를 고려한다. 예를 들어 TCP 종료 페이지라면 세그먼트에 FIN과 ACK가 함께 실릴 수 있는지 같은 세부 사실보다, 양쪽이 각자 송신을 끝내고 상대가 확인하는 전체 흐름을 묻는다. 단, 페이지의 핵심이 하나라면 종합 문제를 억지로 추가하지 않는다.

## 4. 문제의 위치와 정답 노출

쉬운 확인 문제는 해당 개념을 설명한 문단 뒤에 배치해, 막 배운 내용을 바로 떠올려 보게 한다. 여러 문단에 걸쳐 설명한 내용은 근거가 나온 뒤에 묻는다. 앞 문제의 보기나 정답이 뒤 문제의 답을 그대로 알려주지 않는지도 확인한다.

## 5. 보기와 오답의 품질

오답 보기는 초보자가 실제로 헷갈릴 법한 생각을 반영한다. 발문과 무관한 엉뚱한 답으로 정답을 쉽게 알아맞히게 하지 않는다. 정답만 유난히 길거나 구체적이라 눈에 띄지 않게 하고, 모든 보기가 문법과 의미상 같은 종류의 답이 되도록 맞춘다.

## 6. 정답 피드백

오답 피드백은 “다시 확인해 보세요”처럼 막연하게 끝내지 않는다. 왜 그 선택이 맞지 않는지, 본문에서 어떤 기준을 다시 보면 되는지 짧게 알려준다. 정답 피드백도 정답만 반복하지 말고 핵심 이유를 덧붙인다.

## 7. 불확실한 수정 방향

페이지의 학습 목표가 불분명하거나 타당한 수정 방향이 여러 개라면 임의로 결정하지 않는다. 왜 선택이 필요한지 짧게 설명하고 A/B/C 선택지를 제시하며, 추천안을 표시한다. 사용자가 고르기 전에는 그 선택에 의존하는 문항을 수정하거나 게시하지 않는다.

## 8. 페이지 목표와 문항 선택

퀴즈를 만들기 전에 이 페이지에서 학습자가 꼭 이해해야 할 핵심을 먼저 정리한다. 문항은 그 핵심을 확인하는 데 우선순위를 두고, 애니메이션의 장식적인 숫자나 본문에 잠깐 나온 주변 사실은 페이지 목표에 꼭 필요할 때만 묻는다.
