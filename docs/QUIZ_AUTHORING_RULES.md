# 퀴즈 작성 및 검토 규칙

이 규칙은 Network Foundations의 퀴즈를 만들거나 고치는 AI 세션이 초보자 관점과 페이지별 학습 목표를 일관되게 다루도록 돕는다. 퀴즈는 본문 학습을 확인하는 짧은 체크포인트이며, 페이지의 설명을 대신하지 않는다.

## 기본 원칙

1. **페이지의 학습 목표를 먼저 확인한다.** 해당 페이지를 처음 읽는 사람이 무엇을 이해하고 다음에 무엇을 할 수 있어야 하는지 한 문장으로 적는다. 문항은 그 목표를 직접 확인해야 한다.
2. **초보자가 본문에서 배운 내용만 묻는다.** 새로운 용어와 규칙은 퀴즈보다 먼저 쉬운 말로 설명하고, 생활 예시와 혼동하기 쉬운 구분을 연결한다. 다른 페이지나 외부 지식을 알아야만 답할 수 있는 문항은 추가 설명을 먼저 넣거나 삭제한다.
3. **짧은 답 문제는 만들지 않는다.** 퀴즈는 객관식으로 작성한다. 선택지는 기본적으로 5개를 사용한다.
4. **문항 수보다 흐름을 우선한다.** 첫 문단 뒤에는 쉬운 확인 문제를 둘 수 있고, 설명이 쌓인 뒤에는 적용이나 비교 문제를 둔다. 정해진 문항 수를 채우려고 같은 사실을 되풀이하지 않는다.
5. **문항을 배운 내용 뒤에 배치한다.** 인라인 퀴즈는 답의 근거가 본문에 먼저 나온 뒤 표시되게 한다. 앞 문항의 보기나 정답이 뒤 문항의 답을 그대로 알려주지 않는지 확인한다.

## 페이지 전체를 묶는 종합 문제

각 페이지에서 다룬 핵심이 여러 단계나 구분으로 이루어져 있다면, 그 관계를 함께 묻는 종합 문제를 고려한다. 종합 문제는 사소한 문구나 계산 하나가 아니라 “이 단계들이 함께 어떤 결과를 만드는가?”, “이 두 역할을 함께 보면 무엇을 알 수 있는가?”처럼 페이지를 다 읽고 이해했는지 확인한다.

예를 들어 TCP 종료 페이지라면 FIN과 ACK가 실제 세그먼트에 함께 실릴 수 있는지 같은 부가 사실보다, 양쪽이 각자 송신 종료를 알리고 상대가 확인하는 흐름과 마지막 상태 정리를 묻는 편이 페이지의 핵심을 더 잘 확인한다.

종합 문제가 모든 페이지에 의무적으로 필요한 것은 아니다. 페이지의 목표가 하나의 간단한 사실이라면 쉬운 확인 문제 하나로 충분할 수 있다. 종합 문제를 넣더라도 이미 앞 문항에서 답 전체를 노출하지 않게 하고, 해당 페이지 본문으로 풀 수 있게 한다.

## 객관식 품질 기준

- 발문이 묻는 유형과 선택지의 유형을 맞춘다. “몇 개인가요?”에는 수량을, “무엇인가요?”에는 대상이나 개념을, “왜 그런가요?”에는 이유를 답하게 한다.
- 선택지는 문법과 의미 범주를 맞춘다. 정답만 유난히 길거나 자세해서 눈에 띄지 않게 한다.
- 오답은 초보자가 할 법한 혼동을 드러내도록 만든다. 질문과 무관한 엉뚱한 답으로 정답을 쉽게 찾게 하지 않는다.
- 피드백은 정답을 반복하는 데 그치지 말고, 핵심 이유나 다시 볼 본문 기준을 한 문장으로 설명한다.
- 정답 위치를 여러 선택지에 분산하고, 연속되는 위치 패턴이 생기지 않았는지 확인한다.
- 기술적으로 정확한 표현을 쓰고, 예시를 일반 규칙처럼 과장하지 않는다.

## 검토와 불확실성 처리

문항마다 다음을 확인한다.

- 초보자가 이 페이지를 읽고 답할 수 있는가?
- 문항이 페이지의 핵심 목표를 확인하는가, 아니면 주변부 세부사항만 묻는가?
- 근거가 문제보다 먼저 설명되었는가?
- 앞 문항이나 보기에서 정답이 유출되지 않는가?
- 발문, 선택지, 정답, 피드백이 서로 일치하는가?

둘 이상의 타당한 수정 방향이 있거나 페이지의 학습 목표가 불분명하면 임의로 고르지 않는다. AI 세션은 간단한 근거와 함께 **A / B / C** 선택지를 제시하고, 권장안을 표시해 사용자 결정을 기다린다. 선택이 필요한 동안에는 해당 결정에 의존하는 문항 수정이나 게시를 진행하지 않는다.
