## 기준과 읽는 방법

- 원고 기준: GitHub `stage`의 `1e473dd979d8d9948b1ade7d260620d9e26e7a56`. `main` 비교 기준: `e6544d51196b6a9f165c1b1c12c61abac1af9296`.
- 두 기준은 동일하지 않다. Unit 구성은 같지만 Unit 1 설명 일부와 Unit 2~4의 원고·퀴즈 등에 차이가 있다. 표의 페이지와 내용은 위 stage 스냅샷 기준이다. 이후 병합·페이지 재구성 시 다시 대조한다.
- 대상: **Unit 2 Lesson 2~Unit 10의 31개 Lesson**. Unit 1의 4개 Lesson과 Unit 2 Lesson 1은 선행 설명 연결만 포함한다. 심화편 Unit 11~14는 포함하지 않는다.
- `UxLy Pz`는 이 스냅샷의 표시 위치다. 클릭하면 해당 SHA의 원고 제목 줄로 이동한다. 끝의 원본 목록에는 기존 Lesson ID를 함께 기록했다. 디렉터리 번호는 재편 전 번호가 남아 있으므로 Unit 번호로 해석하지 않는다. 영구 Page ID는 만들지 않는다.
- **원고에서 관찰한 사실:** 설명이 있는 위치와 후속 원고가 사용하는 개념. **이 문서의 제안:** 핵심 선정, 요구 수준, 새 복습 연결. 새로 제안하는 연결은 표에 따로 표시했다. 후속 위치는 대표 사용처이며 모든 등장 위치의 색인은 아니다.
- 표의 문장은 학습 목표 초안이다. 용어의 모든 기술적 예외를 확정한 정의나 바로 게시할 문항으로 취급하지 않는다. 상충·단순화는 아래 검토 쟁점에 남겼다. 학습 효과를 측정했다고 주장하지 않는다.

### 요구 수준

| 표기 | 학습자에게 기대할 것 | 확인 예 |
| --- | --- | --- |
| R · 회상 | 핵심 용어와 짧은 뜻을 스스로 떠올린다. | “요청에 응답해 서비스를 제공하는 역할은?”에 Server/서버를 떠올린다. |
| A · 구별·적용 | 주어진 상황에서 개념·계층·역할의 차이를 설명하거나 고른다. | 같은 노트북이 다른 통신에서는 Server가 될 수 있음을 판단한다. |
| L · 찾아보기 | 지금 모든 이름·값·절차를 외우지 않아도 된다. 필요한 역할과 다시 읽을 위치를 안다. | 헤더 도식을 보고 특정 필드의 위치를 찾는다. |

한 개념의 이름·뜻은 R, 그 개념을 쓰는 상황은 A일 수 있다. 따라서 R/A는 개념을 서로 배타적인 상자로 나누는 분류가 아니다. L은 본문 삭제나 해당 페이지 평가 제거를 뜻하지 않는다. 모든 페이지의 기존 평가 원칙은 유지하고, 문항 목표와 내용의 정합성은 #32와 후속 검토한다.

## 다음 검토의 초점

1. Unit 2 Lesson 2의 Host/Endpoint/Client/Server는 제안한 R/A 수준이 적절한지, Peer와 특수 장비명은 L로 두어도 되는지 확인한다.

3. 선정표를 검토한 뒤 누적 복습 배치표를 작성한다. 현재 페이지 통과와 누적 복습 기록은 구분하고, 누적 오답으로 진도를 다시 잠그지 않는 원칙을 유지한다.
