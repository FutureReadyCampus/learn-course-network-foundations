2. Page 1: "...DPI 기반의 능동형 보안으로 넘어간다. ... 방화벽은 ...정책을 정했지만, 탐지 장비는 ...탐지 규칙이 핵심이다." -> "방화벽은 ...정한다. 탐지 장비는 ...핵심이다." / 대비 두 문장으로 나눔, "상위 내용"을 "그 위 계층의 내용"으로.
3. Page 2 (막을까, 알리기만 할까?): "...IPS를 두어 검증된 규칙만 차단으로 쓴다. 서버 구역 안의 8080 구간은 평문이라고 가정하고, 인터넷에서 오는 TLS는 ...들어오므로 IPS는 ...모두 본다. 사무실 스위치의 ...(...)." -> 문장 6개로 분리 / 원인(TLS가 어디서 끝나는지)과 결론(IPS가 보는 범위)을 따로 읽히게 함.
4. Page 2: "가짜 RST로 연결을 끊으려는 개입은 시도할 수 있지만 진짜 응답보다 늦으면 실패한다." -> "가짜 RST(연결을 끊으라는 신호)를 보내 연결을 끊어 보려는 시도는 할 수 있다. 하지만 진짜 응답보다 늦게 도착하면 실패한다." / 명사 덩어리를 동사로, 용어 풀이.
5. Page 2: "같은 IPS라도 장애 시 동작을 어떻게 두느냐에 따라 위험이 달라지므로, 장비를 고르는 기준에 이 항목을 넣는다." -> "...동작 설정에 따라 위험이 달라진다. 그래서 장비를 고르는 기준에 이 항목을 넣는다." / 원인·결과 분리.
6. Page 3 (공격의 '지문'은 어떻게 찾을까?): "HTTPS의 Payload는 암호문이라(혼공네트 07-2) TLS가 풀리기 전 구간에 놓인 센서는 패턴을 읽지 못한다." -> "HTTPS의 Payload는 암호문이다(혼공네트 07-2). 그래서 TLS가 풀리기 전 구간에 놓인 센서는 패턴을 읽지 못한다." / 이유와 결과를 나눔.

8. Page 4 (정상 요청이 공격으로 찍혔다면?): "규칙이 공격이 아닌 것을 공격으로 판단하면 오탐, 실제 공격을 놓치면 미탐, 공격을 맞게 잡으면 정탐이다." -> 오탐 문장 / 미탐·정탐 문장으로 분리, "공격이 아닌 것"을 "정상 요청"으로 / 개념 세 개가 한 문장에 몰려 있었음.
9. Page 4: "이상 행위 기반 탐지는 평소의 사용 기준을 익힌 뒤 거기서 벗어난 행동을 찾는다." -> "먼저 ...익힌다. 그리고 거기서 벗어난 행동을 찾는다." / 두 단계를 두 문장으로.
