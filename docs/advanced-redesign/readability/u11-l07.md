# U11 Lesson 7 문장 가독성 수정 기록

- 요약: 본문·퀴즈 문장 약 30곳 수정, 한 문장을 둘 이상으로 나눈 곳 약 25곳. 본문 문장 138 → 166개, 평균 47.0 → 39.2자, 최대 105 → 87자, 70자 초과 25 → 3개.
- 풀이를 더한 용어: 서버 풀(서버 여러 대를 묶은 것), 부하 분산 장치(요청을 여러 서버에 나눠 주는 장치), 펌웨어(장비 내장 프로그램). 오리진 서버는 "정식 응답을 만드는 원래 서버"로 풀어 씀.
- 손대지 않은 곳: 「이 Lesson에서 가져갈 것」·「이번에 쓴 생각법」 상자(형식 유지, 상자 안 긴 줄 3개 70자 초과), 표 셀, 코드·주소, 퀴즈 보기(정답·길이 균형 유지). 70자 초과로 남은 본문 문장은 없음(남은 3개는 모두 상자).
- 문단 수·question_placements·illustrations 위치 그대로.

## 대표 수정

1. Page 1 「손님 대리인과 서버 경비는…」
   - 이전: 표준 문서(RFC 9110)는 이 경비를 게이트웨이, 다른 이름으로 리버스 프록시라 부르고 이렇게 정의한다. 바깥쪽 연결에 대해서는 오리진 서버처럼 행동하지만, …
   - 이후: …리버스 프록시라 부른다. 바깥쪽 연결에는 오리진 서버처럼 행동하면서 받은 요청은 안쪽의 다른 서버로 전달하는 중개자라는 뜻이다.
   - 이유: "이렇게 정의한다" 뜸 들이기 제거, 문장 분리.
2. Page 1
   - 이전: 고객 브라우저는 … TCP 연결을 맺는데, 그 연결을 받는 것은 앞단의 리버스 프록시다.
   - 이후: …TCP 연결을 맺는다. 이 연결을 받는 것은 앞단의 리버스 프록시다.
   - 이유: "~는데" 연결 어미를 끊어 주어 분명히.
3. Page 2 「서버 앞 첫 관문은…」
   - 이전: IPS는 경로 안에 놓인 인라인 장치라서, 정책에 따라 패킷을 통과시키거나 버려 원래 연결에 직접 영향을 준다. 주로 … 통제하고, 알려진 공격 패턴(Signature)을 대조하거나 DPI로 …
   - 이후: IPS는 경로 안에 놓인 인라인 장치다. 정책에 따라 … 버리므로 … 영향을 준다. 주로 … 통제한다. 알려진 공격 패턴을 대조하거나 …
   - 이유: 장치 정의·동작·검사 기준을 문장별로 분리.
4. Page 2
   - 이전: 같은 규칙이라도 TLS가 풀리기 전에 놓인 센서는 암호문을 대조할 뿐이고, 풀린 뒤에 놓인 센서여야 요청 내용을 대조할 수 있다.
   - 이후: …암호문만 대조한다. 요청 내용을 대조하려면 TLS가 풀린 뒤에 놓여야 한다.
   - 이유: 대구를 두 문장으로 분리.
5. Page 3 「암호는 어디서 풀어야 할까?」
   - 이전: 서버 대신 TLS 연결을 받아 암호를 풀고, 풀린 요청을 안쪽으로 넘기는 장치를 TLS 종단 프록시(SSL Accelerator라고도 부른다)라고 부른다.
   - 이후: …넘기는 장치가 있다. 이를 TLS 종단 프록시라 하고, SSL Accelerator라고도 부른다.
   - 이유: 긴 관형절을 풀고 새 용어를 따로 제시.
6. Page 3
   - 이전: 이 기능은 부하 분산 장치나 WAF와 한 상자에 합쳐지기도 한다.
   - 이후: 이 기능은 부하 분산 장치(요청을 여러 서버에 나눠 주는 장치)나 다음 Page의 WAF와 …
   - 이유: 처음 나오는 용어 풀이, WAF는 다음 Page에서 설명함을 알림.
7. Page 4 「AI 서버를 노린 이상한 요청을…」
   - 이전: 이런 주소에는 `customer=1042' OR '1'='1`처럼 데이터베이스 질의를 비틀어 남의 상담 이력까지 꺼내려는 요청이 흔히 들어온다.
   - 이후: 이런 주소에는 공격 요청이 흔히 들어온다. 예를 들어 `customer=1042' OR '1'='1`은 데이터베이스 질의를 비틀어 …
   - 이유: 긴 수식절을 먼저 결론(공격 요청)으로 요약하고 예를 뒤에 둠.
8. Page 4
   - 이전: 그래서 처음에는 차단 대신 기록만 하는 모드로 돌려 보고, 실제 요청에 맞게 규칙을 다듬은 뒤 차단으로 바꾸는 식으로 점검을 이어 간다.
   - 이후: …기록만 하는 모드로 돌려 본다. 실제 요청에 맞게 규칙을 다듬은 뒤에야 차단으로 바꾼다.
   - 이유: "~하는 식으로 ~을 이어 간다" 군더더기 제거.
9. Page 5 「앞단 한 대로…」
   - 이전: 원 서버의 주소를 바깥에 드러내지 않고, 요청을 … 나눠 보내고, TLS를 대신 끝내고, … 돌려주고(캐시), WAF 검사를 붙인다.
   - 이후: 원 서버의 주소를 바깥에 감추고, 요청을 … 나눠 보낸다. TLS도 대신 끝낸다. … 돌려주고(캐시), WAF 검사도 붙인다.
   - 이유: 다섯 동작이 한 문장에 이어지던 것을 셋으로 나눔.
10. Page 5
   - 이전: 누가 보낸 요청인지 알려면 앞단이 원래 고객 주소를 헤더(표준 `Forwarded`, 흔히 쓰는 `X-Forwarded-For`)에 덧붙여 넘기도록 설정해야 한다.
   - 이후: …헤더에 덧붙여 넘기도록 설정해야 한다. 표준 헤더는 `Forwarded`, 흔히 쓰는 헤더는 `X-Forwarded-For`다.
   - 이유: 괄호 속 부연을 별도 문장으로.
11. 퀴즈 p06 q02 prompt
   - 이전: 장비 A는 '…', 장비 B는 '…'고 적혀 있다.
   - 이후: 장비 A에는 '…'고 적혀 있다. 장비 B에는 '…'고 적혀 있다.
   - 이유: 두 장비 설명을 문장별로 분리.
12. 퀴즈 p05 q02 prompt
   - 이전: …앞단 장비의 펌웨어를 업데이트하느라 재시작한 몇 분 동안 상담 페이지 전체가 열리지 않았다.
   - 이후: …펌웨어(장비 내장 프로그램)를 업데이트하려고 재시작했다. 그 몇 분 동안 상담 페이지 전체가 열리지 않았다.
   - 이유: 용어 풀이와 문장 분리.
