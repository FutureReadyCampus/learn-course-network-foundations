## 대표 수정

1. Page 1 (보안 점검, 무엇부터 물어야 할까?): "...점검을 지시했고, 담당은 ...지우다. 지우는 ...한계, 곧 ...점이 출발점이라고 느낀다." -> "...지시했다. 담당은 지우다. 지우는 ...한계를 떠올린다. 접속 IP만 보고는 ...점이 이번 점검의 출발점이다." / 주어 셋이 한 문장에 섞여 있었다.
2. Page 1: "...방화벽, IPS, NAC, SIEM 같은 이름이 줄줄이 적혀 있어 어디서부터 봐야 할지 막막하다." -> "낯선 이름이 줄줄이 적혀 있다. 방화벽, IPS, NAC(사내망에 들어오는 기기를 확인하는 장치), SIEM 같은 것들이다. 지우는 ...막막하다." / NAC 첫 등장에 풀이를 더하고 문장을 나눔.
3. Page 1: "🔁 같은 모양 찾기로, 장치가 ...있나, ...있나, ...하나를 묻고, 패킷과 Stream 중 ...묻는다." -> "두 가지를 묻는다. 하나는 ... 다른 하나는 ..." / 나열이 겹쳐 무엇을 묻는지 흐렸다.
4. Page 1: "표준 방식은 802.1X와 RADIUS다." -> "802.1X(스위치 포트에서 기기를 인증하는 표준)와 RADIUS(신원을 확인해 주는 인증 서버)다." / 약어 첫 등장 풀이.
5. Page 2 (회사 기기인지 무엇으로 알아볼까?): "Probe는 ...관찰한다(🔁 ..., 한결디자인에서는 관리 주소 ...)." -> "...관찰한다. 🔁 ...같은 모양이고, 한결디자인에서는 관리 주소가 ...이다." / 괄호 속 긴 덧말을 풀어 씀.
6. Page 2: "...줄을 더하고 빼야 하므로, 누가 언제 장부를 고치는지 담당을 정해 두지 않으면 곧 현실과 어긋난다." -> "...더하고 빼야 한다. 누가 언제 고칠지 담당을 정해 두지 않으면 장부는 곧 현실과 어긋난다." / 이유와 결과를 나눔.
7. Page 3 (포트를 내리면 끝일까?): "ARP는 ...구조라(혼공네트 03-1), ...길을 잃게 만든다. 이는 ...같은 원리라 ...다루며, ...권하지 않는 편이다." -> 네 문장 / 원리 수준 내용은 그대로 두고 "~라 ~하며" 연결만 끊음.
8. Page 4 (접속하자마자 안내 페이지가 뜨는 이유는?): "...보면, 안내 페이지로 가라는 응답(HTTP 리다이렉트, ...)을 먼저 보낸다." -> "...보면 응답을 먼저 보낸다. 안내 페이지로 가라는 응답(HTTP 리다이렉트, ...)이다." / 동사와 긴 수식어를 떼어 놓음.
9. Page 4: "HTTPS는 TLS가 ...확인하는데, 끼어든 응답이 ...척하면 ...실패한다." -> "HTTPS에서는 TLS가 ...확인한다. 그래서 끼어든 응답이 ...실패한다." / 원인과 결과를 나눔.
10. Page 5 (들어오기 전에 신분을 확인하려면?): "...노트북은 ...쪽이고, 스위치는 ...문지기이며, RADIUS 서버는 ...담당자다." -> "노트북은 ...쪽이다. 스위치는 ...문지기이고, RADIUS 서버는 ...담당자다." / 세 역할을 한 문장에 몰아 넣었다.
