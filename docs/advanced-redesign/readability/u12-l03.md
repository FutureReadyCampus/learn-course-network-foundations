# U12 L03 문장 가독성 기록: 밖에서 사내 AI 서버로 들어오는 길: 포트 포워딩

- 요약: 고친 곳 31개 문장·구절(본문 25, 퀴즈 prompt·feedback 6), 두 문장 이상으로 나눈 문장 약 20개. 문단·블록 수, 퀴즈 수(14), `question_placements`(7)는 그대로.
- 지표(문장 수 / 평균 길이 / 최대 길이 / 70자 초과): 전 104 / 46.8 / 125 / 11 -> 후 124 / 39.4 / 89 / 6.
- 풀이를 더한 용어: 없음(헤어핀 NAT, CGNAT, 이중 NAT, 정적 매핑은 이 Lesson 안에서 이미 풀이됨).
- 손대지 않은 곳: 표 전체(구조·열 유지), 「가져갈 것」 Lookup 줄(찾아볼 항목 나열), 퀴즈 보기·정답(길이 균형 유지; audit ok), 주소·RFC 번호가 길게 들어간 70자 안팎 문장(수치를 쪼갤 수 없음).
- 구별 유지: 포트 포워딩(주소 바꿔 전달하는 변환 규칙) 대 방화벽 허용·차단, 헤어핀 NAT, CGNAT(`100.64.0.0/10`) 대 이중 NAT(사설 WAN) 표현은 뜻을 바꾸지 않고 문장만 나눔.

## 대표 수정

1. 변환표에 줄을 미리 적어 두면 어떨까?
   - 이전: 이 규칙 한 줄이 들어가면 바깥에서 `198.51.100.25:8080`으로 온 요청에 맞는 행이 생긴 셈이므로 공유기는 요청을 GPU PC로 넘길 수 있다.
   - 이후: 이 규칙 한 줄이 들어가면, 바깥에서 `198.51.100.25:8080`으로 온 요청에 맞는 행이 이미 있는 셈이다. 그래서 공유기는 요청을 GPU PC로 넘길 수 있다.
   - 이유: 원인-결과가 한 문장에 겹쳐 있어 둘로 나눔.
2. 포트 포워딩 설정 화면, 뭘 채워야 할까?
   - 이전: 규칙을 저장했다고 접속이 허용되고 보장되는 것은 아니다.
   - 이후: 규칙을 저장했다고 접속이 허용되는 것은 아니다.
   - 이유: "허용되고 보장되는"이 이중 피동으로 뜻이 흐려져 하나로 줄임.
3. 포트 포워딩 설정 화면, 뭘 채워야 할까?
   - 이전: 해결은 GPU PC에 같은 주소를 주도록 DHCP 예약(...)을 걸거나 PC 자체에 고정 주소를 설정하는 것이다. 고정 주소는 DHCP가 나눠 주는 범위 밖에서 골라야 다른 기기와 겹치지 않으므로, 가능하면 예약 쪽이 낫다.
   - 이후: 해결은 두 가지다. GPU PC에 늘 같은 주소를 주도록 DHCP 예약(...)을 걸거나, PC에 직접 고정 주소를 설정한다. 고정 주소는 ... 겹치지 않는다. 그래서 가능하면 예약 쪽이 낫다.
   - 이유: "~하는 것이다" 명사화를 풀고, 방법 두 가지와 판단(예약이 낫다)을 분리.
4. 박 팀장은 어떤 주소로 접속해야 할까?
   - 이전: 고객사에서 박 팀장의 요청이 나갈 때 ... 요청은 공유기 바깥쪽에서 `198.51.100.25:8080`을 목적지로 도착한다.
   - 이후: 박 팀장의 요청이 고객사에서 나갈 때, ... 요청은 `198.51.100.25:8080`을 목적지로 공유기 바깥쪽에 도착한다.
   - 이유: 주어(박 팀장의 요청)를 앞세우고 어순을 정리.
5. 박 팀장은 어떤 주소로 접속해야 할까?
   - 이전: 공유기 안에서 AI 서버가 돌아가는 것이 아니라, 공유기는 주소만 바꿔 전달하는 것이다.
   - 이후: AI 서버가 공유기 안에서 돌아가는 것이 아니다. 공유기는 주소만 바꿔 전달한다.
   - 이유: "~하는 것이 아니라 ~하는 것이다" 구문을 두 문장으로 분리.
6. 서비스가 둘이면 규칙도 둘일까?
   - 이전: AI 서버를 열고 나니 이번에는 직원들이 도면을 모아 두는 사내 도면 NAS(...)도 밖에서 열어 달라는 요청이 들어온다. 규칙을 하나 더 넣으면 될 것 같지만 그 전에 ...
   - 이후: AI 서버를 열고 나니 요청이 하나 더 들어온다. 직원들이 ... NAS(...)도 밖에서 열어 달라는 것이다. 규칙을 하나 더 넣으면 될 것 같다. 하지만 그 전에 규칙 하나가 몇 곳으로 보낼 수 있는지부터 확인해야 한다.
   - 이유: 긴 관형절을 문장 둘로 풀고 "하지만"으로 전환을 분명히 함.
7. 서비스가 둘이면 규칙도 둘일까?
   - 이전: 공인 주소 하나에서 같은 TCP 포트를 두 서버가 함께 쓸 수는 없고, 서비스마다 외부 포트를 나눠서 규칙을 추가한다.
   - 이후: ... 함께 쓸 수는 없다. 그러니 서비스마다 외부 포트를 나눠서 규칙을 추가한다.
   - 이유: 제약과 해결을 나눠 인과를 드러냄.
8. 사무실에서 공인 주소로 시험하면 왜 안 될까?
   - 이전: 출발지가 지우 PC 주소 그대로 GPU PC에 도착하면 GPU PC가 응답을 공유기를 거치지 않고 직접 보내, 지우 PC는 ... 응답을 받게 된다. 그래서 출발지까지 바꿔서 되돌려 줘야 하는데, 장비와 설정에 따라 지원하지 않을 수 있다(...).
   - 이후: ... GPU PC는 응답을 공유기를 거치지 않고 직접 보낸다. 그러면 지우 PC는 ... 응답을 받게 된다. 그래서 출발지까지 바꿔서 되돌려 줘야 한다. 하지만 장비와 설정에 따라 지원하지 않을 수 있다(...).
   - 이유: 헤어핀 NAT의 가장 어려운 설명(125자)을 단계별 문장으로 쪼갬. 기술 내용은 그대로.
9. 포워딩했는데도 왜 밖에서 안 열릴까?
   - 이전: 재택 직원 집이나 LTE 라우터를 쓰는 임시 현장 사무소처럼 공유기 WAN 주소가 `100.66.7.9`와 같이 `100.64.0.0/10` 안이라면, 통신사가 NAT를 한 번 더 두고 있다는 신호다(CGNAT, RFC 6598).
   - 이후: 재택 직원 집이나 LTE 라우터를 쓰는 임시 현장 사무소를 예로 들자. 공유기 WAN 주소가 `100.66.7.9`처럼 `100.64.0.0/10` 안이라면, 통신사가 NAT를 한 번 더 두고 있다는 신호다(CGNAT, RFC 6598).
   - 이유: 예시 장소와 판별 조건이 한 문장에 겹쳐 있어 분리(CGNAT 판별 기준 `100.64.0.0/10`은 그대로).
10. 포워딩했는데도 왜 밖에서 안 열릴까?
    - 이전: 이 Page의 요점은 안 열리면 서버부터 다시 설치하는 대신, 확인 순서를 정해 하나씩 지워 간다는 것이다.
    - 이후: 이 Page의 요점은, 안 열릴 때 서버부터 다시 설치하지 말고 확인 순서를 정해 하나씩 지워 간다는 것이다.
    - 이유: "~하는 대신" 번역투를 명령형 대비로 풀어 줌.
11. 포트를 열어도 정말 괜찮을까?
    - 이전: ... 답은 아니다. 포트 번호는 관례일 뿐이어서, 바꾸면 찾기가 조금 어려워질 뿐 열린 것은 같다.
    - 이후: ... 답은 아니다. 포트 번호는 관례일 뿐이다. 바꾸면 찾기가 조금 어려워질 뿐, 열린 것은 같다.
    - 이유: "~일 뿐이어서 ~일 뿐" 반복을 끊음.
12. 퀴즈 u12-l03-p06-q02 prompt
    - 이전: ... 라우터의 WAN 주소는 `100.72.14.3`이고 '내 IP 확인' 결과는 `203.0.113.200`이다.
    - 이후: ... 라우터의 WAN 주소는 `100.72.14.3`이다. '내 IP 확인' 결과는 `203.0.113.200`이다.
    - 이유: 두 단서(WAN 주소, 내 IP)를 문장으로 분리(보기·정답은 그대로).
