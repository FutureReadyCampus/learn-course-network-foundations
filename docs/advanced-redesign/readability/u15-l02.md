# U15 Lesson 2 (방화벽) 문장 가독성 검토

- 고친 곳: 본문 약 33개 문장 묶음 + 퀴즈 prompt 2개. 문장 수 127 → 159, 평균 46.4 → 37.4자, 최대 146 → 90자, 70자 초과 26 → 10.
- 나눈 문장: 본문 약 30개 문장을 둘 이상으로 나눔 (문단 수·표·코드·주소·`question_placements`·`illustrations` 그대로).
- 풀이를 더한 용어: 세션("연결 하나"), 정상 전이("상태 변화의 정상 순서"), IPS("공격을 막는 기능", 처음 쓰는 Page 4에서), UTM(정의 문장을 앞에 둠).
- 손대지 않은 곳: 남은 70자 초과 문장은 Unit 참조 괄호·`192.168.x.x` 주소·"가져갈 것/생각법" 상자 불릿이라 의미 단위가 끊기거나 형식 유지가 필요해 둠. 퀴즈 보기·feedback은 이미 짧아 prompt 2개만 수정. 서버 구역 이전(192.168.10.50 → 192.168.40.50)과 규칙 표는 그대로.

## 대표 수정

1. Page 1 (방화벽은 패킷의 무엇을 보고 막을까?)
   - 이전: 시연 때 연 포트 포워딩이 닫히지 않은 채 남아 있어, 인터넷에서 … SSH(22)와 모델 API(8080)가 모두 응답한다.
   - 이후: …닫히지 않고 남아 있다. 그래서 인터넷에서 … 모두 응답한다.
   - 이유: 원인과 결과를 두 문장으로 나눔.
2. Page 1
   - 이전: 패킷 필터링 방화벽은 경로 안(Inline)에 놓여 Packet 헤더의 … 보고 통과(Bypass)시키거나 차단(Drop)한다.
   - 이후: …경로 안(Inline)에 놓인다. Packet 헤더의 … 보고 통과(Bypass)시키거나 차단(Drop)한다.
   - 이유: 위치와 동작을 한 문장에 하나씩.
3. Page 1
   - 이전: 이때 중요한 것은 장비의 성능이 아니라 … 규칙이 늘수록 관리가 어려워지고 서로 충돌하기 쉬우며, 정책을 …
   - 이후: 여기서 따질 것은 … 규칙이 늘수록 관리가 어렵고 서로 충돌하기 쉽다. 정책을 …
   - 이유: "중요한 것은" 상투구 제거, "~하며" 연결 끊기.
4. Page 2 (AI 서버가 사내 PC와 같은 구역이라면?)
   - 이전: 스위치가 Frame을 L2에서 직접 전달하므로 게이트웨이를 거치지 않는다.
   - 이후: 스위치가 Frame을 L2에서 바로 전달한다. 그래서 통신이 게이트웨이를 거치지 않는다.
   - 이유: 원인과 결과 분리.
5. Page 2
   - 이전: …AI 서버를 `192.168.40.50:8080`으로 옮겼다. 사내 PC가 서버에 가려면 … 이 서버를 가리키던 설정, 곧 … 새 주소로 함께 바꿨고, 앞의 규칙 표도 …
   - 이후: …배정했다. 그리고 AI 서버를 `192.168.40.50:8080`으로 옮겼다. 이제 … 그래서 모든 접속이 … 설정도 새 주소로 함께 바꿨다. PC의 접속 주소와 … 가 그렇다. 앞의 규칙 표도 …
   - 이유: 220자 가까운 한 문단 덩어리를 동작 순서대로 쪼갬. 주소 이전 사실은 유지.
6. Page 3 (돌아오는 응답은 왜 막히지 않을까?)
   - 이전: TCP는 연결 전, 수립 중, 연결됨, 종료 같은 상태를 거치며(혼공네트 04-2), 방화벽은 이 변화를 세션 단위로 따라간다.
   - 이후: TCP 연결은 … 상태를 거친다(혼공네트 04-2). 방화벽은 이 변화를 세션(연결 하나) 단위로 따라간다.
   - 이유: 문장 분리, 세션 풀이 추가.
7. Page 3
   - 이전: …정상 전이에서 벗어난 패킷은 이상으로 보고 버린다.
   - 이후: 방화벽은 장부에 있는 연결의 응답만 통과시킨다. 상태 변화의 정상 순서(전이)에서 벗어난 패킷은 이상으로 보고 버린다.
   - 이유: 주어를 앞세우고 "전이"를 풀이.
8. Page 4 (세션 표가 가득 차면 무슨 일이 생길까?)
   - 이전: …세션 기록을 한 칸씩 쓰는데, 동시에 관리할 수 있는 세션 수는 이런 장비의 성능을 설명하는 기준 중 하나다.
   - 이후: …한 칸씩 쓴다. 동시에 관리할 수 있는 세션 수는 이런 장비의 성능 기준 중 하나다.
   - 이유: 두 문장으로 나누고 "설명하는" 군더더기 제거.
9. Page 4
   - 이전: 같은 숫자라도 IPS나 악성코드 검사 같은 기능을 함께 켜면 줄어드는 제품이 있을 수 있으니, …확인하자.
   - 이후: 같은 숫자라도 IPS(공격을 막는 기능)나 악성코드 검사를 함께 켜면 줄어드는 제품이 있을 수 있다. 그래서 … 확인하자.
   - 이유: 이 Lesson에서 처음 쓰는 IPS 풀이, 문장 분리.
10. Page 5 (포트 443이면 모두 웹 요청일까?)
    - 이전: …도메인 이름(…SNI)은 풀지 않고도 보일 수 있어 어느 서비스로 가는지는 가를 수 있지만, 요청 내용 자체를 보려면 …있어야 한다.
    - 이후: …은 암호를 풀지 않아도 보일 수 있다. 그래서 어느 서비스로 가는지는 가를 수 있다. 하지만 요청 내용 자체를 보려면 … 필요하다.
    - 이유: 3개 절을 세 문장으로.
11. Page 6 (한 대에 다 넣으면 무엇을 잃을까?)
    - 이전: 패킷 필터링, NAT·라우팅, … 등을 한 장비에 결합한 것이 UTM(Unified Threat Management)이다.
    - 이후: UTM(Unified Threat Management)은 여러 보안 기능을 한 장비에 결합한 것이다. 패킷 필터링, … 등이 들어간다.
    - 이유: 정의를 먼저, 기능 목록은 뒤에.
12. 퀴즈 u15-l02-p02-q02 prompt
    - 이전: …허용하려 했는데, 누군가 맨 위에 "…" 줄을 끼워 넣었다.
    - 이후: …허용하려 했다. 그런데 누군가 맨 위에 "…" 줄을 끼워 넣었다.
    - 이유: 긴 prompt를 나눔 (정답·보기 불변).
