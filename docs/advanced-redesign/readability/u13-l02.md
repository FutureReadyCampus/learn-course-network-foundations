# U13 L02 이중화로 장애에 대비하기 - 문장 가독성 검토 기록

요약
- 고친 문장 수: 약 28개 (수정 지점 25곳). 나눈 문장: 약 18개.
- 풀이를 더한 용어: 펌웨어(장비 안의 기본 프로그램), 이미지(서버 내용을 통째로 담은 틀), 스냅샷(어느 시점의 상태를 찍어 둔 것).
- 문장 수 107 -> 132, 평균 길이 43.2 -> 35.6자, 최대 112 -> 95자, 70자 초과 9 -> 1.
- 손대지 않은 곳: 퀴즈 전부(문장이 이미 짧고 보기 길이 균형을 지키기 위해), front matter, 「가져갈 것」·「생각법」 상자. 남은 70자 초과 1개는 Page 2 첫 문단의 따옴표 인용 뒤 문장 경계를 측정기가 못 나눈 것이다(실제 문장은 짧다).
- VRRP·페일오버·액티브/스탠바이·액티브/액티브·두 주인 상태(스플릿 브레인) 사실은 그대로 두고 문장만 나눴다. 새 용어(스플릿 브레인 등)는 더하지 않았다.

대표 수정

1. 예비 장비는 쉬게 둘까, 같이 일하게 할까?
- 이전: 액티브/스탠바이는 한 대만 일하고 한 대는 대기하다가, 일하는 장비가 고장 나면 넘겨받는 방식이다.
- 이후: 액티브/스탠바이는 한 대만 일하고 한 대는 대기하는 방식이다. 일하는 장비가 고장 나면 대기하던 장비가 넘겨받는다.
- 이유: "~하다가"로 이어진 문장을 나누고 넘겨받는 주어를 밝혔다.

2. 같은 Page
- 이전: 두 장비가 성능이 같고 평소 각각 60%를 쓴다면 한 대가 고장 났을 때 남은 한 대가 120%를 맡아야 해서 넘친다(가정).
- 이후: 두 장비의 성능이 같고 평소 각각 60%를 쓴다고 하자(가정). 한 대가 고장 나면 남은 한 대가 120%를 맡아야 해서 넘친다.
- 이유: 가정과 결과를 두 문장으로 분리했다.

3. 같은 Page
- 이전: 처리량이 모자라지 않고 안정이 목적이라면 스탠바이, 성능도 필요하다면 액티브/액티브로 하되 ... 용량을 잡는 것이다.
- 이후: 처리량이 모자라지 않고 안정이 목적이면 스탠바이를 고른다. 성능도 필요하면 액티브/액티브를 고르되, ... 용량을 잡는다.
- 이유: 명사 나열형 문장을 동사로 풀고 선택지별로 나눴다.

4. 장비가 바뀌어도 손님은 왜 같은 주소로 올까?
- 이전: 지금 일하는 장비가 주기적으로 "내가 맡고 있다"는 신호(하트비트)를 보내고, 그 신호가 정해진 시간 동안 끊기면 예비 장비가 VIP를 넘겨받는다.
- 이후: ...신호(하트비트)를 보낸다. 이 신호가 정해진 시간 동안 끊기면 예비 장비가 VIP를 넘겨받는다.
- 이유: 신호 보내기와 끊겼을 때의 동작을 나눴다.

5. 같은 Page
- 이전: 두 장비는 같은 네트워크 구간에 있어야 하고, 방식에 따라 가상 MAC을 쓰거나 주소록(ARP) 갱신을 알려 준다.
- 이후: 두 장비는 같은 네트워크 구간에 있어야 한다. 방식에 따라 가상 MAC을 쓰거나 주소록(ARP) 갱신을 알려 준다.
- 이유: 조건과 방식을 별개 문장으로 분리했다.

6. 같은 Page
- 이전: 예비 장비는 ... VIP를 가져가고, 일하던 장비도 멀쩡히 자기가 주인이라 여겨 둘 다 "내가 맡겠다"고 나선다.
- 이후: 예비 장비는 일하는 장비가 죽었다고 여겨 VIP를 가져간다. 일하던 장비는 멀쩡해서 자기가 주인이라 여긴다. 그래서 둘 다 "내가 맡겠다"고 나선다.
- 이유: 두 장비의 판단을 하나씩 말하고 결과를 이어서 두 주인 상태가 생기는 과정을 따라가게 했다.

7. 두 대를 뒀는데 왜 같이 멈췄을까?
- 이전: 두 장비를 같은 네트워크 구간(VLAN)을 지나는 서로 다른 스위치에 꽂고, 전원도 따로 공급하고, 가능하면 회선도 나눈다.
- 이후: 두 장비를 서로 다른 스위치에 꽂는다. 두 스위치는 같은 네트워크 구간(VLAN)을 지나게 한다. 전원도 따로 공급하고, 가능하면 회선도 나눈다.
- 이유: 수식어가 겹친 한 문장을 동작별로 나눴다.

8. 같은 Page
- 이전: 로드 밸런서를 ... 스위치 펌웨어를 올리던 날
- 이후: 스위치 펌웨어(장비 안의 기본 프로그램)를 올리던 날
- 이유: 처음 나오는 용어에 쉬운 풀이를 붙였다.

9. 고장 난 서버, 수리를 5일이나 기다려야 할까?
- 이전: ...만들어 둔 이미지로 새 VM을 바로 띄울 수 있고, 스냅샷으로 문제가 생기기 전 상태로 되돌릴 수도 있다.
- 이후: ...만들어 둔 이미지(서버 내용을 통째로 담은 틀)로 새 VM을 바로 띄울 수 있다. 스냅샷(어느 시점의 상태를 찍어 둔 것)으로 문제가 생기기 전 상태로 되돌릴 수도 있다.
- 이유: 설명 없이 나온 용어 두 개를 풀이하고 문장을 나눴다.

10. 몰리는 시간에만 서버를 늘릴 수 있을까?
- 이전: 컨테이너를 필요한 만큼 켜고 끄는 관리자가 오케스트레이션 도구이고, 이것이나 클라우드의 자동 확장 기능을 쓰면 ... 로드 밸런서에 자동으로 붙일 수 있다.
- 이후: ...오케스트레이션 도구다. 이 도구나 클라우드의 자동 확장 기능을 쓰면 부하에 따라 서버를 늘릴 수 있다. 헬스 체크를 통과한 서버만 로드 밸런서에 자동으로 붙일 수도 있다.
- 이유: 새 개념이 한 문장에 몰려 있어 개념마다 한 문장으로 나눴다.

11. 같은 Page
- 이전: 대가는 세 가지다. 쓰는 만큼 계속 내는 비용, 모델을 싣는 시간 때문에 늘어나는 데 몇 분의 시차(가정)가 있다는 점, 그리고 ... 처리된다는 점이다.
- 이후: 대가는 세 가지다. 첫째, 쓰는 만큼 계속 내는 비용이다. 둘째, ... 서버가 늘어나기까지 몇 분의 시차(가정)가 있다. 셋째, ... 처리된다.
- 이유: 나열을 순서대로 한 문장씩 풀어 쓰고 뒤틀린 "늘어나는 데 ... 시차" 표현을 바로잡았다.

12. 서버는 멀쩡한데 왜 한결봇이 통째로 멈췄을까?
- 이전: 해결의 방향은 고장을 없애는 것이 아니라, 고장이 나도 계속 돌아가게 설계하는 것이다.
- 이후: 고장을 없애려 하지 말고, 고장이 나도 계속 돌아가게 설계해야 한다.
- 이유: 추상적인 "해결의 방향은 ~것이다" 구조를 직접 문장으로 바꿨다.
