# U15 L04 가독성 수정 기록 (경보가 쏟아지고 장애가 났다)

- 고친 줄(문단·문항) 25곳, 문장을 나눈 곳 약 30곳. 문장 수 98 → 123, 평균 49.5 → 39.8자, 최대 214 → 117자, 70자 초과 21 → 8.
- 풀이를 더한 용어: 식별자("대상을 가리키는 정보"), 복호화("암호를 푸는").
- 손대지 않은 곳: 표 셀(구조·열 유지), 코드 규칙 줄, 「이 Lesson에서 가져갈 것」, 🧠 상자 형식, 문항 보기·정답, SIEM 영문 풀네임 문장(영어 철자 유지).
- 남은 70자 초과 8개 중 다수는 측정 도구가 인용문·코드·불릿 머리를 이어 붙인 결과다.

## 대표 수정

1. **흩어진 로그를 이으면** (도입)
   - 이전: 장비마다 관리 화면이 따로라 하나씩 돌며 로그를 보는데, 규칙 기반 장비는 정탐이든 오탐이든 로그를 내니 하루 수천 건의 경보에 묻혀 중요한 한 줄을 놓칠 때가 있다.
   - 이후: 장비마다 관리 화면이 따로라, 지우는 화면을 하나씩 돌며 로그를 본다. 규칙 기반 장비는 정탐이든 오탐이든 로그를 남기므로 경보가 하루 수천 건 쌓이고, 그 속에서 중요한 한 줄을 놓칠 때가 있다.
   - 이유: 세 절이 이어진 문장을 나누고 주어를 세움.
2. **흩어진 로그** (ESM)
   - 이전: 모으는 것은 "어디를 볼까"를 줄일 뿐 "무엇이 중요한가"를 정해 주지는 않는다.
   - 이후: 모으면 "어디를 볼까"는 줄지만 "무엇이 중요한가"는 정해지지 않는다.
   - 이유: 명사화된 "~을 줄일 뿐 ~을 정해 주지는" 구조를 동사로 풀음.
3. **흩어진 로그** (MAC/IP 연결)
   - 이전: NAC는 MAC으로, 방화벽과 IPS는 IP로 적으므로 DHCP 기록(...)으로 둘을 먼저 이어 붙인다.
   - 이후: NAC는 기기를 MAC으로 적고 방화벽과 IPS는 IP로 적는다. 그래서 DHCP 기록(...)으로 MAC과 IP를 먼저 이어 붙인다.
   - 이유: "둘"이 무엇인지 분명히 하고 두 문장으로 나눔.
4. **이 경보는 어떤 규칙이 울렸을까** (읽는 순서)
   - 이전: 먼저 괄호 앞에서 ...를 읽고, 괄호 안에서 ...를 읽고, 마지막으로 맨 앞의 동작으로 ...를 확인한다.
   - 이후: 먼저 괄호 앞에서 ...를 읽는다. 다음으로 괄호 안에서 ...를 읽는다. 마지막으로 맨 앞의 동작에서 ...를 확인한다.
   - 이유: 세 단계를 한 문장씩 나눠 순서가 보이게 함.
5. **이 경보는 어떤 규칙이 울렸을까** (읽는 법)
   - 이전: 어디서 오든(출발지 제한 없음) 목적지 포트가 80인 TCP 통신에서, Payload에 ... 남긴다. 포트 80은 ... 관례일 뿐이라, 이 규칙이 실제로 보는 것은 ...
   - 이후: 출발지는 어디든 상관없다(제한 없음). 목적지 포트가 80인 TCP 통신에서 Payload에 ... 남긴다. 포트 80은 ... 관례일 뿐이다. 이 규칙이 실제로 보는 것은 ...
   - 이유: 조건을 하나씩 끊어 읽게 함.
6. **규칙 하나 바꿨는데 왜 장애가 났을까** (변경 기록)
   - 이전: 장애가 났을 때 이 한 줄이 있으면 ...을 바로 짚을 수 있고, 없으면 모두가 기억에 의존해 서로를 의심하게 된다.
   - 이후: ...바로 짚을 수 있다. 없으면 모두가 기억에 의존해 서로를 의심하게 된다.
   - 이유: 있을 때와 없을 때를 나눔.
7. **한 장의 지도에 요청 하나를 올리면** (장치 배치)
   - 이전: 길목에 UTM이 Inline으로 서고, 그 뒤에 ... 이어지며, 별도 포트 뒤에 서버 구역과 ... 서버 풀이 있다.
   - 이후: 길목에 UTM이 Inline으로 선다. 그 뒤에 ... 이어진다. 별도 포트 뒤에는 서버 구역과 ... 서버 풀이 있다.
   - 이유: 세 위치를 한 문장씩 나눔.
8. **한 장의 지도에 요청 하나를 올리면** (TLS 종료 앞뒤)
   - 이전: TLS 종료 앞 구간의 센서는 암호문만 보고, 종료 뒤의 WAF와 IPS는 풀린 요청을 보고 막을 수 있다.
   - 이후: ...센서는 암호문만 본다. 종료 뒤의 WAF와 IPS는 풀린 요청을 보고 막을 수 있다.
   - 이유: 대비되는 두 내용을 나눠 비교하기 쉽게 함.
9. **장치마다 보는 층은 어떻게 다를까** (URL·MAC 요청)
   - 이전: "URL을..."는 HTTP 층의 정보이니 ...가 맡고, "MAC을..."는 L2의 정보이니 ...가 맡는다.
   - 이후: "URL을..."는 HTTP 층의 정보라서 ...가 맡는다. "MAC을..."는 L2의 정보라서 ...가 맡는다.
   - 이유: 두 요청을 한 문장씩 분리. 식별자·복호화에는 쉬운 풀이를 더함.
10. **이제 안전하다고 답할 수 있을까** (마무리 문단)
    - 이전: Module 3(접근통제 자동화)에서 ... 적용하는 방법으로, ... Module 4(...)에서 ... 찾는 방법으로, ... Module 5(자동대응)에서 ... 수행하는 방법으로 이어진다. (214자 한 문장)
    - 이후: 장부와 규칙표를 직접 고치던 일은 Module 3(접근통제 자동화)으로 이어진다. 사람이 정한 접근 정책을 자동으로 적용하는 방법이다. (Module 4·5도 같은 두 문장 형식) 다만 정책과 승인 범위는 계속 사람이 정한다.
    - 이유: 소리 내어 읽기 쉽게 "일 -> 모듈 -> 방법"을 세 번 같은 모양으로 반복. 사실은 그대로.
11. **퀴즈 u15-l04-p02-q02** (prompt)
    - 이전: NAC는 ...기록했고, DHCP 기록도 ...준 적이 없고, 고정 IP로 설정된 기기도 없다고 한다.
    - 이후: NAC는 ...기록했다. DHCP 기록도 ...준 적이 없고, 고정 IP로 설정된 기기도 없다고 한다.
    - 이유: 긴 상황 설명을 두 문장으로 나눔.
12. **퀴즈 u15-l04-p06-q02** (prompt)
    - 이전: 센서를 하나씩 놓고 같은 시험 요청을 보냈다.
    - 이후: 센서를 하나씩 놓았다. 그리고 같은 시험 요청을 보냈다.
    - 이유: 두 행동을 나눔. 보기·정답은 그대로.
