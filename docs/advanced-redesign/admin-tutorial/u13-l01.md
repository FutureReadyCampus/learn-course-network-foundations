# Unit 13 Lesson 1 관리자 튜토리얼 기록

방향: 지우 = 신입 네트워크 관리자, 박 팀장 = 요청 직원, 서 이사 = 비용·보안 결정권자. 서비스는 고객용 예약·문의 사이트(`203.0.113.10:443`, 풀 `192.168.20.11`~`.13`, 주소 그대로). Lesson 제목: 점심마다 느려지는 예약 사이트. 기술 설명, learn-page-id, 퀴즈 ID·개수·정답, SVG 파일명은 그대로다. 생성기: `scripts/svg_pairs/u13_l01_rev.py`, `u13_l01_lb.py`(`--svg-only`).

- Page 1: 점심 한결봇 지연 -> 예약·문의 사이트 지연 티켓, GPU 100% -> 서버 CPU 100%. 퀴즈: q2 이벤트 날 한결봇·GPU -> 예약 이벤트 날 예약 사이트·서버 CPU. SVG: p1-slow(문구 교체). 한계: 수치는 기존 가정(30%·25%) 그대로.
- Page 2: 포트 포워딩 vs L4 로드 밸런서. 한결봇/한결디자인 표현만 예약 사이트/회사로. 퀴즈 변경 없음. SVG 변경 없음(재생성만). 한계: Unit 12 본문이 아직 "시연"이면 "외부에 잠깐 열어야 할 때"와 어긋날 수 있음.
- Page 3: VIP. 도메인 bot.hangyeol.example -> booking.example, 고객사 -> 거래처. 퀴즈: q2 고객사 허용 목록 -> 거래처 허용 목록. SVG: p3-vip-one-address(도메인 교체).
- Page 4: 대화 기록이 사라짐 -> 예약 중 고른 날짜(20일)가 사라짐(세션 고정·공유 저장소). 퀴즈: q1 대화 기록 -> 진행 정보, q2 도면 PDF -> 견적 요청서 PDF 업로드 파일. SVG: p4-forgets-first-line, p4b-sticky-session(말풍선·값 재작성). 한계: "서버 메모리에 맥락" 개념을 예약 진행 정보로 옮겨 같은 구조 유지.
- Page 5: 라운드 로빈 vs 최소 연결. AI 긴 견적 계산 -> 예약 사이트의 견적서 PDF 만들기. 퀴즈: q2 GPU 서버 -> 새 서버. SVG: p5-round-robin-vs-least(라벨 교체).
- Page 6: L4 vs L7. 도면 분석·큰 GPU -> 견적서 요청(`/api/estimate`)·큰 서버. 퀴즈: q1 경로·파일 내용 보기 교체. SVG: p6-l4-vs-l7-requests(라벨 교체). 한계: 요청 경로 이름은 새로 지은 예시.
- Page 7: 모델 로딩 -> 서버 시작 시 캐시(예약 가능 날짜 등) 올리는 시간, 헬스 체크 설명 동일. 퀴즈: q1 모델 로딩 -> 캐시 올리는 중. SVG: p7-health-check-ready(라벨 교체). 한계: 캐시 채우기 시간 "몇 분"은 가정.
- Page 8: 서버 빼기·드레이닝. 대화 -> 접속 표현만. 퀴즈: q2 보기·해설 표현. SVG: p8-drain-headroom(문구 교체).
- 가져갈 것·생각법: 한결봇/GPU 표현을 예약 사이트/서버 CPU로.
