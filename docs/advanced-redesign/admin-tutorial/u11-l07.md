# Unit 11 Lesson 7 관리자 튜토리얼 기록

티켓 5(회사 서버를 밖에 열어 두면 안전한지). 사내 AI 서버 -> 사내 그룹웨어 서버(`192.168.10.50:8080`, 같은 주소). 외부 접속자는 외근·출장 중인 직원(`192.0.2.77`)으로 바꿨고, 호스트 이름은 `ai.hangyeol.example` -> `gw.company.example`(공인 주소 `198.51.100.25`는 그대로). Lesson 제목: "사내 그룹웨어 앞에 경비를 세우자: 리버스 프록시". 기술 설명, learn-page-id, 퀴즈 ID·개수·정답, Page 수는 그대로다. 생성기: `scripts/svg_pairs/u11_l07_story.py`, `u11_l07_new_scenes.py`, `u11_l07_rev.py`.

- Page 1: 도면 걱정·GPU PC AI 서버 시연 -> 박 팀장의 외근 중 전자결재 티켓 + 서 이사의 "밖에 열면 공격받지 않아요?". 퀴즈: q1 보기 e(AI 모델 프로그램 -> 그룹웨어 프로그램), q2 고객사 시연 접속 -> 외근 직원 접속. SVG: story-open-server(재작성), front-flow(라벨 교체). 한계: 없음.
- Page 2: 시연 중 질문 -> 외근 직원 접속(HTTPS). 퀴즈: q2 상담 질문 입력란 -> 게시판 검색란. SVG: story-gate-flood(서버 이름), ips-pass-block(라벨 교체). 한계: 없음.
- Page 3: AI 서버가 TLS를 푼다 -> 그룹웨어 서버가 푼다, 개인 PC에 설치할 것 없음. 퀴즈: q1 보기 e(GPU 암호 계산 -> 서버 안에 설치돼 대신 처리), q2 보기 e(외부 AI 서비스 -> 외부 클라우드 저장소). SVG: story-who-decrypts, tls-ends-at-front. 한계: 없음.
- Page 4: 상담 이력 조회 `/history?customer=1042` -> 결재 문서 조회 `/approval?doc=1042`, 공격 `doc=1042' OR '1'='1`. 오탐 설명을 "자유롭게 쓴 AI 질문" -> "게시판·결재 의견란 글"로. 퀴즈: q2 20MB 도면 PDF -> 결재 문서에 첨부하는 20MB 견적서 PDF. SVG: story-odd-request(재작성), waf-reads-request, front-order. 한계: 없음.
- Page 5: 시연 요청이 앞단 하나를 지남 -> 외근 접속이 앞단 하나를 지남. 퀴즈: q2 상담 페이지 -> 그룹웨어 로그인 페이지, 보기 e 고객 -> 직원. SVG: story-front-fails, single-front, client-address(라벨 교체). 한계: 없음.
- Page 6: 포워드 대 리버스 비교표와 Lesson 첫머리 다섯 티켓 표를 시범 Lesson 1의 티켓 이름으로 맞춤. 퀴즈: q2 장비 A/B 견적서 문구(내부 그룹웨어 서버로 분배 / 직원의 외부 사이트 요청). SVG: forward-vs-reverse(포워드 쪽 서버를 외부 클라우드 저장소로), story-handoff(박 팀장이 거래처에 나간 장면으로 재작성), next-unit12. 한계: 마지막 문장 "처음에는 거래처 주소에서만 임시로 열어 본다"는 Unit 12 이야기와 이어지는지 Unit 12 담당이 확인 필요.
