# Unit 11 Lesson 4 관리자 튜토리얼 기록

방향: 시범(u11-l01)과 같은 이야기 틀. 지우 = 신입 네트워크 관리자, 박 팀장 = 요청하는 직원, 서 이사 = 비용·보안 결정권자. AI 서비스 -> 외부 클라우드 저장소(`203.0.113.80`, 장부 주소 그대로), 회의록·AI 앱 -> 파일 동기화 프로그램. Lesson 제목은 front matter의 `title`을 '프록시 티켓을 맡은 신입 관리자: 대신 다녀오는 심부름꾼, 포워드 프록시'로 바꿈(unit.md·계약 파일에는 옛 제목이 없음). Page 제목 두 개(1, 4)의 AI 표현 제거. learn-page-id, 퀴즈 ID·개수·정답, SVG 파일 이름은 그대로. 생성기: `scripts/svg_pairs/u11_l04_story.py`, `u11_l04_rev.py --svg-only`, `u11_l04_new_scenes.py --svg-only`.

- Page 1: 서 이사의 "누가 어느 AI에 무엇을" -> "누가 어느 외부 클라우드 저장소에 어떤 파일을" 새 티켓. Page 제목에서 AI 삭제. 퀴즈: q2 고객 도면 업로드 -> 거래처 자료 업로드, 보기 e의 AI 서비스 응답 -> 외부 사이트 응답. SVG: story-ai-request(재작성), client-chooses(라벨 교체), features-on-demand(생성기 재실행, 내용 동일). 한계: 파일명 `story-ai-request`에 ai가 남음.
- Page 2: AI 채팅·AI 회의록 앱 -> 외부 클라우드 저장소 웹 페이지·파일 동기화 프로그램(용어 풀이 추가), 호스트 이름 `storage.example`. 퀴즈: q1 AI 서비스 -> 외부 클라우드 저장소, q2 디자인팀 AI 이미지 생성 앱 -> 영업팀 파일 동기화 프로그램. SVG: story-proxy-field(재작성), p02-browser-proxy(라벨 교체). 한계: 없음.
- Page 3: AI 서비스 점검 -> 클라우드 저장소 점검, 박 팀장 티켓으로 캡처가 올라옴. 퀴즈: q1 AI 서비스 -> 저장소, q2 마케팅팀 AI API 호출 스크립트 -> 영업팀 자료 업로드 스크립트("프록시↔저장소 구간"). SVG: story-tunnel-fail(말풍선 교체), two-connections, which-leg(라벨 교체). 한계: 없음.
- Page 4: 한결디자인·AI 서비스 -> 회사·클라우드 저장소. 퀴즈: q1 한결디자인 PC -> 회사 PC, q2 디자인팀 직원 5명 -> 영업팀 직원 5명. SVG: story-seen-address(재작성), seen-address, who-sent, p04-seen-address(라벨 교체). 한계: `p04-seen-address.svg`는 lesson.md에 연결되지 않은 기존 파일(새 이야기에 맞춰 내용만 교체).
- Page 5: 막아 둔 AI 사이트 -> 막아 둔 개인 클라우드 사이트, 우회한 이유 "업무에 AI 필요" -> "거래처에 큰 파일을 바로 보내야 함", 승인된 경로는 회사가 허용한 파일 전송. 퀴즈: q1 AI 질문 -> 올린 파일 내용, q2 신입 디자이너·AI 이미지 사이트 -> 신입 영업 사원·개인 클라우드 사이트. SVG: story-free-proxy(재작성), stranger-operator(문구 교체). 한계: 우회 도구 이유가 "파일 전송"으로 바뀌어 박 팀장 사례가 Lesson 1 Page 4와 같은 방향(자료 유출)으로 이어짐.
- Page 6: "AI 답이 늦다" -> "외부 사이트가 늦게 열린다", "AI 대화는 캐시 불가" -> "로그인한 사람마다 다른 화면·개인 파일 목록은 캐시 불가". 퀴즈: q1 b의 AI 서비스 -> 외부 사이트, q2 AI 서비스 장애 -> 클라우드 저장소 장애. SVG: story-extra-hop(재작성), extra-steps, spof(라벨 교체). 한계: 없음.
