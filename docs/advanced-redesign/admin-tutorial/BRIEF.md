# 심화편 Unit 11~15 — 네트워크 관리자 튜토리얼 기준서 (2026-11-17)

사용자 결정: "AI 채팅이 네트워크와 관계가 없다. 디자인팀·시안 설명문 말고, 네트워크 관리자가 되기 위한 튜토리얼처럼. AI 채팅 대신 **일반 회사가 가장 흔히 쓰는 가벼운 서비스**를 예로 들 것." 시범: Unit 11 Lesson 1 (`docs/advanced-redesign/admin-tutorial/u11-l01.md`, 이미 stage에 있음 — 문체·티켓 틀의 기준으로 먼저 읽는다).

## 이야기 틀
- 직원 약 40명 회사(업종 무관, "한결디자인"·"디자인팀"·"인테리어"·"시안"·"도면"·"쇼룸" 쓰지 않음). 신입 네트워크 관리자 **지우**가 직원·상사의 관리 요청(**티켓**)을 한 건씩 처리하며 배운다.
- **박 팀장** = 요청하는 직원(팀 이름 없이 "팀장"). **서 이사** = 비용·보안을 따지는 결정권자. 말투는 업무 요청("~해 주실 수 있어요?").
- Page마다 "왜 배우나→문제→원인→해결과 대가", Lesson 끝 "이 Lesson에서 가져갈 것"과 「🧠 이번에 쓴 생각법」(🧩쪼개기 🔁같은 모양 찾기 🗺️필요한 것만 남기기 📋순서대로 확인하기 ⚖️대가 따지기 5개 고정)은 유지. AI 전환(AX) 이야기만 뺀다. 글 분량은 줄이지 않는다.

## 서비스 대응표 (AI → 일반 회사 서비스) — 모든 Lesson이 같은 대응을 쓴다
| 옛 설정 | 새 설정 |
|---|---|
| 외부 AI 채팅 서비스 / 외부 AI API (`203.0.113.80:443`) | **외부 클라우드 저장소**(파일 올리고 공유하는 웹 서비스) — 같은 주소 |
| 사내 AI 서버(GPU PC, 사내 문서 연동) `192.168.10.50:8080` (Unit 15부터 `192.168.40.50:8080`) | **사내 그룹웨어 서버**(전자결재·게시판·일정 웹 시스템) — 같은 주소 |
| 고객용 한결봇(`203.0.113.10:443`, 풀 `192.168.20.11`–`.13`, 도쿄 `203.0.113.20`) | **고객용 예약·문의 사이트**(회사 홈페이지의 예약 서비스) — 같은 주소 |
| 모델 로딩 중인 서버 | **시작 중(캐시 올리는 중)인 서버** |
| AI 플러그인·AI 앱 | **파일 동기화 프로그램**(PC에 깔린 클라우드 저장소 앱) 등 일반 프로그램 |
| 고객 도면·개인정보를 AI에 붙여넣기 | **거래처 자료·개인정보 파일을 개인 클라우드/메일로 올리기** |
| 도면 NAS `192.168.10.30` | **공유 자료 NAS** — 같은 주소 |
| 도쿄 쇼룸 LAN `10.20.0.0/24` | **도쿄 지사 LAN** — 같은 주소 |
| 화상회의·STUN/TURN `203.0.113.60` | 그대로 (화상회의 서비스) |
- 자주 쓰는 가벼운 서비스 예: 웹메일, 클라우드 저장소, 화상회의, 업무 메신저, 그룹웨어(전자결재), 회사 홈페이지·예약 사이트, 공유 NAS. 실제 제품명은 쓰지 않는다.
- IP 장부(`docs/advanced-redesign/BRIEF.md` "통일 주소 장부")의 주소·포트 값은 **바꾸지 않는다**(이름만 위 표로 바꾼다).
- 가짜 수치·가짜 제품 동작을 지어내지 않는다.

## 바꿀 것 / 그대로 둘 것
- 바꾼다: 본문·퀴즈(상황·보기·해설)·`page_metadata`의 그림 제목/alt/캡션·Lesson/Page 제목에 남은 AI/디자인 표현·SVG 속 글자와 상황 장면.
- 그대로: 기술 내용과 흐름, `learn-page-id`, 퀴즈 ID·개수(Page당 2)·정답 구조, Page 수, 폴더 이름(slug는 `ai-서버`가 들어 있어도 **바꾸지 않는다**; URL·계약·alias 때문), SVG 파일 이름.
- 기술 본문이 "AI 서비스 특성"(모델 로딩, 토큰, 프롬프트, GPU 등)에 기댄 곳은 같은 네트워크 개념을 보여 주는 일반 서비스 특성으로 바꾼다(예: 모델 로딩 → 서버 시작 시 캐시 채우는 시간; 긴 응답 스트리밍 → 대용량 파일 다운로드·화상회의 같은 오래 가는 연결). 개념이 달라지면 억지로 맞추지 말고 보고한다.
- 용어 하이라이트·문체·초보자 눈높이는 기존 방식 그대로.

## 그림
- 개념 SVG: 구조 설명은 그대로, AI/도면 글자·상황만 위 표대로 교체. 상황 SVG(`u11-l0N-pN-story-*` — Unit 11만 있음): 새 이야기에 맞게 장면·말풍선 다시. 생성기는 `scripts/svg_pairs/` 아래(Lesson별 `uNN_lNN_*.py`; `grep -rl` 로 해당 파일명 찾기). 규약: 960×540, 4단계 SMIL, 단계당 바뀌는 것 하나만 주황 강조, 라벨 단계당 3개 이하, 글자 16px 이상. 렌더 확인 `python3 /tmp/svgwork/snap_l2.py <svg> <png>` 후 PNG를 직접 본다(없으면 playwright로 2×2 프레임 도구를 다시 만든다). 인물 그리기는 `scripts/svg_pairs/hangyeol_cast.py`(공용 — 수정 금지; 시범처럼 story 스크립트 안에서 역할 줄만 덮어쓴다).
- Unit 12~15에는 상황 SVG가 없다. 새로 만들지 말고 기존 SVG만 고친다.

## 공용 파일 규칙 (여러 agent가 동시에 일한다)
- **자기 Lesson의 `lesson.md`, `assets/animations/*.svg`, 자기 Lesson 생성기 스크립트, `docs/advanced-redesign/admin-tutorial/u{UU}-l{LL}.md` 기록만** 고친다. `unit.md`, `course.yaml`, `docs/advanced-restructure-contract.json`, 공용 glossary·공용 SVG 도구(`hangyeol_cast.py`, `kit.py`, `u11_new_common.py` 등), 다른 Lesson은 건드리지 않는다. 필요한 공용 변경(Lesson 제목 바꿈 등)은 보고서 맨 끝 "공용 변경 요청"에 적는다.
- 다른 Lesson 작업 때문에 `build_course.py`·테스트가 일시적으로 실패하면 자기 Lesson 관련 오류만 고친다.
- `git add/commit` 금지.
