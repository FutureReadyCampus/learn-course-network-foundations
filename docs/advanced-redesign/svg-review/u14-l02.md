# Unit 14 Lesson 2 (터널을 지나는 패킷) SVG 점검 기록

생성기: `scripts/svg_pairs/u14_l02_rev.py` (옛 `u14_l02_tunnel.py`는 import만 하던 헬퍼 외에는 쓰지 않음). 옛 SVG 6개는 같은 파일명으로 덮어썼다(파일명 유지). Lesson 1의 "두 개의 점선 사이트 상자" 배경 대신 **한 줄 경로 띠(쇼룸 PC - 도쿄 SG - 인터넷 - 서울 SG - 서버, 구역은 색 막대) + 아래의 패킷 엑스레이**로 구성해 두 Lesson이 달라 보이게 했다. 안쪽=파랑, 바깥·터널=보라, 주황은 방금 바뀐 것만. 인터넷 타원에는 글자를 넣지 않아 패킷이 지나가도 가리지 않는다.

| Page | 판정 | 이유 | 파일 | 남은 한계 |
| --- | --- | --- | --- | --- |
| 1. 지사 PC의 질문은 어디로 출발할까? | 교체 | 옛 그림은 2단계 규칙 상자가 터널 위에 얹히고 글자가 15px였다. PC→기본 게이트웨이, SG 규칙, 터널, 규칙에 없는 목적지(203.0.113.80) 일반 경로까지 4단계에 넣고 글자를 16px 이상으로 | `u14-l02-p1-first-hop.svg` | 4단계에서 터널이 사라지고 두 번째 패킷이 나타남(둘 다 같은 질문의 다른 목적지) |
| 2. 사설 주소 패킷은 왜 인터넷을 못 건널까? | 교체 | 옛 그림은 원본 패킷이 비어 있는 2단계에서 실패와 해결이 섞였다. 원본 → 그대로 내보내면 버려짐(✗) → 새 IP 헤더로 감쌈 → 터널로 건넘 순서로 한 단계에 하나만 바꿈 | `u14-l02-p2-private-wrap.svg` | 구매 대행 비유는 그림에 넣지 않음 |
| 3. 안쪽 IP와 바깥 IP는 누구 주소일까? | 교체 | Lesson의 핵심 그림. 옛 그림은 오른쪽 아이콘이 화면 끝에 붙고 글자 13~15px, 본문에 없는 "IPsec 헤더" 표기였다. 큰 층 구조(바깥 IP 헤더 / 암호화 헤더 / 안쪽 IP 헤더+데이터)와 라우터가 읽는 곳·못 읽는 곳, "어느 터널로 / 누가 누구에게"를 행에 맞춰 붙임 | `u14-l02-p3-inner-outer.svg` | 3단계에서 읽음/못 읽음 두 가지가 함께 나옴(대비가 목적) |
| 4. 본사 SG는 포장을 어떻게 풀까? | 수정 + 하나 더 | 4단계가 "허용 규칙 없음"으로 끝나 본문의 응답 경로와 어긋났다. 이 그림은 도착 → 벗기고 복호화 → 서버에 출발지 10.20.0.15로 보임 → 응답 포장 후 같은 터널로 복귀로 바꾸고, 허용 규칙은 둘째 그림으로 | `u14-l02-p4-unwrap.svg`, `u14-l02-p4b-allow-rule.svg` | 4단계에서 패킷 이동과 엑스레이 내용이 함께 바뀜(응답이 거꾸로 가는 한 가지 사건) |
| 5. 터널 밖에서는 무엇이 보일까? | 교체 | 옛 그림은 터널이 비어 있고 안쪽 주소 줄이 13px였다. 터널 안 패킷 위에서 통신사가 보는 것(두 SG 주소·크기·시간)과 가려진 것(안쪽 주소·질문 내용)을 16px로 좌우 비교 | `u14-l02-p5-visible.svg` | 터널링과 암호화의 구분(본문 둘째 문단)은 그림에 넣지 않음 |
| 6. 포장을 한 겹 더 하면 뭘 치를까? | 수정 | 구조는 맞았으나 "+ 헤더"가 100px 칸에 눌려 있고 4단계에서 막대 두 개가 남았다. 헤더 칸을 "바깥 IP / IPsec 헤더"로 키우고, 4단계는 같은 줄에서 원본을 헤더만큼 줄인 모습으로 | `u14-l02-p6-mtu.svg` | MTU 1,500바이트 막대 길이는 상대 비교용 |

두 번째 SVG: Page 4(`p4b`). 한 Page에 "포장 풀기와 응답 경로"와 "터널은 연결됐는데 허용 규칙이 없어 서버가 응답하지 않는 실패 경로"가 따로 있어 4단계 하나에 담기 어렵다.
