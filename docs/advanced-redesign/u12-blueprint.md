# Unit 12 — 사내 AI 서버를 밖에서 쓰려면: 공유기와 NAT (기존: 「공유기와 NAT의 동작」)
이야기 시점: 지우가 사무실 GPU PC에 사내용 AI 모델 서버를 직접 띄운 직후. 사무실 안에서는 잘 되는데 고객사에 간 박 팀장은 접속하지 못한다. / 이 Unit을 마치면 지우가 할 수 있게 되는 것: 주소가 사설인지 공인인지 가려 "왜 밖에서 안 열리는지"를 NAT 변환표로 설명하고, 포트 포워딩을 설정·점검하면서 그 노출 대가를 서 이사에게 말할 수 있다. 공유기에서 프로그램이 몰래 연 UPnP 매핑을 찾아 정책을 세우고, 포트를 열지 않는 P2P·화상 통화 앱이 NAT를 넘는 방식(홀 펀칭·중계)도 구별한다.

**이야기 고정값(모든 Lesson 공통, 집필 때 이 숫자를 쓴다)**

| 대상 | 값 | 비고 |
| --- | --- | --- |
| 사무실 내부망 | `192.168.0.0/24`, 공유기 LAN 주소 `192.168.0.1` | 기존 L2 숫자와 맞춰 둔다 |
| 공유기 바깥(WAN) 주소 | `198.51.100.25` | 기존 L2·L5 SVG 숫자. 문서용 범위 |
| 지우 PC / 디자인팀 PC | `192.168.0.10` / `192.168.0.11` | 기존 L2 숫자 |

**Lesson 순서를 바꾼 이유:** 기존에는 L3(매핑·필터링)이 L4(포트 포워딩) 앞에 있었다. 새 순서는 이야기 흐름을 따른다. "밖에서 안 열린다(12-1) → 변환표에 바깥에서 온 요청에 맞는 줄이 없다(12-2) → 줄을 직접 적는다(12-3) → 프로그램이 그 줄을 몰래 적는다(12-4) → UPnP를 끄면 화상회의는 어떻게 되나(12-5)" 순서다. 매핑·필터링은 "포트를 열지 않는 앱이 어떻게 연결되나"라는 질문 안에서 배울 때 왜 필요한지가 가장 또렷하다.

## Lesson 12-2 — 답장은 어떻게 제자리로 돌아올까: NAT 변환표  (기존: 「NAT 변환표로 통신 따라가기」 Lesson 2, 11개 Page + Lesson 4의 1개 Page → 새 7개 Page)

## Lesson 12-5 — 포트를 안 열어도 화상회의가 되는 이유: NAT 통과  (기존: 「NAT의 매핑과 수신 허용 방식」 Lesson 3, 7개 Page + Lesson 1·2에서 1개씩 → 새 7개 Page)
- 왜 배우나 (한결디자인 장면 2~3문장): UPnP를 끈 다음 날, 박 팀장이 걱정한다. "해외 협력사랑 화상회의를 하는데 끊기면 어떡해요?" 그런데 회의는 멀쩡하다. 양쪽 다 NAT 뒤에 있고 아무도 포트를 열지 않았는데, 어떻게 연결된 걸까?
- 이 Lesson의 질문 하나: NAT 뒤의 두 기기는 어떻게 직접 연결을 시도하고, 안 되면 어떻게 할까?
- 🧠 생각법: 🧩 쪼개기(NAT 동작을 매핑·필터링 두 질문으로), 🗺️ 필요한 것만 남기기(옛 Cone 이름 대신 두 기준만), ⚖️ 대가 따지기(직접 경로 vs 중계 비용)
- 집필 주의: "모든 화상회의 서비스가 P2P"라고 쓰지 않는다. "일부 영상 통화·원격 지원 앱은 직접 경로를 먼저 시도하고, 안 되면 중계한다" 수준으로 쓴다.
