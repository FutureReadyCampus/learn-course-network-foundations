# Unit 15 독자 검토

기본편 Unit 1~10만 마친 독자로, 4개 Lesson 28 Page(7+7+6+8)를 순서대로 읽고 정리했다. 칭찬: (1) Page 길이는 대부분 800~1,000자라 한 Page씩은 읽기 편하다. (2) 점검을 네 질문으로 쪼갠 첫 Page의 표가 Unit 전체의 지도 역할을 한다. (3) 장애 때 "최근 변경부터 하나씩 되돌리기"(L4 p4), 시그니처가 TLS 앞뒤에서 다르게 보인다는 설명(L3 p3)은 장면으로 이해가 된다.

## 상

1. `심각도 상` · L1 전체(Page 2~5) · 문제: NAC를 처음 배우는 독자가 정작 핵심인 802.1X(Page 6)보다 먼저 약한 방식 셋(MAC 장부 → 포트 차단 → ARP 방식 → 안내 페이지)을 4 Page 동안 읽는다. 이 중 ARP 방식은 "왜 사라졌는가"를 배우는 Page라, 독자는 지금 안 쓰는 기술에 한 Page를 쓴다. 게다가 한 Lesson에 Probe, MAC/IP 장부, ARP 스푸핑, HTTP 리다이렉트, 802.1X, RADIUS, TACACS+, VLAN, WIPS가 모두 나온다. · 제안: Page 3(포트)과 Page 4(ARP)를 Page 하나로 합쳐 "막는 방법 비교표(포트 차단 / ARP / 안내 페이지)"로 줄이고 ARP는 3문장으로 끝낸다. 또는 순서를 바꿔 "들어오기 전 인증(802.1X)"을 먼저 보여 주고, 장부·Probe·안내 페이지는 "인증 못 하는 기기를 어떻게 다루나"의 후속으로 둔다. TACACS+는 본문에서 삭제(퀴즈 u15-l01-p07-q01 오답 보기로만 남아 있어 본문에 없는 개념이 보기에서 튀어나온다).

2. `심각도 상` · L4 Page 8 「다음에 막히면 어디부터 의심할까?」 · 문제: 끝맺음이 약하다. (a) 서 이사의 첫 질문 "우리 회사, 지금 안전하다고 답할 수 있어요?"(L1 p1)와 고객사 보안 점검표가 끝까지 답을 못 받는다. Unit이 열었던 약속이 닫히지 않는다. (b) 마지막 Page 하나(약 2,070자)에 순서표 + 한계 문단 + "가져갈 것" 3줄 + 생각법 5개 + 다리 문단이 몰려 있어 가장 중요한 자리가 가장 빽빽하다. (c) 다리 문단이 "가져갈 것"과 생각법 상자 뒤에 붙어 있어 덤처럼 읽힌다. · 제안: 순서표 뒤에 지우가 서 이사에게 점검표에 답하는 장면 3~4문장을 넣는다("안전하다"는 말 대신 "네 질문 중 어디까지 답할 수 있고 어디가 비었다"). 그다음 생각법 회고 상자, 마지막에 다리 문단 순으로 두고, "가져갈 것" 3줄은 이 Page에서는 상자와 겹치므로 상자로 흡수한다.

3. `심각도 상` · L4 Page 5~7(지도 / 요청 하나 따라가기 / 보는 층) + Page 8 · 문제: Lesson 4의 후반 4 Page가 모두 "정리"다. Page 5의 구조×장치 표는 Unit 11 L1의 세 구조 표를 그대로 재사용하고, Page 8의 6단계 표와 생각법 5개 상자가 다시 같은 내용을 접는다. 독자는 같은 요약을 세 번 읽는다. Page 7의 Frame/Packet/Segment/Stream 표는 새 개념이 마지막에 슬쩍 들어온 것이라 Page 5·6의 표와 열이 겹치면서도 어느 쪽이 기준인지 헷갈린다. · 제안: Page 5와 Page 6을 합쳐 "지도 위에 요청 하나 올리기" Page로 만들고(표 두 개 중 하나만 남김), Page 7의 "층" 표는 Page 6의 '보이는 것' 열에 흡수하거나 삭제한다. 이 경우 Lesson 4가 6~7 Page가 되고 끝이 가벼워진다.

4. `심각도 상` · L2 Page 7 「재택 직원에게 웹 화면만 열어 주려면?」 · 문제: 방화벽 Lesson 한가운데서 갑자기 SSL VPN 포털이 나온다. "IPsec VPN을 쓰면 사내망 전체가 열린다"는 전제가 Unit 14와 맞는지 독자가 확인할 수 없고(Unit 14에서 분할 터널을 배웠다면 모순처럼 읽힘), 추가 인증까지 얹혀 1,577자로 가장 길다. Lesson 제목 "AI 서버로 가는 문, 누구에게 열어 줄까"와도 거리가 있다. · 제안: Unit 14로 돌려보내거나, 남긴다면 "문 하나를 줄이면 더 눈에 띄는 문이 생긴다"는 한 문단 + 표 한 줄로 줄이고 IPsec/SSL 구분 설명을 삭제한다.

5. `심각도 상` · 본문 곳곳(L1 p2 마지막 문단, L1 p4 "원고도 이 방식이…", L2 p2 "원고는 …철조망에 비유한다", L2 p5 "원고의 Bastion Host", L3 p5 "원고의 표기…MPS", L3 p5 "원고도 완벽한 해결책은 아니라고", L4 p1 "원고의 예시는 ESM과 SIEM을 섞어 쓰는데") · 문제: 독자는 "원고"가 뭔지 모른다. 집필 과정의 메모가 본문에 새어 나와 신뢰를 깎고 문장이 끊긴다. L1 p2 마지막 문단("L2 수준이라는 비유…")은 독자가 본 적 없는 말을 정정한다. · 제안: 위 문장을 모두 삭제하거나 "흔히"로 바꾼다. L1 p2 마지막 문단은 통째로 삭제. MPS 약어는 본문에서 뺀다.

## 중

6. `심각도 중` · L1 Page 1 「보안 점검, 무엇부터 물어야 할까?」 · 문제: 첫 Page가 (a) 서 이사의 질문, (b) 회의실 노트북, (c) 장비 이름 4개, (d) 세 구조로 보는 법, (e) 네 질문 표, (f) NAC 두 갈래와 "국내에서는 PC 방화벽(에이전트)과 Probe…제품 조합"까지 한꺼번에 담는다. 에이전트 얘기는 이후 Page에서 다시 나오지 않아 낯선 용어만 남는다. "Page 6", "Page 2~5" 같은 쪽수 참조도 쉽게 틀어진다. · 제안: 마지막 문단에서 "두 갈래"·에이전트·쪽수 참조를 삭제하고 "이번 Lesson은 첫 질문, 누가 들어오나"로만 닫는다.

7. `심각도 중` · L2 Page 2~3(ACL / 상태 추적) · 문제: Page 1에서 패킷 필터 규칙표를 보고, Page 2에서 라우터 ACL 표를 또 보고, Page 3에서 상태 표를 본다. ACL과 패킷 필터는 같은 모양이라 Page 2가 "같은 말 다시"로 읽힌다. Screening Router라는 이름은 독자에게 전혀 필요 없다. · 제안: Page 2를 Page 1에 흡수해 "ACL은 위에서부터 읽고 처음 맞는 줄에서 멈춘다"는 순서 규칙 하나만 남긴다. 그러면 L2가 6 Page가 되어 7 Page인 p7 SSL VPN을 지우는 방향과 맞는다.

8. `심각도 중` · L2 Page 5 「포트 443이면 모두 웹 요청일까?」 · 문제: 한 Page에 Proxy형 방화벽, 애플리케이션 방화벽, Bastion Host, Hybrid, WAF, 회사 CA, TLS 검사가 들어온다. 이름 4개가 한 문단에 나열된다. Unit 11을 읽은 독자라면 프록시 설명이 반복이다. · 제안: "헤더로 거를 것은 패킷 필터, 내용이 필요하면 프록시형" 한 줄과 표 하나만 남기고 Bastion Host·Hybrid는 삭제한다.

9. `심각도 중` · L3 Page 2 「막을까, 알리기만 할까?」 · 문제: IPS(Inline)/NIDS(Out of path) 비교표는 Unit 11 L1의 인라인·경로 밖 설명을 다시 쓴 것이다. 새로 얻는 것은 "IPS가 고장 났을 때 통과/차단 중 어느 쪽인가" 한 가지뿐인데 마지막 문단에 묻혀 있다. · 제안: 표는 "탐지하면"과 "고장 나면" 두 행만 남기고 Unit 11을 그대로 불러오는 문장("🔁")을 줄인다. fail-open/fail-closed 이름은 필요 없고 장면으로 충분하다.

10. `심각도 중` · L3 Page 6 「남들이 이미 아는 악성일까?」 · 문제: 평판, 층층이 쌓는 흐름, IP 평판의 한계, 외부로 보내는 정보, 다음 Lesson 예고가 한 Page(1,431자, 8블록)에 있다. 샌드박스(p5)와 평판(p6) 사이에 "처음 보는 파일은 지연"이라는 새 대가가 계속 늘어나 시그니처→샌드박스→평판 세 방식을 외우는 느낌이 든다. · 제안: 평판은 한 문단으로 줄이고, "알려졌나 / 실행해 보니 / 남들은 아나" 3층 표 하나로 정리한다. 로그 폭증 예고 문장은 L4 p1 도입으로 옮긴다.

11. `심각도 중` · L4 Page 1~2(ESM / SIEM) · 문제: ESM과 SIEM의 구분("모으는 쪽 / 분석하는 쪽")은 초보에게 말장난처럼 보이고, 둘 다 약어다. Page 1은 "모으기만 해서는 줄지 않는다"는 말에 비해 장면이 약하다(본 것은 한 화면, 헬스 체크). · 제안: ESM 이름은 한 문장으로만 쓰고 Page 1·2를 합쳐 "한 화면에 모으면 → 시간순으로 엮으면 사건이 보인다"로 만든다. 위의 L4 합치기 제안과 같이 쓰면 Lesson 4가 6 Page가 된다.

12. `심각도 중` · L4 Page 3 「이 경보는 어떤 규칙이 울렸을까?」 · 문제: `alert tcp any any -> any 80 (msg:…; content:…; sid:…; rev:…;)` 한 줄을 읽게 한다. 초보에게는 문법 암기처럼 보이고, 규칙 형식을 외울 이유(Module 4와의 연결)가 Page 안에서 안 보인다. 포트 80이 곧 HTTP는 아니라는 경고는 좋다. · 제안: sid·rev 행은 빼고, "위치(누가 어디로) → 찾는 것 → 동작" 읽는 순서만 남긴다. 규칙 한 줄을 자세히 읽는 이유를 "오탐인지 알려면 규칙을 읽어야 한다"로 첫 문단에 분명히 적는다.

13. `심각도 중` · L2 Page 6 「한 대에 다 넣으면 무엇을 잃을까?」 · 문제: UTM 설명에서 G-to-G VPN, 웹 방화벽, IPS, 악성코드 검사를 나열하지만 아직 IPS·악성코드 검사는 Lesson 3에서야 나온다. 독자는 모르는 기능이 들어 있는 장비를 먼저 산다. · 제안: 기능 나열은 "방화벽·VPN·(뒤에서 볼 탐지 기능)"처럼 줄이고, 기능을 하나씩 켜 보며 확인하는 부분을 중심에 둔다.

14. `심각도 중` · 전체 문체 · 문제: 거의 모든 Page가 "…대가도 있다/하지만 대가는…" 문단과 "그래서 ~는 ~기로 한다" 마무리로 끝나고, 🔁 표시도 Page마다 나온다. 27 Page를 읽으면 리듬이 같아 지루하다. 한 Page에서는 좋은 형식이 반복돼 기계적으로 읽힌다. · 제안: 대가가 핵심인 Page(포트 차단, UTM, 오탐)는 그대로 두고, 나머지는 대가를 표 한 줄로 옮기거나 생략한다. 🔁는 새 모양을 발견하는 순간(L2 p4 표 3종)에만 쓴다.

15. `심각도 중` · 제목 약속과 내용 · 문제: Unit 제목은 "AI를 들인 회사, 정말 안전할까"인데 AI 특유의 위험(사내 문서를 읽는 AI 서버, 고객 도면)은 L1 p1 한 줄과 L3 p1에서 대상 서버로만 나오고 이후엔 일반 보안 제품 설명이다. L2 제목 "AI 서버로 가는 문"도 실제 내용은 일반 방화벽이다. · 제안: 각 Lesson의 첫 Page 도입에서 "AI 서버에 닿는 길"로 다시 연결하는 문장을 넣거나, 제목에서 AI 약속을 줄인다(제목 변경은 사용자 확정 사항이므로 본문 쪽을 고치길 권한다).

## 반박 (2차)

고친 원고(Lesson 4개, 25 Page)를 다시 읽었다. R14(대가 마무리 반복)는 "대가" 문장이 Unit 전체에서 약 22회로 Page마다 나오지는 않아서 철회한다. 아래 5개만 다시 주장한다.

1. `상` · 15-2 p2 「AI 서버가 사내 PC와 같은 구역이라면?」(R15 관련, 새로 생긴 문제) · 서버 구역 이전이 두 문장으로 끝난다. 독자는 "서버를 옮긴다"는 큰 작업이 이전 시연·VPN·한결봇 주소와 어떻게 이어지는지 모른다. `192.168.40.0/24`는 Unit 11~14에서 한 번도 나온 적이 없고, "이 Page부터는 새 주소를 쓴다"는 문장은 집필 메모처럼 읽힌다. 제안: "지우가 주말에 AI 서버를 서버 구역으로 옮기고, 박 팀장 PC의 접속 주소와 이름 기록을 고쳤다" 같은 장면 한 줄로 바꾸고, 새 주소가 왜 40번 대인지(방화벽 전용 포트 뒤 구역)를 한 구절로 밝힌다. 이 Page 앞에서 본 `192.168.10.50` 시연 규칙(p1)과 이후 `.40.50` 규칙이 한 화면에 섞이지 않는지도 확인해야 한다.
2. `중` · 15-1 p3 「포트를 내리면 끝일까?」(1,499자) · 포트 차단 설명, ARP 원리와 부작용, 4방식 표, 다음 Page 예고가 한 Page에 있다. ARP는 3문장이라 했지만 실제로 한 문단(약 5문장)이고, 표에서 안내 페이지와 802.1X가 설명 전에 나온다. 제안: ARP 문단을 2문장으로 줄이고, 표 앞에는 "앞의 두 방식"만 쓰며 표를 이 Page 마지막 비교로만 남긴다. 표 마지막 문단의 "이 Lesson의 목표가 이것이다"는 p5 도입으로 옮긴다.
3. `중` · 15-1 p6 「몰래 켠 와이파이는 누가 찾을까?」(1,553자 + 정리 상자) · RADIUS, TACACS+, WIPS, 허가 AP 목록, 오탐이 한 Page이고, 뒤에 "가져갈 것"과 생각법 상자까지 붙는다. 이 Lesson 생각법 상자에는 802.1X·WIPS 장면이 없고 p4 안내 페이지만 있어 상자가 Lesson의 중심(802.1X)을 놓친다. 제안: TACACS+ 괄호를 삭제하고, WIPS 4문단을 3문단으로 줄이며, 생각법의 ⚖️ 줄을 802.1X 예외 기기로 바꾼다.
4. `중` · 15-4 p2 「흩어진 로그를 이으면 무엇이 보일까?」(1,387자) · ESM 정의, 로그 표, MAC↔IP(DHCP) 연결, SIEM 정의, 상관 규칙, 시각 동기화, 계정(802.1X) 연결, 보관 정책이 모두 들어 있다. 개념 6개가 한 Page다. 독자는 DHCP 기록으로 MAC과 IP를 잇는 단계와 계정 연결을 구별하기 어렵다. 제안: ESM은 첫 문단 한 문장으로만 쓰고, 계정 연결과 보관 기간은 "대가" 문단에서 한 문장씩만 남기며, 마지막 Page의 "비어 있는 것" 표로 넘긴다(이미 거기에 있다).
5. `중` · 15-4 p6 「이제 안전하다고 답할 수 있을까?」(2,205자) · 서 이사 질문에는 이제 답한다(좋다). 그러나 Page가 여전히 가장 길다. 네 질문 표, 순서표, R/A/L 3줄, 생각법 5줄, 다리 3문장이 모두 남아 있고, "가져갈 것"과 생각법이 위 두 표와 거의 같은 말이다. 다리 문단은 "이어서 살펴볼 …에서 …방법으로 이어진다"가 세 번 반복돼 읽기 무겁다. 제안: R/A/L의 Recall은 한 줄로 줄이고 순서표 아래 한 문장으로 합친다. 다리는 세 Module을 "장부→Module 3 / 로그→Module 4 / 포트 내리기→Module 5" 한 줄씩 짧게 쓰고, 마지막 문장 "정책은 사람이 정한다"로 끝낸다.
