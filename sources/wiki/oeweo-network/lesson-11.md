# IPv4주소의 기본 구조

핵심 개념을 주제별로 정리했다.

## L2와 L3의 식별자

하위 계층에서 Ethernet과 브로드캐스트를 살펴보았으므로 L3의 IP로 넘어간다. 그 위에는 L4의 TCP·UDP, SSL 또는 TLS, 상위의 HTTP를 연결해 볼 수 있다. L2에서 중요한 식별자인 MAC 주소는 48비트 주소 체계를 사용한다. IPv4 주소는 이와 크기와 구조가 다르다.

## IPv4의 32비트 구조

IPv4는 32비트 주소 체계를 사용한다. 이를 8비트씩 네 부분으로 나누어 표현한다. 8비트로 만들 수 있는 경우의 수는 2의 8제곱인 256가지다. 0000 0000은 0, 1111 1111은 255이므로 표현 범위는 0~255다. 모든 비트가 1인 값을 보면 브로드캐스트처럼 특별한 용도인지도 생각해 볼 필요가 있다.

## 8비트씩 나눠 읽기

Windows에서 ipconfig를 실행하면 자신의 IP 주소를 확인할 수 있다. 공유기를 사용하는 환경에서는 192.168로 시작하는 주소를 볼 수 있으며, 이를 사설 주소의 예로 소개한다. 사설 주소의 의미는 뒤에서 다룬다. IPv4는 8비트씩 나눈 값을 점으로 구분한다. 각 부분에는 0~255만 들어갈 수 있으므로, 어느 부분에 256이 있다면 이 표기 방식에 맞지 않는다. 168을 2진수로 쓰면 1010 1000이다. 이 설명의 192에 대한 2진수 표기는 자릿수 확인이 필요하다.

## Network ID와 Host ID

192.168.0.10을 예로 들어 앞의 24비트를 Network ID, 뒤의 8비트를 Host ID로 나누어 보자. 여기서 세 부분을 묶은 길이는 8비트씩 세 번, 총 24비트다. 실제 경계는 어떤 기준으로 나누는지에 따라 정해지며, 그 기준은 이후에 다룬다. IP 주소는 인터넷에 연결된 호스트를 식별하는 번호이며, 내부적으로 Network ID와 Host ID라는 두 부분으로 구분해 이해할 수 있다.

## 주소를 나누는 이유

주소를 나누는 방식은 ‘서울시 강남구 역삼동’ 같은 지역과 그 안의 구체적인 번지를 나누는 것에 비유할 수 있다. Network ID를 지역, Host ID를 그 안의 상세 주소로 생각하면 된다. 인터넷에서는 IP 주소를 근거로 목적지까지 찾아가야 하므로, 먼저 어느 네트워크인지 구별하고 그 안의 호스트를 찾는 방식이 유용하다.

## 물류센터로 이해하는 라우터

인터넷은 도로망뿐 아니라 택배 물류 체계에도 비유할 수 있다. 배송 추적을 보면 택배가 여러 물류센터를 거쳐 특정 지역의 센터에 도착한다. 지역센터에서는 같은 동네로 갈 물건을 모아 트럭에 나누어 싣고, 그 뒤에 개별 주소를 찾아 배송한다. Network ID는 목적지 네트워크를 판별하는 데 쓰인다. 해당 네트워크에 진입한 뒤에는 그 안의 구체적인 호스트를 찾는다. 역삼동으로 갈 택배를 먼저 모은 다음 지번을 확인하는 것과 비슷하다.

## 주소 구조 정리

IPv4 주소는 Network ID와 Host ID로 나누어 이해한다. 표기할 때는 32비트를 8비트씩 네 부분으로 끊고 점으로 구분한다. 각 부분의 숫자는 0~255다. 이 구조를 기억하면 이후의 주소와 네트워크 구분을 이해하기 쉽다.
