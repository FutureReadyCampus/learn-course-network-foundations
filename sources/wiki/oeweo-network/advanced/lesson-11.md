# Symmetric NAT 방식

핵심 개념을 주제별로 정리했다.

## 주소와 포트를 함께 바꾸기

Symmetric NAT에서는 IP 주소와 포트 번호를 함께 변환한다. IP 헤더의 주소, TCP 또는 UDP 헤더의 포트가 어느 시점에 어떤 값으로 바뀌는지 따라가야 한다. 포트라는 말도 내부·외부·원격지에 따라 다르게 쓰이므로 각 위치를 구별한다.

## 내부 사설망과 외부 공인망

공유기의 내부 인터페이스를 192.168.0.1로 두고, 내부 PC를 192.168.0.10이라고 가정한다. PC는 공유기를 게이트웨이로 사용한다. 이 사설 주소는 공용 인터넷에서 그대로 사용할 수 없다. 공유기는 ISP에서 받은 Public 또는 Global IP를 외부 인터페이스에 사용한다.

## 내부 PC가 연결을 시작

PC가 설명용 웹 서버 abc.com에 접속하고, DNS가 그 주소를 15.15.15.15라고 알려 주었다고 하자. 클라이언트의 출발지 포트는 운영체제가 배정한 3000, 서버의 목적지 포트는 HTTP의 80으로 가정한다. 처음 생성한 패킷은 출발지 192.168.0.10:3000, 목적지 15.15.15.15:80이다.

## Outbound · 출발지 주소·포트 변환

Inline 장치인 NAT Gateway를 지나 외부로 나가는 Outbound 시점에 값을 바꾼다. 공유기의 공인 주소가 3.3.3.3이라면 출발지 IP를 이 주소로 바꾸고, 출발지 포트도 예를 들어 23000으로 변환한다. 인터넷으로 나가는 패킷의 출발지는 3.3.3.3:23000이 된다. 목적지 웹 서버는 그대로다. 공인 주소로 바뀌었으므로 외부 네트워크에서 응답할 수 있다.

## 웹 서버가 보는 접속 주체

웹 서버는 내부의 192.168.0.10보다 자신에게 직접 보이는 3.3.3.3을 접속 주체로 인식한다. 서버가 보는 연결 정보와 내부 PC가 보는 연결 정보가 달라지는 것이다. NAT의 기록이 만들어지는 계기는 이 예에서 Outbound 트래픽이다. 이 기록을 바탕으로 외부 응답을 내부 장치에 전달한다.

## NAT Table에 남기는 기록

공유기는 내부 IP·포트, 원격 서버 IP·포트, 바꾼 외부 포트를 NAT Table에 기록한다. 메모리에 둔 간단한 데이터베이스라고 생각할 수 있다. 이 예의 기록은 내부 192.168.0.10:3000이 원격 15.15.15.15:80에 접속하며 외부 포트 23000을 사용했다는 대응 관계다. 이 기본 동적 매핑은 Outbound에서 만들어지며, 이후 Inbound는 그 기록을 찾아 되돌리는 데 사용한다.

## 서버에서 응답이 돌아오기

웹 서버가 SYN에 대한 SYN+ACK를 보내면 패킷의 출발지는 15.15.15.15:80, 목적지는 3.3.3.3:23000이다. 공유기는 원격지 IP와 포트, 외부 매핑 포트 등을 근거로 NAT Table을 검색한다. 일치하는 기록을 찾으면 이 응답이 어느 내부 호스트의 통신인지 알 수 있다.

## Inbound · 원래 PC로 되돌리기

Inbound 시점에는 목적지를 원래의 192.168.0.10:3000으로 바꾸어 내부 PC에 전달한다. 서버가 보낸 3.3.3.3:23000이라는 목적지 정보가 내부의 주소와 포트로 복원되는 것이다. Outbound의 출발지 변환과 Inbound의 목적지 복원을 한 쌍으로 이해해야 한다.

## 다른 PC의 연결도 구분하기

다른 PC인 192.168.0.11도 같은 서버에 접속할 수 있다. 내부 포트가 4000이고 공유기가 외부 포트 23001을 배정했다고 가정하면, 별도의 NAT 기록이 생긴다. 내부 호스트가 여러 개여도 서로 다른 변환 정보를 이용해 각각의 응답을 올바른 PC로 돌려보낼 수 있다.

## 서버가 구별하는 연결

서버 관점에서는 두 내부 호스트가 접속한 사실보다 공인 주소 3.3.3.3에서 서로 다른 포트로 두 번 연결한 것으로 보인다. 발생량 기반 탐지처럼 IP 단위로 판단하는 기능과도 관계될 수 있다. 공유기는 Outbound에서 사설 출발지 주소·포트를 공인 주소·외부 포트로 바꾸고 기록한다. 외부 포트를 ‘지정한다’는 말이 공유기 애플리케이션이 실제로 그 포트의 소켓을 열었다는 뜻은 아니다.

## Local·Remote·External 용어 정리

공유기 안쪽 호스트와 포트는 Local, 바깥의 서버 주소와 포트는 Remote, 변환한 바깥 포트는 External이라는 용어로 구별한다. 응답이 오면 이 정보를 이용해 매핑을 찾아 내부 목적지로 복원한다. 포트의 많은 값을 나누어 관리하고 재사용하므로 여러 호스트가 하나의 공인 주소를 함께 사용할 수 있다. 약 6만 5천 개 규모의 포트 값과 일반적인 실제 사용량을 비교해 설명한다. Local·Remote·External의 대응과 NAT Table을 이해하면 이후 방화벽의 기록과 통신 허용 원리도 연결해 보기 쉽다.
