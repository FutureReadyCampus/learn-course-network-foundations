# 네트워크 보안 솔루션 종류

핵심 개념을 주제별로 정리했다.

## 보안 장치를 세 가지 구조로 보기

네트워크 보안 장치도 먼저 Inline, Out of path, Proxy 중 어떤 구조인지 살펴보면 이해하기 쉽다. Inline과 Out of path는 패킷을 다루고, User mode 애플리케이션인 Proxy는 소켓 수준에서 조립된 Stream을 다룬다. 앞서 본 세 구조를 보안 솔루션에 적용해 보는 복습이다.

## PC 방화벽과 NAC

PC 방화벽은 개별 PC에서 작동하는 예다. NAC(Network Access Control)는 네트워크 접근을 통제하는 체계다. 이 절은 인증 기반의 표준적인 구성과, PC 방화벽·Probe 센서 등을 결합한 구성을 구별한다. 이 차이는 이후 접근통제 방법을 비교할 때 다시 살펴본다.

## 방화벽·IPS·망분리의 배치

패킷 필터링 방화벽과 IPS는 기본적으로 Inline, NIDS는 Out of path의 탐지 구조로 설명한다. VPN은 경로상의 게이트웨이로, SSL 가속기와 WAF는 Proxy로 구성되는 예가 있다. UTM은 여러 보안 기능을 한 장비에 결합한다. 망분리와 망연계도 등장하지만 방화벽이나 VPN과 완전히 같은 개념은 아니다. 이름보다 어디에 놓여 어떤 데이터를 처리하는지 살펴보아야 한다.

## NIDS와 Proxy 기반 보호

앞단 IPS에서 패킷을 통과시키거나 차단하고, SSL 처리 뒤 평문이 된 요청을 WAF가 검사하는 구성을 생각할 수 있다. Out of path의 NIDS는 경로를 직접 통과시키는 대신 복사본으로 추가 관찰을 한다. 여러 검사가 서로 다른 위치에서 서버를 보호하는 구조다.

## OSI 계층에 장치를 놓아 보기

OSI 그림에는 아래의 Ethernet과 IP, L4의 TCP·UDP, 상위의 SSL과 HTTP를 연결해 볼 수 있다. TCP의 데이터 단위는 Segment, L4에서 중요한 식별자는 포트 번호다. 보안 장치가 어느 계층의 정보를 보는지 파악하는 기준이 된다.

## NAC · 네트워크 접근통제

IP는 Packet과 IP 주소, L2는 Frame과 MAC 주소, 소켓 위 애플리케이션은 Stream과 연결한다. 보안 솔루션마다 패킷 헤더를 볼지, 상위 Stream을 볼지가 다르다. 이 절은 L2~L3 수준에서 IP·MAC의 대응을 관찰해 네트워크 접근을 통제하는 NAC 형태를 소개한다. 표준적인 인증 구성과의 차이는 뒤에서 다시 설명한다.

## ARP를 이용한 접근 유도

IP와 MAC 주소를 쌍으로 관리하고 허용되지 않은 호스트를 발견하면 접근을 막는 방식이 있다. 스위치 포트를 내려 물리적인 Link를 끊거나, ARP 관련 정보를 이용해 게이트웨이 접근을 방해하는 방식 등을 예시에서 비교한다. ARP를 이용한 방식은 네트워크 장애를 일으킬 수 있다. LAN을 특정 계층과 연결한 설명은 개념을 구분하기 위한 관점이며 엄밀한 정의와는 구별한다.

## HTTP Redirect 방식

Probe가 트래픽을 관찰하고 허용되지 않은 사용자의 HTTP 접속을 안내 페이지 등으로 Redirect하는 구성이 있다. 로컬 네트워크에서 빠르게 반응할 수 있다는 설명이다. 또 다른 방식은 스위치와 인증 서버가 연동해 접근을 허용하는 것이다. RADIUS 같은 인증 체계를 이용해 인증된 대상만 네트워크에 접속하게 한다. 이 절은 이를 인증 기반 NAC의 기본 형태로 설명한다.

## 무선·단말 접근통제

무선에서는 WIPS 같은 접근 탐지·차단 체계도 생각할 수 있다. 보안상 무선 사용을 금지한 조직에서 몰래 사용하는 무선 NIC나 정보 유출 경로를 찾아 제한하려는 목적이다. 무선 접속도 RADIUS나 TACACS 등의 인증 체계와 연결될 수 있다. 인증 후 접속을 허용하는 구성과, 허가되지 않은 무선 사용 자체를 찾아 막는 목적을 구별하면 된다. 원문에 혼재한 약어 표기는 자료와 대조해 읽을 필요가 있다.

## Packet Filtering과 방화벽

Packet Filtering Firewall은 IP 주소와 포트 번호 등을 보고 허용과 차단을 결정하는 Inline 장치다. NAT가 다루는 정보 범위와도 연결해 생각할 수 있다. 상위 애플리케이션에서 Proxy로 구현하는 방화벽도 있으며 두 방식을 결합하면 Hybrid라는 표현을 사용한다. Stateful Inspection은 TCP 연결의 상태 변화를 추적해 판단하는 것과 연결된다. 연결 전·중·후의 전이를 보고 비정상적인 상황을 인지하려면 세션을 추적할 수 있어야 한다.

## 세션 관리와 Hybrid 방화벽

동시에 관리할 수 있는 세션 수는 이런 장비의 성능을 설명하는 기준 중 하나다. WAF처럼 소켓 Stream의 HTTP를 보는 장치와 패킷 헤더를 보는 장치는 관찰 수준이 다르다. G-to-G VPN은 Inline Gateway 형태의 보안 기능과 연결된다. 패킷 필터링, NAT, 라우팅, VPN, 웹 방화벽 등을 한 장비에 결합할 수도 있다.

## VPN·SSL VPN

여러 위협 대응 기능을 통합한 장비를 UTM(Unified Threat Management)이라고 부른다. 한 대로 여러 기능을 제공하는 편의가 있지만, 고성능 개별 장비와 비교한 처리 성능도 고려해야 한다. 이 절은 중소 규모 환경의 통합 구성 예로 소개한다. SSL VPN은 애플리케이션 수준의 VPN이라는 관점으로 설명한다. 특정 웹 서비스를 Proxy 방식으로 제공하는 예를 들며 앞서 본 IPsec 기반 Gateway 구성과 비교한다.

## 기본 필터링에서 능동적 탐지로

Screening Router는 ACL(Access Control List) 규칙으로 간단한 허용·차단을 할 수 있다. 패킷 필터링 방화벽의 일부 기능과 비슷한 관점이다. 이 절은 이런 정책 기반 체계를 철조망 같은 보안 인프라에 비유한다. 무엇을 허용하고 막을지 정하는 Policy가 중요한 단계다.

## IPS와 NIDS

이보다 더 안쪽의 Payload와 상위 내용까지 살피는 DPI 기반 탐지로 확장할 수 있다. 대표적인 장치는 Inline의 IPS와 Out of path의 NIDS다. IPS는 탐지 후 차단할 수 있고, NIDS는 경로 밖에서 탐지를 수행한다. IP·포트·상태 외에 내용의 패턴까지 판단하므로 탐지 Rule이 중요해진다.

## DPI와 Signature 검사

Signature 검사는 Payload 안에 특정 패턴이 있는지 찾는 방식이다. 그러나 이것만으로 알려지지 않은 파일형 악성코드를 모두 막기는 어렵다. Sandbox는 가상 환경에서 의심 파일을 실행하고 이상 행동을 관찰하는 방식으로 소개한다. 이 절은 이를 MPS라는 악성코드 방지 체계와 연결하지만, 이것도 완벽한 해결책은 아니라고 설명한다. 이후 클라우드의 추가 분석·평판 정보와 결합하는 방향으로 이어진다.

## Reputation · 평판을 활용

Reputation 시스템은 파일이나 대상이 알려진 악성 항목인지, 신뢰할 만한지에 관한 평판 정보를 참조한다. 장비 자체 분석과 외부 정보를 함께 활용할 수 있다. 다양한 탐지 Rule이 작동하면 정탐·오탐의 판단과 함께 많은 로그가 발생한다. 여러 보안 장비의 기록과 상태를 관리하는 체계가 필요해진다.

## ESM · 로그를 모아 분석

ESM(Enterprise Security Management)은 여러 보안 장비의 관리와 로그·상태 관찰을 통합하는 개념으로 설명한다. 로그가 방대해지면 모아서 분석하고 사건을 따라 추적할 필요가 있다. SIEM(Security Information and Event Management)은 이런 통합 분석과 연결된다. 예시에서 앞뒤로 혼재한 약어는 여기서 각각의 역할에 맞춰 구분했다.

## NIDS 탐지 규칙 읽기

NIDS Rule의 예에는 Alert라는 동작, TCP라는 프로토콜, 출발지·목적지 IP와 포트 조건, 검사할 Content가 있다. 출발지를 제한하지 않고 목적지 포트 80을 보는 예라면 웹 통신을 대상으로 이해할 수 있다. Payload 안에 ‘테스트’라는 문자열이 있으면 ‘테스트어택’이라는 로그를 내는 식이다. 이 문자열이 Signature가 된다. Rule에는 식별자와 수정 버전(Revision) 등의 정보도 있다. 기본은 조건과 패턴의 조합이다. 어느 범위의 어떤 데이터를 검사해 어떤 동작을 할지 읽을 수 있어야 한다.

## 여러 보안 기능의 결합

네트워크에는 라우터와 일반 스위치뿐 아니라 보안 스위치와 탐지 장치도 함께 작동한다. IPS나 NIDS의 Rule을 바꾼 뒤 이전에 없던 장애나 이상 현상이 나타날 수 있다. 따라서 각 장치가 어디에 있고 무엇을 검사하는지 알아야 네트워크 문제의 원인도 살펴볼 수 있다.

## 구조별 역할 정리

보안 솔루션을 만났을 때 Inline·Out of path·Proxy 중 어떤 구조인지, 다루는 데이터가 Packet인지 Stream인지 먼저 구별하면 된다. 기초편과 응용편은 여러 기술의 큰 흐름을 연결해 설명하는 과정이다. 각 주제를 더 깊이 이해하려면 이후 별도의 자료와 실습으로 보충하면 좋다.
